# 脚本型 Bot 使用用户维护的 TypeScript 与已有 Bun，复用节点交接流程

2026-11-16 修订：原先将两个 Rust 能力编入后端，用户不能自行添加并绑定脚本，改动也要重建后端。改用用户维护的 TypeScript。Bot 的 `script` 是普通 Task 和 Map 之外的互斥目标。后端用部署者提供的独立 Bun 进程加载脚本，不捆绑或自动安装运行时，也不依赖 Pi 或 OMP 内嵌的 Bun。不新增脚本管理界面。[脚本编写与绑定](../usage.md#动态-typescript-脚本)由使用说明维护。

脚本是可信本机代码，具备执行账户的文件、网络和进程权限。路径检查和独立进程都不是沙箱；依赖须预先安装。后端负责运行与交接，脚本负责业务，不另建固定能力注册表。脚本修改系统定义时仍须遵守文件协调、revision 与合法保存约束，不直接覆盖内部 JSON。

脚本复用现有派发、命名文件绑定和报告，不伪造节点 Chat 或会话，也不在业务执行期间持有 Run 操作锁。正常退出不代表成果成功。宿主核实结构化结果和约定输出，批准有效的成功成果并生成报告；manager 仍显式 complete。失败保留真实部分效果和有效材料，不自动回滚、重试、跳过或派发下游。

## 两个发布脚本与迁移范围

只把创建流程的空白创建与四字段合并保存交给脚本，不把通用 `replace-text` 从修订流程移走，也不为两例构建通用替换引擎。保留稳定 Bot 引用和命名交接，不重写历史 Chat。迁移做法见[脚本空白 Bot 创建](../usage.md#脚本空白-bot-创建)。[V1 业务材料契约](../business-materials.md#创建分支-v1可校验表示与空白创建)维护严格命名输入、真实基线、目标与 revision 检查和写后完整读回。V1 不把人类批准凭据嵌入业务材料；通用成果批准仍是独立执行事实。此约束不改写 V2 的专用契约，也不要求任意脚本提交指南或 handoff。

## 验收边界

在隔离数据上通过真实 Map 节点执行验证创建空白 Bot、四字段正文合并保存、完整读回、文件交接、报告通知及 manager 完成流程，不以直接调用脚本函数替代端到端验证。验证目标冲突、原文或 revision 不匹配时不误写、不报告成功。生产数据不用于破坏性验收。
