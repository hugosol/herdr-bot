# 脚本型 Bot 使用编入后端的 Rust 能力，复用节点交接流程

已确认的设计；本文不表示实现或实际运行验收已完成。

Bot 增加与普通 Task、Map 互斥的固定脚本执行目标，用于不需要 Chat 的确定性工作。业务逻辑使用 Rust 编入后端，由固定能力标识选择；不执行临时生成的代码，不引入外部解释器、独立可执行文件或沙箱。这样发布后无需另装语言环境，代价是能力变更需要重新构建后端。

manager 通过现有派发入口启动工作后立即返回，后端异步执行 Rust 业务并接入共享报告处理，保存结果并通知 manager；不增加等待批次机制，业务执行不得长期占用 Run 操作锁。复用文件输入解析、输出绑定、报告及完成规则，不伪造节点 Chat 或 session 身份。脚本自动报告，结束时回收执行资源，没有 Chat 或 Tab 需要关闭。manager 使用现有等待与报告读取机制，并显式 complete 后继续安排下游；不增加自动完成、自动派发、自动重试、回滚或跳过功能。异常保留错误与实际效果，由用户或 agent 修复并显式重跑。

脚本复用 input_rule、output_rule 及命名文件绑定，不消费 node.input 自然语言指示。业务请求和必要材料采用严格结构化格式，缺项、歧义或冲突直接拒绝；不进行自然语言语义判断，也不将其转移为隐含的 manager 职责。Rust 仅在确定性检查、真实写入及完整读回均成功后报告 canComplete=true，manager 无需重复语义验收，但仍调用原有 complete。报告保存不等于节点完成。

- 空白 Bot 创建者：保留 create-blank-bot 的身份和现有 Map 引用，改为 Rust 执行目标；替代验证后删除原 Task task-18e33fdc55177d1c-1，不兼容该 Task 的历史来源恢复需求，不迁移或删除历史 Chat 数据。
- 通用文本替换者：保留 replace-text 的名称、能力、Task 绑定及修订流程用途，不收窄其语义。另建三份指南为空的创建流程专用脚本 Bot，负责三路指南合并、合法保存和完整读回；仅将 create-bot-wrapper.json 的 save_bot 改为引用新 Bot。不增加 Map 私有 Bot 或禁止复用机制。
- 两个 Rust 实现只覆盖当前创建流程的固定输入输出，不建设通用替换引擎。保留现有输入输出 ID 和材料接线，仅在创建流程收紧 request、baseline 及必要交接材料格式，同步调整生产与消费要求，不改变原通用替换 Bot 或修订流程契约。
