# Suite 按单一 harness 分型，保留统一管理

Pi 与 oh-my-pi（OMP）的技能选择、扩展及专属配置语义已经分化。决定将 Suite 从可同时适用多个宿主的实体改为仅属于一个 harness 的配置类型：Pi Suite 与 OMP Suite 分别拥有有效字段、校验和装配规则，不再接受另一宿主的字段后静默忽略。保留 Suite 作为场景工具集的业务统称，不扩展其职责去承载 Task 的模型或初始指示。

本决策已落实为单值 `harness` 的配置与 HTTP 表示、独立宿主字段及编辑器约束；仓库权威 Suite 与 Task 引用已一次性迁移。原生消费和恢复须以对应验收结果判断，类型转换本身不代表原生验收通过。

## 边界与取舍

- 保留一份 Suite 权威清单、统一 API、统一管理入口和全局唯一 ID，不拆成两套存储或管理系统。公共身份字段共享，单值 harness 决定专属配置结构，不再使用多宿主选择及双宿主资源映射。
- 创建时单选 harness，保存后不可切换；需要另一宿主时新建 Suite，不自动转换或清空不兼容字段。编辑器只显示所选 harness 的有效字段。
- Pi 保留单技能目录、Pi 扩展、prompt templates、codemode 和独立的 MCP 选择；OMP 支持集合与单技能目录的显式来源对象、OMP 扩展、LSP 和独立的 MCP 选择。
- 底层资源目录、集中 MCP 定义、路径解析、存储及其他通用设施尽量共享。共享资源定义不意味着共享 Suite 选择：修改一份 Suite 的选择不影响另一份；修改双方引用的资源定义仍可能影响双方。
- Task 只能选择匹配其 agent 的 Suite。切换 agent 后若原 Suite 不兼容，必须显式重选或取消选择后才能保存，不按名称自动配对、不自动转换或静默清空。
- Suite ID 统一以 `-omp` 或 `-pi` 标明 harness，显示名称统一以 `· OMP` 或 `· Pi` 标明归属。

接受两份 Suite 可能重复声明相同资源选择的维护成本，换取独立身份、生命周期和配置演进；拒绝仅拆表单而保留双宿主实体，也不为配置类型独立而复制所有底层设施。

本决策在身份层进一步收紧 [ADR 0018](0018-host-specific-native-skill-paths.md) 的宿主边界，取代同一 Suite 内按宿主分别声明资源的结构；其原生技能路径、发现隔离及启动产物生命周期约束保持不变。

## 一次性迁移

备份配置并停止服务写入后，一次性转换全部现有 Suite 及其有效结构化引用，校验通过后启动新版本。不保留旧格式兼容层或旧 ID 别名，不热更新已有 agent 进程；新配置用于后续启动或需要新进程的恢复。

双宿主 `codebase-exploration` 拆为 `codebase-exploration-omp` 与 `codebase-exploration-pi`，各自保留适用资源并复制原有 MCP 选择，按 Task 原有 agent 更新 Suite 引用。其他现有 Suite 同样统一添加对应宿主后缀并迁移引用，不改变 Task ID 或 agent。实施时重新读取数据、检查 ID 冲突及引用完整性，不依赖设计讨论时的记录数量。

Chat 历史登记保存来源 Task ID，而非 Suite 引用或配置快照；保持 Task ID 不变即可在恢复时取得迁移后的最新环境，无需重写历史登记。检查其他持久数据中实际存在的 Suite 结构化引用，仅更新相关引用；不全文替换提示词、原生聊天正文或其他历史文字，不修改已有启动产物，不推测缺失的来源 Task 关联。

## 实施验收边界

后续实现须覆盖两种类型的保存与字段拒绝、harness 不可变、Task 兼容性约束、一次性迁移后的引用完整性，以及两宿主的真实启动与历史 Chat 恢复。文档确认不代表这些行为已实现或已验证。
