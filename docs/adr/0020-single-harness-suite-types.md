# Suite 按单一 harness 分型，保留统一管理

Pi 与 oh-my-pi（OMP）的技能选择、扩展及专属配置语义已经分化。决定将 Suite 从可同时适用多个宿主的实体改为仅属于一个 harness 的配置类型：Pi Suite 与 OMP Suite 分别拥有有效字段、校验和装配规则，不再接受另一宿主的字段后静默忽略。保留 Suite 作为场景工具集的业务统称，不扩展其职责去承载 Task 的模型或初始指示。

本决策已落实为单值 `harness` 的配置与 HTTP 表示、独立宿主字段及编辑器约束；仓库权威 Suite 与 Task 引用已一次性迁移。原生消费和恢复须以对应验收结果判断，类型转换本身不代表原生验收通过。

## 边界与取舍

- 保留一份 Suite 权威清单、统一 API、统一管理入口和全局唯一 ID，不拆成两套存储或管理系统。公共身份字段共享，单值 harness 决定专属配置结构，不再使用多宿主选择及双宿主资源映射。
- 创建时单选 harness，保存后不可切换；需要另一宿主时新建 Suite，不自动转换或清空不兼容字段。编辑器只显示所选 harness 的有效字段。
- Pi 保留单技能目录、Pi 扩展、prompt templates、codemode 和独立的 MCP 选择；OMP 支持集合与单技能目录的显式来源对象、OMP 扩展及独立的 MCP、LSP、DAP 选择。
- MCP、LSP、DAP 分别使用集中目录，每个选项独占一个 JSON 文件，文件名提供稳定 ID。各 Suite 只引用选项 ID；修改一份 Suite 的选择不影响另一份，编辑它们共同引用的定义则影响后续各自的装配。页面可编辑已有选项，选项创建或删除仍由文件维护者管理；不改变原生宿主的优先级或加载规则。
- Task 只能选择匹配其 agent 的 Suite。切换 agent 后若原 Suite 不兼容，必须显式重选或取消选择后才能保存，不按名称自动配对、不自动转换或静默清空。
- Suite ID 非空、全局唯一，仅允许英文字母、数字、连字符和下划线，不要求宿主后缀；宿主匹配依据 `harness` 字段。读取权威文件与创建、编辑时均执行通用校验。显示名称仍统一以 `· OMP` 或 `· Pi` 标明归属。已有 ID 及其引用不因取消后缀约束而改名。

接受两份 Suite 可能重复声明相同资源选择的维护成本，换取独立身份、生命周期和配置演进；拒绝仅拆表单而保留双宿主实体，也不为配置类型独立而复制所有底层设施。

本决策在身份层进一步收紧 [ADR 0018](0018-host-specific-native-skill-paths.md) 的宿主边界，取代同一 Suite 内按宿主分别声明资源的结构；其原生技能路径、发现隔离及启动产物生命周期约束保持不变。

## 一次性迁移

只迁移 Suite 及仍被执行读取的结构化引用，不保留旧格式兼容层或旧 ID 别名。按 Task 现有 agent 匹配拆分后的 Suite，保留 Task ID。Chat 历史只记录来源 Task，恢复通过同一 Task 读取最新环境，因此不重写历史、不猜来源、不修改旧启动产物或热更新进程。现有部署按[从多宿主 Suite 一次性切换](../usage.md#从多宿主-suite-一次性切换)停服、备份和迁移。

## 实施验收边界

持续核对两种类型的保存与字段拒绝、harness 不可变、Task 兼容性，以及迁移后的引用完整性。两宿主实际启动与历史 Chat 恢复须有原生消费证据，不能由配置保存或迁移结果代替。
