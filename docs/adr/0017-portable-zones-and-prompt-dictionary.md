# 可移植定义分离 zone 身份、本机绑定与提示词词典

- 状态：accepted
- 日期：2026-11-03

为让同一 Map 在不同 server 使用，zone 由路径身份改为用户指定的稳定 ID，各 server 独立绑定本地目录。推荐 `namespace/name`，但不把 Git remote 或命名格式作为身份校验依据；一个 ID 对应一个目录，不同 ID 可以共享目录。Map 的 node 引用 ID，直接文件输入使用 zone 内相对路径及可选 zone ID，省略时使用本次 manager zone，而不是执行 node 的 zone。这扩展了 ADR 0009 的 zone 模型，不改变其与 Herdr Workspace 的术语区分。

Run 启动时检查并记录所需绑定，后续派发使用本次路径；改绑和取消登记只影响新 Run，避免一次运行悄然跨目录，也不需要为运行增加登记编辑锁。文件在派发时检查存在性及 zone 安全边界，报告产物仍保存真实本机地址。定义可跨 server 共享不意味着文件同步、内容一致或 Run/Chat 历史可迁移。旧路径定义通过显式映射迁移，不长期保留“ID 或路径”双语义。

提示词参考信息使用独立本机词典，与程序路径根配置、zone 执行绑定分开。统一 module 在明确的配置字段消费处进行单次替换，不解释用户输入、报告或产物，不递归或执行表达式；定义持久化保留占位符。系统发起 Chat（含流程派发）时，仅当替换前的 Task 固定 prompt 存在未转义且完整闭合的 `${key}` 引用，才追加词典路径及规则；不扫描用户输入、其他消息段或替换值，`$${key}` 和未闭合写法不触发。这样避免无词典引用的 slash 命令将公共说明误作参数；含词典引用的 slash 命令仍须自行满足命令参数协议。agent 直接读取原始 Map/Bot 文档时自行查值，不要求所有文件读取都经过解析视图。这样保留普通文件的可编辑性并避免重复模板实现，代价是直接读取的完整性由 agent 指引约束；系统实际发送时已经发现的缺失标签仍须明确拒绝。词典按每次消息组装读取最新内容，不随 Run 固定。
