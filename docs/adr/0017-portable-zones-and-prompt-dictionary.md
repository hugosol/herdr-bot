# 可移植定义分离 zone 身份、本机绑定与提示词词典

- 状态：accepted
- 日期：2026-11-03

为让同一 Map 在不同 server 使用，zone 由路径身份改为用户指定的稳定 ID，各 server 独立绑定本地目录。推荐 `namespace/name`，但不把 Git remote 或命名格式作为身份校验依据；一个 ID 对应一个目录，不同 ID 可以共享目录。Map 的 node 引用 ID，直接文件输入使用 zone 内相对路径及可选 zone ID，省略时使用本次 manager zone，而不是执行 node 的 zone。这扩展了 ADR 0009 的 zone 模型，不改变其与 Herdr Workspace 的术语区分。

固定 node zone 与直接文件输入引用的 zone 在 Run 启动时检查并记录绑定，后续派发使用本次路径；改绑和取消登记只影响新 Run，避免一次运行悄然跨目录，也不需要为运行增加登记编辑锁。

2026-11-16 扩展：允许显式声明动态 zone，以支持上游在 Run 中才创建并登记执行位置。manager 为每次派发或重试选择登记 ID，系统将 ID 与路径固定到本次 execution，而不是固定到整个 Run。无默认位置，也不改写 Map 或覆盖固定绑定；恢复原执行不重新选址。相同 Map 可并发运行，各自保留实际选址。文件来源与 node 执行位置仍是独立约定。定义可共享不代表同步文件、保证内容相同或迁移 Run 与 Chat 历史。旧路径定义须显式映射，不长期兼容“ID 或路径”。操作见[跨 server 使用 zone 与定义](../usage.md#跨-server-使用-zone-与定义)。

提示词参考值由独立的[本机提示词词典](../usage.md#本机提示词词典)提供，不与程序路径根或 zone 绑定混用。系统只替换指定配置字段，不引入通用模板或修改原始定义。读取原始 Map 或 Bot 时由 agent 按指引查值。这保留了定义文件的可编辑性，不强制所有读取经过中间层。只有 Task 固定提示词确实引用词典，系统才附上读取说明，避免无引用的原生 slash 命令误把说明作为参数。发送时发现未知标签则明确失败。
