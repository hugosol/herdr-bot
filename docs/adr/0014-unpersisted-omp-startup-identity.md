# 接受尚未落盘的 omp / pi 启动身份

2026-10-29 补充：pi 同样先分配会话 ID 和路径，首次用户或助手消息出现前不创建原生文件。下述受限启动身份规则同时适用于官方 `herdr:pi` 引用及 pi 的相同时间戳与 UUID 文件名约定；pi 不接受 omp 专属的标题元数据行。此扩展也覆盖可信启动历史对应的未落盘当前 Chat 定位，但不改变实际新进程恢复时的文件及原身份确认要求。

omp 在新会话中先分配原生 ID 和文件路径，默认在产生 assistant 消息后才创建会话文件。Herdr 官方集成优先上报路径，而 workflow 要求先保存真实身份关联再提交初始指示，因此不能把文件尚未落盘等同于会话不存在。只修改 herdr-bot，不修改 Herdr 集成、不预先发送任务、不伪造原生文件：对本次新启动的 omp，仅当官方 `herdr:omp` 引用为绝对路径、文件打开失败为 NotFound、文件名符合 omp 的时间戳与 UUID 约定且有实际进程 cwd 时，接受路径中的原生 ID。

这是对 Herdr 引用和 omp 命名约定的显式信任，不等同于文件头验证。文件存在时仍以文件头为准；权限、损坏、非标准路径及 omp / pi 之外的 agent 不使用此例外。取得身份后照常先保存 Run 关联和历史，再提交初始指示；历史保留预期文件路径及仅由可信发起流程写入的 `startupIdentityPath`，不承诺文件已落盘或当前可恢复。

Resume 仅对保存的原生 ID、`startupIdentityPath` 与当前官方路径引用完全吻合的未落盘候选允许定位，不向任意历史或其他候选推广。实际读取已保存身份对应的文件时若发现 ID 冲突，明确拒绝，不跳过冲突后启动另一 Chat，也不覆盖原身份。新进程恢复仍须确认原身份，不因路径符合命名约定就声称恢复成功。

不新增后台落盘轮询、补关联、自动改绑或原生文件修复，不改变现有失败 Run。没有选择延长等待（无法消除首次输入前不落盘的依赖环）或先提交任务（会让尚未关联的 Chat 开始执行）。此决定依赖 omp 的原生文件名约定；约定变化应明确拒绝，而非猜测。
