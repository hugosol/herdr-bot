# 统一文件持久化采用常用操作与协调范围

- 状态：accepted
- 日期：2026-10-30

文件是本系统的持久化载体。系统持久数据的读取、枚举、创建、替换、追加和删除，以及产品代码直接执行的文件系统变更，统一经过 `files` module；业务不直接使用原生文件操作、文件句柄或文件锁。采用“常用操作＋协调范围”的 interface：常用读改存及条件发布隐藏完整文件协议，复杂操作通过受限访问对象组合；业务仍拥有数据校验、状态转换与引用规则。目标是集中文件正确性知识的 locality，并让 Task、zone、Chat、Map、Bot、Run 和启动迁移共享 leverage，而不是建立仅转发 `std::fs` 的 shallow module。

协调覆盖一次读取、检查和修改；文件范围与目录子树范围发生重叠时互斥，不相交的数据仍可独立推进。所有入口共用同一实例进程内的协调机制，不以全局持久化锁串行化全部文件操作。路径身份处理不得绕过既有链接和重解析点拒绝规则。Run 的业务操作锁与文件协调独立：前者可以覆盖外部 Chat 启动，后者不得跨越 Herdr、Git 或其他外部效果。持久化 module 不接管业务缓存和通知，也不把文件成功等同于全部业务步骤成功。

统一文件持久化本身保留文件路径、JSON／JSONL 格式、缺失文件策略、条件写入、新建不覆盖、损坏记录拒绝及部分生效语义。后续定义数据布局调整将 Task、Bot、Map 的默认路径移至 `meta-data`，不改变统一文件入口或业务格式。不新增跨文件事务、自动重试、自动修复、通用回滚、多进程写入协议或断电恢复保证。Run 当前事实成功而历史失败仍须明确反馈部分生效；zone 目录创建后 Git 初始化或登记失败仍按 ADR 0007 保留目录。启动迁移保留已有目标的权威性与旧源数据。定义布局切换不沿用 zone 的“已有目标直接优先”规则：Task／Bot／Map 新旧内容不一致时拒绝启动，避免静默丢失定义；目标缺失时复制旧源，完全一致时确认切换，分项记录完成后不再读取旧备份。显式自定义位置不参与默认布局迁移。定义可通过 UI 或手工编辑并纳入 Git，运行事实仍保留在 `.data`；node 的 zone 绑定不随目录调整改变。

不采用通用命令计划解释器：它会让普通读改存承担结果槽位、条件和数据依赖的额外语言。也不只提供一个大回调，让所有业务继续重复常见保存协议。当前没有第二种实际存储 adapter，不为假想数据库引入存储 trait 或领域 repository 框架。

测试夹具可使用原生文件操作制造记录和故障。外部 Git／Herdr 自身执行的写入不由此 module 接管；zone 文件浏览、Git 工作树观察、原生 Chat 和扩展入口等外部内容的只读访问不自动扩大到系统持久化范围。配置文件与 Task 选项目录的读取属于统一入口。
