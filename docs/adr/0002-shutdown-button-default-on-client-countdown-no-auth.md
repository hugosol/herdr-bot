# 关机按钮默认开启、倒计时在前端、配置在前端项目、暂不做认证

- 状态：accepted
- 日期：2026-09-30

控制面板新增“关机”按钮；点击后弹窗确认，确认后由**前端**做可见倒计时（默认 10 秒），期间可取消，倒计时结束前端才 `POST /api/shutdown`，后端随即触发本机 Windows 关机。刷新或关闭页面会丢失倒计时，也就是不发送关机信号（用户明确接受）。服务端不保存倒计时状态，也不提供取消接口；关机与“停止”是两个独立动作：不参与执行资格、不因有脚本在执行而禁用或告警、也不先执行停止脚本。

关机的全部配置都在前端项目里，是**构建期常量**（`frontend/src/config.ts`）：倒计时秒数与是否显示按钮。后端不提供 `[shutdown]` 配置段，`POST /api/shutdown` **永远注册**；前端的“关闭”只隐藏按钮，不关闭端点。改这些值需要重新 `npm run build`。

## 备选与代价

- 备选：服务端权威倒计时 + 取消接口（用户否掉，刷新丢失信号可接受、客户端实现最小）；`[shutdown] enabled` 留在 `omp-bot.toml`、页面通过能力接口读取（用户否掉，选择配置全放前端）；后端把配置注入页面（用户否掉）。
- 代价：没有运行时关闭开关——要关掉关机入口只能改前端重新构建；且任何能访问监听端口的局域网设备都可以绕过页面的倒计时，直接调用端点立即关机。关机不可逆，误触发无法撤销。
- 因此交付文档必须写明“仅可信局域网、端点可被任何 LAN 设备调用”；运行时开关与安全检查留到后续版本再评估。
