# 手动关机与完成后关机监听共享后端权威倒计时

- 状态：accepted
- 日期：2026-10-08
- 部分替代：[ADR-0002](0002-shutdown-button-default-on-client-countdown-no-auth.md) 的倒计时归属、刷新／关闭页面语义及倒计时时长配置决策。
- 领域边界修订：[ADR-0006](0006-server-authoritative-session-lifecycle.md) 确定离线成员暂留、登记删除才移出，以及所有成员在线并等待输入才触发。

用户需要无人值守的完成后关机监听，并能在本机或局域网设备重新打开 omp-bot 主界面时看到并取消真实的关机安排；ADR-0002 的前端倒计时无法满足这些要求。因此，手动关机与完成后关机监听共享唯一的后端权威关机倒计时，由后端保存截止时间、处理取消并在到期时调用同一实际关机能力，前端仅展示和提交用户操作。

> 本文记录已接受的设计决策，不表示当前实现已符合全部规则。原关机工作见 [spec](../../.scratch/session-completion-shutdown/spec.md) 与 [contract](../../.scratch/session-completion-shutdown/contract.md)；本次会话生命周期和监听边界修订以 [ADR-0006](0006-server-authoritative-session-lifecycle.md) 为准，原 spec、contract 中“离线即移出”的规则不再代表新目标设计。内部模块划分和实现细节不在本 ADR 固定。

## 决策

- 倒计时时长由后端配置，默认 10 秒，手动与自动入口共用。手动关机保留确认步骤，确认后直接开始倒计时，无需等待监听成员结束。
- 同一实例同一时刻至多一个活动倒计时；重复发起沿用现有截止时间，不重置、不延长，也不重复发出实际关机调用。迁移后不保留绕过统一倒计时的旧立即关机行为。
- 已打开的前端同步关机安排；新打开、刷新或重连的前端恢复当前安排与剩余时间。关闭前端不会取消监听或倒计时。
- 监听和倒计时只属于当前后端进程，不持久化；后端重启清空两者，避免恢复过期关机意图。
- 可信局域网内任一可访问主界面的设备均可设置／撤销监听及取消全局倒计时，不限于发起设备。后端确认取消生效前，前端不得宣称已经取消；无响应时保留提醒并说明电脑仍可能关机。
- 取消关机是全局清空意图：后端原子清空当前监听集合并撤销当前尚可取消的倒计时，不绑定用户所见安排的标识；仅有监听而没有倒计时时也可清空。执行开始前已生效的取消阻止本次关机；实际关机执行已开始则不可取消。前端归零或连接断开不能作为关机成功的证据。
- 手动确认页和关机调用结果页的“返回”均为纯前端事件，不向后端提交取消或清除结果命令。最近一次关机结果保留至新安排替代或进程重启，其他设备关闭结果页不改变它。
- 会话与关机安排共享现有观察流：首帧恢复两类状态，关机变化使用独立命名事件携带完整关机状态。该选择不要求合并后端内部模块；公开读取 interface 的演进需要协调会话与关机的 adapter。
- 启动期配置 `[shutdown] countdown_seconds` 缺省为 10，接受 1 至 4294967295 的整数秒；缺段的旧配置仍可加载，非法值与拼错字段明确拒绝启动，不支持热加载。
- 实际关机失败明确反馈，不自动重试；关机指令已发出也不等于已经观察到电脑完成断电。

## 完成后关机监听的领域边界

- 完成后关机监听独立于 agent 状态、keepAlive 和“已接入”。仅在线且工作中的会话可新增监听；已监听的会话进入等待用户输入后，仍保留可撤销的监听按钮。
- 自动触发条件是监听集合非空且所有成员**当前都在线并等待用户输入**，不是任意一个成员结束，也不是各成员历史上结束过一次。离线成员的最后状态不能作为当前完成证据；等待用户输入只表示轮次结束，不保证整个任务成功完成。
- 倒计时开始前，成员离线时保留在集合中并阻塞自动触发；保留期内恢复在线后，原监听继续有效，重新执行同一判定。会话登记被清除、明确注销或用户撤销监听时，同步移出该成员并立即对剩余集合重新判定；空集合不触发。已移出的成员重新注册不会自动加入监听。登记的在线有效期与离线保留期见 ADR-0006。
- 任一入口开始倒计时即消耗整组监听，期间不接受新增监听；取消后不恢复监听，需要用户重新选择。会话重新工作、离线或注销不自动取消已开始的倒计时。

## 替代范围与保留边界

本决策替代 ADR-0002 中“前端持有倒计时、刷新或关闭页面丢失安排、前端归零后才请求立即关机、后端无倒计时与取消状态、倒计时时长为前端构建期常量”的决定。ADR-0002 正文保留为历史记录，而不是新流程的实现约定。

不改变 ADR-0002 的关机按钮默认显示、按钮显示开关与倒计时时长是不同配置、可信局域网无认证，以及关机独立于固定操作执行资格、不先执行停止脚本的边界；本次不新增后端运行时启用／禁用关机开关。实际关机仍采用 [ADR-0003](0003-shutdown-uses-exitwindowsex-forceifhung.md) 的 Windows 调用与失败处理原则。浏览器关机操作的局域网权限不放宽 [ADR-0004](0004-session-write-boundary-same-host.md) 对扩展写入会话事件的同机来源限制。

## 备选与代价

- **保留前端倒计时**：实现最小，但没有前端打开时无法自动执行，刷新会丢失安排，也无法让多个前端可靠同步或取消同一个关机意图；不再满足本次需求。
- **手动前端倒计时与自动后端倒计时并存**：保留旧行为的改动较小，但产生两套截止时间、取消和执行语义，与用户要求统一逻辑冲突。
- **持久化并在后端重启后恢复安排**：能够跨重启保留意图，但可能执行过期或用户已遗忘的关机安排；用户选择重启清空，不恢复。
- **绑定所见安排的取消**：能够阻止延迟请求撤销后来的新安排，但用户选择“清空当前所有倒计时和监听”的全局意图，以省去安排校验及过期取消交互；延迟取消可能撤销后来安排的风险明确接受。安排标识仍可用于观察与区分结果，不用于取消目标校验。
- **独立关机观察流**：可独立演进，但增加一条连接及跨流状态协调；用户选择共享现有观察流。若未来要求两类读取独立发布，需要调整读取 interface 与相关 adapter，后端唯一关机裁定不变。
- **代价**：后端需拥有安排的生命周期及取消／到期竞争结果，前端需同步权威状态并明确取消未确认的风险；关闭页面不再是取消关机的方式，用户必须显式取消。
- **接受的后果**：A 在线且等待用户输入而 B 仍工作中时，B 离线先阻塞触发；B 的登记被清除、注销或被用户撤销监听后，仅剩 A 的非空集合可能立即启动倒计时。监听目标是当前剩余成员，不永久绑定最初选择的名单；移出 B 不保证 B 的任务完成。可信局域网内其他设备也能取消安排，来源可访问性并非用户身份认证。
