# 后端权威会话快照与有界离线登记

- 状态：accepted
- 日期：2026-10-08
- 修订：[ADR-0005](0005-backend-authoritative-shutdown-countdown.md) 的监听触发条件及离线成员移出时机。

用户希望简化会话列表的心智模型，而不是单纯删除“离线”标签。决定让后端成为唯一业务事实来源，前端只呈现权威快照并提交关机相关操作；会话上报过期后暂留登记供观察及恢复，保留期结束后清除登记，关机监听始终按当前成员统一判定。

> 本文是已确认的目标设计，不代表已实现。本次只更新领域文档，不修改代码、运行配置或扩展恢复策略。讨论时后端仍采用固定 30 秒在线窗口、离线登记不自动删除，并在成员离线时立即移出关机监听；这三项行为需要在实现本决策时迁移。原关机工作的 spec、contract 及当前运行说明不能代替本次修订。

## 唯一业务权威

- 扩展上报会话信息与 agent 状态，后端维护会话登记、上报存活性、完成后关机监听集合及关机安排。浏览器只读会话数据；在会话列表范围内，写入意图仅限设置／撤销监听、发起关机和取消关机。
- 前端操作提交明确目标，由后端接受或拒绝；不以旧的全量快照覆盖后端数据，不自行乐观修改业务状态，未得到确认不能宣称操作成功。
- 前端通过一个权威快照入口更新业务展示。打开、刷新或重连时取得当前完整快照，页面打开期间持续接收后端更新；显示缓存及请求中的交互提示不是第二套业务事实。此决定不要求每次 SSE 更新都传全量数据，不固定增量传输或内部模块划分。
- 浏览器与后端失去观察连接时，保留最后快照并明确标注可能过期；不能因此把会话判为离线、把列表判为空，或认为关机已取消。浏览器关闭、刷新和断线不改变后端业务状态。

## 两阶段会话登记生命周期

会话列表展示后端当前所有已登记会话，包括离线登记。在线／离线仅表达最近上报是否过期；agent 状态为最后上报值，离线时不作为当前完成证据。未登记、已注销或已清除的会话不属于列表；删除登记不删除 agent 对话或聊天记录。

在线有效期与离线保留期是独立的 server 启动期配置，默认分别为 10 秒与 30 秒，不热加载。目标配置位置及名称为：

```toml
[sessions]
online_timeout_seconds = 10
offline_retention_seconds = 30
```

以上是目标配置，不表示当前后端已能加载这些字段。在线有效期不绑定扩展心跳周期，离线保留期也不是扩展重试时长。

以最后一次被后端接受的 `register`、`heartbeat` 或 `state` 写入为起点，令上报年龄为 `age`、在线有效期为 `T_online`、离线保留期为 `T_offline`：

| 条件 | 登记及展示 |
| --- | --- |
| `age <= T_online` | 保留登记，在线 |
| `T_online < age <= T_online + T_offline` | 保留登记，离线 |
| `age > T_online + T_offline` | 清除登记，列表移除 |

- 有效上报重新计时；离线保留期内普通心跳或状态写入仍可刷新原登记并恢复在线。不另存“首次扫描发现离线”的时刻，不以前端观察到离线的时刻计时。
- `unregister` 立即删除登记，不等待两个窗口；后端重启清空登记、监听与倒计时，不持久化这些意图。
- 沿用现有每 5 秒扫描的节奏，后端负责广播变化及清除；发布离线或删除可能比阈值晚约一个扫描周期。前端不自行计时或删除登记。
- `register` 仍是建立登记的入口；登记删除后普通心跳或状态写入按现有协议返回 `404 unknown-session`，须重新注册才能建立登记。本次不改变扩展的失败预算、重试、停止接入或自动重注册策略，也不放宽 [ADR-0004](0004-session-write-boundary-same-host.md) 的写入来源边界。

## 当前监听集合的统一判定

自动关机只在监听集合非空、且所有当前成员都在线并等待用户输入时触发；空闲、状态尚未同步、工作中或离线成员均不满足条件。不是历史上各成员曾经完成过一次，也不永久绑定最初选择的成员名单。

- 只有在线且工作中的会话可新增监听。已监听成员进入离线后仍保留在集合中，并阻塞自动触发；即使其最后状态是等待用户输入，也不能以离线状态满足条件。
- 保留期内恢复在线后，原监听继续有效，按后端当前状态重新判定；工作中则继续等待，在线且等待用户输入则可能让整组满足条件。
- 登记被清除、明确注销或用户撤销监听时，同步移出该成员，再对剩余集合执行同一判定。删除最后一个成员不触发；不采用“失去任一成员就取消整组监听”的规则。
- 手动关机仍不需要等待监听成员。任一入口开始倒计时即消耗监听集合；已开始的倒计时不因会话离线、删除、注销或重新工作而自动取消，沿用 ADR-0005 的全局取消规则。

## 取舍与接受的后果

- **不删除离线标签或无限保留离线登记**：前者丢失短期失联可见性，后者留下无限期残留。选择有界保留，同时提供观察窗口与迟到上报的恢复空间；不把它解释为等待恢复的持久连接或聊天历史。
- **不在进入离线时立即移出监听**：避免短暂上报中断通过缩小集合直接促成关机。离线成员暂时阻塞，但登记删除后仍按剩余成员判定，不取消整组意图。
- 默认在线有效期 10 秒与现存扩展契约的 10 秒心跳周期相同，没有为请求或调度抖动留出余量，可能短暂显示离线。用户接受这一点；离线期间保留监听并阻塞触发，扩展策略另行调整。默认合计 40 秒仅提供 server 登记留存空间，不保证扩展会在整个窗口内持续尝试恢复。
- A 在线且等待用户输入、B 仍工作中时，B 离线先阻塞；若 B 恢复在线并等待输入，或其登记最终被清除／注销，剩余非空集合可能立即启动倒计时。删除 B 不证明 B 已完成任务，用户明确接受“当前剩余成员”的组语义。
