# Suite 按宿主声明技能源路径

后续 [ADR 0020](0020-single-harness-suite-types.md) 决定将 Suite 身份收紧为单一 harness，取代同一 Suite 内的多宿主资源声明结构；本记录的原生技能加载语义与启动产物生命周期约束保持不变。该后续决策已落实单宿主配置格式及权威数据迁移。

Suite 技能加载不再创建符号链接，避免把 Windows 符号链接权限变成普通 Chat 启动前提。`skills` 按宿主分别声明：OMP 以 `{kind, path}` 来源对象选择集合目录或单技能目录，可以混选；集合读取有效直接子技能，单技能只读取目标目录中的 `SKILL.md`。herdr-bot 在每次启动或需要新进程的来源 Task 会话恢复时重新解析选择。Pi 保留单技能目录字符串数组，均由原生宿主消费。不选 Suite 时保留原生行为。

OMP 使用现有全局安装已支持的原生 `--config`，只对 `skills` 做会话级高优先级局部覆盖：集合来源传入源集合目录，单技能来源传入目标技能目录的父目录，扫描目录去重；再传入本次选择解析的最终技能名称白名单 `includeSkills`，将已有七个 `enable*` 来源开关设为 `false`、`ignoredSkills` 设为 `[]`，并按有效名称是否非空设置 `enabled`。不修改 OMP 源码、全局安装或宿主默认配置，不新增宿主配置能力。

同一 canonical 真实资源重复引用去重，不同实体声明同名则失败并指出来源；名称冲突检查包括不会进入最终有效白名单的已解析技能。空集合使用空白名单且 `enabled: false`，不回退；缺失或不可读声明明确失败。隔离承诺是原生最终可用技能列表只含本次选定名称，不承诺宿主完全不扫描默认目录。它不关闭原生扩展、agent、MCP、LSP 或项目指令，也不是文件访问沙箱。

## 取舍

不使用 junction、复制或自动提权替代符号链接。OMP 复用原生目录发现和名称白名单，不修改宿主；单技能来源的同级技能仍会被扫描，但只有所选名称进入最终白名单。集合中的新增有效技能会在下次启动时进入白名单，单技能来源不随同级成员增加而扩大范围。白名单不是文件路径绑定；用户自行处理同名问题，保留已有去重与同名报错逻辑，不新增冲突机制。OMP 的对象来源与 Pi 的单技能路径在配置及界面中显式区分。

只取消技能链接目录，保留每次启动独立的 OMP／Pi、LSP、MCP 配置产物及其发布生命周期。硬链接原子发布、外部输入路径安全检查与本决策无关。

## 验收

默认回归覆盖真实资源选择与失败边界；交付还须在不能创建符号链接的 Windows 普通权限环境，通过 Chat 发起流程实际消费两宿主的技能及相对资源，覆盖多目录、最终可用技能隔离、同名冲突、无效路径与空集合。OMP 验收使用现有全局安装，核对 OS 实际进程身份、原生最终技能列表及真实资源消费，不部署新的宿主构建，也不把未观察到默认目录扫描作为通过条件。跳过或受阻不能以其他回归全绿抵消，配置产物存在也不等于原生消费成功。
