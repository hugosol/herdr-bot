# Suite 按宿主声明技能源路径

Suite 技能加载不再创建符号链接，避免把 Windows 符号链接权限变成普通 Chat 启动前提。`skills` 按宿主分别声明：OMP 选择多个技能集合目录，herdr-bot 在每次启动或需要新进程的来源 Task 会话恢复时重新读取集合中的有效直接子技能；Pi 选择单技能目录，均直接交给宿主消费。不选 Suite 时保留原生行为。

OMP 使用现有全局安装已支持的原生 `--config`，只对 `skills` 做会话级高优先级局部覆盖：传入源集合目录和本次解析的最终技能名称白名单 `includeSkills`，将已有七个 `enable*` 来源开关设为 `false`、`ignoredSkills` 设为 `[]`，并按有效名称是否非空设置 `enabled`。不修改 OMP 源码、全局安装或宿主默认配置，不新增宿主配置能力。

同一 canonical 真实资源重复引用去重，不同实体声明同名则失败并指出来源；名称冲突检查包括不会进入最终有效白名单的已解析技能。空集合使用空白名单且 `enabled: false`，不回退；缺失或不可读声明明确失败。隔离承诺是原生最终可用技能列表只含本次选定名称，不承诺宿主完全不扫描默认目录。它不关闭原生扩展、agent、MCP、LSP 或项目指令，也不是文件访问沙箱。

## 取舍

不使用 junction、复制或自动提权替代符号链接，也不把 OMP 集合目录选择伪装为单技能选择。接受 OMP 以集合目录为选择单位，再用现有原生名称白名单约束最终可用列表：目录中的新增有效技能会在下次启动时进入白名单，不再保留旧的固定技能数量；Pi 仍逐技能选择。两宿主的不同选择语义在 Suite 配置及界面中显式区分。

只取消技能链接目录，保留每次启动独立的 OMP／Pi、LSP、MCP 配置产物及其发布生命周期。硬链接原子发布、外部输入路径安全检查与本决策无关。

## 验收

默认回归覆盖真实资源选择与失败边界；交付还须在不能创建符号链接的 Windows 普通权限环境，通过 Chat 发起流程实际消费两宿主的技能及相对资源，覆盖多目录、最终可用技能隔离、同名冲突、无效路径与空集合。OMP 验收使用现有全局安装，核对 OS 实际进程身份、原生最终技能列表及真实资源消费，不部署新的宿主构建，也不把未观察到默认目录扫描作为通过条件。跳过或受阻不能以其他回归全绿抵消，配置产物存在也不等于原生消费成功。
