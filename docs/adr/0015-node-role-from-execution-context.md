# 普通与节点 Task 合并，节点角色由执行上下文确定

- 状态：accepted（设计决策；不表示执行代码已切换）
- 日期：2026-10-29

Task 类型收敛为普通（normal）与流程管理者（manager），取消独立 node 类型。同一个普通 Task 可从 zone 独立发起 Chat，也可经 node → Bot → Task 关系用于 workflow 节点派发，避免为了不同发起方式维护重复预设；manager 类型暂时保留。Task 类型与会话 agent 类型正交，保留当前 omp、pi 对 manager 和 node 的支持，不重新加入 omp 专属限制。

节点执行角色由本次 workflow 执行上下文确定。代码固定要求节点 Chat 加载对应宿主的 node-chat，不再通过 Task 的 node 分类或可配置的 taskType 适用规则决定是否加载；独立发起的普通 Chat 不加载该角色扩展。扩展实际入口位置仍来自部署配置，不将机器绝对路径硬编码进业务规则。此处替代现有按 node Task 类型选择角色扩展的设计，不改变 Task 是可复用预设的定义。

恢复已有节点 Chat 时沿用原 Run/node 执行关联及节点角色，不新建执行、不重放发起指示；恢复独立普通 Chat 不因此获得节点角色。该规则与从来源 Task 读取最新会话环境的既有原则共同适用。本次按配置在运行期间保持不变的使用前提采取最简单实现，不处理来源 Task 在运行中被动态改动的冲突，不额外引入配置快照、版本管理或热更新协调机制；这不是承诺动态修改后仍可无冲突恢复。

存量数据通过显式一次性迁移将 node Task 原地转为 normal，保留 Task ID、配置内容、Bot 引用及历史 Chat 来源关联。已有重复预设不自动合并或删除。新版不保留旧 node 类型的运行时兼容分支；迁移不重写既有 Run/node 执行身份。
