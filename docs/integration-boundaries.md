# 集成边界

## 发起 Chat 不等于任务完成

Bot 的 **trigger config（发起配置）** 包含初始消息、初始 Skill 调用、model 与 thinking；**env config（会话环境配置）** 当前交付的是固定／可选扩展配置。发起 Chat 应用两组配置；Resume 新进程只加载环境，不重放发起动作。这里描述的是交付规则，不是本次文档整理已经运行并验证其他实现的声明。

Bot 的固定 prompt 与本次 input 属于用户输入，不是 system-role 指示或系统提示词注入。初始 Skill 调用按目标 agent 的原生语法与初始消息合成为一次提交，不先运行无任务的 Skill 轮次再补发任务；它不是持续环境中的加载型 Skill。未来加载型 skills 与系统提示词注入均不在本次交付范围，不能把初始指示或扩展加载当作这两项能力已经交付。

Herdr 确认 agent 可交互且初始指示提交获确认，才表示发起成功；这不证明模型完成任务、Skill 已加载或执行成功。终端信任提示、资源加载、账号权限及模型可用性仍由目标 agent 决定。

失败保留已经创建的 Tab／Pane／agent，不自动删除、重建或重发初始输入；超时不能证明外部操作未发生。只有尚未创建外部对象的 Workspace 查找失败允许在原弹窗重新提交。

## 扩展与默认配置

Bot 保存稳定的选项标识，不保存入口映射副本。`meta-data/bot-options.toml` 是 Bot 选项目录，定义 agent、模型、思考级别及扩展适用关系；变更后下次操作重新读取。正常发起 Chat 仍严格验证选择与入口，失效项需要显式修正并保存，不能悄悄替换为默认值，也不采用 Resume 的逐项跳过规则。

正常发起 Chat 关闭扩展自动发现，再显式加载固定项与 Bot 所选可选项。Herdr 官方状态／原生身份扩展是固定项；它不代替可选的 connect-bot。入口可读检查不执行扩展，也不证明实际加载成功。Resume 则先区分有无来源 Bot，再选择下述环境策略，不能一概关闭默认发现。

## 原生对话与历史

每次发起 Chat 新建 Herdr Tab 和 agent 控制对象，但不保证新建原生对话。发起命令不传 `--session-dir`；原生会话文件及附属记录由 agent 管理，herdr-bot 不覆盖原生会话目录、不搬动文件，也不修改 agent 原生配置。历史材料提到的 `autoResume` 属于 agent 自身设置，不是本项目提供或新增的自动续接功能。来源 Bot 关联用于 Resume 读取环境配置，不以原生自动续接行为作为建立关联的理由。历史证据中的旧参数或配置保留原状，不代表当前发起命令。

历史按完整原生会话身份收录，不按名称、cwd 或最近修改的文件猜测身份。发起成功后，历史身份收录独立进行，最多等待 30 秒；失败仅给出服务端诊断，不把已成功发起的 Chat 改成失败，也不重发初始输入。

确认原生身份后，正常发起收录把本次明确选择的 Bot 稳定 ID 保存为可选 `sourceBotId`；该信息只在持久文件及内部恢复选择中使用，不增加公开来源查询或历史写入接口。connect-bot register 不能指定来源，即使同名、同目录或提供自称来源的额外字段也不采信。发起与 register 共用同一持久化事务锁和补齐规则：按完整身份去重，空白／缺省信息不擦除已知值，首次可信来源和原位置不被后续发起或 register 改写，首次收录时间与备忘保留；原来无来源的记录仅由后续明确发起补齐来源。该入口不查询 Herdr，也不在 Resume 时修复历史。

connect-bot 是独立的接入机制：未接入的 Chat 也可以存在并被收录到历史；接入后才有当前会话登记。删除当前登记不删除历史或原生对话。

## 历史 Workspace 与备忘

`GET /api/sessions/history` 保留分页和原有字段，新增可选 `originalWorkspaceName` 和 `memo`。当前页存在已记录的原 Workspace ID 时，只查询一次当前 Herdr Workspace 清单，按已保存的 `originalWorkspaceId` 补充名称；名称不落盘，也不参与恢复决策。清单失败、格式不可用或原位置已删除不使历史读取失败，页面显示 ID；原位置从未记录时显示“未记录”，不按 cwd 或当前焦点推断。

`PUT /api/sessions/history/memo` 接收且成功返回 `{sessionId: string, memo: string}`，沿用其他浏览器操作的局域网访问边界，不使用 connect-bot 上报的本机来源限制。未知身份返回 HTTP `404`／`unknown-chat`，存储读写失败返回 HTTP `500`／`history-save-failed`，不会创建新历史或覆盖损坏文档。每条原生对话仅保存一份文本，逐字保留空白与换行；显式保存空串仍返回 `memo: ""`，从未保存的旧记录省略该字段。备忘与收录共用历史事务锁，重复 register、zone 收录和服务重启均保留它；不写原生对话文件，不记录时间线。它属于服务端共享数据，因此不同设备读取同一份备忘。

页面通过“新增备忘”或“编辑备忘”打开多行编辑器，只有“保存”才写入，“取消”不修改持久值；保存失败保留草稿并明确提示。

## 历史 Chat Resume

历史列表的 **Resume** 与 `POST /api/chats/resume`（仅提交 `sessionId`）使用同一条恢复路径。先查询 Herdr 的原生对话身份；找到已有目标只做 Herdr 内部导航，查询失败不会当作无匹配。定位成功的消息固定为“已切换到当前herdr焦点”，页面不展示目标详情；API 仍保留 `target` 和 `matchCount`，多匹配继续按稳定顺序选择。恢复或失败结果保留准确详情，不承诺 Windows 前台窗口状态。缺少／未知／不支持的 agent 类型会明确拒绝，不按文件形状猜测类型。

同一 herdr-bot 实例按所选历史 Chat 持有执行资格，覆盖查找、创建、启动、确认与聚焦，不依赖单页按钮状态。同一 Chat 已在执行时，其他页面或独立请求立即收到 HTTP `409`／`resume-in-progress`；本次未执行、不会排队，也不会在首个操作完成后自动启动。浏览器呈现后端忙碌结果，不乐观宣称成功；定位、恢复完成或明确失败后释放资格，用户新发起的操作仍从查找开始。已接受操作不因原请求连接关闭而提前释放资格；不同 Chat 互不阻塞。该边界仅在当前服务实例内，不是多实例分布式锁，也不改变会话登记、历史身份或原 Workspace 的生命周期。

成功查询且没有匹配时，Pi／OMP 共用恢复流程，在历史记录的绝对 cwd 中创建新 Tab 并加载指定原生对话。目录必须实际存在，不静默替换。历史使用可选 `originalWorkspaceId` 保存原 Herdr Workspace 的稳定 ID，而不是名称或当前焦点：正常发起 Chat 收录已确认的创建位置；connect-bot 的 `register.data.originalWorkspaceId` 可上报已知位置，非 Herdr 来源可以省略，服务不按名称或 cwd 推断。首次获知位置后，重复收录也不会覆盖原值；历史读取接口仅在已知时返回该字段。

恢复降级的选择与反馈由 `resume.rs` 中同一 module 集中管理，与持久历史信息补齐分离；不新增自动修复或后台重试。公开恢复结果的 `degradations` 数组逐项保留 `element`、已知 `reason` 和实际选定的 `strategy`，页面通过同一结果消息显示所有已发生的降级；失败或启动未确认不会被降级说明改成成功，尚未成功选择的替代位置不标为已采用。既有 `fallback` 字段继续只表示 Workspace 回退，不是所有降级的汇总标志。

恢复优先按该 ID 查找原 Workspace，即使其已更名也返回原位置。缺少信息的旧格式记录无需迁移或手工重写；旧记录或成功查询证实原位置已删除时，使用 `[herdr] workspace_name` 精确匹配的唯一默认 Workspace，并在页面和操作结果中说明回退。原 Workspace 查询失败或响应无法判定存在性时直接报错，不作为已删除回退；默认 Workspace 缺失、重名或查询失败都不创建替代位置。Resume 始终不写历史：原位置恢复、删除后回退、定位其他位置的已有目标都不改写已收录的原 Workspace，也不为旧记录补写位置。删除当前登记不影响这些持久信息或原生内容。

恢复优先使用可读取且原生 ID 一致的 `sessionFile`，不可用时只使用所选原生 ID：Pi 传给 `--session`，OMP 传给 `--resume`。文件若属于另一对话则拒绝恢复。文件缺失、不可读或无法核实其 header 时，降级反馈保留具体文件路径及已知读取错误，并明确仅使用所选精确原生 ID；未记录文件时也说明该事实。若历史身份本身是已不可读的路径而不能核实 ID，则明确失败，不扫描最近文件或改用空白对话。

仅在需要新进程时，使用 Herdr 当前配置的对应 `pi`／`omp` 启动命令，并按来源选择环境：

- **来源 Bot 存在**：读取其最新 env config，结合当前 Bot 选项目录解析该 agent 的固定与已选可选扩展；不是创建时的快照，不提供 Bot 版本回放。映射缺失、入口不存在或不可读时逐项跳过，其余可用项继续显式加载，扩展自动发现保持关闭。全部被过滤也仍是关闭发现的空显式集合，不切换到默认发现；缺少必要身份集成时仍须如实返回失败或未确认，不因提交命令就认定恢复成功。
- **来源关联缺失或 Bot 已删除**：使用 agent 原生默认扩展发现，不传 `--no-extensions`，也不显式追加 Bot 固定／可选扩展。旧记录和外部接入不按名称、cwd 或当前 Bot 猜测来源，历史查询也不补绑来源。
- **Bot 存储或配置无法可靠读取**：明确报错，不当作“无来源／Bot 删除”启动默认配置，不自动修复；这与可明确定位的单项扩展缺失不同。

来源 Bot 关联由明确的发起流程提供，用于后续环境选择；关联首次有效后，不由普通 register、重复收录或 Resume 覆盖或擦除。读取最新环境不是重放 trigger config：不提交初始消息或初始 Skill 调用，不传 Bot 的 model／thinking 覆盖原生会话；这些发起选择失效也不阻止按可用 env config 恢复。已有匹配目标只定位，即使来源 Bot 或目录已改，也不额外要求加载环境、不重启、不另开目标、不提交输入。

OMP 禁止使用会自动继续中断任务的 `--restore`。Resume 不自动继续中断任务，不是通用进程恢复；agent 自身如何恢复模型设置不由本项目重新解释。

Bot 的 trigger config 与 env config 在执行结构上分开；普通发起仍完整校验并应用两类配置。Bot 的 HTTP／磁盘字段形状保持不变，无需迁移；历史仅新增可省略的来源字段，已有无来源记录保持无来源。

启动命令返回不等于恢复成功：确认新进程报告同一原生身份和实际 cwd 后，还需确认聚焦正确的 Workspace／Tab／Pane，才返回 `restored`。类型、工作目录、必要集成、启动、身份或聚焦失败均有可见结果；已经创建的目标保留供检查，不自动另开、删除或重发输入。页面／HTTP 成功只表示 Herdr 内部导航，不保证 Windows 窗口已置前，也不承诺 agent 自身的模型恢复规则。Pi 使用 session 加载、OMP 使用 resume，且项目不提交输入。既有原生恢复证据由 [01 的真实恢复 smoke](evidence/chat-history-resume/recovery-degradation-01.json) 继续核对：独立专用 Herdr session 中两者都实际显示已知历史、报告正确原生文件及历史 cwd，随后只定位；OMP 停留在旧中断任务的 Read 之后、等待输入，没有新模型请求或新 user／tool 活动。OMP 原生 CLI 可追加一条标明前进程中断的空 assistant／aborted 记录，这不表示本项目修复文件或继续任务，不应把整个文件字节不变作为其加载语义。受控调用记录本身仍不代表真实原生加载证明；本 smoke 不代签后续真实扩展集合的用户确认。

本票逐项过滤的自动证据见 [Pi 页面与受控提交](evidence/chat-history-resume/extension-filter-04-pi-extension-filter-NOT-real-loading.json)、[OMP 页面与受控提交](evidence/chat-history-resume/extension-filter-04-omp-extension-filter-NOT-real-loading.json)：交付页面分别展示部分可用集合的具体跳过原因，以及空显式集合缺少身份确认后的未确认结果；这些记录不证明真实扩展加载。另有 [04 真实恢复 smoke](evidence/chat-history-resume/extension-filter-04-native-smoke.json)：专用隔离 Herdr session 中，真实 Pi／OMP 在有效官方身份项与缺失可选项并存时确认原始 ID／文件／cwd、显示已知旧历史并保持 idle；复制的原生文件未变化，隔离模型端点没有请求，后续 Resume 只定位。smoke 的来源字段是隔离预写样例，可信来源收录另由正常发起的公开 HTTP 测试覆盖；它不代替 H-Pi／H-OMP 的完整显式／默认／ambient 集合人工确认。

恢复降级不等于恢复成功。发生扩展逐项过滤、默认扩展发现、Herdr Workspace 回退或精确原生 ID 回退时，页面与操作结果保留所有已发生要素、各自已知原因和实际采用策略；组合发生时不能只剩最后一条。确认恢复且有降级时明确说明有降级；失败或启动结果未确认时仍保留已发生的降级，而不虚构尚未作出的选择。权威的失败／未确认结果不能被统一成功提示替代。

创建 Tab、提交启动命令、确认正确原生对话与完成聚焦是不同阶段。Pi／OMP 在 Tab 创建等待、agent 启动等待或随后的原生身份确认等待超时，均返回 HTTP `502`、`outcome: "unconfirmed"`、`code: "restore-unconfirmed"` 和实际阶段（`tab`／`start`／`confirm`），不能当作安全失败或恢复成功。`target` 只包含实际取得的 Workspace／Tab／Pane ID，`agentName` 是已提交的启动名称而非加载成功证明；页面显示这些信息及“启动结果未确认”。`progress` 区分已确认创建 Tab、已提交启动、原生对话确认与聚焦：Tab 创建本身超时时 `tabCreated` 为 `null`（未知），不能据此断言 Tab 没有产生。

超时不清理已创建目标、不终止 agent、不自动新建或再次启动，也不提交输入；停止等待不等于终止外部启动。该不确定性也适用于 Herdr CLI 自身返回的结构化 `error.code: "timeout"`（例如 `timed out waiting for agent startup`）：CLI 非零退出不表示原生启动确定未发生，不按错误描述文字猜测超时。执行资格在未确认结果返回后释放；等待期间的独立请求立即被拒绝且不排队，超时后的并发重试仍只有一个能执行。只有用户重新发起 Resume 才有新操作，新操作始终重新查询：首次启动迟到后可识别的原生目标会被定位，不盲目重放启动。查找、影响匹配的身份核实、聚焦失败仍明确拒绝，不通过重放规避失败。

## 验证边界

受控 Herdr 可以证明提交了哪些参数及如何处理受控响应，不能证明真实 agent 加载了扩展、旧历史已经加载或任务没有自动继续。本轮 env config 的人工确认只有 **H-Pi** 与 **H-OMP** 两项：每个 agent 在专用隔离环境核对有来源 Bot 的最新显式集合、有效与缺失项并存时的部分集合，以及无来源／Bot 删除时的原生默认发现集合，并用可区分的 ambient 对照检查实际发现策略；不操作用户现有 Chat。

这两项须以原生 ID／文件身份、实际 cwd、来源 Bot 与原生默认配置、真实扩展加载观察、Herdr 目标、页面降级反馈及可重复步骤为证据，不能只提供命令行。全部扩展被过滤的空集合不另加人工项，但也不能未经身份与聚焦确认就记为恢复成功。**本轮 H-Pi／H-OMP 在用户明确确认前仍未验证**；本文档票不宣告其他实现票或人工验收已完成，也没有运行新功能来证明上述行为。

[既有验收材料](bot-acceptance.md) 保留原生对话、历史内容、焦点与 OMP 未自动继续任务的既有人工边界，不代替本轮扩展集合确认，过去的通过数也不属于本轮运行证据。桌面浏览器窄屏仿真不能替代真实手机的触摸、软键盘和输入法验证；手机及真实断电不追加为本轮扩展验收项。历史原始证据保留在 [`evidence/`](evidence/)，不改写历史 ADR、父级 spec／contract 或历史证据来消除差异，也不作为当前构建已经重新通过的证明。
