# Scheduler：轻量文件列表与按钮交互参考

调研日期：2026-10-26。仅设计调研，不实施 UI；Scheduler 是静态 Map 定义浏览器，不是执行器或编辑器。

## 当前约束（来自任务说明，非本次代码核验）

- 左侧是 JSON 文件名按钮列表，单选文件后查看对应 Map。
- 「刷新列表」「重载当前」实际都更新共享 revision：刷新文件列表、当前 Map、模板，并清除节点选择。因此两个标签暗示的作用范围与实际副作用不一致。
- 图中箭头仅表示 `blocked_by` 前置依赖，不表示运行顺序、运行状态或数据流。

## 四个成熟参考：来源事实与适配建议

### 1. PatternFly Simple list：目录不是一组主操作

**来源事实：** Simple list 用于页面内可选择条目；文档明确区分默认与选中状态，选中状态用于表达用户当前选择。[官方指南](https://www.patternfly.org/components/simple-list/design-guidelines/)

**适配建议：** 文件名保留整行可点击，但视觉改为紧凑目录行：默认无实心按钮背景，hover 给浅底，当前项用浅色底、边线或标记突出。焦点轮廓与选中样式分开；不把每个文件做成同等醒目的主按钮。保留完整文件名识别能力，长名优先换行或提供可访问的完整名称，不只依赖鼠标悬浮。使用原生可聚焦控件保留键盘操作，不为了外观套用未完整实现的 listbox 键盘模型。

**风险：** 当前只有文件名这一主要维度，没有跨列比较需求；不引入企业表格、复选框、批量操作、排序或分页。密度提升不能以文件名无法辨认为代价。[参考依据：Simple list](https://www.patternfly.org/components/simple-list/design-guidelines/)

### 2. PatternFly Primary-detail：目录—Map—节点详情

**来源事实：** 主从布局由可选条目与对应详情组成；左侧控制右侧展示，详情标题应关联当前条目。文档要求当前条目具有选中状态；无选择时应有引导空态；窄屏可一次展示一个面板并提供返回入口。主区可以是 Simple list，不必使用表格；只有空间确有不足时才需要可拖动分隔条。[官方指南](https://www.patternfly.org/patterns/primary-detail/design-guidelines/)

**适配建议：** 左侧固定为 Map 目录，主区标题显示当前文件名并承载依赖图；节点详情属于当前 Map 内第二层查看，不与文件选择混成同一类高亮。桌面保留目录上下文；窄屏采用目录 → Map 的返回关系。未选择文件显示「选择一个 Map 查看定义」；选了文件但未选节点显示「选择节点查看定义」。

**风险：** 不机械照搬遮挡画布的抽屉；也不因参考支持表单就引入编辑。刷新清除节点选择后，应回到明确的节点未选择状态，不能保留旧节点详情造成错配。[参考依据：Primary-detail](https://www.patternfly.org/patterns/primary-detail/design-guidelines/)

### 3. PatternFly Toolbar：只借搜索与数量，不搬整套管理工具栏

**来源事实：** 工具栏可容纳文本搜索筛选；无分页时可显示数量，例如总数或筛选后的「10 of 17」。应靠近其控制的数据；不需强调的操作可用次级按钮。[官方指南](https://www.patternfly.org/components/toolbar/design-guidelines/)

**适配建议：** 若文件增多确实影响查找，可在目录顶部放一个「按文件名筛选」输入框及「匹配 3 / 共 12」；文件少时只保留标题与数量。建议即时、本地匹配，不让输入筛选触发共享 revision。筛选是缩小目录，不是选择或重载 Map；即使当前文件被筛掉，主区也继续明确显示当前文件名。

**风险：** 必须区分「尚无 Map 文件」「没有匹配文件」「列表读取失败」，否则错误可能被误认为目录为空。不要照搬参考中的批量选择器、复杂筛选组、溢出菜单或分页。[参考依据：Toolbar](https://www.patternfly.org/components/toolbar/design-guidelines/)

### 4. Ant Design Button：按钮层级和加载反馈

**来源事实：** Button 用于触发操作；一个区域最多一个主按钮。Default 用于没有优先级的操作，Text 用于更次要操作；`disabled` 表示操作不可用，`loading` 提供按钮内加载图标并避免重复提交。[官方指南：When To Use、API](https://ant.design/components/button/)

**适配建议：** 浏览型页面可以没有实心主按钮；刷新使用一个普通描边按钮即可，文件选中态不要借用「主操作」样式。刷新期间按钮显示加载状态和「正在刷新…」，避免重复发起；刷新完成或失败后恢复可操作状态。反馈覆盖其真实刷新范围，而不是只提示「列表已更新」。

**风险：** 加载图标不等于刷新成功，也不应让用户误解为 Scheduler 正在运行 Map。未满足所有刷新范围时不能统一提示「全部刷新完成」。[参考依据：Button](https://ant.design/components/button/)

## 推荐结论：合并刷新入口，先让文案忠于现状

以下均为本项目的**设计建议**，不是上述设计系统对 Scheduler 行为的规定。

| 阶段 | 推荐文案与反馈 | 与当前副作用对齐 |
| --- | --- | --- |
| 入口 | 在共同页面标题区只保留一个普通按钮「刷新全部」 | 移除含义重复的「刷新列表」「重载当前」，不伪装成两个局部动作 |
| 操作前 | 就近说明「重新读取文件列表、当前 Map 和模板，并清除节点选择」 | 关键副作用不要只藏在图标 tooltip 中 |
| 进行中 | 「正在刷新…」与按钮内 loading；受影响区域明确提示更新中 | 用户知道这次操作不是运行或执行 |
| 完成 | 「刷新完成，节点选择已清除」；节点详情回到未选择空态 | 仅在相关读取全部成功后显示；当前文件仍存在时保持其身份明确 |
| 失败 | 「刷新未完成：当前 Map 读取失败」等具体范围提示 | 使用同一刷新入口重试；若保留旧内容，必须标记尚未更新，不能冒充最新 |

- 当前 Map 文件若刷新后不存在，显示「当前 Map 文件已不存在，请重新选择」，不继续把旧图当成当前定义。
- 不建议为只读刷新增加确认弹窗；副作用通过操作前的可见说明及结果反馈表达。
- 如果未来确实要保留「刷新列表」「重载当前」两个入口，必须先真正拆分数据刷新边界：前者不能再重载当前 Map/模板并清除节点选择，后者也不能再冒充列表刷新。这是行为改动方案，不是本次推荐的纯样式调整；仅改标签、位置或图标不足以解决问题。

## 取舍

优先采用 **Simple list 的行样式 + Primary-detail 的上下文关系 + 单一真实范围的刷新按钮**。搜索与数量按目录规模选用。引用的是交互原则，不建议为此引入多个设计系统组件库；没有新增执行、编辑、批量删除或其他管理功能。
