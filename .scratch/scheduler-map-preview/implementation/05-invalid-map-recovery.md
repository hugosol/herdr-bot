# 05: 无效 Map 的拒绝、清场与恢复

**What to build:** 用户打开无法读取、无法解析或结构、依赖非法的 Map 时，明确看到问题而不是伪成功图；旧图与旧详情被清除，仍能选择其他有效 Map。

**Delivers:** P23, P24；P22 的 Map／node 结构覆盖；P29 的 Map 文件故障隔离覆盖。

**Test owner for:** P22 的 Map／node 必需字段、类型、未知字段、版本、显式空值与漏填，以及 parameters 自由键；P29 的坏 Map 与好 Map 共存。06 负责模板侧覆盖，各承诺在两票覆盖通过后才整体完成。

**Blocked by:** 03 — 合法 Map 的依赖图与 node 详情。

**Status:** in-progress

## Acceptance criteria

- [x] Map 与 node 固定定义字段严格遵守已批准格式：必需字段缺失、类型不符、未知结构字段或 schema_version 不支持均明确报告，不静默补默认值或忽略拼写错误。
- [x] 分别使用缺失 blocked_by、误写 blockedBy、字符串代替数组及未知版本的独立输入，定位具体问题；显式空对象、空数组、空文本与漏填按格式区别处理，不把合法空内容一概拒绝。
- [x] parameters 的自由键及直接 JSON 值不被误判为未知结构字段，不引入模板 inputs 或真实资源存在性校验。
- [x] 分别验证未知前置节点、自依赖及依赖环；明确指出问题，不静默删节点、删边或将非法关系当作有效图。
- [x] 使用真实非法 JSON、结构错误、依赖错误及可复现的 Map 文件加载失败验证错误路径，不以目录整体假失败替代单文件错误。
- [ ] 经真实浏览器完成有效 A → 无效 B → 有效 C；B 失败时清除当前图与 node／模板详情，不把 A 当作 B 的结果；选择 C 后恢复正常展示。
- [x] 坏 Map 与好 Map 同目录共存，列表仍能用于选择好 Map 并完整查看；不因单文件错误使其余有效定义不可访问。
- [x] 通过 S1 观察错误、清场与恢复，通过实际生产 S2 核对结构及依赖错误；预写反例与独立预期，不从实现生成期望。
- [x] 遵守真实隔离数据、无定义修改、无执行副作用及测试网络护栏约束；同步更新 Map 错误定位和恢复说明。
