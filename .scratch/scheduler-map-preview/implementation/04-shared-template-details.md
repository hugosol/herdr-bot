# 04: 共享模板关联与按需明细

**What to build:** 用户查看 node 时，先看到具体工作，主动展开模板明细后才看到其引用的共享业务能力说明；共享模板从独立服务端目录真实读取，可跨 node 和 Map 复用。

**Delivers:** P14, P15, P16；P6, P7, P8 的共享模板目录覆盖。

**Test owner for:** P6 的共享模板目录独立配置与 cwd 解析；P7 的模板默认目录创建与已有文件保留；P8 的模板目录创建／读取失败与正常空态。02 负责对应 Map 目录覆盖，各承诺在两票覆盖通过后才整体完成。

**Blocked by:** 03 — 合法 Map 的依赖图与 node 详情。

**Status:** ready-for-agent

## Acceptance criteria

- [ ] Map 与共享模板目录可独立配置并实际读取不同内容；隔离进程的 cwd 与配置文件位置不同，证明相对模板目录按 cwd 解析。
- [ ] 未配置时使用 spec 已确认的默认共享模板目录，缺失目录及父目录自动创建；预置模板文件内容保持不变，不自动安装示例。
- [ ] 模板目录只扫描直接包含的 JSON 文件，不递归读取；目录创建／读取失败明确报告，真实空目录与目录故障有区别。使用实际文件系统反例，不用空响应模拟读取失败。
- [ ] 模板明细默认收起；用户点击入口后展示当前 node 对应模板，切换 node 后不显示错误关联或上一 node 的说明。
- [ ] 逐项展示模板标题、use_when、description、命名 inputs／outputs 的文本说明，以及 chat 实现类型；使用独立编写的预期文本核对全部字段。
- [ ] 通过仅含 Chat 的 Rust 枚举表达实现类型，JSON 表示为 chat；展示不等于执行，不增加实际执行配置或启动能力。
- [ ] 模板身份来自 id 而不是文件名；使用与 id 不同的文件名，验证同 Map 多个 node 及多个 Map 引用同一说明。模板文件重命名后重新读取仍能关联，可通过重新进入页面验证，不提前认领 07 的完整显式重载覆盖。
- [ ] 所有文本安全展示，正常模板读取不修改定义、不执行代码、不按参数读取文件；08 负责完整安全验收，06 接续模板局部错误与重复身份处理。
- [ ] 通过 S1 与主界面实际调用的 S2 验证真实文件关联，沿用隔离、安全及 npm 网络护栏约定；更新共享模板配置和明细使用说明。

## Contract coverage

P6、P7、P8 的共享模板目录覆盖及测试归本票；对应 Map 目录覆盖及测试归 02。模板目录级失败归本票，单个模板文件不可读等局部故障归 06 的 P20。
