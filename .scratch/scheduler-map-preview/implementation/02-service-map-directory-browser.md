# 02: 浏览服务级 Map 目录

**What to build:** 用户进入 scheduler 后可以浏览服务所在电脑上的 Map 文件列表，区分没有文件与无法读取；Map 不属于当前 zone，也不依赖访问设备本地文件。本票完成 Map 目录闭环，共享模板目录的可观察读取由 04 接续。

**Delivers:** P5, P9；P6, P7, P8 的 Map 目录覆盖。

**Test owner for:** P6 的 Map 目录配置与 cwd 解析；P7 的 Map 默认目录创建与已有文件保留；P8 的 Map 目录创建／读取失败与正常空态。04 负责对应的共享模板目录覆盖，各承诺在两票覆盖通过后才整体完成。

**Blocked by:** 01 — scheduler 导航与 server 入口迁移。

**Status:** ready-for-agent

## Acceptance criteria

- [ ] 通过真实服务、隔离文件和两个独立浏览器上下文观察同一组 Map；切换 zone 不改变 Map 归属，不宣称这代替了真实 LAN 验收。
- [ ] Map 目录可配置，配置结构允许它与共享模板目录独立指定；实际读取来自指定的 Map 目录。真实进程使用隔离 cwd，配置文件位于不同位置，证明相对路径按 cwd 而非配置文件位置解析。
- [ ] 无自定义配置时使用 spec 已确认的默认 Map 目录；缺失目录及父目录自动创建，预置文件内容不被覆盖或清空，不自动安装示例。
- [ ] 使用普通文件占据目录位置等真实场景验证创建失败；使用实际可复现的读取失败验证明确错误。已有且不含 JSON 的目录显示正常空态，不能用伪造空响应代替失败场景。
- [ ] 列表只包含 Map 目录直接包含的 JSON 文件；预置顶层 JSON、非 JSON、子目录 JSON 与独立文档样例，按预写名单核对出现及排除项。
- [ ] 生产读取仅面向配置目录，不接受任意本地路径，不跟随链接泄露目录外内容；不根据业务参数读取文件，不修改定义或执行脚本。08 负责完整安全覆盖，不允许把安全实现延后。
- [ ] 经 S1 观察列表、空态和错误，并通过主界面实际使用的 S2 验证目录行为；不新增仅供测试的读取 interface。
- [ ] 真实进程、文件及可变存储均由场景独占，监听数值回环地址并正确清理；同步更新 Map 配置和首次使用说明。

## Contract coverage

P6、P7、P8 的 Map 目录覆盖及测试归本票；共享模板目录覆盖及测试归 04。共享模板目录尚未完成真实读取前，不宣称这些承诺已经整体完成。
