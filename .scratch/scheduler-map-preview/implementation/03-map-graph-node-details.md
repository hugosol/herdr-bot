# 03: 合法 Map 的依赖图与 node 详情

**What to build:** 用户选择真实的合法 Map 后，可以看到完整依赖图，选择 node 核对本次工作的参数和前置依赖，而不是看到模板默认值或运行状态。

**Delivers:** P10, P11, P13, P17。

**Blocked by:** 02 — 浏览服务级 Map 目录。

**Status:** ready-for-agent

## Acceptance criteria

- [ ] 读取受支持格式的真实 Map；全部 node 都以标题与 Map 内 ID 显示，包括独立节点，不能只显示有连接的节点。
- [ ] 边仅来自 blocked_by；B 依赖 A 时显示 A → B，不增加执行路由、材料传递或隐含边。
- [ ] 使用事先固定的 A、B、C、D 节点及仅 A → C、B → C 的预期，通过真实图形核对箭头方向、连接端点、并行与汇合，并确认 D 无连接；预期不从实现结果反推。
- [ ] 依次选择引用同一模板但参数与依赖不同的 node，逐项显示当前 node 的参数与前置依赖，不残留其他 node 内容，不补入模板默认值。
- [ ] parameters 接受命名参数对象中的直接 JSON 值，包括结构化值、未在模板 inputs 声明的键及不存在的 zone、Bot 名称；这些内容本身不能导致资源有效性或参数契约错误。
- [ ] 业务文本按文本安全渲染，结构化参数可读地格式化；不执行文本、不按参数读取路径、不启动 Chat、不修改 Map 或模板。08 负责跨入口安全验收，本票实现不得先引入不安全临时方案。
- [ ] 通过 S1 的真实页面和真实文件验证节点、连线与选择行为；基本图形无需手工安排节点位置，完整布局与视图交互验收由 09 负责。
- [ ] 使用隔离服务和项目既有浏览器入口验证，不使用硬编码 UI 示例作为真实文件读取证据；同步更新受影响的预览与参数展示说明。

## Contract coverage

本票认领合法输入下的 P10、P11、P13、P17。05 负责无效 Map 的结构错误、依赖错误、旧展示清理及恢复；04 负责模板明细。
