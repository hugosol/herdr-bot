# 04: 保持脚本执行的并发、断连、暂停和重启语义

**What to build:** 脚本业务在后台运行时，manager 仍能合法管理同 Run；派发调用断开或暂停不撤销在途业务，真实后端重启后旧 Run 保持只读且不自动重跑。

**Delivers:** P4, P16, P17, P18

**Blocked by:** 02 — 通过真实 Map 异步创建空白 Bot 并交接报告。

**Repositories:** herdr-bot

**Status:** ready-for-agent

## Acceptance criteria

- [ ] 以真实 Map 派发实际 Rust 能力，在测试拥有的业务外部资源边界保持业务在途；在释放业务前分别观察同 Run 合法查询和 pause 已完成。不得用最终都返回、私有锁断言或空任务代替不长期占锁的证据。
- [ ] 派发请求已被后端接受后实际断开调用连接，独立读取原 execution 的真实业务结果和报告；不取消已接受业务，不再派发一次来获取结果。
- [ ] 在途业务与 pause 交错：pause 后新 dispatch/retry 按现有规则拒绝；原业务继续写入、读回和报告。resume 只恢复资格，不自动派发、重跑或重新通知业务。
- [ ] 使用真实独占后端进程，记录执行/报告/文件后实际终止并重启。旧 Run 保留已保存事实，按既有规则拒绝运行写动作，无自动恢复或业务重跑；不以重建 AppState 代替进程重启。
- [ ] 用有界观察、门闩进入/释放和独立读取证明因果关系，明确观察预算不构成新增产品超时或无限期无行为保证。所有失败路径释放测试门闩，保留原始错误和清理错误。
- [ ] 更新现有运行说明中的脚本断连、暂停及重启语义，不新增调度器、取消协议、重试队列或恢复系统。
