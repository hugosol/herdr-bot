# Contract — 脚本型 Bot 与创建流程固定 Rust 执行

Source: [spec](spec.md)
Acceptance mode: Rapid iteration
Approval: seam 选择、六表面约束审查及验收模式均已获用户明确批准。

本契约继承 spec 的范围及 ADR 0019；不表示实现、自动化验证或人工验收已经完成。Coverage 中的自动化工作归 agent，具名人工项归用户最终确认。交付归属由 `/to-tickets` 补入，不保存手工维护的承诺状态列。

**Complete implementation and all assigned automated checks before the human-led acceptance round. Planned human-led checks do not pause otherwise executable work. At the final handoff, report the remaining checks together with their prepared evidence; they remain unverified until the user confirms them. Report genuine blockers when encountered.**

H1、H2 仅保留真实 manager 会话闭环的最终确认。工具适配、角色指引、错误呈现、隔离设施、自动化验证及证据准备仍全部由 agent 完成；人工验收前不将这两项视为通过。

所有自动化预期来自上述承诺、独立字面输入或手工推导实例，不复制实现算法生成期望值。安全隔离、所属进程退出确认、实际读回及现有测试网络约束适用于全部覆盖项。自动化失败不转交给人工作为计划例外。

## Seam decisions

|Seam|Exposes|Hides|Alternatives considered|Reversibility|
|---|---|---|---|---|
|S1 定义与 workflow 的公开 HTTP／文件 interface|定义、预检、既有 manager 动作、Run/执行/报告事实及真实输入输出文件；承载主要确定性承诺|Rust 业务内部函数、锁组织、报告内部编排及材料生产实现|仅测 Rust 函数无法证明派发、真实保存及完成门禁，拒绝；新增公共执行函数 interface 无必要，不采用|中：公开定义和持久材料变更会影响消费者；内部 Module 组织保持自由|
|S2 manager 原生工具与报告接收 interface|真实工具派发、报告接收、collect、fail/retry、complete 和无脚本 Chat 的宿主事实|工具传输细节及后端内部实现|只验 S1 不能证明真实 manager 消费；新增脚本工具增加协议且与已批准复用方向冲突，拒绝|低至中：受独立维护的 agent/toolkit/Herdr interface 约束；现有动作和归属规则保持|
|S3 现有 Bot／scheduler／workflow 页面 interface|脚本定义编辑与预检、真实执行类型、报告、状态与可用入口|前端状态组织、渲染实现和后端内部结构|只读 HTTP 不能证明用户实际可维护和观察；独立脚本执行器页面扩大范围，拒绝|高：布局与文案可调整，公开语义和操作能力必须保持|

复用以上三个现有 seam，不新增公共脚本执行工具或独立文件交接体系。执行目标、无 Chat 报告来源以及页面的对应表达需要扩展，但不要求对外暴露内部 Rust Module。seam 被实现事实推翻时，先修订本契约再重开受影响票据。

### 已批准的约束决定

- 保持 manager 显式 fail/retry；脚本异常报告不自动将节点改为 failed，已结束的脚本不适用 recover。执行生命周期与节点交接状态必须分别可观察。
- 本次空白创建仅支持普通 Task/Map 目标。创建脚本型 Bot 的通用自举能力不纳入本次；专用三路合并 Bot 随定义迁移交付。
- 保存成功但材料生成失败不回滚、不刷新 baseline、不凭当前内容相同认定成功。修复后重跑仍执行真实冲突检查。
- 创建分支材料变更不得破坏共享 Task 的修订分支。现有 Task/Map 历史可读规则保留；不兼容仅限用户明确删除的旧空白创建 Task 来源需求。
- 暂停、断开连接、后端重启及旧执行迟到报告按 Promises 中的既有语义延伸，不引入新的自动恢复系统。

已拒绝替代：同步聚合整个业务批次增加等待和取消复杂度；自动完成或自动失败改变 manager 状态动作归属；用 Chat 身份伪装脚本违背真实执行事实；原地收窄通用文本替换者破坏其他消费者。相关架构取舍已由 ADR 0019 记录，无需重复另立 ADR。

## Not yet specified

- **具体数据表示待细化，不阻塞本契约批准**：固定 Rust 能力标识的具体字段和值、无 Chat 执行与报告来源的序列化表达、创建分支 request/baseline/handoff 的字段清单及失败阶段/错误码。后续交付必须把它们明确为可校验的公开数据契约并形成独立字面验收实例，不能把含糊自然语言或不透明对象视为已实现严格契约；这些表示不得改变上述承诺。若细化产生新的行为或兼容取舍，先修订契约取得批准。
- **内部实现保持自由**：Rust Module 组织、内部 seam、具体异步任务与锁实现、前端布局不由本契约选择。
- **执行环境待验收时核实**：真实宿主、授权及隔离环境可用性不在此伪称已验证。缺失时报告真实阻塞；H1/H2 的人工归属不代表可以遗漏实现或证据准备。
- 无未解决的批准阻塞项。H1/H2 是已批准的人工作业分配，不是已完成验收。

## Out of scope

继承 [spec 的 Out of Scope](spec.md#out-of-scope)，不扩展或缩减：无解释器或独立业务 exe、沙箱、通用替换框架、新工具/批次调度、自动完成/重试/回滚/跳过、自然语言语义判断、原通用替换能力收窄、旧空白创建 Task 历史兼容或 Map 私有 Bot 机制。已确认 chief 不新增直接执行脚本的入口；本功能在 Map 节点执行。

## Coverage review

- 35 项承诺全部映射到至少一个已批准 seam；例外：无。
- S1、S2、S3 均承载承诺；无空 seam。
- entry：S1 的现有 HTTP/file interface、S2 的原生工具和 S3 的页面均已审查；不新增 CLI，所以专用 CLI 表面不适用。
- data and state：目标互斥、无 Chat 执行、固定命名材料、报告归属、显式完成及迁移保留范围均已覆盖。
- external dependencies：Rust 计算是 in-process；文件/配置使用真实隔离本地资源；独立维护的 agent/toolkit/Herdr 按 remote-but-owned interface 处理，受控 adapter 覆盖故障、真实 S2 由 H1/H2 确认。无新增第三方执行平台。时间/随机 ID 不承诺具体值，以独立身份和因果归属验证。
- errors and failure：拒绝、部分写入、报告保存与通知分离、显式 fail/retry、无 recover/回滚/跳过、重启只读已审查。
- output and observability：报告、实际文件、公开运行事实和现有页面共同观察；不新增 stdout 协议或 metrics 平台。
- resources and concurrency：无节点 Chat、锁外业务执行、断开后结果归属、暂停与重启语义、迟到结果、隔离进程清理均附着 S1/S2/S3，不另建资源 seam。不承诺新调度器或未议定的性能数字。
- 验收模式：Rapid iteration。人工覆盖：H1/P34（同时覆盖 P3/P5/P10/P12/P29 的真实 S2 部分）、H2/P35（同时覆盖 P13/P14 的真实 S2 部分）。其他自动化覆盖仍须完整完成。
