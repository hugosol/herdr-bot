# Ticket 05 TDD 执行复盘

## 证据范围

本复盘仅使用本 ticket 执行对话及其工具结果，不引用父 session 或其他票据执行。实现提交为 `f64f8cc`。静态页面构建、两个定向测试及完整后端入口最终通过；完整入口耗时 346.7 秒，build、全部测试 binary、doctest 均通过，未派发为零。以下建议不否定这些结果，也不将受控 HTTP／报告边界证据外推为真实 manager H2 验收。

## 高：把验收场景设计细化到每个行为切片

**事实**：首个测试成功捕获生产缺陷：脚本已有真实失败报告后，manager `fail` 返回 500，原因是仍要求原 Chat 关联。但该测试同时覆盖失败、确认拒绝、recover、重跑和两个消费者；修改 fail 后，又先后暴露了两处夹具问题：替代 Bot 仍使用已绑定目标，导致新报告为 false；collect helper 则携带了接口不接受的 `nodeId`。执行中还修正了对 handoff 文档不存在的 `request` 字段的断言。

**建议**：在现有 TDD 指导中，将“设计 before red”的完成条件收紧为：当前切片的合法请求、独立预期和观察路径均已从现有公开接口／材料实例确定。先用一个小场景闭合“真实失败后可以显式 fail”的红绿循环，再增加 retry 确认、真实新材料和报告交错场景。跨多个业务阶段的最终组合测试可以保留，但不应承担所有阶段的首轮探索。

**预期收益**：生产缺陷与夹具错误更易区分，减少一次测试反复失败却分别属于不同原因的情况。

## 中：为受控报告提交边界提供明确的测试设施入口

**事实**：票据允许在报告提交边界控制交错，同时禁止新增任意 execution 的公共工具。执行为此新增了库内测试，复用集成测试 common；首次编译失败，因为 common 使用了仅集成测试目标提供的 `CARGO_BIN_EXE_herdr-fixture`。随后增加显式 fixture 可执行文件入口、测试 crate 别名，并提取已有 Windows 文件门闩，才完成该路径。

**建议**：在现有测试文档中，为“库内测试需要真实外部 fixture”的分支提供一个精确指针，集中说明可复用设施、fixture 产物来源和定向构建前提。后续建设共享支持时，让测试显式取得当前 target 的 fixture 产物，避免每个新用例重新解决 Cargo 测试目标差异。继续保持报告归属入口只在测试内可见。

**未验证**：此次记录不足以判断这套设施是否值得进一步抽取为独立测试支持 crate；不建议仅凭本次经历立即增加该层抽象。

## 中：按检查类型拆分测试指引，降低必读成本

**事实**：测试指引约 576 行，首次读取超过工具输出上限，只返回约前 204 行；接着又读取了后续约 100 行，其中包含多个与本票无关的原生宿主专项。真正影响本票的内容主要是后端入口、独立 target、真实 fixture、文件门闩和进程清理要求。

**建议**：保留短小的入口选择与通用安全要求，将各专项验收按分支下沉到独立文档。指针以触发条件开头，例如“Rust 脚本 HTTP／文件验收”或“真实宿主验收”，让实现代理只加载本次需要的路径。不要在 AGENTS.md 中复制专项细节。

## 中：让检索失败更便宜，限制目录输出

**事实**：首次描述性 find 的 23 个候选判断请求全部因区域不可用失败；结果明确不能证明代码不存在。随后建立当前 worktree 索引，使用符号搜索和声明大纲顺利定位实现。另一次依赖探测顺带列出了整个 Temp 目录，产生 18,646 个条目的输出，对本票没有相应信息收益。

**建议**：工具侧对明确不可用的检索后端尽早熔断，并返回可执行的替代路径；代理侧将依赖探测限制为指定文件／目录是否存在及工具路径。目录枚举默认设置数量上限，宽目录需要额外显式请求。

**推断**：这能减少无效检索与上下文噪声；本次记录没有性能对照，无法量化节省时间。

## 低：区分完成检查等待与无效停滞

**事实**：必需的完整后端回归在后台执行。代理已完成代码、文档和定向验证，等待期间提交了实现；多次 wait 仍收到“等待不是进展”的通用提示，最后该回归正常通过。

**建议**：宿主将“正在等待本任务必需且唯一剩余的检查”识别为合法阻塞状态，使用完成通知或一次长等待，避免反复催促产生无关动作。保持“检查结束后停止，不增加额外审计”的完成条件。

## 保留的有效做法

- 首轮红测来自真实 Map、文件冲突和公开 manager HTTP，确实命中了 Chat-only fail 缺陷，而不是仅凭缺少接口建立红灯。
- 报告交错由获准的受控提交边界制造，保存、完成门禁和材料解析仍使用真实实现；没有增加公共执行选择后门，也没有编辑 Run 记录制造资格。
- 最终报告区分了 S1 自动化通过与仍由其他验收负责的真实 manager H2，没有将完整回归通过解释为所有验收层均完成。
