## 2. 中高 · 把交付脚本纳入现有 `typecheck`

**事实。** `bun run typecheck` 已经运行 TypeScript 和 `check:authoring`。首次执行捕获了测试代码使用 ES2020 不支持的 `Array.at`，但项目 `tsconfig.json` 未覆盖生成的 watcher。代理另外运行严格检查，第一次因 TypeScript 7 要求 `--ignoreConfig` 退出 1；修正后，项目检查与 watcher 的单独检查均退出 0。实现对话没有证明 CI 或提交钩子是否调用该命令。

**建议。** 在现有 `bun run typecheck` 串接一个继承项目编译选项的交付脚本检查，覆盖清单登记并实际运行的 TypeScript 入口及其依赖，排除原始上游快照。不要为 `Array.at` 增加 reviewer 文本规则：现有编译器已能发现；应消除的是交付入口是否被检查的偶然性。

## 3. 中 · 用可辨识的外部边界失败保护 TDD 的 red

**事实。** 队列测试最初因交付入口不存在而失败。迁入入口后，受控 `gh` 没有处理 `PrCommitStatuses`，watcher 把测试夹具错误当作可重试查询，进入默认 60 秒等待，先触发的是 5 秒测试超时。补齐独立状态响应后，才观察到有效的行为 red：CLI 成功退出，但没有报告实际队列条目。之后，合并目标分支、部分合并后查询失败、`gh` 缺失三个场景也分别观察到了预期的行为失败和修复。

**建议。** 在既有测试指南的外部进程夹具章节记录一种做法：不测试重试的业务场景用公开 CLI 的查询错误预算 `1` 停在首个失败，保存不匹配的请求与退出；专门验证重试的场景保留真实重试路径。只有请求到达预定边界，并且独立的行为断言失败，才记为 red。不要延长测试超时来掩盖夹具漏接。
