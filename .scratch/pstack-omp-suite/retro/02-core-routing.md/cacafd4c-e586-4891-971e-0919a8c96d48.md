# 02-core-routing：TDD 执行复盘

范围：仅复盘指定 `02-core-routing` 执行代理的对话和工具结果。未重跑验收，也未改动环境。以下按严重度排序。

## 1. 高：让回归测试先在行为断言上变红，而不只是在缺文件时退出

**事实。** S1 首次红灯在读取尚未生成的 `poteto-mode/SKILL.md` 时以 `ENOENT` 结束；它证明入口缺失，但没有走到「默认路由错误地推荐暂缓能力」的断言。S3 首次运行失败是 capture 请求编号从 1 开始，而测试按 0 开始编排，导致没有执行预期的 `read`。修正后，实际 OMP 返回了调查正文，并对六个暂缓技能报告 `Unknown skill`；历史中没有观察到误配置被同一回归测试拒绝的红灯。

**建议。** 将 TDD 指引中的红灯条件落实为一个验收句：对目录、路由等否定约束，先让真实宿主运行到判别点，再观察同一断言拒绝一个可辨别的错误状态。对于本场景，可在测试自有的临时资源树放入一个意外可用的暂缓技能，观察它出现在原生目录或可被原生读取，随后移除并通过；不改交付目录，不模拟 OMP 结果。缺文件与驱动装配错误单独记为准备阶段证据。

## 2. 中：让 dock 按待执行动作编排受控回复，而不是靠请求奇偶

**事实。** 首次 native dock 已成功启动并收到一个真实模型请求，却因编号假设跳过了工具调用。修正奇偶后场景通过；新增测试仍通过奇偶和下标指定每次回复。

**建议。** 在现有 capture fixture 的 `respond` 用法旁提供多轮工具调用示例：按各轮独立的输入标记选择动作，按真实工具结果识别续轮；未预期的请求明确失败。保留真实 OMP `tool_execution_end` 的 `isError` 与结果正文断言。这样 fixture 不负责判断技能是否存在，增加一轮请求也不会把后续用例悄悄错配。

## 3. 中：把工作树目录的 TypeScript 校验提前到首个可执行切片

**事实。** `bun run test:pstack` 首次完整运行已通过 16 项，但随后 `bun run typecheck` 因 `Array.at` 和 `String.replaceAll` 不在当前 ES2020 类型范围内失败。修正后，两项检查均通过。已有 `package.json` 类型检查入口，无需另加重复 lint 规则。此执行对话未核实 CI 或 pre-commit 是否调用它。

**建议。** 在 `docs/agents/testing.md` 的迭代指引中，把「新增或修改测试/支持代码」直接指向现有 `bun run typecheck`：第一次 focused 测试运行后就完成校验，不留到完整分区的最后。若后续检查发现 CI 尚未接入，再接入同一个命令，而不是另建 ES API 黑名单。

## 4. 低：让资源调查一次返回固定来源与窄范围清单

**事实。** 执行中先列出 100 个索引项目，再对工作树做精确状态查询；上游清单的第一次递归展开还输出了大量本票无关的 statechart 测试语料。两处后来都用更窄的查询取得了需要的信息。
