# 05: 独立面板席位、并行产物与模型偏离事实

**What to build:** 确认的面板席位可分别由原生 task 调用，明确并行任务产生隔离且对应的真实结果；迁移文本保留竞争、裁判、综合及取证方法，实际模型偏离有可读取事实。

**Delivers:** P22, P23, P29, P30

**Blocked by:** 04: 首次 setup、确认绑定与原生执行角色

**Repositories:** toolkit

**Status:** ready-for-agent

- [ ] 通过 S1/S3 生成逐席独立 persona 与供技能读取的角色清单，共用明确角色正文来源；模型回退数组不得算成多个席位。
- [ ] 内容审查 swarm 分片／同题竞速／混合组织、done predicate、SHA／方法证据、缺口报告，以及 arena rubric、独立裁判、厂商身份、基底／综合后验证，interrogate 对抗评审与复跑要求。
- [ ] 明确逐席及批量发起原生 task，以受控模型 adapter 驱动真实工具调用，在独占隔离目录生成并独立读回不同已知文件，核对各席实际调用、结果关联和产物；不同 ID 不构成文件隔离证明。
- [ ] 在临时 Git 仓库／owned 资源上验证原生任务隔离，既不创建 herdr Map，也不增加角色执行引擎。
- [ ] 本票独占 P30 自动用例：已知不可用模型、操作者覆盖、角色身份与厂商信息，观察原生实际解析、诊断及可供工作流读取的事实；不能伪报与配置匹配。
- [ ] 审查文本明确报告模型／面板偏离、不以代理名推断厂商多样性；不测试模型自主分片、评分、选裁判、综合质量或发现问题效果。

## 契约与执行边界

依据：[已批准 contract](../contract.md)（S1 套件维护命令、S2 Suite 选择及 Chat 发起／恢复、S3 OMP 原生会话交互）。以 P 编号和本票 coverage 为验收依据，不改 spec／contract 的承诺。

只保证迁移内容语义和代码机制，不测试模型自主路由、评分、综合、授权服从或输出质量；内容审查由 agent 完成，不转成人工必验。受控 adapter 只证明请求和真实工具交互。不得用源码字符串、参数正确或产物存在替代消费者可见效果；期望来自独立指定输入、批准上游方法或独立字面结果。

复用现有原生机制和测试归属，已有覆盖不重复新增。修改前读取目标仓的适用指引。使用 owned 临时配置、Git 仓库、端口、页面和可追踪进程，保留证据并只清理所属资源。缺依赖、错误或未运行必须如实报告。不要安装／修改宿主、全局模型或生产配置来伪造通过。

更新生成资源／模型前停止使用同包的 pstack 会话，完成后重新发起；不引入热加载、在线快照或跨进程强制停用检测。正常并行会话不被禁止。先完成代码、内容审查和全部可执行自动检查，再进行 H1/H2 人工验收；人工未确认项继续标为未验证，不阻止其他工作。
