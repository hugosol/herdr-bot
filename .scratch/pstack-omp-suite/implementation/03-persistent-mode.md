# 03: 原生持续模式的开启、关闭与跨进程恢复

**What to build:** 新进程中的 pstack 会话首轮默认开启持续模式，用户可显式开关并看到状态，恢复保留已保存状态，一次性原生技能调用不改变模式。

**Delivers:** P15, P16, P17, P18, P20, P21, P40

**Blocked by:** 02: 可读取的核心路由、工程方法与暂缓边界

**Repositories:** toolkit

**Status:** ready-for-agent

- [ ] 通过 S3 复用 toolkit 现有声明式模式及 OMP adapter，不新建状态／注入框架；通过生成来源贡献工程规则，不每轮灌入所有叶技能正文。
- [ ] 实际 OMP 无保存状态首轮请求已包含开启贡献；多轮 on/off 检查新增贡献、状态事件及原生历史，关闭仅停止新贡献，不撤回历史。
- [ ] 拥有 P17 原生会话分区：on/off 均跨真实进程恢复并检查首轮贡献；公开 herdr Chat 恢复分区由 13 拥有。
- [ ] 关闭后明确执行一次性原生 skill 调用，核对正文实际读取、下一轮及再次恢复的持久状态均不被隐式开启。
- [ ] 拥有 P20 原生读取分区：不同 cwd、含空格源目录下明确发起主会话与子代理读取，核对独立已知资源正文及实际来源基准，不依赖父聊天隐式继承；Suite 装配后分区由 13 拥有。
- [ ] 区分隐藏技能的默认目录曝光、手工 skill 入口、原生 URI 与相对文件读取；实际验证批准入口可读，不要求隐藏技能自动触发。
- [ ] 自动观察仅切换模式的副作用，不产生合并、部署或对外业务动作；内容审查模式开启不等于业务授权，不宣称阻止模型以后所有未授权操作。
- [ ] 准备 H1：隔离真实 TUI 的启动／退出／恢复步骤、预期显示、on/off 前后会话记录、自动检查结果与原生日志；覆盖可见开关和关闭后恢复仍关闭。真实显示只有用户确认才通过。

## 契约与执行边界

依据：[已批准 contract](../contract.md)（S1 套件维护命令、S2 Suite 选择及 Chat 发起／恢复、S3 OMP 原生会话交互）。以 P 编号和本票 coverage 为验收依据，不改 spec／contract 的承诺。

只保证迁移内容语义和代码机制，不测试模型自主路由、评分、综合、授权服从或输出质量；内容审查由 agent 完成，不转成人工必验。受控 adapter 只证明请求和真实工具交互。不得用源码字符串、参数正确或产物存在替代消费者可见效果；期望来自独立指定输入、批准上游方法或独立字面结果。

复用现有原生机制和测试归属，已有覆盖不重复新增。修改前读取目标仓的适用指引。使用 owned 临时配置、Git 仓库、端口、页面和可追踪进程，保留证据并只清理所属资源。缺依赖、错误或未运行必须如实报告。不要安装／修改宿主、全局模型或生产配置来伪造通过。

更新生成资源／模型前停止使用同包的 pstack 会话，完成后重新发起；不引入热加载、在线快照或跨进程强制停用检测。正常并行会话不被禁止。先完成代码、内容审查和全部可执行自动检查，再进行 H1/H2 人工验收；人工未确认项继续标为未验证，不阻止其他工作。
