# Contract — pstack 专用 OMP Suite

Source: [spec](spec.md)
Acceptance mode: Rapid iteration
Approval: approved — 三个 seams、六面检视方向及两项生命周期取舍、快速迭代与所列人工验收项均获用户明确确认。

## 承诺口径

- 本 contract 保证迁移内容与已确认方法相符、资源可用和代码机制准确；**不承诺、也不测试模型自主执行 skill／提示词的具体效果**，不把这些效果转成人工必验。角色选择、评分、综合、发现问题、代码质量或授权指令服从等模型判断均不得由“提示已注入”推定通过。
- 明确输入下的原生资源读取、状态恢复、模型解析、task 分发、脚本与产物属于可验证机制。受控模型 adapter 可用于检查请求与工具交互，但不得声称证明真实模型理解或策略质量。
- Coverage 中“内容审查”是核对批准文本语义、必要步骤、依赖与引用，不是运行真实模型验证效果；它由 agent 承担，不是人工验收例外。
- 预期结果来自本 contract、独立指定的小样例及批准的上游方法。不能调用 implementation 自身计算期望值来证明正确。
- Promise 的完成状态从交付票据和所需证据派生，不维护状态列。`/to-tickets` 通过 P 编号登记交付归属；当前尚未产生交付票据，也没有已通过的产品验收结论。
- **Complete implementation and all assigned automated checks before the human-led acceptance round. Planned human-led checks do not pause otherwise executable work. At the final handoff, report the remaining checks together with their prepared evidence; they remain unverified until the user confirms them. Report genuine blockers when encountered.**

### 已批准生命周期与取舍

- 无角色绑定也可进入 setup；确认并生成后重新发起 Chat 使用角色。拒绝以占位默认模型绕过确认，也不为此引入同会话热加载。
- 更新生成资源或模型前先停止使用同一套件包的 pstack 会话，完成后重新启动。正常并行使用不受此约定限制；不自动新增跨进程强制检测。
- 选择停用更新是为了不引入运行中快照、热切换及并发发布承诺。未来在线更新需求会影响 S1 的发布、S2 的装配和 S3 的按需读取，需要重审；本期不把它提前实现为平台。
- 不把整个验收压到一个 seam：S1 的可重现与所有权、S2 的 Suite 装配、S3 的原生消费各能区分不同的真实违约，不能互相替代。
- 保留 pstack 的提示词方法，通过内容审查控制迁移差异；拒绝把不可靠的模型行为效果测试作为交付门禁，也不将其强行转给用户。

### 依赖类别与证据口径

- **In-process**：映射、模板和清单计算，直接通过 S1 的输入／输出验证，无额外公开 adapter。
- **Local-substitutable**：文件系统、Git、宿主子进程、本地 UI/CLI 驱动、Java/TLC 和媒体工具。使用独占真实资源及已有受控 adapter；受控宿主不替代实际 OMP 资源消费。
- **Remote but owned**：herdr 调用与会话协调。复用已有 interface 和实际／受控 adapter，不创建 pstack transport module。
- **True external**：模型厂商和 forge。模型 adapter 的受控响应足以验证本 contract 的机械请求和分发，不证明模型策略质量；forge 的受控检查与真实交互按 P38 分工。

## Not yet specified

**阻塞本 contract 批准的决定：无。**
