# Contract — Node 成果批准与交接门禁

Source: [spec](spec.md)
Acceptance mode: Full automation
Approval: 已批准。用户依次批准 S1＋S2＋S3、约束检视 B1–B3 的修正方向，并选择全自动验收。无人工验收例外。

## Promises

Coverage 中的检查由 agent 全部负责；真实宿主、真实模型或其他授权依赖缺失时如实保留未验证，不以受控结果替代。预期结果来自 spec、以下承诺及独立字面业务样例，不通过复用实现计算预期。交付归属由 /to-tickets 回填至各行 Coverage，不维护人工状态列。

### Inherited decisions and approved refinements

- spec 的业务职责和范围整体继承；ADR 0015 的执行角色与结束节点语义继续成立。ADR 0019 中脚本无 Chat、自动报告和显式 complete 保留，旧脚本授权检查按 spec 移除。
- B1：用户明确不要求兼容旧 Run 数据。拒绝新增旧运行升级入口、旧字段适配、静默补批准或旧策略映射。保留旧数据，不主动删除或批量改写；本契约不承诺新版本可以继续或呈现旧 Run。此处与“不兼容旧 V1 业务材料”分别成立。
- B2：批准与报告正交，不新增批准通知。拒绝批准成功后主动通知 manager 的方案，因为正常 node-chat 先 approve 再 report 已承担交接；低层允许独立调用，不用隐式机制修补未发报告的调用顺序。
- B3：批准工具不要求说明，拒绝非空交接说明参数及成果报告引用。用户基于当前对话判断，原生工具仅询问“当前会话的成果是否已达到预期，可以交接并推进后续流程？”。不产生新的文本、产物或版本准入条件。
- 成果批准仍不保证无报告可以 complete。现有最新报告 canComplete=true 及其他门禁继续适用；approved 与 canComplete 是不同事实。
- 人工确认由官方宿主工具的原生 UI 路径保证；后端承担同机来源、真实执行归属与持久门禁，不扩展为抵御同机任意恶意程序伪造宿主操作的新安全系统。
- 人工与自动批准来源不得混淆；自动批准不能被展示为用户 Yes。不要求冻结或版本化正文。
- 验收模式为全自动；没有预留给用户的交互、模型判断或页面验收例外。依赖／授权缺失属于真实未验证项，不降格为受控成功。

### Dependency categories

- In-process：形状校验、状态判定和门禁决策隐藏于现有 module；不为测试新增外部 seam。
- Local-substitutable：本机文件系统与受控宿主具有隔离测试资源或 adapter，但落盘、重启、并发及脚本效果承诺必须用真实独占资源证明，替身只覆盖其适用的确定性故障。
- Remote but owned：后端与配套工具集之间复用现有传输 interface／adapter，既有受控 adapter 可验证请求与故障；实际跨宿主承诺仍经过生产传输。
- True external：已安装 OMP／Pi、Herdr 与模型 provider 的实际行为需原生证据。受控 adapter／provider 只证明机制，不冒充真实模型选择、用户确认或加载成功。真实模型与凭据访问须显式授权。

### Six-surface review

|Surface|Applicable constraints and observations|
|---|---|
|Entry|S1 公开操作、S2 双宿主原生工具、S3 真实页面覆盖；无新增独立 CLI 产品入口。工具不要求 LLM 指定执行身份，不允许非节点身份误批准。|
|Data and state|批准模式按执行冻结；批准事实持久化、同次恢复保留、retry 不继承。旧 Run 与旧 V1 材料不兼容，但不删除或改写历史。V1/V2 分别保持业务协议。|
|External dependencies|真实文件、Bun、后端进程、Herdr、OMP／Pi 与授权模型分别记录证据；受控协议和真实业务不能混称。时间观察使用现有产品预算，不延长产品超时以凑验收。|
|Errors and failure|拒绝／取消／超时／无 UI 均不批准、不使工作失败；存储失败不返回批准成功；报告保存／通知错误保持原语义。无自动重试、回滚、重新派发或批准通知。|
|Output and observability|公开状态与真实页面可区分模式、批准事实及来源；report 自由发送，approve 不制造报告。实际副作用和完整读回独立核对，不以文字成功声明代替。|
|Resources and concurrency|原生确认等待不持有阻塞 Run 的工作资源；并发批准不重复业务效果，旧确认不得批准 retry 新执行。测试进程、目录、端口及原生会话独占，结束确认退出，原错误与清理失败均保留。|

六类 surface 均适用，无整体不适用项。私有 module interface 不是额外 contract seam。无新增性能 SLA、成本阈值或任意恶意本机调用防御承诺。

### Trade-off notes

- 不兼容旧 Run 和旧 V1 材料，换取干净切换；若未来要求跨版本续跑，需要重新规定迁移与旧执行批准语义，受影响的是持久数据读写及恢复 interface。本次不预建兼容层。
- 不增加批准通知，保留 approve/report 正交及自然工具顺序；若未来引入不再 report 的自动执行者并要求 manager 立即感知批准，需要重新审视通知承诺。本次不提前建设。
- 批准不锁定正文，避免将节点讨论变成版本审批系统；若未来要求精确版本签署，批准 interface、材料身份及下游消费规则都需重新制定。本次不加摘要批准锁。
