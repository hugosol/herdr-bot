# 02: 从 zone 创建默认配置 Bot，贯通进展与结果

**What to build:** 用户从 zone 行的“+”打开创建弹窗，选择模板、填写普通任务、查看本次名称，确认后在服务端配置的 Herdr Workspace 中创建 Bot。页面展示启动与提交阶段，只有就绪和提交确认后才在弹窗报告成功并提供定位信息。

**Delivers:** P8, P10, P11, P23, P25, P26, P27, P32, P33, P34, P35, P41, P43, P44, P46；P49 的名称侧覆盖，正文覆盖由 04 补齐。

**Test owner for:** P49 的名称经生产调用包装层保真且无额外执行。

**Blocked by:** 01 — 管理共享、持久化的 Bot 模板。

**Status:** ready-for-agent

## Acceptance criteria

- [ ] 普通目录与 Git 工作树对应的 zone 行均有“+”；真实浏览器打开的弹窗绑定正确 zone，选择模板、输入任务并发起真实创建链路。基线场景为默认 model/thinking、无 Skill、非空普通 input；不能用模拟成功代替贯通。
- [ ] 命名支持四个已承诺字段和固定文字。给定 zone、模板、agent 与已知短标识，以预写完整名称验证实际命名，不调用命名函数生成期望。zone.name 为 zone 目录末级名，bot.id 不是 Herdr Tab ID。
- [ ] 弹窗只读预览本次实际将使用的名称，无手工覆盖入口；同次创建的浏览器预览与独立 Herdr 侧名称一致。可捕获动态标识，但不能用同一命名函数生成两侧期望。
- [ ] 用真实 TOML 输入和进程启动观察验证：Workspace 配置缺失、空或纯空白均启动失败，合法显式值启动成功。部署明确配置 bot-playground 或本次显式目标，不能用代码缺省值掩盖缺失。
- [ ] 每次创建按服务端配置名称精确选择唯一 Workspace；受控集合中当前焦点指向其他 Workspace，仍选择配置目标。公开请求试图覆盖 Workspace 也不能改变实际目标。异常匹配的完整故障矩阵由 06 负责。
- [ ] 新建 Tab 及其初始 Pane，显式以所选 zone 目录为 cwd 启动 agent；普通目录和 Git 工作树均以独立预建目录为期望，故意令当前焦点 cwd 不同，外部记录确认实际目录。
- [ ] 启动已接受但就绪被阻塞时无初始输入；目标就绪后才投递。分别延迟就绪和提交响应，真实浏览器稳定呈现“正在启动”和“正在提交初始指示”。不能以固定延时或启动返回代替就绪。
- [ ] 就绪或投递任一未确认都不成功；两者确认后显示“创建成功，初始指示已提交”。受控 agent 仍工作中时即完成创建，不等待轮次结束、Skill 完成或 connect-bot 接入。
- [ ] 公开结果与独立外部记录比对 Bot 名称、zone、已知 Tab/Pane 标识，未取得的标识不伪造。成功和基础失败均留在弹窗，由用户关闭，不自动切换会话列表。未确认时不假报成功；完整部分失败语义归 06。
- [ ] 独立读取公开会话、监听和关机信息，创建本身不产生 connect-bot 登记、监听或 keepAlive 修改；保留原有同机来源限制，不要求 agent 接入 connect-bot。
- [ ] 名称含引号、中文、空格及 Shell 特殊字符的独立字面样例经实际生产交互方式后保真；外部观察确认包装层没有额外 Shell 执行。bot-name 仍是单行规则，不为测试扩展产品输入范围。
- [ ] 从首次实现即使用独立对象标识、接受时模板快照和后端拥有的创建生命周期；不能先依赖显示名唯一、可变模板引用、请求存活或全局单飞资格。05/07 补齐专门场景及证明，不授权基线引入相反行为。
- [ ] 完成适用自动检查和实际运行观察。受控 adapter 负责时序检查，生产 adapter 支撑真实变化；记录必须区分两者，不能以受控记录声称真实 Herdr/agent 已验证。

## Human-led coverage preparation

本票负责 H1 中 P25/P26/P27/P33 的证据准备：四组真实运行的预期 Workspace 和目录、Tab/Pane 定位、可独立读取的实际 cwd、就绪到投递时序，以及提交确认与成功展示的对照。与 03/04/05 共用一组四组合验收，避免要求用户重复执行。没有外部标识时不得伪造；受控 adapter 证据不可充当真实终端证据。实现及全部自动检查先完成，账号、费用、登录相关最终真实运行由用户确认，待确认项明确保留为未验证。
