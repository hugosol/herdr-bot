# 07: 浏览器断开与多客户端并发不改变创建责任

**What to build:** 后端一旦接受创建就独立负责执行；浏览器断线、刷新或关闭只失去观察，不取消创建。电脑和手机同时提交的请求分别接受并执行，各自保持对象、模板快照和输入隔离。

**Delivers:** P50, P51。

**Blocked by:** 02 — 从 zone 创建默认配置 Bot，贯通进展与结果。

**Status:** ready-for-agent

## Acceptance criteria

- [ ] 公开入口确认后端已接受后，分别在尚未就绪及尚未投递的受控时点断开观察连接。独立外部查询证明同一次创建继续完成，只有一次初始化提交，不关闭、重建或重发。
- [ ] 真实浏览器覆盖断线、刷新及关闭页面；未收到确认结果的页面不能显示成功。刷新后不承诺找回结果，不为满足本票建设回执检索或恢复系统。
- [ ] 两个独立客户端同时对同一 zone 提交，再同时对不同 zone 提交，分别得到接纳和独立外部对象。每次任务使用独立预写样例，外部记录显示输入与对应目标一致，不合并、不复用。
- [ ] 利用受控启动/提交屏障证明两个已接受创建可以独立推进，一个受阻不使另一个排队等待；不以仅先后请求成功证明并发。
- [ ] 验证并发请求各自采用接受时的模板快照。使用独立客户端与预写不同版本，使配置和输入对应每次接受的意图，不依赖私有状态；05 负责单个挂起请求前后编辑的专项回归。
- [ ] 不复用固定操作的单飞执行资格，不引入全局忙碌拒绝、自动排队、限流数值或额外并发上限；保持原有固定操作行为不变。
- [ ] 真实执行失败仍按既定中断和现场保留规则处理，浏览器连接终止不能伪装为 Herdr 执行失败。独立外部记录验证副作用，而非只检查任务包装器未报错。
- [ ] 完成自动时序/并发检查和真实浏览器运行验证；遵循契约 B1/B2，不增加后端崩溃后的创建恢复承诺。

## Coverage ownership

本票拥有 P50 的断线/刷新/关闭覆盖与 P51 的同 zone、不同 zone 独立并发覆盖。05 拥有 P40 的单请求模板编辑快照案例；本票的并发快照案例用于证明 P51 的隔离，不重复认领同一案例。06 的错误/超时矩阵不把浏览器失去观察连接作为取消条件。

## Contract boundaries

依据已批准的《Contract — Bot 模板管理与从 Zone 创建 Bot》及来源 spec，尤其批准取舍 B1/B2。本票补齐并证明 02 已采用的后端所有权与独立执行设计，不允许以“后续修复”为由先交付断线取消或全局单飞实现。进度传输和内部调度保持自由，不新增数值性能或容量 SLA。
