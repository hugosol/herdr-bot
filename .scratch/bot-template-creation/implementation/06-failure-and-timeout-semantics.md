# 06: 失败与超时保留现场，准确表达不确定性

**What to build:** 创建失败时用户能区分完全未创建、已有现场但提交失败、投递结果未知等情况；系统停止本次后续步骤，保留已经产生的对象，不通过重建、重发或删除掩盖问题。

**Delivers:** P36, P37, P38, P42。

**Blocked by:** 02 — 从 zone 创建默认配置 Bot，贯通进展与结果。

**Status:** ready-for-agent

## Acceptance criteria

- [ ] Herdr 不可达、目标 Workspace 零匹配和多匹配三类情形分别经公开创建入口失败；独立外部记录确认无 Tab 创建、无 Workspace 创建、无自动启动 Herdr 或回退目标，不任取第一个匹配。
- [ ] Tab 创建后、agent 就绪后及投递超时分别注入受控故障，页面及公开结果明确失败阶段、已有现场和已知对象标识；未取得的定位信息不伪造。
- [ ] 任一步实际执行错误或超时后不执行后续阶段；外部独立查询证明已创建对象仍保留，不关闭 Tab、Pane 或 agent。浏览器失去观察连接不是执行错误，按 07 的 B1 行为继续。
- [ ] 外部已产生副作用后返回失败或不确定响应，独立外部记录证明无额外创建、重复投递、删除或关闭动作；不能只断言内部调用包装层返回值。
- [ ] agent 已就绪但提交被明确拒绝时，说明现场已存在且提交失败；投递超时而无法确认时表述为结果未确认，不能说成确定未发送，也不能显示创建成功。
- [ ] 在 Workspace 查询、Tab 创建、启动/就绪和提交各适用阶段观察错误/超时的中断语义，确认没有隐藏自动重试、固定延时假定就绪或失败后继续。涉及未知副作用时仍只保留已知事实。
- [ ] 真实浏览器在稳定的受控故障下检查结果可读且留在弹窗，页面与独立外部现场相符；用户关闭前不自动切换会话列表。
- [ ] 完成自动故障矩阵和适用运行验证。使用公开 S1/S2 与外部 S3 观察，不通过读取私有状态、清理现场或模拟回显伪造通过。

## Coverage ownership

本票拥有 P36/P37/P38/P42 的故障矩阵测试。04 单独拥有 P31 的全空提交被拒绝场景；07 单独拥有 P50 的观察连接断开后继续执行场景。相同实现可以共用，但不重复认领覆盖项。基础保存失败归 01，不将存储事务算法扩展为本票范围。

## Contract boundaries

依据已批准的《Contract — Bot 模板管理与从 Zone 创建 Bot》及来源 spec，尤其 B1。受控 adapter 提供确定的时序和副作用故障；不能把这些记录当成真实外部正常路径证据。不增加自动回滚、重试队列、重建、重发、修复 Workspace 或恢复系统。
