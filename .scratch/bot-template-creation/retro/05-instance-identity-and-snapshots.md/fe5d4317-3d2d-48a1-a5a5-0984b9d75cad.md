# 复盘建议：05 实例身份、模板快照与独立新对话

本轮按 TDD 先红后绿完成实现：新增 5 个集成测试，后端完整套件 330 passed / 3 ignored / 41 suites，前端 176 passed；真实 Herdr → OMP/Pi 的 H1 未执行。以下建议按严重度排序，事实、推断与未验证项分别标注。

## 1. 建立唯一的仓库检查入口，把前端构建纳入后端测试前置（高）

**事实**：首次执行 `cargo test --manifest-path backend/Cargo.toml` 在 `backend/tests/herdr_config.rs:73` 失败，原因是工作树缺少 `backend/static/index.html`；执行 `npm --prefix frontend run build` 后，同一完整套件变为 330 passed。`frontend/package.json` 与 README 只提供分开的 build/test 命令。

**建议**：在仓库根增加一个检查脚本（例如 `scripts/check.ps1`，或根 `package.json` 的 `check`），固定顺序为：安装/构建前端 → 后端测试 → 前端单元测试 → 仅对改动 Rust 文件执行 `rustfmt --check`。在 README 的“构建/检查”段落只引用这个入口；如果已有 CI 或预提交钩子，把它接进去。另一种低成本修补是让 `herdr_config` 在缺少打包页面时以清晰的前置条件信息跳过，但单一入口能同时覆盖所有 ticket，优先选它。

**落点**：`scripts/check.ps1`、README、CI/预提交配置。

**置信**：失败与修复是事实；仓库当前没有根检查入口是基于本轮所见的推断，CI 目录本身未检查。影响是每个新 worktree 都会重复踩到，并可能被误报为代码回归。

## 2. 把 Bot 创建测试的公共夹具收进 `tests/common`，并增加“保存助手返回本次对象”的评审规则（高）

**事实**：新增的 `backend/tests/bot_identity.rs` 有 672 行，重复了 `backend/tests/bot_creation.rs` 中的 `config_with`、`register`、`save_template`、`preview`、`create`、`creation`、`wait_stage`、`calls_of_kind` 等助手。`save_template` 最初返回列表的 `first()`，在第二个测试中实际拿到的是先保存的 OMP 模板，导致“必须启动 Pi”失败；而第一个参数化测试当时只断言了数量和目录，没有断言 `agent_kind`，所以它曾以错误的模板通过。修复为按本次保存的显示名匹配、并补充 `kinds == ["omp", "pi"]` 后才真正覆盖两个 agent。

**建议**：把这些助手抽到 `backend/tests/common/bot.rs`（或 `common::bot`），两个测试文件共用；在 `CODING_STANDARDS.md`/review checklist 中加两条：保存类助手必须按返回 id 或唯一预写字段返回“刚保存的对象”，禁止取列表首项；按外部目标参数化的测试必须断言每个目标的类型和自己的外部记录，不能只断言数量。为降低并行 worktree 的冲突，重构可以由集成子代理在合并后统一完成，而不是在各 ticket 分支内做。

**落点**：`backend/tests/common/`、`CODING_STANDARDS.md`。

**置信**：助手 bug 与重复是事实；合并后重构无冲突是推断。这条直接关系到验收测试的可信度，优先级高。

## 3. 把 H1 四组合复现写进仓库文档，而不是只留在代理交付消息（中高）

**建议**：在 `docs/` 下新增一份简短的 H1 验收单（或扩展现有 `bot-template-agent-inputs.md`），包含：四组合表、每组的预期启动参数、`<模板存储目录>/bot-sessions/<creationId>` 的定位公式、旧/新会话文件 id 对比方法、Tab/Pane/cwd 记录位置、以及“Herdr 不提供会话 id 时如何用真实会话文件或上下文对照”的限制。由主文档或 ticket 链接过去。

## 5. 增加“只检查改动文件”的 rustfmt 门禁，另开全仓格式化任务（中）

**事实**：`cargo fmt --check` 在多个未改动文件报告差异（`examples/safe_shutdown_shell.rs`、`src/browse.rs`、`src/commit.rs`、`src/countdown.rs`、`tests/zone_watch.rs` 等）；本 ticket 修改的 `backend/src/bots.rs` 用 `rustfmt --check` 是干净的，新增测试文件也已格式化。

**建议**：在检查脚本/预提交钩子中加入 `git diff --name-only --diff-filter=ACM` + `rustfmt --check` 的改动文件门禁；仓库级格式化作为独立任务，等当前所有 worktree 合并后再做，避免制造大面积冲突。若工具链版本会影响结果，在脚本中固定 edition/toolchain。

**落点**：检查脚本、CI/预提交。

**置信**：现有格式漂移是事实；全仓格式化会与并行分支冲突是推断。

**建议**：在 `herdr-bot.toml` 的 `[bot_templates]` 注释或 README 中写明该目录的来源和默认位置，便于备份、清理与排查；在 review checklist 增加一条：任何由配置派生的运行时数据目录都必须在其默认位置被忽略并有文档。只有当日志/会话需要用户自选位置时，才考虑新增配置字段，不要为局部需求扩大配置面。

**落点**：`herdr-bot.toml` 注释、README、`CODING_STANDARDS.md`。

**置信**：派生路径与忽略规则是事实；是否需要配置字段是产品判断，尚未验证。
