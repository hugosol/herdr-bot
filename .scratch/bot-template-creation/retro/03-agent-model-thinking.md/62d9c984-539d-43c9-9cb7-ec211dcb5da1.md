## 建议（按严重度）

### 1. 建立仓库级 guardrail 与单一检查入口（高）

**事实**：仓库无 `.github/` CI、无 `rust-toolchain.toml`/`rustfmt.toml`。初始干净 worktree 上执行 `cargo fmt` 改写了 45 个文件（+1388/−586），只能全部还原；README 只写「新增 Rust 文件通过 rustfmt --check」。另一次 `cargo test ... | tail` 丢失退出码，导致整套 5 分钟重跑。

**建议**：
- 先固定 `rust-toolchain.toml` 与 `rustfmt.toml`，做一次基线格式化提交；或提供 `scripts/format-changed.ps1` 只格式化本票改动文件，并在 worktree 说明中禁止全仓 `cargo fmt`。
- 增加 `scripts/check.ps1`（或 CI）：`cargo fmt --check`、`cargo test`、`npm --prefix frontend run test`、`npm --prefix frontend run build`、`npm --prefix frontend run test:browser`；每步检查 `$LASTEXITCODE`，最后输出汇总。
- 浏览器套件依赖构建产物，检查脚本中显式先执行 `cargo build` 与前端 build。

**验收**：干净基线运行检查脚本为绿；故意破坏格式或测试时非零退出；检查过程不产生未预期文件改动。

**证据**：session 中 `cargo fmt` 后 `git diff --stat` 45 files；初始 `git status` 为空；仓库文件列表无 CI/工具链配置。

### 2. 把 agent/model 能力事实做成可验证的单一事实源（高）

**事实**：`backend/src/templates.rs` 原表把 Pi/gpt-6.1-sol 写成 off..high；目标 Pi 1.3.0 的 `getSupportedThinkingLevels` 实际返回 minimal/low/medium/high/xhigh/max（off=null）；OMP 18.12.4 catalog 与表中另外两组一致。01 的后端测试、前端 mock、浏览器用例各自复制了错误字面表，所以全绿无法发现；03 在独立查询目标运行时后才修正。

**建议**：
- 新增 `fixtures/agent-capabilities.json`，记录目标版本（`pi --version`、`omp --version`）、查询命令与四组集合；后端 options/测试、前端测试 mock、README H1 表都从它派生或由它校验。
- 新增 `scripts/verify-agent-capabilities.mjs`：本地有目标 agent 时读取实际能力并比对 fixture；CI 可只跑离线 fixture 与后端一致性测试。
- 在 `docs/bot-template-agent-inputs.md` 增加目标运行时的 navigation pointer：安装路径、版本命令、能力查询入口，避免从缺 data 的源码 checkout 猜测。

**验收**：升级 agent 或手改表时，verifier 指出具体 agent/model/级别差异；三处测试不再维护各自的能力字面表。

**证据**：session 中 Pi 直查输出、OMP catalog 输出、原 `backend/tests/bot_templates.rs` 的相反断言。
