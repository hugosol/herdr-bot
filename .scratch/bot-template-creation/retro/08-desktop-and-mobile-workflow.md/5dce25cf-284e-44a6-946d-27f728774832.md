### 1. [高] 把 `browser-tests` 纳入类型检查

**[事实]** `frontend/tsconfig.json` 的 `include` 只有 `src`、`tests`、`vite.config.ts`、`vitest.config.ts`，不包含 `browser-tests`；`package.json` 没有 `typecheck:browser` 或等价的 script。`npm run build` 会执行 `tsc --noEmit`，但它看不到本票新增的 `mobileWorkflow.spec.ts`（417 行）、`lanAccess.spec.ts`（213 行）、`ui.ts`（74 行）以及修改过的 `support.ts`。`npm run build` 成功并不代表这些测试代码类型正确。

**[推断]** Playwright 执行 TS 时走转译而不是完整类型检查；`browser-tests` 里的类型漂移（例如 helper 参数改了、`TemplateView` 字段对不上）只会在运行时暴露，甚至可能悄悄少跑断言。

**建议**：新增 `frontend/tsconfig.browser.json`（`extends` 现有配置，`include: ["browser-tests"]`，补充 `types: ["node", "@playwright/test"]`，必要时显式安装 `@types/node`），增加 `"typecheck:browser": "tsc -p tsconfig.browser.json"`，并接入下面的仓库级检查入口。不要把 browser-tests 直接塞进应用构建的 tsconfig，避免 DOM/Node lib 冲突。

**验收方式**：在任一 spec 中故意写一个类型错误，`npm run typecheck:browser` 必须非零退出；当前所有 spec 在无错误时通过。

### 4. [中] 浏览器测试先断言完整矩形，再操作；覆盖弹窗的每个操作

**建议**：把这条写进 `docs/agents/testing.md` 或 `frontend/browser-tests/README.md`：对固定定位/可滚动容器内的操作，先断言完整矩形 `x >= 0、y >= 0、x+width <= viewport.width、y+height <= viewport.height`，再执行 `click`/`tap`；同时检查弹窗的主操作与关闭/取消两个入口，不要只点主按钮。用 `test.setTimeout(30_000)` 或显式 action timeout，避免让 Playwright 的 action retry 充当 90 秒的失败信号。`ui.ts` 已经有正确实现，文档应指向它。

**验收方式**：故意把某个操作按钮移出视口，用例在 5 秒内以“操作按钮左侧应进入视口”之类的命名断言失败，而不是 90 秒超时；模板/创建弹窗的关闭与主操作都被实际走到。
