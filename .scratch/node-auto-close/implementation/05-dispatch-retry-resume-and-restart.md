# 05: 新派发采用新设置，恢复与重启不补关

**What to build:** 自动关闭选择跟随具体节点执行的身份。新派发和独立 retry 使用当时的 Map 设置，恢复已有 Chat 沿用原执行；读取、刷新、服务重启及完成后恢复都不重放关闭动作。

**Delivers:** P8, P18, P19

**Blocked by:** 02: manager 完成后非阻塞关闭本次执行 Tab（提供执行设置及可观察的关闭行为）。

**Status:** ready-for-agent

- [ ] P8：修改 Map 后分别新派发节点和独立 retry，覆盖设置的两个方向，独立核对新执行采用派发时的配置，并在完成后核对实际关闭行为；旧执行与新执行关联不能混淆。
- [ ] P18：完成后通过公开读取、真实页面刷新及隔离服务进程重启，核对没有重新触发或补发关闭。
- [ ] P18：加载已完成但无关闭结果的记录，确认不补发；负向检查设定明确观察窗口并核对命令记录，不声称有限等待证明无限未来，也不新增持久关闭结果字段支持该检查。
- [ ] P19：未完成节点执行经过真实 Chat 恢复入口后，仍沿用原执行的自动关闭选择；在 Map 已变更为相反值的场景完成，核对关闭行为遵从原执行。不能以重新派发或新建执行替代恢复。
- [ ] P19：已完成 Chat 经恢复入口主动打开新 Tab 后，新 Tab 不被再次自动关闭，完成事实和原执行身份不被重建为一次新完成；通过命令记录取得有界观察证据。
- [ ] 本票负责 P8、P18、P19 的完整自动化覆盖及必要实现。02 的 P7 负责运行中原执行配置固定；本票区分新派发/retry、恢复、被动读取和重启，不用其中一个入口替代另一个。
- [ ] 沿用节点执行角色来自执行上下文的领域规则；恢复保留原 Run/node 关联，不重放发起指示，不把 Task 来源重新解释为执行身份，不改变既有 Chat 恢复机制。
- [ ] 不扫描待关闭记录，不增加重启补偿、后台重试、可靠投递或跨崩溃 exactly-once 保证。所有进程、数据和恢复目标归测试独占，持续消费进程输出并清理资源；按仓库规则审查时间观察场景标签。
- [ ] 通过 S1/S2 真实恢复、读取、派发及重启入口与 S3 命令记录取得证据，执行相关运行场景并更新受影响文档；记录实际结果与未验证项。
