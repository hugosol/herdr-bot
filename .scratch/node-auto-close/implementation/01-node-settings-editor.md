# 01: 编辑并保存 node 自动关闭与报告策略

**What to build:** Map 编辑者能够在 scheduler 节点编辑器中独立选择节点完成后自动关闭和报告提交策略，理解关闭后果，并通过控件或现有 JSON 编辑同一份配置。保存后的定义可重开、独立读取并用于派发，既有报告提交语义和 manager 完成权限不变。

**Delivers:** P1, P2, P3, P4, P5, P6

**Blocked by:** None (can start immediately).

**Status:** ready-for-agent

- [ ] P1：`auto_close` 是 node 可选布尔配置，不从 Bot/Task 继承。真实浏览器将两个节点设置为不同值，保存、重开并独立读取确认；无关节点和非目标定义字段不变。读取、编辑、保存及校验沿用现有定义约定。
- [ ] P2：分别从新增草稿和省略 `auto_close` 的旧定义进入编辑、保存及重读，确认开关默认关闭、配置按 `false` 使用；不因缺字段启用自动关闭。
- [ ] P3：报告策略使用互斥单选圆点，标签严格为 `auto`、`manual`；真实浏览器分别操作、保存、重开并独立读取确认。缺少配置时沿用 `auto`。
- [ ] P4：分别从控件与 JSON 修改两个配置，再保存、重开；使用独立字面值核对最终值及非目标字段。覆盖交替编辑，陈旧控件值覆盖较新的 JSON 或反向覆盖必须失败；沿用现有无效草稿处理方式，不静默丢弃原始内容。
- [ ] P5：真实浏览器确认自动关闭开关旁可见说明表达“关闭会终止 Tab 内终端及相关进程”；断言含义，不固定非关键措辞。
- [ ] P6：经真实派发观察发送给 node 的策略指示：`auto` 在结果可交接时报告；`manual` 在本 Chat 获得用户确认后报告，补充和更正报告也需确认。通过既有 report 与 complete interface 证明没有新增后端审批门禁、审批按钮或 manager 权限变化；不把提示词证据表述为模型必然遵从。
- [ ] 本票负责 P1–P6 的完整自动化覆盖；浏览器证据使用交付页面，不能仅以 HTTP 或组件检查替代。复用 S1/S2/S3 中本票所需的既有入口，不新增自动关闭专用 API。
- [ ] 遵守仓库测试指引，使用测试独占数据、进程和回环端口，前端验证经 npm 入口保留网络护栏；更新受影响使用文档，记录实际执行的检查与未验证项，不修改承诺范围。
