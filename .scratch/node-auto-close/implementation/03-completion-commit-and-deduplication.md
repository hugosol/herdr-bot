# 03: 完成提交故障与重复请求保持一次关闭

**What to build:** manager 完成操作遇到持久化故障或重复请求时，关闭资格始终由实际保存的完成转换决定。完成事实没有保存就不关闭；事实已保存但历史失败不回滚；同一次完成在顺序和并发重复请求下最多尝试关闭一次。

**Delivers:** P11, P12

**Blocked by:** 02: manager 完成后非阻塞关闭本次执行 Tab（提供可观察的完成到关闭路径）。

**Status:** ready-for-agent

- [ ] P11：在测试独占持久数据中制造当前完成事实保存失败，通过公开 complete 结果、独立重读事实及命令记录确认没有完成提交、没有关闭调用。
- [ ] P11：独立制造当前事实保存成功而历史追加失败，确认完成事实仍存在、仍允许触发关闭，且公开结果保留既有历史失败及部分生效反馈；不得误报回滚或以此授予重复关闭资格。
- [ ] P12：对同一次完成先后重复提交，核对实际关闭调用总数为 1，重复请求不产生新的完成事实。
- [ ] P12：通过公开 HTTP interface 并发提交重复 complete，协调请求形成真实竞争，核对实际关闭调用总数为 1、只有一个完成事实；不能以串行调用冒充并发覆盖。
- [ ] 本票拥有 P11、P12 的全部测试与必要修复。02 拥有触发入口资格的 P10；本票专门验证保存边界、顺序重复及并发重复，不重复认领 P10。
- [ ] 沿用现有文件持久化常用操作与协调范围、Run 业务操作协调及部分生效反馈；文件协调不得跨越 Herdr 外部效果，不引入跨文件事务、通用回滚、持久投递、重试或跨崩溃 exactly-once 保证。
- [ ] 使用隔离临时数据制造真实本机持久化故障，不为假想数据库增加 adapter。观察来自 S2 公开结果和事实、S3 实际命令计数，而不是只检查内部转换函数。
- [ ] 按仓库测试指引执行相关运行场景与回归，确认修复不破坏关闭挂起时同一 Run 的推进；更新受影响文档，记录实际证据与未验证项。
