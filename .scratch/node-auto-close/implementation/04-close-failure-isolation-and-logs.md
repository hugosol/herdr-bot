# 04: 关闭异常不影响业务，结果仅留后端日志

**What to build:** 关闭是完成之后的一次尽力清理。关联缺失或 Herdr 失败时，工作仍然完成并能继续推进；系统不猜目标、不重试、不绕过确认，只在后端记录可定位的真实结果，不为 workflow 或持久运行事实增加关闭结果。

**Delivers:** P14, P17, P20, P21

**Blocked by:** 02: manager 完成后非阻塞关闭本次执行 Tab（提供可观察的关闭路径）。

**Status:** ready-for-agent

- [ ] P14：构造缺少可靠 Tab 关联的有效历史执行，经合法 complete 后确认状态仍完成、没有关闭调用且存在后端诊断；不得扫描或猜测替代目标。
- [ ] P17：分别模拟关闭命令失败、执行不可用及 `confirmation_required`，核对完成事实不撤销、同一 Run 后续合法业务能继续、最多一次尝试且没有重试；不可用场景区分一次执行尝试与外部命令未实际启动。
- [ ] P17：确认 `confirmation_required` 不引发强制确认、自动绕过保护或本项目新增确认流程。
- [ ] P20：捕获生产路径后端输出，覆盖关闭尝试、成功、命令失败、执行不可用、额外确认及缺失目标跳过等适用结果；日志能定位 Run/node/执行或已知 Tab，不能把错误记为成功。断言语义与上下文，不固定日志文本格式。
- [ ] P21：在成功和失败场景中观察真实交付 workflow 页面、公开运行结果及持久运行事实，确认没有新增关闭成功/失败展示、前端通知、持久关闭结果字段或业务状态，节点沿用既有状态；配置字段 `auto_close` 不属于被禁止的结果字段。
- [ ] 本票负责 P14、P17、P20、P21 的完整自动化覆盖及必要实现。02 的 P13 负责有可靠关联时精确选目标；06 的 P22 负责真实外部效果，日志“成功”不能替代该证据。
- [ ] 复用 S1/S2/S3 与既有可配置命令入口，扩展测试 adapter 提供确定的失败及确认响应；不新增存储抽象、持久清理队列或外部 API。
- [ ] 使用测试专属数据、进程与回环端口，浏览器验证经 npm 入口保留网络护栏；完成实际运行验证并更新受影响使用与诊断文档，记录未验证项。
