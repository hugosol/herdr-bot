# 02: manager 完成后非阻塞关闭本次执行 Tab

**What to build:** 节点派发时固定本次执行的自动关闭选择。manager 合法完成节点并成功保存完成事实后，仅向该执行可靠关联的 Herdr Tab 发出一次尽力关闭命令；业务响应及同一 Run 后续操作不等待关闭返回，不要求 agent 停轮或空闲。

**Delivers:** P7, P9, P10, P13, P15, P16

**Blocked by:** 01: 编辑并保存 node 自动关闭与报告策略（提供 node 配置的保存、读取与缺省行为）。

**Status:** ready-for-agent

- [ ] P7：经真实派发与 complete 分别覆盖派发后 Map 从 `false` 改为 `true`、从 `true` 改为 `false`；核对原执行完成时的实际关闭调用，不只核对快照字段。
- [ ] P9：加载缺少新字段的旧执行并走合法完成流程，确认按 `false` 处理、没有关闭命令；读取旧记录不产生功能性补偿，也不为启用功能改写历史。
- [ ] P10：真实派发后，manager 成功提交实际节点完成转换且本次执行启用自动关闭，才有关闭资格。验证 `false`、拒绝的 complete、报告、停轮、等待输入、失败/取消及整体 finish 等适用入口不会独立触发；对不存在的入口记录不适用依据，不新增入口凑场景。
- [ ] P10：保留既有 manager 权限、完成说明和可完成资格，包括既有规则允许完成的执行阶段失败节点；不把报告视为完成，不另增审批、停轮或状态限制。
- [ ] P13：同时布置 manager、其他节点及旧执行的不同 Tab，经现有 Herdr 命令接缝核对精确目标和调用次数；只关闭当前执行可靠关联的 Tab，不扫描无关目标、不按名称猜测。
- [ ] P15：让受控关闭命令保持未返回，在释放之前观察 complete 已返回、同一 Run 符合既有条件的后续操作已完成。用事件顺序证明非阻塞，有界超时仅用于防挂死；不得让外部命令等待占用业务推进所需的锁或文件协调范围。
- [ ] P16：节点仍报告工作中时由 manager 合法完成，观察关闭命令发出；不得额外发送停轮作为触发条件，也不引入宽限期、退出或收尾文字条件。
- [ ] 本票负责上述 promises 的完整自动化覆盖，通过 S2 真实 HTTP 派发/完成及 S3 命令接缝观察。复用既有可配置执行入口，需要的受控挂起及命令记录随本票实现，不新增通用执行框架。
- [ ] 当前事实提交成功是关闭前提；重复完成不能取得新关闭资格。不得把已知保存失败仍关闭、重复关闭等缺陷留给后续票；03 拥有故障与并发专项覆盖，不是推迟正确性的许可。
- [ ] 不增加重试、补偿、关闭结果状态或 workflow 通知。遵守既有持久化与节点执行角色 ADR，使用测试专属资源；完成运行路径验证并更新受影响文档，真实 Herdr 外部效果由 06 单独取证。
