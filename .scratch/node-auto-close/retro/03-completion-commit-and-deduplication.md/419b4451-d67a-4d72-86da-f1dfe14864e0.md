## 保留的有效做法

- **真实故障留在被测路径内。** P11 通过 Windows 文件共享限制制造本机持久化错误，没有替换内部保存函数或引入假想数据库 adapter。
- **并发有协调证据。** P12 在真实同 Run 派发 gate 释放前保持两个独立 HTTP complete 请求均未返回，之后同时观察事实和外部命令计数，不以简单顺序调用冒充并发。
- **断言覆盖首次事实和外部效果。** 顺序重复不仅检查 `changed=false`，还核对完成 ID、说明、文件字节、唯一历史事件和实际关闭命令。
- **正确实现不制造伪 red。** 四个新场景首次通过，代理保留既有生产实现；没有为满足形式上的红绿循环暂时破坏代码。
- **结果没有被成功摘要掩盖。** 最终交接同时列出定向通过、完整回归失败、未派发与未验证范围，并把真实 Herdr 效果与受控 transport 证据分开。

本轮没有足够证据支持新增 reviewer 判断规则、扩充全局代理指令或认定仓库缺少 CI。优先改进应是已有验收入口的前置条件与工作树环境供给，而不是继续叠加常驻提示。
