# 可复用迁移方法与转换规则：Lighthouse

> Question and discussion: [可复用迁移方法与转换规则](../decision/05-reusable-migration.md)

## Question

怎样让 Agent 与用户开始并完成一条选定流程的迁移讨论，将这个方法复用于其他流程，而不预先穷举各流程的全部边界？

## Discussion

### 复用起手问题，而非另建通用迁移规程

用户指出，先前 wayfinder · 39e757 处理[关联提示词的联合设计与确认](04-coherent-prompts.md)时，已对「创建map」实践过迁移；复制其 Question 就能开始下一次工作。不同流程的边界会在实际调查和 grilling 中逐步展开，难以事前评估工作量，但已有足够明确的起手方式。

本票据此收敛：以该 Question 为模板，替换具体流程及目标；读取实际关联实现，复用已批准结构、调用和共享维护规则，在同一讨论中联合处理相关内容。字段映射、引用、共享影响、中断处理等是遇到时检查的问题，不再逐项制造独立政策。新事实由 Agent 调查，业务选择由用户决定；已有政策需要改变时明确提出修订并回到原权威。

不为本轮建立通用迁移工具或新的状态机制，不要求开始前穷举范围或承诺工作量。单会话是组织工作的方式，不保证任意流程都可在一次会话内完成；未完部分按既有交接方式保留。

### 可复用文档与结果边界

用户要求生成供 Agent 使用的通用 Markdown：[在一个会话中迁移一条流程](../../../docs/agents/workflow-migration.md)。该文档是本决策的操作入口，包含起手 Question、调查与 grilling 顺序、确认内容的归位和交付条件；字段与公共政策仍引用各自权威，不复制一套 schema。

「创建map」已确认的正文继续由原 Lighthouse 维护。那次实践的成果是迁移设计与正文确认；其发布记录明确实际 Bot/Task/Map、代码与工具包尚未改写。本票发布方法文档，不据此声称完整转换资产、生产落地或运行验证已经完成。完整样例与切换交接仍分别由其原票据承接。

### 确认来源与未采纳建议

确认来源：本票本轮会话，用户在 Q4 后明确：“是的，这个起手方式实际上就已经解决了本票提出的问题，我希望你可以生成一个通用的md文档，告诉agent怎么用一个会话去迁移流程，本票就可以宣告完结了”。Q4 提议已得到确认，授权发布文档并结束本票。

前轮 Q1–Q3 的独立问卷被本轮收敛方式取代，不将未逐项回答的建议当成新增政策，尤其不新增强制 Git 定位格式或恢复协议。共享原件、Git 历史、三状态和用户验收仍取自原权威。

静态证据来自现有配置链、plan_workflow.json、plan-to-map Bot、scheduler 保存说明及前置 Lighthouse；这证明起手资料可定位，不证明运行中服务配置或新格式已可执行。没有运行流程或修改生产定义。

## Decision

复用「关联提示词的联合设计与确认」的起手 Question，以一条流程为单位调查并与用户 grilling，实际边界随讨论展开；以通用 Agent 指引承接操作，不另建完整迁移规程。本票问题已解决。

## User stories

1. 作为用户，我希望 Agent 从已有起手问题开始迁移，以便不必预先穷举不同流程的边界或估算工作量。
2. 作为后续 Agent，我希望读取通用会话指引和已有决策权威，以便联合整理关联内容，而不重新决定已确认政策或临时补写业务语义。
3. 作为维护者，我希望区分设计确认、完整转换和实际运行，以便后续交接不会误把已确认正文当作生产迁移完成。

## Preconditions

- 用户选定具体流程；实际来源、实现与引用资料由 Agent 按配置调查。
- [流程迁移清单与共享影响范围](01-flow-inventory.md)、[Bot 与 Map node 的完整数据结构和知识归属](02-definition-schema.md)、[调用上下文与系统代码改造契约](03-call-context-design.md)提供已批准约束，不代表代码已实现。
- [关联提示词的联合设计与确认](04-coherent-prompts.md)提供已实践的起手问题和「创建map」已确认正文；其他流程不照搬其业务答案。

## Postconditions

- 通用文档可直接作为下一次迁移会话的入口，不要求另开发迁移工具。
- [单条流程全要素初步转换试验](../decision/06-conversion-trial.md)可消费本方法及已确认正文，继续完成其完整资产问题；本票不代替它完成。
- [选择性迁移的系统切换与开发交接门槛](../decision/07-cutover-handoff.md)仍负责部署、历史与活动执行边界。

## Invariants

- 共享原件、Git 历史、清单三状态及用户实际运行验证遵循原清单权威，不新增副本或状态体系。
- Bot 能力索引、实现完整、node 本次差异及公共角色分层遵循结构和调用权威；按实际涉及的 Task/script/Map 与调用场景核对信息可达。
- 每项政策只有一个权威，修订回到其原主题；默认 Wayfinder 规划边界和本地图的完整样例例外保持。
- 会话不足以完成时交接，不静默缩小范围；正文批准、定义转换与运行验收分别陈述。
