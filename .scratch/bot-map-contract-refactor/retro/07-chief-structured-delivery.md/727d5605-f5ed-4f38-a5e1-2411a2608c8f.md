# 票 07 · TDD 执行复盘

以下只依据指定执行代理的对话与工具回执，不采用父会话或其他票的执行结果。本轮仅提出建议，未改动文件或重跑检查。

## 高｜让测试记录区分接口红灯、行为红灯与夹具失败

**事实：** 首轮预览红灯是 HTTP 不认识 `outputRule`，首轮 Task 报告红灯是 HTTP 不认识 `outputs`。两者证实接口尚未接通，但当时未走到遗漏成果、非法路径或不持久化的行为断言。Map 红灯不同：当时 HTTP 已认得字段，却允许了未声明的公开输出 ID。P57 首次遇到 Rust 测试夹具的部分移动编译错误，之后又在 Resume 阶段因受控宿主缺少配置所选 Workspace 而失败；两次都没跑到旧权限断言。最终定向检查为 `chief_delegation` 32/32、`chief_authority` 2/2、`workflow_start` 直接调用者 3/3；这不改变早期失败分别证明了什么。

**建议：** 在现有测试指引的 TDD 取证处，把三类结果明确写成 **接通接口／击中违规／夹具失败**。接通接口后，对高价值守卫至少取得一条可观察的行为红灯：例如在 `outputs` 已可解析的状态下，用有效委派提交缺一项的成功报告，并观察该请求可被错误接受；绿灯再同时检查拒绝、journal 未变和没有外部调用。对已满足的行为，记录现有实现及公开对照的绿灯，不制造失败。这样既不把测试写成复刻算法，也不把解析错误当成下游校验的反证。

## 中｜给 chief 故障与恢复各一个短入口，沿用现有夹具

**事实：** P57 复用 Map 委派夹具；该夹具为 Run 启动设置了自己的 Workspace 清单，却未包含 Resume 按配置选择的默认 Workspace。补上正确的受控 Workspace 后，才观察到实际恢复、重新登记、旧职责拒绝和字节保留。测试指南已存在至少 46 秒观测要求，最终回执实际测得 TUI 保存失败和通知失败分别为 46,019 ms、46,015 ms，App 两个宿主格也超过 46 秒；这不是缺少时间护栏。

**建议：** 在 `docs/agents/testing.md` 现有「Chief 委派与报告」入口，把 **切换恢复** 和 **部分效果** 各做一个分支指针。恢复分支指向现有恢复用例，注明外部夹具必须提供配置所选的 Workspace，且以「恢复成功、当前 chief 重新登记、旧权限被拒绝」三条独立回执完成。部分效果分支指向现有 46 秒用例，优先跑短的准入和持久读回，再开计时观察；把 journal、调用记录和退出结果分别归档。复用现有 Cargo 目标和受控宿主，不另加测试专用产品接口或另一套计时器。

## 中｜提供跨阶段证据的明确回填路径

**事实：** 执行委托禁止修改工作流报告；交接消息又要求回填 P59。执行代理在最终交接中给出测试数量、窗口和日志，产品提交没有修改既有 P59 报告。此轨迹未显示最终证据是否由后续阶段回填。

**建议：** 让编排器明确区分两个写入者：**实现者交证据，集成者回填**。实现回执指明精确选择器、原始失败、最终结果、实际窗口、清理和未验范围；集成者只回填指定的 P59 条目，标注实现轮与集成轮的来源，不把合并状态当成验证。把 required evidence 交给接收到该回执的一方，避免要求同一个代理同时写与不写同一份报告。

## 低｜减少索引与权威材料的探索往返

**事实：** 工作树起初没有图索引；执行代理建索引前用推测的协调仓键查询失败，随后从项目列表找到了实际键。覆盖命令帮助展示 `--paths <STRING>...`，但单次旗标后的多个值被拒绝，JSON 数组成功；该不一致已上报。执行还读取了数份设计原文才定位到 chief 的实际接口与最终提示词章节。

**建议：** 在编排器的工作树交接中给出实际索引项目键，或直接提供应索引的绝对路径；修正 MCP `--paths` 帮助，使其与实际解析一致。在票据里把指针锚到消费分支：**委派和报告**指向调用设计 §5，**发送正文**指向最终提示词中对应的两段，**清理恢复**指向切换边界 §3。保留权威正文原位，不在 `AGENTS.md` 复制。依据本次记录，导航与工具入口比新增编码规范更能解决实际摩擦。
