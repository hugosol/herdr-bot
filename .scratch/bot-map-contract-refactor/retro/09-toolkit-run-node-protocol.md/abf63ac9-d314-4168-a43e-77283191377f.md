# 票据 09：TDD 执行复盘

范围仅限本票实现代理的对话及工具结果。以下建议未执行；不评价父会话、其他票据或新协议的跨仓验收结果。

## 1. 高｜把类型检查放在原生 dock 的启动门槛

**事实：** 本票并行启动了 `bun run typecheck` 和原生回归。类型检查立即发现 `role-dual-load.test.ts` 中捕获的 `request.tools` 在闭包内丢失窄化（TS18046、TS7006），而 Bun 已可运行该测试。为保持运行中的证据对应同一份源码，代理等原生批次结束后才修正类型。该批次耗时约 211 秒；修正后类型检查用时约 1.55 秒。没有因这次纯类型修正重跑原生批次；这不是原生行为失败。

**建议：** 在 toolkit 现有测试调度入口加一道快速前置检查：涉及工具定义或测试夹具的原生回归，先跑现有 `bun run typecheck`，退出 0 后再占用原生窗口。不新增 lint 规则，也不改变红灯阶段的定向测试。完成标准：类型错误在启动首个宿主进程前返回，且保留原始诊断。

**未验证：** 本票没有调查 CI 是否已串行执行这些检查，因此不建议另建 CI 检查。

## 2. 高｜把配对构建与原生窗口前置为派工输入

**事实：** 票据要求用同次构建的安全壳跑具名 dock，但环境未提供产物路径；默认 backend target 中没有安全壳。实现代理向协调方确认边界后，导出固定后端基线，在独占 target 构建安全壳和 fixture，记录了它们与匹配 metadata 的哈希，随后通过旧协议 dock 8 项。原生批次运行期间，票 10 请求同一验证窗口，靠消息交接。

**建议：** 派工首次给出 **配对清单**：后端基线提交、同源安全壳／fixture／metadata 的绝对路径（未构建时给出独占构建入口）、该跑的具名 dock 和窗口归属。把清单接到现有 toolkit 测试指引，不在每票复制构建命令。完成标准：首个需要真实后端的 dock 运行前，能核对三件产物同源，并明确此次是旧协议回归还是新协议联调。

**边界：** 同一基线构建有望复用；本票没有验证跨票复用条件。旧协议 dock 不证明票 11 的新协议，也不证明票 12/13 的安装验收。

## 3. 中｜把跨票共享接口写在消费点前，而不是等代理互问

**事实：** 09 和 10 的共同改动涉及同一份 chief 报告指引，以及报告回执的共享分类。09 通过协调消息确认：09 消费现有 `INIT_PROMPT` 路径，10 持有独立入口正文；`WorkflowResponse.uncertain` 是内部元数据，不是 HTTP 字段。10 随后询问如何在自己的隔离工作树验证 manager 路径，09 提供了精确提交作为可叠加的输入。

**建议：** 给这种并行票只写一条 **提供者／消费者接口**：谁拥有导出、谁持有调用点、独立验证可使用哪个基线或提交、合并后哪项验证由谁执行。通过指针指向唯一正文，不在票据或测试里复制文本。完成标准：两票能分别开发，且不会各自提交同一处 wiring；本地受控验证不会冒充组装后证据。

## 4. 中｜提示词测试按公开贡献身份选取，不按工具名搜整段消息

**事实：** 第一版共享指引断言查找含 `chief_resend_report` 的第一条消息，命中了宿主 system 消息而误报；收窄到非 system 的唯一消息后，最终 dock 批次通过。已有 `role-prompts` 测试从原生历史观察 `扩展 ID:标签` 的持久贡献身份。

**建议：** 在现有 prompt 测试支持代码中复用原生历史的贡献身份定位正文，再与真实 provider 请求交叉核对一次。对工具名也可能出现在宿主消息的场景，要求匹配唯一贡献；保留宿主文本不计入角色证据。完成标准：宿主 system 消息新增同名工具时断言不误判，而角色指引缺失或重复时仍失败。

## 5. 低｜优先取能回答当前问题的权威段落和诊断摘要

**事实：** 实现初期同时载入了完整 spec、contract、覆盖表和数篇迁移权威；后续真正决定 toolkit 行为的是调用契约、最终提示词的工具段落、09 的覆盖分工及本地源码。编辑整份旧提示词和静态集成检查又返回了大量原文／供给位置，其中最终检查所需的摘要只是状态、退出码和日志路径。

**建议：** 票据给 **分支指针**：协议字段、角色正文、影响验证的迁移边界分别定位到节，仍保留上位权威可追溯。工具默认回传操作状态、变更范围与失败位置；完整正文或结构诊断保存在可按需读取的日志。完成标准：一轮能定位票据适用分支；遇到失败还可读原始拒绝、类型诊断或回执，且无需重跑获取输出。
