# 复盘建议：Bot 四字段切换的 TDD 执行

以下仅依据票据 02 自身的执行对话和工具回执。建议按影响排序，未执行任何修改或验收。

## 1. 高｜为定义格式切换建立按部署范围运行的契约检查

**事实**：旧字段同时存在于 Rust、前端、Bun、发布图、材料 Schema 和夹具中。真实浏览器用例曾因示例目录中仍有旧格式 Bot 而等待不存在的按钮，最终超时 90 秒。与此同时，未选流程的旧定义按票据授权保留，不能对整个仓库做无差别的旧字段扫描。

**建议**：扩展既有 Schema／字面例检查，为实际发布或隔离部署的定义集合增加一个快速预检，复用现有测试入口。检查每个在线 Bot 的必填字段、类型与互斥目标，以及涉及的流程材料绑定；直接报出对象 ID、文件及错误字段。反例、历史归档和未选旧定义明确排除。完成标准：在浏览器启动前，故意放入一份旧格式在线示例或旧材料绑定，预检能定位并拒绝；同样文件位于离线备份时不影响检查。真实启动、页面和 Bun 回归仍各自取证。

**未验证**：本轮记录确认了现有脚本 Schema 测试、前端构建及浏览器网络护栏，但没有核实 CI 或钩子是否已接入同类检查；应先查现有配置，再决定补接线还是扩展检查。

## 2. 中高｜把历史对照移出真实业务链的前置门槛

**事实**：`workflow_dispatch` 首轮为 33/35。两个 `create_migration_` 用例尚未进入发布图和 Bun 的关键断言，就因历史 `task-options.toml` 对照未计入已存在的 `design-taste-frontend` Skill 条目而失败。仅修正历史预期后，独立复跑这两项为 2/2；未重跑首轮其余用例。

**建议**：保留独立字面预期验证历史迁移职责，但让发布图的 Bun 场景从本轮隔离部署取运行前快照，再与运行后的配置、revision 和文件字节比较。历史断言单列，用精确选择器运行。完成标准：新增一个与 Bot 无关的 Skill 不会挡住业务场景；工作流误写一个受保护的定义仍会让业务场景失败。

## 3. 中｜批量迁移结构化接线时，先校验关系，再交给文本差异

**事实**：发布 wrapper 的第一次批量编辑后，公开契约测试发现 writer 多出了本应属于 optimizer 的输入绑定。修正为以原图为基准生成完整 `nodes` 对象，再应用结构化变更；独立契约测试随后通过。已有 node ID 保留，内容字段和材料 ID 才切换。

**建议**：在现有审查入口为结构化配置迁移加一条判断型准则：审查身份、材料来源、前置依赖和执行策略分别有哪些获准变化；机械不变量由独立契约测试验证，不再手工扮演校验器。对重复 JSON 节点，按 ID 变换并比较对象关系，避免用逐行差异定位写入。完成标准：改错 writer 的来源、漏掉一个保存绑定或重命名既有 node，各自能被现有目标中的独立预期发现。

## 4. 中｜把备份边界写成操作入口，不是目录名约定

**事实**：在线读取范围之外还有一个独立的历史布局启动导入机制。票内后来把 P53 从进程内用例转到真实后端启动、HTTP 列表／读取／预检及独立文件对照；真实启动隔离与历史标记不重导入两项均通过。未移动实际数据，也未验证未切换的完整仓库目录可运行。

**建议**：在既有定义切换说明入口使用触发式指针，例如：**备份：移动 Bot／Map 或核验回退边界前，读取「四字段 Bot 定义切换」。** 正文要求操作者按部署配置列出在线根和启动导入源根，并核对离线目的地在全部范围之外。完成标准：交接证据包含实际解析出的根、备份位置，以及启动前后公开读取和独立文件结果；隔离结果不替代现场签收。

## 5. 低｜缩短 TDD 导航与失败诊断路径

**事实**：开头批量读取了长篇测试指引、覆盖表和多个设计正文；快速索引虽建立成功，但若干测试文件大纲为空，Rust 引用查询初次超时、TypeScript 无语言服务器。HTTP 的第一次红灯也先遇到测试闭包生命周期编译错误；修好夹具后才观察到旧解析器拒绝 `description` 的行为红灯。

**建议**：在现有测试索引放一条面向定义切换的指针，直接指向 HTTP／文件、浏览器、真实 Bun、真实启动四个入口及覆盖归属；只有需要精确条款时才转入完整权威正文。索引返回空大纲时，改用精确路径的窄范围读取；测试日志保留首次失败的实际响应和目标选择器，并明确区分夹具红灯与行为红灯。完成标准：后续同类票能从一个导航入口到达首个可运行的公开反例，不必先通读整份测试手册。

**证据边界**：上述建议基于本票的定向检查和实际失败；未据此判断全仓回归、集成分支、真实模型遵从或现场切换已通过。
