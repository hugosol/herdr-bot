Source: [spec](spec.md)
Acceptance mode: Rapid iteration
Approval: approved — 用户已明确确认四个 seam、五项约束审视结论、tester 专项延期及 Rapid iteration 分工；批准不表示实现或验收完成。

## Promises

Source 中的“故事”指 [spec 的 User Stories](spec.md#user-stories)；“决定”指 [Implementation Decisions](spec.md#implementation-decisions) 的对应小节。源要求、字段细则和完整提示词由 spec 及其链接权威维护，不在本契约另立版本。

Coverage 约定：

- **自动**：Agent 本轮完成产品实现、产品仓内 TDD、适用前端/浏览器回归及工具包检查。通过公开 interface 和独立文件/外部效果观察，不用私有实现的结果计算期望值。
- **延期 tester**：该项在 `E:\Developer\myhub\herdr-bot-tester` 中所需场景的新增、适配及执行，由后续专项完成；本轮跳过这些工作，不纳入本轮 TDD 执行队列。这不是将产品功能延期，也不是转交用户手工替代。Coverage 中列出的场景名是复用入口，须核实并补齐新契约 case，不以旧脚本通过代表覆盖。
- **人工**：仅保留需要用户判断的实际业务效果和迁移完成确认。Agent 准备对应证据并修订，不代用户确认。
- **操作核验**：实际切换是另行安排的受控操作，不由发布契约触发；隔离演练不替代实际数据现场的处理记录，不自动转成新增 tester 设施。

**Complete implementation and all assigned automated checks before the human-led acceptance round. Planned human-led checks do not pause otherwise executable work. At the final handoff, report the remaining checks together with their prepared evidence; they remain unverified until the user confirms them. Report genuine blockers when encountered.**

本轮“assigned automated checks”不包括已明确延期的 tester 专项；其缺证须与人工待验项分开报告。产品实现可以先完成，全部必需覆盖完成前不能宣告整体契约验收完成。工具包检查并未因 tester 延期而一并跳过。

### 交付追踪规则

/to-tickets 为每项 promise 关联实际 delivering work，允许多个故事归入同一 promise，也允许一项 promise 由多张票交付；本次不预先切片或安排实现顺序。

- tester 新增/适配/执行工作必须拆为独立验收票，记录目标项目、关联 P 编号、所需场景和证据，并显式注明“延期至 tester 专项，不纳入本轮 TDD 执行队列”。不把对应产品功能一起跳过。
- Coverage 中标记延期的检查，不得通过运行产品仓内回归、设施自测或用户业务确认替代。未选中格、缺权限/安装、清理失败等保留原始事实。
- 不维护 promise 状态列。完成与否由 delivering work、所有必需检查及人工确认推导；产品实现票完成不意味着对应 promise 的延期验收已通过。
- 后续证明 seam 或 promise 不成立时先修订本契约，再重新打开受影响票；不得先改票悄悄缩小承诺。

### 决定与理由

- 用户先明确“同意复用4个seam”，随后确认冻结的实际作用、中途报告与正式交付区分、失败部分效果、切换独立证据、资料可达与模型遵从区分。上述要求是已批准行为的落实，不重新开放需求。
- 用户明确要求 tester 对应测试票先不由本轮 TDD 实现，后续在独立 tester 项目实现并核实；随后确认整体验收保留缺口的安排。拒绝把延期解释为删除检查、人工替代或延期产品功能。
- 用户最终明确“同意Rapid iteration”。选择本轮完成产品实现和适用自动工作，真实业务效果/迁移完成由用户确认，tester 单独延期。未选择 Full automation，因为用户明确不希望本轮自动展开 tester 场景建设与执行。
- 不提出新 module interface 或测试专用 port；新功能和新 case 不构成另造 seam 的理由。已确认的提示词集中维护属于上游实现决定，不把私有 module 列为验收 interface。
- 成本说明：本轮产品完成后，原生/黑盒新契约仍有暂时缺证；后续专项若发现接入问题，需返修产品及其回归。这是已批准的时间分配，不降低完成标准；保留 P 编号和证据要求，避免重做需求讨论。
- 本轮没有新增难以逆转的架构选择；既有 ADR 和 spec 决策继续适用，不另写重复 ADR。

### 依赖与观察原则

- **In-process**：定义和协议计算从公开 interface 观察，期望来自独立字面值、手工推导例子及已批准规则，不重用被测算法。
- **Local-substitutable**：文件和本地进程使用隔离资源及既有受控 adapter；文件承诺仍读取真实字节。真实 Bun 脚本场景不能用纯模拟调用替代文件效果。
- **Remote but owned**：工具包与产品之间的 HTTP/通知交互复用已有实际 adapter 和受控测试 adapter，不为了本契约新增一层转发。产品实现检查与真实配对链路各自保留证明范围。
- **True external**：安装的 agent/宿主、模型 provider 等外部运行依赖使用现有受控 adapter 做确定性检查；安装接入和模型行为由相应真实场景或用户业务验收证明。无凭据/外网/既有会话授权时不得偷偷扩大访问。
- 资源归属附着 S1/S2/S3/S4：只使用本轮拥有的进程、端口、状态和证据目录，保留来源/版本及退出清理证据；不新增吞吐、延迟或资源上限承诺，不把退出码或目录可删除当作进程退出证据。
