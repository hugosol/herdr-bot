# 14: 手动：实际切换、逐项迁移确认与业务验收

**What to build:** 在另行安排的操作窗口内，由用户主导实际切换、选定流程迁移完成确认和真实业务效果验收；Agent 准备并核对证据，不因本票发布就停机、移动/删除数据或运行真实业务。

**Delivers:** P4, P28, P33, P40, P41, P42, P43, P44, P45, P47, P48, P49, P50, P51, P52, P53, P54, P55, P56, P58, P59

**Blocked by:** 08 落地创建map资产、唯一资料与选择性迁移交接; 11 手动：两仓工具协议与角色接入联调

**Repositories:** bot, toolkit

**Status:** ready-for-human

**执行方式：** 仅用户主导的手动操作/验收；各阶段另行安排并保留独立授权。

来源：[批准契约](../contract.md)、[spec](../spec.md)。实施前读取适用的[结构权威](../lighthouse/02-definition-schema.md)、[调用/模块决定](../lighthouse/03-call-context-design.md)及[最终提示词正文](../lighthouse/04-coherent-prompts.md)，后续 Traverse 修订优先；迁移/切换另读[清单政策](../lighthouse/01-flow-inventory.md)、[复用方法](../lighthouse/05-reusable-migration.md)和[切换边界](../lighthouse/07-cutover-handoff.md)。不从早期候选或本票摘要重新创作业务语义。

## Acceptance criteria

- [ ] 本票为手动票，不进入自动开发队列。开始人工验收前完成所有可执行的本轮开发/适用自动检查和 11；12/13 的 tester 延期单独列缺证，不作为自动开发或本票操作的隐式阻塞，也不能用用户签收将其补成通过。
- [ ] 阶段 A：按实际运行服务配置定位定义、Run、chief、Chat 和产出范围，列出在途执行、外部进程/效果、停止/退出证据及仍未知项；暂停、后端退出、managed=false 不表示业务停止/成功/回滚。仅在已明确安排并授权的窗口处理真实数据。
- [ ] 阶段 B：停止相关执行并核实现场，再停服务、更新两仓部署与必要定义。旧 Map/Bot 移至在线范围外 backup，稳定身份逐项迁入；旧 Run 完整原始目录离线归档，不补副本/公开成果、不上线展示或续接。分别记录来源、去向、原始文件清单/字节完整性和在线排除。
- [ ] 阶段 C：只清理已批准 chief 身份账本/委派/报告/接收确认；保留全部 Chat 历史、chief 与其他 agent 原生对话、zone、业务文件和无关数据。独立核对保留字节和实际清理集合，不整目录清理数据根；保留 Chat 不恢复旧 Run 管理权。
- [ ] 阶段 D：用户核对创建map 三阶段/非目标设置/共享影响、批准正文、输入与最终配置及未验证项，逐项确认迁移范围；未经用户确认的对象保持未开始，未选择不算废弃。确认迁移完成不要求业务已运行通过。
- [ ] 阶段 E（单独授权）：仅可删除明确获用户迁移完成确认的 Map/Bot backup 旧副本，逐项保留确认来源和前后文件证据；不删正式定义、未处理项、废弃项或共享依赖。此阶段不以所有流程迁移完成或后面的业务运行成功为前提，不由本票一个笼统签收自动授权。
- [ ] 阶段 F：首条流程具备条件即可由用户实际运行，不等全量迁移。Agent 准备配置、输入、产物、授权、共享消费者、保存/省略检查、实际动作和失败/未知项，用户分别判断方案成熟度、方案/配置一致性、资料遵从、chief 呈现及业务效果。模型判断不由静态/受控检查冒充；其他未选流程不造结果。
- [ ] 各阶段分别记录完成/未执行事实和操作授权，不把准备、演练、文件可达或服务退出当现场通过。更新迁移清单的三种状态及实际运行结果备注，回填交付报告；自动结果、延期 tester、人工确认和实际切换四类始终分开，不维护 promise 状态列。

## 检查与证据

实际操作前复核 01–10 的同版本检查证据，以及 11 两仓分别通过的联调证据；按实际部署分别核对 bot 与 toolkit 来源、版本和产物，不使用旧 checkout 的日志代替。实际数据操作清单和逐项命令由操作者依据实际配置及批准窗口确定并记录，不在本票硬编码用户数据目录、不创建自动迁移/回滚工具。

P52–P56 的隔离自动检查分别由 02/04/07/08 交付，不能替代本票现场前后字节、归档/保留清单、停止和外部效果证据。用户业务运行仅在其明确授权下执行；发生未知外部效果或范围不明时保留现场并报告，不扩大删除、不宣称回滚。

## 覆盖及测试所有权

[逐 promise 覆盖分区](../tickets.md#coverage-partition)中标为 14 的每个 case 由本票负责编写、维护和取证；不同证据层级不能互相补格。若一个 case 同时证明多个 promise，引用同一份证据，不复制测试。依赖票提供能力，不自动承担本票的验收 case。

本票的 Delivers 仅指所负责 coverage；有延期 tester、人工或操作核验的 promise 不能因本票完成就宣告整体通过。发现批准 seam/promise 不成立先修订契约，不通过缩小本票或弱化断言消除失败。
