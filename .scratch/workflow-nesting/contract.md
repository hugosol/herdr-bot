# Contract — Map 型 Bot、嵌套 Run 与命名文件输入

Source: [Spec](spec.md)
Acceptance mode: Full automation
Approval: Approved — seam selection、约束审查及验收模式均已获用户明确确认。

本契约记录外部可观察承诺，不规定构建顺序、私有模块或存储布局。Promises 的完成状态由交付工作与所需检查结果推导，不维护状态列；/to-tickets 后续关联交付票据。批准契约不表示实现或验收已经完成。

## Promises

Coverage 中的 A 均表示 agent 负责自动执行、收集与核对证据，无 human-led 例外。真实依赖或证据缺失保持阻塞／未验证，不降级成通过。预期来自 Spec、独立字面样例及实际输入，不使用被测 implementation 计算预期。

## Seam decisions

|Seam|Exposes|Hides|Alternatives considered|Reversibility|
|---|---|---|---|---|
|S1：主界面的配置、发起与运行查看 interface|用户可编辑的定义/输入，发起与拒绝反馈，运行列表及真实执行关联导航。|页面内部组织、状态管理、控件实现、请求封装。|仅通过S2验证被拒绝：不能证明实际页面能完成配置、刷新及导航。没有为新页面另增seam。|界面布局可自由调整；只要用户仍可完成同一操作与辨认结果，无需改变promise。|
|S2：公开定义与运行操作 interface|定义读写、预检、启动、角色操作及公开运行事实；通过实际持久结果与宿主副作用核对输入、身份、完成、故障、恢复、删除和并发。|角色表示、父子存储布局、输入解析器、协调锁、私有helpers及内部调用关系。|存储/锁/每个内部模块独立成为契约seam被拒绝：会固定implementation且不能增加调用者可见保证。只验成功响应被拒绝：不足以识别副作用或持久化违规。|现有调用者依赖其语义；内部重构自由，若公开操作或错误意义改变需先修订契约。|
|S3：原生Chat的角色工具与业务交付 interface|OMP/Pi真实工具、实际角色指引与输入、会话归属和关闭效果、真实文件与配置交付、独立Chat业务行为。|扩展内部组织、提示词具体措辞、宿主装配细节、业务内部步骤实现。|只用受控adapter或只看S2记录被拒绝：不能证明原生同载、模型使用材料、manual行为或案例业务交付。提示词全文快照不能替代行为。|底层组织可变；宿主工具与交付语义改变时复核contract。不要求同一次模型运行逐字复现文本。|

选择已获批准：复用三个现有seam，不新增专为验收的interface。三个seam承载不同可观察事实，不能以页面展示代替运行语义，也不能以单次业务成功代替确定性错误路径。

### Dependencies and evidence

- In-process：规则及引用计算通过S2观察，不暴露私有seam。
- Local-substitutable：隔离真实临时文件、运行记录及既有受控宿主adapter，用于确定性失败与副作用观察；存在性/不可读检查不能仅mock返回错误。
- Remote but owned：herdr-bot与toolkit通信沿用现有interface及adapter；受控adapter证明确定性协议，真实接线由S3承担，不另造单adapter的假想seam。
- True external：实际宿主与模型提供方可在机制检查中使用mock adapter；真实原生加载及业务交付仍需真实证据。使用明确授权模型和独占环境，不读用户凭据或操作用户会话。

S2的持久效果可通过重读、隔离重启和现有持久记录独立观察，不把具体文件布局定为contract。期望文件、身份、状态和失败原因由独立样例指定，不能使用implementation重算预期。

### Approved constraint review

六个surface均适用并已审视：

|Surface|在所选seam的处理|
|---|---|
|Entry|S1实际用户路径，S2公开调用，S3原生角色与独立Chat；不新增CLI产品入口。|
|Data and state|局部ID、可选缺席、冻结地址、父子execution、旧记录与目标配置保持；通过S2/S3读回证明。|
|External dependencies|真实文件/宿主/模型与受控adapter证据分开；缺依赖不转通过。|
|Errors and failure|拒绝不启动、部分效果可核实、完成不等于材料齐备、迟到报告与重启规则；不添加自动修复。|
|Output and observability|界面、操作结果、运行事实、原生历史、真实文件与配置交付相互佐证，不以单一渲染值证明其他保证。|
|Resources and concurrency|隔离并清理所属进程；无父子互等、无意外级联或重复启动；不增加任意深度/并发规模性能承诺。|

用户已确认的inferred义务仅为兑现现有承诺：可选缺席贯穿消费者；子接口必需项不能被父可选性绕过；完成与可消费分开；部分启动效果分阶段可核实；恢复/旧记录/并发不串执行；共享Task兼容与业务保护保留。它们不增加新seam或新业务范围。

内部选择由build决定，不占用用户决策；未新增高影响trade-off。已拒绝通过额外全输出finish门禁、文件快照、持续可读保证或任意规模性能来简化验收。

## Not yet specified

- **阻塞批准的决定：无。** 三个gate均已确认；Full automation无human-led coverage。
- **已知但延后核实的执行前提：** 隔离原生宿主、已授权真实模型及跨仓运行环境的实际可用性。agent应自行核实并报告真实阻塞，不以mock抵消缺失证据；不因此预留人工验收例外。
- **尚未形成的seam承诺：无。** 当前所有promise都有可观察seam。
- 字段最终拼写、公开请求的精确形状、错误细分类别、私有模块划分和持久协调方式属于实现细化，不在此预切票，也不允许改变已批准语义。若实施证明选定seam无法携带promise，先修订contract并重新取得必要批准，再调整票据。
