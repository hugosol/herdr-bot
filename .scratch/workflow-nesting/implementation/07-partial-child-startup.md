## Acceptance criteria

- [ ] 隔离故障覆盖 child 未创建、已登记未完成记录初始化／未启动、Chat 已启动但关联失败、输入提交失败或结果未知。
- [ ] 每个阶段联合核对操作反馈、公开运行事实、独立持久读回及宿主实际效果；已登记 child 不能因 Chat 缺席而消失。
- [ ] 核实流程识别已有 child、Chat、关联和提交效果，不重放触发动作，不自动重建、重派或回滚。
- [ ] 响应未知与明确未发生分别反馈；不确定状态不能通过核实获得盲目 retry 资格，向 08 提供真实公开语义。
- [ ] 使用既有受控 adapter／真实临时持久数据制造确定性阶段失败，不新增验收专用产品 API。
- [ ] 所有受影响调用方与既有行为检查同步切换，删除被本次替代的死路径，不引入旧字段别名或以兜底吞掉失败。
- [ ] 更新所属长期使用／运行／验证说明，记录真实执行的入口及证据边界；临时 ticket／证据不作为长期文档唯一依赖。
