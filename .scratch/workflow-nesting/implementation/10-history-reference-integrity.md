# 10: 删除历史时保护父子引用完整性

**What to build:** 用户清理历史时不级联删除 child，也不能破坏父子执行引用；启动与删除并发时仍保持引用完整。

**Delivers:** P38

**Blocked by:** 04: 派发 Map 型节点并建立执行级父子关联

**Repositories:** herdr-bot

**Status:** ready-for-agent

依据：[批准契约](../contract.md)；[规格](../spec.md)。契约 Approval 已获批准，本轮 24 票修订方案由用户授权发布。发布不代表实现、自动验收或用户部署操作已完成。

## Acceptance criteria

- [ ] 分别尝试删除有父引用的 child 历史和有 child 引用的父历史，明确拒绝及定位关联；不级联、不自动解绑。
- [ ] 无关联的既有历史删除路径仍可使用，保留原有安全边界及损坏／不可读记录的可靠判定。
- [ ] 以受控阶段门闩交错历史删除与 child 创建／关联／迟到启动保存，独立读回无悬空关联且已删除记录不复活。
- [ ] 关联扫描、删除和启动协调不依赖名称猜测，不通过清空引用或自动回滚外部效果获得成功。
- [ ] 失败分支清理所属异步任务并保留原始错误；不删除用户运行数据。
- [ ] 所有受影响调用方与既有行为检查同步切换，删除被本次替代的死路径，不引入旧字段别名或以兜底吞掉失败。
- [ ] 更新所属长期使用／运行／验证说明，记录真实执行的入口及证据边界；临时 ticket／证据不作为长期文档唯一依赖。
