# scheduler：node 与共享 node_template 管理

Status: ready-for-agent

## Problem Statement

用户目前可以在 scheduler 入口选择服务级 Map、查看 node、前置依赖和共享 node_template，但页面只读。维护具体工作和共享能力需要离开页面、手动修改服务主机上的 JSON 文件，再刷新查看结果。模板说明仅在 node 详情内展开，没有独立的模板管理入口；用户无法在页面完成新增、修改、删除，也缺少删除引用检查和防止覆盖外部修改的保护。

用户希望继续使用直观的 JSON 源码编辑，而不是为每个字段建立复杂表单，同时能够区分 Map 内的具体工作与跨 Map 共享的能力定义。

## Solution

在 scheduler Tab 右上角“刷新全部”旁增加“模板管理”，在同一 Tab 内容区提供共享模板列表、可读预览及增删改；从 node 的“模板明细”直接进入对应模板预览，返回时保留原 Map 和 node 的选择。

在当前 Map 的节点列表与详情中增加 node 的新增、修改、删除。node 与 node_template 使用一致的编辑体验：新增时单独填写 ID，修改时 ID 只读，JSON 编辑区仅承载 ID 以外的内容。新增内容由现有文档示例预填，用户自行修改；只有显式保存才持久化。

保存沿用现有格式与依赖校验，并防止覆盖编辑期间发生的外部修改；删除前检查引用，无法证明无引用时不删除。所有操作仍只管理静态工作定义，不调度或执行工作。

## User Stories

1. As a 计划维护者, I want 在 scheduler 的“刷新全部”旁看到“模板管理”, so that 可以直接进入共享能力维护而不离开当前入口。

3. As a 能力维护者, I want 在模板目录没有模板时看到明确空态并可以新增, so that 可以建立第一个共享模板。
4. As a 能力维护者, I want 区分读取错误与正常空列表, so that 不会误以为已有模板消失。
5. As a 能力维护者, I want 以可读字段预览模板身份、标题、适用场景、能力说明、输入输出及实现类型, so that 不必进入编辑器就能理解能力边界。

## Implementation Decisions

### 范围与领域含义

- Map 是服务级静态工作定义，不属于 zone；node 是 Map 内的一项具体工作；node_template 是跨 Map 共享的业务能力定义。模板不是 Bot，node 不是执行实例。
- 本次将 scheduler 从只读预览扩展为显式写入管理，但不改变静态定义与执行实例的边界。Bot／Chat 的既有术语决策不变。
- “node 管理页面”指当前 Map 的节点列表及详情，不建立独立 node 库，也不提供 Map 自身的增删改。

### 页面与导航

- “模板管理”位于 scheduler Tab 内右上侧、“刷新全部”旁；进入同一 Tab 内的独立内容页，不打开新的浏览器标签。
- 模板管理入口进入列表；node 的“模板明细”直接进入同一套模板预览，替代原内联展开。
- 模板预览使用可读字段展示；点击编辑后才展示 JSON 源码。缺失或异常模板继续明确诊断，不伪装为正常预览。
- 从 node 进入模板页面再返回时保留原 Map 和 node 的选择，并展示最新模板内容。保留对象已不存在时不能展示陈旧成功数据。

### ID 与持久化格式

- node 与模板采用一致的编辑交互：新增时单独输入 ID，编辑时只读展示 ID；JSON 内容不包含顶层 id。
- node ID 仍为 Map 的 nodes 对象 key；模板 ID 仍持久化为模板 JSON 的 id 字段，由保存逻辑补回。不改变现有格式版本和身份关联语义。
- 顶层内容中手动加入 id 时提示移除，不静默覆盖。此约束不限制 parameters 等开放对象中的任意参数名。
- node ID 在所属 Map 内唯一；模板 ID 是跨 Map 的共享身份。新增身份冲突不得覆盖已有对象；不提供 ID 重命名及引用迁移。
- 新模板自动生成安全且不冲突的文件名，不增加文件名输入；编辑已有模板保留原文件名。模板关联继续按 ID 而非文件名。
- node 的保存只改变当前 Map 的目标 node，保留其他 node 及 Map 元信息；模板修改直接影响所有引用者，不建立副本、历史版本或版本锁定。
- 延续既有服务端配置目录及文件边界；新增写入能力不赋予客户端任意本地路径访问权限。

### 文档示例预填

- 新增 node 使用现有出行准备文档示例的 A 节点：上海出行天气、destination-weather 模板引用及其参数，blocked_by 为空；不使用带有示例前置依赖的汇合节点。
- 新增模板使用现有目的地天气能力示例，移除 id 后预填全部内容字段。两类新增的 ID 输入框均留空。
- 现有文档示例是统一内容来源，随应用提供，避免两套独立维护的示例；部署时不要求能够访问开发仓库中的文档目录。具体打包和复用方式留待后续设计。
- 示例只进入草稿，显式保存前不写入数据目录，也不自动创建示例模板或其他依赖。
- 示例 node 的模板若实际不存在，沿用缺失模板提示，不因本次编辑功能新增保存限制。
- 用户可删改 parameters、inputs、outputs 中的条目及依赖数组项；必需结构字段仍须保留。允许的空文本、空对象和空数组沿用现有规则。
- 编辑已有对象仅加载真实内容，不混入示例。

### 保存校验、冲突与草稿

- 保存前沿用现有 JSON 语法、版本、必需字段、类型、未知字段以及 Map 依赖校验。node 修改后的整个 Map 不得出现未知前置、自依赖或依赖环。
- 不增加 parameters 与模板 inputs 的匹配校验，不检查 Bot、zone 等资源是否存在，不补入模板默认值。
- 保存失败或冲突时不离开编辑器，保留 ID 输入和 JSON 草稿，并给出具体错误。未通过校验的内容不写入定义文件。
- 编辑期间目标文件已发生外部修改时拒绝覆盖并提示重新加载，保留用户草稿；不能采用最后保存者静默覆盖。node 修改以所属 Map 文件为冲突单位，不自动合并。
- 经 /to-contract 用户明确批准的保证范围：同一应用实例内经生产 interface 提交的写入必须协调，保护最终冲突检查、引用检查及实际变更；提交前重新检查外部文件变化。保留直接文件维护，但不承诺与不参与协调的外部编辑器之间具有跨文件原子性；使用说明提示避免页面提交期间同时直接修改相关定义。具体冲突标识及同步机制留给 implementation。
- 有未保存修改时，返回、切换页面或刷新前确认是否放弃；不引入自动保存。

### 删除与引用检查

- 删除 node 前检查当前 Map 内对其 blocked_by 引用；存在引用时阻止删除并列出位置。
- 删除模板前检查全部 Map 对模板 ID 的引用；存在引用时阻止删除并列出位置，不级联删除 node、不自动清除引用、不故意留下失效引用。
- 如果某个 Map 无法读取或解析，不能确定模板是否被引用，必须阻止删除并列出造成检查失败的文件。相关目录无法读取同样不能视为无引用。
- 无引用且检查完整后，仍需用户二次确认才能删除。检查必须保护实际删除，不能仅依赖过期的页面展示结论；具体机制留待后续设计。

### 成功后的页面状态

- node 新增或修改成功后留在当前 Map，选中该 node，更新节点列表、详情与依赖图。
- node 删除成功后留在当前 Map，清除被删除 node 的选择。
- 模板新增或修改成功后显示该模板预览；删除成功后返回模板列表。
- 成功结果立即反映到相关页面，不要求用户额外点击“刷新全部”。
- 原有刷新读取、问题诊断和手动文件维护能力继续存在；本次仅为编辑草稿增加必要的放弃确认，不把导航返回等同于清空选择的全量刷新。

### 留给后续阶段的技术设计

- 本讨论没有确定新模块边界、内部接口、HTTP 路由、冲突令牌形式或测试 seam；这些不在本 spec 决定。
- 共用编辑逻辑是已确认的交互和复用目标，不在此指定组件拆分或文件结构。

## Testing Decisions

- 现有 scheduler 已有真实浏览器场景覆盖目录空态与错误、Map 选择、依赖图、参数与模板展示、共享模板问题、刷新竞争、外部文件变化、文档示例及安全边界；这些是延续行为的 prior art，不应另建一套含义冲突的约定。
- 现有后端严格结构校验与 Map 依赖检查是本次保存规则的依据；无效输入应被拒绝，而不是自动修复、丢弃未知字段或删除依赖边。
- 页面交付遵循项目现有真实浏览器与实际服务验收方式；选择哪些 seam、每项承诺在哪验证以及覆盖分配均留给 /to-contract，不在本 spec 提前决定。
- 所有可变定义、服务工作目录、持久化路径和端口都使用测试独占资源，不操作用户真实 Map、模板或会话。普通测试仅监听数值回环地址，并保留现有网络护栏。
- 本次不执行工作、不启动 Chat，也不触发真实关机；若复用完整应用夹具，继续遵循安全替身和隔离约束。
- 通过项目规定的测试入口运行验证，浏览器交付前使用构建后的当前产物，不绕过 npm hooks。文档示例的预填和保存后真实结果应可被实际页面操作观察。
- 现有“所有 scheduler 操作只读”及“模板明细内联展开”的旧预期需要按本次显式管理能力更新；浏览与预览本身仍不得写入已有定义。不得为了沿用旧测试而保留两套模板详情交互。
- 本 spec 发布仅进行了资料与内容核对，不代表实现、测试或浏览器验收已经完成。

## Out of Scope

- Map 自身的新增、修改、删除，以及向用户开放整张 Map 的 JSON 编辑器。
- 独立 node 文件库、跨 Map 搬移 node、ID 重命名和自动引用迁移。
- 任意文件名输入、文件重命名、任意本地路径访问或部署配置管理。
- 调度、执行工作、发起 Chat、执行实例与运行状态、重试、并发执行、审批和完成门禁。
- 自动保存、自动合并冲突、草稿持久化历史、撤销恢复、模板快照和版本锁定。
- 删除时级联修改、自动移除引用或强制删除被引用对象。
- parameters 与 inputs 的契约匹配、Bot／zone 存在性校验、额外业务类型系统及新实现类别。
- 自动安装文档样例和依赖、示例选择器、复杂字段表单或可视化图编辑。
- 自动文件监听以及对既有格式进行无关升级或迁移。
- 本阶段的模块 seam、测试 seam 和具体接口设计；由 /to-contract 继续处理。
