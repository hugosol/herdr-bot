# 07: 桌面与窄屏体验验收及人工交付

**What to build:** 让桌面和窄屏用户都能实际完成模板往返、两类对象编辑、诊断核对、草稿保护与错误恢复；完成自动页面检查并修复可操作性问题，准备可运行页面和证据供用户评价主观体验。

**Delivers:** P36。

**Blocked by:** 04: 安全删除 node 并更新当前 Map；05: 跨 Map 引用保护下删除共享 node_template。

**Status:** ready-for-agent

## 开始条件与完成门槛

本票的自动检查、页面修正和证据准备可与 06 并行，不以 06 完成为开始条件。人工验收必须等 01–06 及本票全部自动工作结束后进行；06 的修复若影响页面或数据行为，须刷新构建并复查受影响证据。

P36 的自动实现和检查属于 agent；主观阅读舒适度、编辑顺手程度和提示易懂程度由用户判断。用户确认前，人工部分必须明确标记未验收，本票不得仅凭自动通过关闭。准备人工验收不能暂停其他仍可执行的自动工作。

## 验收条件

- [ ] 使用 S1 实际交付页面与真实运行应用，在桌面和窄屏尺寸完成模板列表/预览、从 node 进入及返回、两类对象新增/修改、诊断与错误恢复操作。
- [ ] 通过实际键盘操作验证入口、对象选择、编辑、保存、返回及确认流程可用；窄屏能操作 ID、JSON 编辑和错误提示，不只检查元素存在或截图外观。
- [ ] 实际触发校验错误、写入失败或冲突，确认窄屏仍能核对错误并继续处理保留的草稿；放弃确认的取消与确认路径可操作。
- [ ] 修复自动检查发现的可操作性缺陷，复查受影响的完整用户流程；不得通过放宽 contract、隐藏错误或丢弃草稿来让页面显得可用。
- [ ] 提供当前可运行页面、可复现的隔离示例数据、桌面和窄屏截图、清晰操作步骤及已知限制。数据不安装进用户真实配置，不发起 Chat 或执行工作。
- [ ] 人工交付前确认其他所有自动工作已结束，所附截图和步骤来自最终待验收构建；如存在真实阻塞或未执行检查，明确报告，不能宣称全部自动验收通过。
- [ ] 请用户判断可读性、编辑顺手程度和提示是否易懂，记录其反馈与未验收项；必要修正后自动复查并再次请求用户确认。
- [ ] 仅在用户确认主观体验后，才认为 P36 全部完成；不将“已提供截图”或“等待用户反馈”作为人工通过证据。
- [ ] 更新当前使用说明，准确描述新增管理能力、草稿保护、引用检查和外部编辑保证限定；不改写历史 ADR，不把 scheduler 描述为执行器。

## 测试与资源约束

依据已批准 contract 的 Rapid iteration 模式，本票独占 P36 的实际页面检查和人工交付责任；其他 promise 的测试所有权保持各前序票分配，不重新认领。使用项目规定浏览器构建/验收入口，保留 npm hooks 和网络护栏；真实页面及后端持久化不能用模拟响应替代。

用例独占临时定义目录、工作目录、持久化路径、进程和数值回环端口。并行时与 06 不共用可变测试数据或服务。全部预期以独立数据和 contract 为依据，既有执行安全替身只用于证明不执行；不操作用户真实数据。产物应明确区分自动观察事实、用户确认结果和已知未验证限制。
