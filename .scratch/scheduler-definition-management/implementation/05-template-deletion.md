# 05: 跨 Map 引用保护下删除共享 node_template

**What to build:** 删除共享模板前检查所有 Map 的引用，明确列出引用位置或无法完成检查的原因。仅在完整检查证明无引用后请求最终确认，最终提交重新验证目标和引用；成功后立即返回更新后的模板列表。

**Delivers:** P21, P22, P29；P23, P24 的模板部分。

**Test owner for:** P23、P24 的模板删除分区；对应 node 删除分区由 04 拥有。两类对象的分区全部通过后 promise 才完成。

**Blocked by:** 03: 当前 Map 内 node 新增、修改与即时结果展示。

**Status:** ready-for-agent

## 依赖与范围

必须与 03 的 node 引用写入共享应用内提交协调，保护跨 Map 引用检查和实际删除。不依赖 04，可与 node 删除并行实施。遵循已批准 contract 与 spec，不删除引用者、不清除引用、不建立模板副本，不提供强制删除或 Map 管理。

## 验收条件

- [ ] P21：至少两张 Map 引用同一模板时，页面和直接生产请求都拒绝删除，并列出各引用位置。原模板、node 与引用保持不变。
- [ ] P22：分别构造损坏 Map、不可读 Map 和目录读取失败；检查不完整就阻止删除，指出造成失败的文件或目录及原因。不能把无法检查当成零引用，目标仍保留。
- [ ] P23：完整检查且无引用后才进入最终确认；取消保留文件与对象，确认后实际删除并经生产接口重读。直接请求不得绕过服务端引用及目标检查。
- [ ] P24：确认框打开后目标文件变化、新增引用、模板 ID 变为歧义时，最终请求拒绝不再安全的删除；不随机选择文件，不使用缓存的无引用结论。
- [ ] 所有应用内写入与删除在共同协调边界内形成明确提交顺序，最终引用检查和实际变更受保护。外部文件变化在提交前重新检查；不承诺与任意外部编辑器之间跨文件原子性。
- [ ] 缺失模板引用仍可合法保存；不为了删除安全新增“任何时候不得存在缺失引用”的限制。先删除、后创建缺失模板引用可以合法成功，真正竞争序列由 06/P25 统一验证。
- [ ] P29：删除成功后无需刷新全部，返回更新后的模板列表，不继续展示已删除预览；删除普通模板及最后一个模板分别验证列表和空态。
- [ ] 错误清楚显示，不误报成功，不自动修复定义或执行工作。更新当前模板删除、引用检查失败和外部编辑限定的使用说明。

## 测试所有权与资源

本票拥有 P21、P22、P29 和上述 P23、P24 分区。S1 使用实际页面与真实运行应用；S2 使用页面实际调用的生产 HTTP interface。真实隔离文件、独立预期及重读结果证明副作用，不以模拟响应代替真实删除。06 拥有跨操作竞争、进程重启、目录边界和执行安全的统一 contract 测试；本票交付时生产安全必须已成立。

遵循项目测试指引实施 TDD，通过规定入口和当前构建产物验收，保留网络护栏。用例独占临时定义目录、服务工作目录、持久化路径、进程及数值回环端口；不操作用户真实数据，不发起 Chat、执行真实固定操作或触发第三方动作。
