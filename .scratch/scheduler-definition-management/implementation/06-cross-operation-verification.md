# 06: 跨操作并发、持久化与数据安全验证

**What to build:** 在全部管理路径交付后，通过真实生产请求、页面操作、隔离定义文件及执行记录，证明组合操作仍满足提交协调、真实持久化、文件访问边界和纯数据处理保证；修复发现的生产缺陷，而非只收集测试结果。

**Delivers:** P25, P32, P33, P34。

**Blocked by:** 04: 安全删除 node 并更新当前 Map；05: 跨 Map 引用保护下删除共享 node_template。

**Status:** ready-for-agent

## 职责与 seam

本票独占 P25、P32、P33、P34 的跨操作 contract 测试。02–05 已分别负责在生产路径实现对应安全约束，本票不是最后才补安全的许可。前序票各自保存和删除后的重读证据不重复认领 P32 的完整成功序列与重启验收。

遵循已批准 contract 与 spec。S1 是真实运行应用中的实际交付页面，S2 是页面调用的生产 scheduler HTTP interface。真实隔离文件、重读和现有执行记录是证据，不新增内部测试专用 seam，不用内存文件系统或仅模拟响应的页面替代。测试只检验可观察行为，不锁定路由名称、同步机制、冲突令牌或文件名算法等内部设计。

## 验收条件

- [ ] P25：向同一应用实例实际并发提交同目标更新，结果不能静默双重覆盖；模板和 Map 文件写入均纳入已有协调机制。不要用顺序发送两个请求冒充并发。
- [ ] P25：实际竞争模板删除与 node 新增/修改引用，观察提交先后；若引用已提交，删除必须拒绝。若删除先完成，之后合法保存缺失模板引用不视为违约，不收紧 P16。
- [ ] 上述用例验证最终检查与真实变更之间的应用内协调，不仅验证页面是否禁用按钮。P18 的编辑旧版本冲突用例归 02、03，本票不重复认领其测试所有权。
- [ ] P32：两类对象的新增、修改、删除成功结果与实际文件及生产接口重读一致，不只更新内存或显示成功提示。
- [ ] P32：代表性成功序列经真实服务进程重启后仍成立；明确预先指定应保留的对象、内容及应消失的对象，不能只断言数量变化或非空。
- [ ] P33：直接生产请求中的越界路径、路径分隔符和符号链接/重解析点场景，均不能使配置目录外哨兵被读取或改写；同时保护读取与写入，不只检查页面输入。记录平台实际覆盖，无法执行的场景不能宣称通过。
- [ ] P34：预览、编辑、保存、删除和错误恢复均结合现有实际执行记录，证明不启动 Chat、不执行固定操作；恶意 HTML/脚本不执行，路径参数不导致对应文件被读取。
- [ ] 测试预期来自 contract、独立业务字面量或独立演算，不调用实现计算预期；竞争验证检查有意义的结果和文件状态，不只检查请求返回或未抛错。
- [ ] 修复发现的问题并重验受影响行为，更新有变化的当前使用说明。明确应用内写入协调与外部编辑的保证边界，不增加任意外部编辑器的跨文件原子承诺。
- [ ] 完成对应完整回归入口，记录实际通过/失败与未验证项目。与 07 协调最新构建和变更，避免其交付旧页面证据；不得在自动工作未完成时提前请求人工验收。

## 运行约束与非目标

按项目测试指引执行 TDD 及真实运行验证，使用规定后端/npm 入口、当前构建产物和网络护栏。各用例独占真实临时目录、服务 cwd、持久化路径、进程和动态数值回环端口；仅同一竞争或重启场景共享必要资源。持续消费服务输出并正确清理进程与目录，故障不丢失原始原因。

执行记录使用既有安全替身/记录能力，不触发真实 Chat、第三方调用或关机。不得操作用户真实 Map、模板或会话。不新增数据库、自动重试、监控系统、外部编辑器协议或多实例一致性保证。所有相关生产调用方与必要使用说明随修复同步更新，不保留废弃行为作为兼容替代。
