# 复盘建议：05 经审查复核的整仓 Commit

## 高：缺少一条可复现的统一检查命令

**事实**：本 worktree 初次运行 `cargo test --no-fail-fast` 时，`mdns_conflict` 与 `mdns_failure` 因 `/` 返回 404 失败；原因是 `backend/static` 尚未生成。执行 `npm run build` 后，同样的 mdns 用例单独重跑通过。仓库没有根级 `package.json`，`git ls-files` 中也未见 CI 配置；前后端检查命令分散在 README。

**影响**：全新 checkout 上直接跑后端测试会红，且一次全量运行约 4 分钟。本次为此浪费了一轮完整测试和两个 mdns 目标的失败排查。

**建议**：
- 增加一个根级检查入口（例如 `scripts/check.ps1` 或根 `package.json` 的 `check` 脚本），固定顺序：`npm --prefix frontend run build` → `npm --prefix frontend test` → `cargo test --manifest-path backend/Cargo.toml`。
- 把该入口接进 CI；若暂时不设 CI，至少提供 pre-commit hook 或在 README 顶部给出唯一推荐命令。
- 让依赖打包页面的后端测试自己准备最小页面，或在测试夹具启动前校验 `backend/static/index.html` 并给出“先运行 npm run build”的明确失败信息，避免 404 被误读为产品回归。

## 高：`fixture_behavior` 在全量并行下不稳定

**事实**：两次全量运行中，`fixture_behavior::long_running_fixture_stays_running_until_the_stop_entry_point` 都曾失败，报错为 `long-running=force-killed(...)`；该用例单独重跑通过。

**推断**：满载并行时，夹具的 200ms 轮询/结束宽限不足，测试自带的结束入口先触发了强制结束，而不是让夹具按停止标记退出。根因未通过日志进一步定位。

**建议**：
- 让该用例或整个 `fixture_behavior` 目标串行运行（测试级互斥或检查脚本对该目标使用 `--test-threads=1`）。
- 或提高 `stop_fixtures_with_grace` 的宽限并给轮询更明确的失败诊断，避免把“负载导致的超时”伪装成夹具行为错误。
- 在 README 中标注该目标对并行负载敏感，防止后续 agent 把一次失败误判为本票回归。

## 中：单票体量超过单次执行预算，且没有可用的分派手段

**事实**：本票包含约二十条验收项、后端提交/审查指纹/串行锁/超时、前端交互、真实浏览器证据与文档。执行到 200 次工具调用时收到软预算警告，最终以一次提交收尾；本次会话中 `task` 工具明确提示“Agent spawning is currently disabled”，因此无法把独立切片并行分派。

**影响**：实现、测试、浏览器验证、文档全部串行压在一个上下文里，后期只能压缩验证轮次；TDD 的逐片红绿也被迫让位于吞吐。

**建议**：
- 对超过一定规模的票，工作流自动拆成可独立合入的垂直切片，例如：后端审查/提交核心、提交 UI、超时与并发、浏览器证据；每片单独验收、单独提交。
- 或在宿主允许时为这类票启用子代理，把互不依赖的切片（如前端交互与后端集成测试）并行推进，主代理只负责接口与最终验证。
- 在票据模板中给出“单票最大验收项/预计工具调用”的软阈值，超过时先拆分再开工。

## 中：TDD 的“先红”缺少可检查的证据

**事实**：本次多数切片是先写实现、再补测试。真正观察到红的只有两处：审查标识漏掉分支导致切分支失效用例失败；先判空变更导致 HEAD 变化用例返回 `nothing-to-commit`。其余配置、前端交互与大部分后端用例都是直接通过。

**影响**：无法证明每个验收标准对应的测试真的能抓住违规；本次最后补做了部分突变检查，但没有覆盖全部切片。

**建议**：
- 在 TDD 流程或票据模板中要求一份轻量“red log”：每个切片记录测试名、首次失败输出、随后通过的命令。它可以是票据旁的临时小节，不必新增正式文档。
- 宿主在长时间实现轮中插入一次检查点：“当前切片是否有已观察到的红色？”没有则先补测试再继续。
- 评审代理把“新增测试是否曾红过”作为可检查项，而不是只看最终绿色结果。

## 中：浏览器截图与视口的工具文档与实测不一致

**事实**：
- `tab.screenshot({ path })` 中的 `path` 未按预期落盘，返回的是 `omp-sshots-*.webp` 临时路径；本次改用 `Bun.write(dest, Bun.file(src))` 手动复制，并因漏拷 `desktop-commit-bar.png` 补拍了一次。
- `browser.open({ viewport: { width: 1280, height: 900 } })` 后截图元数据仍为 `1024x720`；改用 `tab.emulate({ viewport })` 后才得到 `390x844` 的窄屏结果。

**建议**：
- 在 `xd://eval/browser` 中明确截图落盘方式：`screenshot` 返回临时文件路径，持久化需 `Bun.write`；若支持 `path`，给出一个可运行示例。
- 明确共享/已打开的 tab 用 `tab.emulate` 改视口，`open` 的 `viewport` 只在新建 tab 时可靠；或直接修复 `open` 的视口参数。
- 在浏览器验收清单中加入“先读回 `window.innerWidth/innerHeight` 再截图”，避免把默认视口当成请求视口。

## 中：未确认终止的证据层级未在票中定义

**事实**：为验证“超时且终止未确认时资格保持”，本次尝试用 PATH/工作目录替换 `taskkill` 启动独立后端进程，但 Windows 仍解析到系统 `taskkill`；两次进程级尝试都得到“已停止本次执行”。随后删除该进程用例，改为 `commit::tests` 的两个单元用例验证资格保持/释放，并以真实超时执行中的重叠请求验证不重叠。

**影响**：票面要求“以较短配置验证……未确认停止时资格保持”，但真实 OS 层未确认终止在本环境不可诱导；实现实际走了保守的 `mem::forget(permit)` 分支，却没有端到端样例。

**建议**：
- 在契约/票据中明确该承诺的证据层级：单元测试（资格保持逻辑）+ 真实执行中的重叠拒绝，是否足以验收；还是必须提供可注入的终止替身。
- 若必须端到端，提供一个仅测试可见的终止程序接缝（例如 debug 构建的 env 覆盖），并由测试使用；不要在票据里留下“自行想办法制造系统级失败”的开放要求。
- 本次应在最终报告中保留“进程级未覆盖”的明确限制，而不是仅以单元测试宣称该项已通过。

## 低：MCP 工具参数摩擦

**事实**：首次 `index_repository` 传了 `path`，实际要求 `repo_path`；首次 `get_file_outline` 缺少 `project`，两次都靠工具返回的 schema 纠正。

**建议**：
- 在 `AGENTS.md` 或 MCP 使用说明中放一行最小示例，标明仓库级工具需要 `repo_path`/`project`，并指向 `xd://mcp__codebase_memory_mcp_*` 的 schema。
- 工具描述可在参数名旁直接给出“项目名来自 list_projects”的提示，减少一次失败往返。

## 低：Cargo 过滤参数作用于所有测试目标

**事实**：执行 `cargo test --lib commit::tests --test workspace_commit -- --test-threads=2` 时，过滤器 `commit::tests` 也套在 `workspace_commit` 上，导致后者显示 `0 tests`；随后单独重跑才得到 19 个用例通过。

**建议**：
- 在检查脚本/README 中分别给出单元与集成目标的推荐命令，避免把过滤词与 `--test` 混用。
- 或约定“先跑单元过滤，再跑完整集成目标”，并在输出中显式检查实际运行的用例数。

## 低：浏览器 smoke 的临时环境清理

**事实**：本次在系统临时目录创建了隔离仓库、bare 远端、fake bin 与配置，测试结束后停止了后端并释放了浏览器 tab，但未删除临时目录。

**建议**：
- 在浏览器/进程验证清单中加入“结束进程、关闭 tab、删除临时目录”三步，并在最终报告注明清理结果，避免后续 ticket 或人工复用残留路径。
