# 06 Sync 票据 TDD 复盘建议

## 事实基线

- 本票在 `06-sync-current-upstream` worktree 完成：新增 `backend/src/sync.rs`、`backend/tests/workspace_sync.rs`、`frontend/tests/sync.test.tsx`，并接入 `git.rs` / `commit.rs` / `lib.rs` / `WorkspaceBrowser.tsx` / `gitApi.ts`。
- 最终验证：`cargo test --manifest-path backend/Cargo.toml` 为 283 passed / 0 failed（33 个测试二进制）；`--test workspace_sync` 15 passed；`npm --prefix frontend test` 146 passed / 20 files；`npm --prefix frontend run build`（含 `tsc --noEmit`）成功。
- 真实 Chromium 环境完成了未检查、检查远端、确认/取消、成功、push 拒绝、恢复与窄屏截图；CLI 独立核对了本地/远端引用、合并提交、干净工作区和未执行 HTML 诊断。
- 实现期间发现并修复了检查记录在“同路径仓库被替换”后继续冒充已检查的缺陷；检查记录现在绑定到实际观察到的远端跟踪引用。
- 一次故障注入：把检查远端的 fetch 改成 no-op 后，`check_remote_updates_real_references_and_is_the_only_fetch_trigger` 以 `behind=0 != 1` 失败；恢复后通过。
- 后端测试对一次 `git pull --no-fetch` 的错误参数变更立即报错（10 个用例失败），确认了真实 Git 语义测试的敏感性；该变更已回退。

## 建议（按严重度）

### 1. TDD 的“红阶段”没有在执行记录中真正建立

**事实**：`sync.rs` 与前端组件基本先于对应测试完成；后端没有记录到先失败后通过的红色阶段。首次真正的红色出现在前端实现后的 “已同步按钮应禁用” 用例（测试发现遗漏后修复）。  
**建议**：在票据模板或执行记录中增加一个不可省略的“首个红色证据”字段，要求粘贴首次失败的命令与断言；在实现前先写一个可运行的最小失败用例。若担心字段被形式化，可让 review 检查该字段与最终测试的对应关系。这一条直接对应 TDD skill 的 “Red before green”，比继续增加测试数量更能改善未来执行质量。

### 2. 浏览器证据缺少“重新构建并确认静态资产新鲜”的前置步骤

**事实**：真实浏览器中“已同步”按钮一度仍可点击；原因是前端源码已修复、但 `backend/static` 仍是旧构建。重新执行 `npm run build` 后按钮才正确禁用。组件测试当时全绿，无法发现这一点。  
**建议**：把浏览器证据固定为 `build → start isolated server → assert key disabled states → screenshot` 的单一路径，并由脚本在启动前重建前端；或在证据 README 中记录当前静态资产哈希。仅靠手工“先测后截”容易再次用到旧页面。

### 3. Rust 格式化缺少可用护栏，且仓库当前并非 rustfmt-clean

**事实**：`cargo fmt --check` 在 `backend/examples/safe_shutdown_shell.rs`、`backend/src/config.rs` 等既有文件上报告差异；对 `workspace_sync.rs` 直接运行 `rustfmt` 时，它沿 `mod common;` 一并格式化了 `backend/tests/common/mod.rs` 与 `sse.rs`，随后需要手动回退这些无关改动。  
**建议**：先确定一个与仓库现有代码一致的 rustfmt/edition 基线，并在 CI 或 pre-commit 中运行 `cargo fmt --check`；在基线清干净之前，文档明确“不要运行仓库级 `cargo fmt`”。若必须按文件格式化测试文件，使用 `skip_children=true` 或只格式化无子模块的文件，避免无关 diff 污染票据。

### 4. 新 worktree 的 Node/npm 引导不完整

**事实**：普通 `npm`/`node` 不在当前 PATH；实际可用命令是 `D:/nvm4w/nodejs/npm.cmd`。同时 `frontend/node_modules` 缺失，必须先执行 `npm install`（本次添加了 103 个包）。  
**建议**：在 agent 环境或仓库文档中写明 Node 的可执行路径与一次性安装命令；更稳妥的是提供统一的 bootstrap/check 脚本，让新 worktree 不必靠搜索 `where node` 才能跑前端测试。

### 5. 浏览器证据工具的截图语义需要封装

**事实**：`tab.screenshot({ path })` 返回的是临时 `.webp` 路径，并未写入指定路径；本次需要用 ffmpeg 再转换为证据目录中的 PNG。`tab.run` 中不能直接使用 `document`；`waitForText` 的参数形式误用导致 20 秒超时并丢失前几张截图的返回路径。  
**建议**：提供一个小的证据辅助脚本/说明：打开标签、显式 `emulate` 选择桌面/窄屏视口、截图后读取返回的临时路径并复制/转换到证据目录、再打印最终路径。这样可避免靠文件大小和修改时间反查截图。

### 6. 运行中的 smoke server 会锁住后端可执行文件

**事实**：启动 `backend/target/debug/omp-bot.exe` 做浏览器证据后，再次 `cargo test` 编译时出现 `failed to remove file ... omp-bot.exe`，只能先停止服务。  
**建议**：证据脚本在启动服务时使用独立的 `CARGO_TARGET_DIR`，或在测试/构建前显式停止 smoke 服务；把这一顺序写进证据运行说明，避免把“服务在跑”误判为构建失败。

### 7. 全量后端测试重复执行的成本偏高

**事实**：完整后端测试约 5 分钟，本次在迭代与最终确认中多次运行；期间还出现过一次被服务锁文件打断的构建。  
**建议**：在仓库文档或脚本中区分“快速回路”（如 `cargo test --test workspace_sync`）与“交接前全量”；迭代时只跑相关测试，最后一次跑全量。若仓库已有类似命令但未记录，补一条导航指针即可。

### 8. 跨票与人工验收项需要结构化防遗忘

**事实**：本票的 P42 与 07/08 的节流窗口交叉验证、以及手机实机 H1 都不由本票完成；本次是在最终报告中手工声明“未验证”。  
**建议**：在票据模板中增加固定的“本票不覆盖、由谁拥有、当前状态”清单，或在测试/证据矩阵中把 deferred 项显式标出。这样不依赖执行 agent 的记忆，也便于 review 检查是否把外部依赖误报为完成。

### 9. `codebase-memory-mcp` 没有实际用于导航

**事实**：本票读取了 1,000 行级的 `git.rs`、`commit.rs`、`lib.rs`，主要靠分段 `read`；会话中只查询了索引状态，没有真正建立/使用符号大纲。  
**建议**：如果临时 worktree 可以被索引，给 TDD 执行增加“先索引/取大纲”的轻量步骤；若不能，则在工具说明中明确“临时 worktree 不适用”，避免 agent 在索引与分段阅读之间反复试探。此条为工具经济性建议，不代表本次阅读方式导致了错误。

### 10. API 错误码与响应形状缺少单一来源

**事实**：本票新增了 `no-upstream`、`sync-dirty-worktree`、`sync-blocked`、`sync-result-unavailable` 等类别，README 记录了主要类别，但 handler、前端判断与文档之间仍是手工同步。  
**建议**：把公开错误码整理成一份可检索的表（README 的一个小节即可），并在 review 中检查新增 handler 是否登记；这能减少未来 ticket 对“这个错误该显示什么”的重新猜测。

### 11. 前端 lint/format 护栏情况未确认

**事实**：`frontend/package.json` 只有 `build`（含 `tsc --noEmit`）与 `test` 脚本；本次没有运行 ESLint/Prettier，也没有检查 CI 是否另有任务。  
**建议**：先确认仓库是否已有前端 lint/format 任务；若没有，补一个最小 lint 或格式检查，至少覆盖本次新增的 `sync.test.tsx` 与 `WorkspaceBrowser.tsx`。这一条是低优先级的 **未验证项**，不应在未确认前直接断言仓库缺少护栏。

## 推断与未验证

- **推断**：全量测试耗时、缺少格式化护栏、缺少 Node 引导共同放大了迭代成本；这是从本次工具结果推断，不代表仓库长期如此。
- **未验证**：仓库 CI、pre-commit hook、rustfmt 版本固定策略、前端 lint 配置是否存在；本次均未检查，不应作为已确认事实写入改进结论。
- **未验证（验收边界）**：真实手机触摸、软键盘与返回手感（H1）未执行；P42 与 07 的节流窗口交叉场景归 08，本票只完成了按需检查与 Sync 前必查的自动化证据。
- **未验证（工具）**：`codebase-memory-mcp` 是否支持本 worktree 的索引，以及浏览器截图 `path` 参数是否本应生效；本次只记录了实际观察到的行为。
