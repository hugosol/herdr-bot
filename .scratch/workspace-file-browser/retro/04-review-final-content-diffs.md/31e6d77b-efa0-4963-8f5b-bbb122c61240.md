## 高严重度

### 1. 视觉承诺缺少真实浏览器自动检查，CSS 回归只能靠人工证据发现

**事实**：前端组件测试（`gitChanges.test.tsx`、`diffReview.test.tsx`）在 jsdom 中运行，断言的是 `change-added` 等 class 是否存在；真实 Chromium 第一次读取 `getComputedStyle` 时，所有变更行颜色都是默认的 `rgb(242, 244, 248)`。原因是 `.change-row { color: inherit; }` 覆盖了 `.change-added` / `.change-modified` / `.change-deleted`，而 jsdom 不计算样式表级联。随后补了 `.change-row.change-*` 规则，真实浏览器才得到绿/蓝/红。另一个同类问题是限制说明里的重复句号「。。」，也是人工读浏览器文本才发现的。

**推断**：本 ticket 的核心承诺（P15、P25、P26、P43、P44、P45）大量是视觉与布局事实；只靠 jsdom class 断言，未来 05–08 的视觉状态仍可能以同样方式漏过。

**建议**：
- 增加一个仓库自有的真实浏览器 smoke，例如 `frontend/tests/browser/change-colors.spec.ts`（Playwright）或 Vitest browser mode。用固定 fixture 断言：
  - 宽屏 `getComputedStyle` 下新增/修改/删除/重命名/冲突行的实际颜色；
  - 默认 diff 的 `data-mode`（宽屏 `side-by-side`，窄屏 `unified`）；
  - 限制/二进制时不存在 `diff-view`，但变更行仍可见。
- 把它接入统一的检查命令（见第 4 条）和 CI/pre-commit（若存在或新增）。
- 将这次真实 Chromium 证据保留为人工/半自动证据，但不要把它当作唯一的视觉 guardrail。

**未验证**：仓库是否已有 CI 或 pre-commit（本次未读取 `.github/` 与 git hooks）；因此不能断言当前完全没有浏览器检查。

### 7. 工具 API 的摩擦消耗了若干轮

**事实**：
- `bash` 传入 `ready: false` 与 `async: true, timeout: ...` 的服务模式参数触发两次 schema 错误；`ready` 必须是对象/null，服务模式不接受 async/timeout。
- `tab.screenshot({path})` 没有写到请求的路径，而是返回 `omp-sshots-...png`/`.webp` 临时路径；本次用 Python 复制到证据目录。
- `tab.waitForFunction` 不是可用方法，调用得到 `TypeError`；改用 `waitForText`。
- `tab.run` 在隔离运行时执行，`document` 未定义；页面 DOM 要用 `tab.evaluate`。

**推断**：这些都不是本 ticket 特有的；每次浏览器证据任务都会重复踩坑，尤其是截图落盘与页面求值。

**建议**：
- 在 `docs/agents/testing.md` 或一个浏览器证据 skill 中给出最小可复制样例：用 `tab.evaluate` 读 DOM/computedStyle，用 `waitForText` 等文本，`screenshot` 返回临时路径并说明如何复制到目标。
- 工具侧：让 `screenshot({path})` 真正写入目标路径，或明确文档化「返回值即临时路径」；补上 `waitForFunction` 或在文档中删掉相关暗示；让服务模式的 `ready`/`timeout` 参数错误信息直接给出合法形状。
- 对 `bash` 中含 `sed`/`cat`/`grep`/`rg` 的读文件命令给一次提示，指向 `read`/`grep`/`glob`；本次确实出现过这些 shell 读文件调用。

**未验证**：这些 tool API 是否为宿主稳定契约；建议属于可用性改进，不假设可立即修改。

### 8. 运行中的 proc 任务被反复读取

**事实**：`read proc://bg_32` 在运行中读取 3 次，`bg_37` 读取 4 次；工具多次返回相同输出并提示「Re-reading ... will not change it」。

**建议**：工具侧对运行中的 job 返回一行「still running; use wait」而不是重复完整输出，或要求通过 `wait` 获取结果。这样比继续在文档里重复「不要 poll」更有效。

**未验证**：`proc://` 的其它消费者是否依赖重复读取完整状态；需要工具维护者确认。
