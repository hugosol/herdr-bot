# 03: 准确定位 Git 待提交变更

**What to build:** 用户在 Git workspace 的独立变更视图中查看准确的待提交列表、当前分支与变更角标，并在文件浏览视图通过一致颜色和现存祖先目录提示定位变化。该票完整回答哪些变更待提交，但尚不开放 Commit。

**Delivers:** P15, P16, P17, P18, P19, P20, P22, P23, P24

**Blocked by:** 02: 在 workspace 边界内只读浏览完整目录.

**Status:** ready-for-agent

依据已批准的 [contract](../contract.md) 与 [spec](../spec.md)，在 S1/S2 上用真实 Git 与真实浏览器验收；不为私有集合或颜色计算新增契约接缝。

## Acceptance criteria

- [ ] Git workspace 的文件浏览视图与变更视图是内部子 tab。普通目录仍仅提供浏览。当前分支名可见，外部真实切分支后主动刷新反映新分支。
- [ ] 待提交集合覆盖 tracked 修改/删除、未忽略 untracked；排除 ignored untracked，但保留后来匹配忽略规则的 tracked 文件。忽略规则文件自身按普通文件处理，不 force-add。
- [ ] 真实浏览器中新增绿色，修改和 Git 已识别重命名蓝色，删除红色；两个视图一致，不显示普通 A/M/D 状态字母。冲突警告不能与普通修改混淆。
- [ ] 多层新增和删除使仍存在的祖先目录显示蓝色，传播到 workspace 根下一级；不把目录染为其子文件的绿色或红色。
- [ ] 删除项在变更列表可见，但不在浏览树伪造仍存在的文件；删除路径的现存祖先仍显示变化提示。
- [ ] ignored untracked 仍能浏览但无待提交着色；Git 元数据仅变化时不增加普通文件着色、祖先提示或角标，且仍能只读浏览。
- [ ] 真实未暂存文件系统改名按 Git 当前结果保留删除加新增；Git 已识别的暂存改名显示旧路径到新路径的一项蓝色变更。不得为了展示修改真实索引，也不得自创相似度配对或断言所有改名必被识别。
- [ ] 角标使用独立固定期望验证：同文件暂存加未暂存只计一次，已识别重命名一次，未识别删加两次，不计目录或 diff 行数；允许 Git 识别结果变化导致项数变化。
- [ ] 分支和本地状态主动刷新取得当前事实；未知、不可访问状态不假装干净，不将普通 Git 错误或单纯分叉误标为文件冲突。
