# 06: 按现有 upstream 与配置安全 Sync

**What to build:** 用户主动检查当前分支远端状态，看到最近检查时间和已知待拉取/推送数量；工作区干净且有已知差异时，经一句确认完成按既有 upstream 与 Git 配置执行的同步。任一步失败即停止，并展示真实结果，不隐式改变仓库策略或隐藏已经生效的步骤。

**Delivers:** P2, P6, P10, P11, P22, P28, P32, P33, P34, P35, P36, P37, P38, P42, P43, P48, P49, P51, P53

**Blocked by:** 05: 经审查复核安全完成整仓 Commit.

**Status:** ready-for-agent

依据已批准的 [contract](../contract.md) 与 [spec](../spec.md)，通过 S1/S2 验收。复用 05 的仓库写入保护；不得为同步另建会绕过它的执行入口。

## Acceptance criteria

- [ ] 主按钮逐态对应真实 Git 事实：存在普通变更为 Commit；干净、有 upstream 且已知 ahead/behind 非零才可 Sync；已知同步为禁用已同步但仍可检查远端；未检查、无 upstream、冲突/未完流程、detached HEAD 分别给出原因，不把缓存说成实时。
- [ ] 提供明确远端检查入口和最近检查时间；隔离远端独立前进后，主动检查更新实际引用和页面。Sync 前必定重新检查；本地文件事件不持续自动 fetch，结合 07 的集成交叉验证归 08。
- [ ] Sync 经一句消息及确认/取消门禁，不重复审查信息；取消后独立核对真实仓库与远端引用，证明无 Git 写入。
- [ ] Sync 在接受/执行时核对当前分支、现有 upstream 和干净工作区；真实外部切分支后操作目标与重新显示、确认的当前分支一致。使用非默认远端和跟踪分支样例，不假设 origin 或固定分支名。
- [ ] 按检查远端、pull、按需 push 的次序执行，遵守已有 merge/rebase/ff-only 配置。只有 behind 时不要求无意义 push；不 stash、不隐式 commit、不强推、不覆盖配置以保证成功。
- [ ] 页面与直接请求都拒绝普通目录、脏工作区、目录不可用/读取失败、detached HEAD、冲突及未完成 Git 流程。无 upstream 显示限制，不配置 upstream 或发布分支。外部完成/撤销流程后刷新恢复，普通认证/网络/策略错误不误标文件冲突。
- [ ] 不递归同步嵌套仓库或子模块内部仓库；隔离样例独立核对它们前后引用和内部状态。
- [ ] 配置拒绝、pull 冲突、push 拒绝等真实场景中失败即停止后续步骤；页面保留 Git 原诊断为纯文本，含 HTML/script 的诊断在真实浏览器不执行。
- [ ] pull 成功后 push 被拒绝，不自动撤销已经生效的本地提交和引用，不宣称事务回滚；独立核对索引、历史、隔离远端引用及页面反馈。
- [ ] Sync/Sync 与 Commit/Sync 混合并发在不同调用者、实际仓库路径别名下均无重叠写入。Sync 观察断开或终止未确认时不释放资格；固定操作的执行资格仍独立。本票拥有这些测试，不回头要求 05 等待。
- [ ] 沿用服务器无需输入的身份与凭据；需要交互的编辑器、凭据或签名条件明确失败或超时，不新增终端/网页凭据流程，不修改既有 Git 策略。
- [ ] 每条命令使用 05 已交付的可配置有限时长；以短配置验证 Sync 阻塞/派生执行终止及后续 pull/push 停止，保留已生效状态。页面标明本功能超时及已有输出，终止未确认时仍保持资格，不伪造 Git 退出诊断。
- [ ] 切 tab 不取消已接受 Sync，返回可观察实际结果；操作中重载默认会话列表且不重放，独立核对真实引用/副作用次数。响应丢失给出未确认，不认定成功或未执行，不自动重试写入，允许查询实际状态。
- [ ] 操作完成后刷新及返回/手动查询反映当前事实，不用自动节流缓存代替主动查询；08 拥有与 07 节流窗口交错的集成验证。
