# 07: 用真实文件事件刷新并报告监听健康

**What to build:** 普通目录和 Git workspace 的外部文件变化自动反映到主界面；工作区及相关 Git 元数据事件按 workspace 合并与节流。监听失效明确显示过期或错误，而不是继续假装自动更新正常。

**Delivers:** P39, P40, P52, P54

**Blocked by:** 03: 准确定位 Git 待提交变更.

**Status:** ready-for-agent

依据已批准的 [contract](../contract.md) 与 [spec](../spec.md)，通过 S1/S2 验收。04–06 不是本票前置条件；本票可以与 diff/Commit/Sync 链路并行推进，不提前固定监听库或更新传输协议。

## Acceptance criteria

- [ ] 用真实交付进程观察真实目录的外部增删改，普通目录浏览随之更新，不依赖 Git 状态作为唯一目录事实。
- [ ] 用真实 Git 外部操作及工作区/相关 Git 元数据写入验证分支与待提交状态更新；不能用模拟通知代替监听确实生效的证据。
- [ ] 自动刷新按 workspace 合并事件，默认最小间隔 10 秒且后端可配置；没有等待窗口时尽快刷新，窗口内记为待刷新并在窗口结束补一次。连续写入不能使最终刷新无限延期。
- [ ] 独立事件时序覆盖窗口首尾、密集及连续写入、多个观察者；可控时间验证节流，真实进程验证监听。多个观察者不各自放大同 workspace 刷新，不把 10 秒最小间隔承诺成 Git 查询必在 10 秒完成。
- [ ] 缺省刷新配置保持 10 秒，合法覆盖生效；旧配置缺段仍可启动，非法类型或不合法值明确拒绝启动而非静默回退。沿用已有启动期配置惯例，不固定键名。
- [ ] 可复现的真实监听失败条件使页面明确显示自动更新错误或过期，不宣称恢复成功；手动查询在实际可用时仍可取得当前事实，失败时显示真实错误。
- [ ] 监听刷新只针对本地状态，不新增周期 fetch 或远端实时通知；最终本地事件与远端按需检查的交叉验证由 08 负责。
- [ ] 自动节流不接管进入/返回、手动刷新、操作后刷新及提交前检查路径；为既有主动查询保留即时取得当前事实的行为。不得因 08 尚未执行而省略此实现；完整窗口交错测试归 08。

## Verification boundaries

以真实文件系统、Git 元数据和交付进程为外部证据，节流时间期望独立于 implementation。真实浏览器观察更新与监听健康反馈；不修改用户工作仓库、不推送业务远端、不执行真实关机。不得借监听失败增加新的恢复、轮询远端或 telemetry 产品范围。
