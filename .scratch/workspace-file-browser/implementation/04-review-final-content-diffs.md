# 04: 审查最终内容与完整 diff

**What to build:** 用户从待提交列表选择变更，审查当前本地分支最新提交到本地最终内容的整体差异。电脑默认左右对照，手机默认统一 diff 并可明确返回；内容预览限制不会隐去变更或被伪装为完整 diff。

**Delivers:** P5, P13, P14, P21, P25, P26, P43, P44, P45

**Blocked by:** 03: 准确定位 Git 待提交变更.

**Status:** in-progress

依据已批准的 [contract](../contract.md) 与 [spec](../spec.md)，通过 S1/S2 验收。内部读取方法和文本识别细节可按项目惯例决定，但不能改变完整审查范围或读取边界。

## Acceptance criteria

- [ ] 用独立写定的旧新文本与真实部分暂存仓库，证明 diff 为 HEAD 到最终本地内容，而不是 index 到工作区或远端到本地；新增与删除内容也能审查。
- [ ] 已初始化但无首次提交的仓库采用空树比较，符合待提交规则的文件作为绿色新增展示；不提供 git init。P47 的完整首提交流程和测试由 05 负责，本票不得因此反向等待 05。
- [ ] 读取、diff 与重命名审查前后独立核对真实文件及索引语义未变，不为展示暂存文件；允许正常只读查询的非语义缓存活动。
- [ ] 本票新增的公开 diff 读取入口同样执行根边界检查，覆盖根外路径、遍历、符号链接、Windows 目录联接和路径替换反例，不通过历史/当前内容选择绕过所选 workspace 范围。
- [ ] diff 文本只作纯文本展示，真实浏览器证明 HTML/script 内容不执行；不以文件后缀白名单决定可预览性。
- [ ] 对 diff 旧侧和新侧分别应用当前配置的单份内容限额，默认 1 MiB；验证精确边界、旧侧超限而新侧很小及相反组合。任一侧超限不渲染完整 diff，明确限制；二进制给出不可文本 diff 原因。
- [ ] 超限或二进制变更仍在两视图中正常可见、着色和计数；不能因预览不可用静默删除待提交项或缩小审查集合。
- [ ] 真实宽屏浏览器验证左列表右内容、默认左右 diff、选择和滚动，提供截图；真实窄屏浏览器验证默认统一 diff、逐层进入、明确返回和列表滚动恢复。
- [ ] 当前页面内切换文件浏览/变更视图及顶层 tab，保留对应选择、展开和滚动上下文；本票负责变更列表/diff 分区，不要求整页刷新恢复临时状态。
