# Contract — Chief Bot

Source: [spec](spec.md)
Acceptance mode: Full automation
Approval: approved — seam 选择、约束审查及验收模式均已获用户明确确认。
Human-led coverage: none

本 contract 约束 herdr-bot 与 my-agent-toolkit 的共同交付，不是实现顺序。范围与叙述由 source spec 拥有；下表只记录承诺、观察位置与证据。Delivering work 由 `/to-tickets` 填入，不手工维护承诺状态。承诺完成由交付工作和所需检查结果共同推导；本文 approved 只表示设计决策获批，不表示功能已经实现或测试通过。

### Coverage rules

- S1 使用真实渲染与实际交互；S2 使用真实后端、隔离存储和必要的进程重启；S3 分别覆盖 OMP/Pi 的实际交付入口、原生确认和工具效果。公开 interface 是测试面，不把私有 helper 当 contract seam。
- 两种宿主必须各自取得功能证据；真实模型行为案例全部使用 GPT-6-luna。测试驱动可给定用户输入与明确批准，但不得替模型选择业务工具或伪造其结果。受控 provider 仅用于机械协议/故障验证，并明确标注证据含义。
- 并发与失败预期来自独立案例：例如两个竞争者只有一个有效身份、报告通知失败后原内容仍存在、相同 ID 重发不新增处理。不得调用产品的同一计算方法生成期望。
- 无自动行为需要有界观察证据，窗口覆盖案例涉及的既有维护/启动/确认预算；具体数值由票据引用实际配置声明，不新增产品等待策略，不以无限等待或即时断言证明“永不”。
- 存储失败、传输失败与崩溃使用隔离资源；保持原始错误及清理错误，不操作用户的 Chat、凭据、目录、关机或正常服务实例。真实依赖缺失、GPT-6-luna 不可用、原生能力不支持或证据不足必须报告阻塞，不能转为通过。
- agent 完成实现、TDD、必要回归和全部约定验收；没有计划内人工验收例外。自动化失败不得用“用户自行检查”替代尚可执行的工作。

### Inherited decisions and dependency treatment

- 继承 spec 的 Implementation Decisions 与已接受 ADR：Task/Chat 与 Bot 区分，chief 不替代 manager，节点身份来自执行上下文，zone 稳定 ID 与本机绑定独立于 Workspace，会话登记清除不等于进程终止。此处不重新投票。
- 已定共享落点保持：后端共享报告保存/通知；workflow-chat 的 common 层共享确认、Session 绑定请求与共同结果解释；业务不下沉 framework，扩展不依赖 framework 私有 implementation。模块粒度仍由 build 决定。
- **In-process**：选择/角色及状态规则，透过已有消费者 interface 验证，无需新增 adapter。
- **Local-substitutable**：时间、文件系统及可控本地故障使用已有隔离设施；持久化承诺仍有真实文件与重启证据。
- **Remote but owned**：toolkit 与 herdr-bot 的请求使用已有公开 interface/传输 adapter，跨仓集成证明共同契约；无需只为本功能再套一层 transport abstraction。
- **True external**：已安装 Herdr、OMP/Pi 及实际模型依赖。受控 adapter 可注入故障，真实原生运行与 GPT-6-luna 案例承载其不可被替身证明的承诺。

### Approved receipt trade-off

接收确认表示报告已可靠接收，不表示模型已经完成呈现，更不表示用户已读或验收。确认后、呈现前崩溃时保留接收事实，不自动重播；发送者重发同 ID 不重复触发处理，用户可在当前 chief 明确要求查看原报告。

拒绝把“Herdr 接受输入”当作接收确认，也拒绝以自动重播消除所有展示空窗：前者缺少证据，后者违背不自动补投且可能重复询问。已批准的取舍是不承诺跨进程崩溃时恰好一次可见答复。

未来若要求事务式的恰好一次展示，需要重审 S3 的两宿主接收/原生历史交互及 P25–P28，而不是悄悄增加自动重试。当前推荐并已批准保留人工恢复方式。

- **留给 implementation 的细节**：公开操作的具体命名/参数表示、报告及接收记录存储布局、chief 占位与撤销的内部机制、同意内容变化的检测方式，以及已有配置对应的精确测试观察窗口。它们不得改变上述可观察结果；遇到无法满足的承诺先修订 contract，不能用内部实现选择缩小范围。
- **留给 /to-tickets 的归属**：Delivering work、逐项测试执行入口与已有设施复用，以及工作间真实依赖。没有未批准的新 seam，也不在此预切实现票。

## Out of scope

继承 [spec 的 Out of Scope](spec.md#out-of-scope)，不增加排除项。特别保留其无自动重投/补投、无自动业务推进、无 chief 对话上下文迁移、无多有效 chief、无强制终止旧进程、无任意本机能力安全沙箱等限制。

人工查看已接收报告是已明确批准的故障恢复，不是自动补投；不将“不保证崩溃时恰好一次可见答复”扩大为可丢弃已保存报告或省略正常结果呈现。
