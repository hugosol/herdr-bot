## Retrospective

## 复盘结论

本轮有真实的 red→green 证据，不能归类为“先实现后补测试”：Map 请求最初因缺少 `managerTaskId` 接口失败；随后分别捕获了定义漂移仍执行、持久启动状态停在 `starting`、词典改变节点业务含义却仍获执行的问题。最终完整后端检查通过，委派目标 13 项通过；浏览器检查 356 项通过、1 项跳过。

主要改进空间是：把确认期间的变化分类提前放进测试设计，以及降低探索和证据读取的开销。以下只提出建议，不修改环境。

## 1. 高：让“批准载荷不变”测试覆盖实际消费的语义

**事实**：第一轮 Map 启动测试通过后，漂移测试发现修改 Map 节点输入仍返回 `201`；加入定义闭包后，又发现仅改变词典中 `${review_scope}` 的值仍能通过确认。后一问题是在实现后段追加场景才暴露的。

**建议**：在此类确认协议的测试设计参考中，增加一个按需读取的“语义漂移”分支。每个批准字段区分：

- 原始定义变化；
- 引用目标或位置绑定变化；
- 定义不变、解析结果变化；
- 地址不变、材料内容变化；
- 引用失效。

当前切片只选择其中一个可观察的反例完成 red→green，不预写整批测试。完成标准是：每类相关变化都有公开接口证据，或明确说明为何不影响本次批准内容。

**价值**：本轮第二次漂移缺口具有明确、独立的失败证据；这比增加泛化的“充分测试边界”指令更有针对性。该分类不应放进常驻 `AGENTS.md`。

## 2. 中：测试夹具应明确原生身份与 cwd 的权威来源

**事实**：两次调试失败来自夹具，而非目标行为：

- Map manager 首次启动失败，因为受控 Herdr 没有名称为 `work` 的 Workspace。
- 内部 node 首次派发失败，因为原生会话文件头仍写着 manager 的 `work` 目录；修改 `native_cwd` 未覆盖该文件头所给出的 cwd。

这些失败均被保留，随后修正了测试前置条件；没有将其冒充业务断言的 red。

**建议**：在现有 Herdr 测试设施的就近说明中，集中记录“Workspace 精确匹配”和“已有原生文件头优先”的夹具约定；为需要不同执行目录的场景提供一个同时接收身份与 cwd 的夹具操作。完成标准是：场景声明的 Workspace、Tab cwd 和原生身份 cwd 能独立核对，错误前置条件有直接诊断。

**边界**：这是测试环境可用性建议，不是放宽产品的目录核实规则，也不是新增生产测试入口。

## 3. 中：把真正影响范围的差异保留在测试场景中

**事实**：最初的 node zone 漂移场景同时改变了材料所在 zone；已有材料绑定比较也可能捕获它，不能独立证明内部 node zone 检查有效。本轮后来引入独立的 `review-zone` 身份，使该场景与请求材料绑定分离，并验证了实际 node Tab cwd。

**建议**：在 TDD 的“设计前红灯”提示中强调一个具体审题动作：命名的错误机制是否能被另一项检查偶然挡住？若能，先分离场景条件，再运行测试。

**完成标准**：每个关键负例能指出唯一需要暴露的差异，以及为何相邻检查不能替它通过。

**价值**：这是保留本轮有效修正的经验，不需要再追加一条宽泛的审查禁令。

## 4. 中：减少无效探索调用和大范围输出

**事实**：

- 首次 `find` 的 27 个判断请求全部因区域不可用返回 451；随后改用索引工具和精确搜索才定位实现。
- 一次带路径过滤的图搜索返回零结果，放宽到已知符号后找到了 manager／preflight 接口。
- 一次文本搜索列出的多个路径不存在，因为相应模块实际位于目录内。
- 有些读取产生数百行源码或说明，工具随后截断输出。

**建议**：

1. 让查找工具在同一会话遇到确定性的服务不可用后，直接给出可用替代入口，避免继续支付同类请求成本。
2. 给图搜索增加小型使用提示：精确符号优先；文件过滤无命中时先移除过滤，不把零结果解释为代码不存在。
3. 已知模块位置尚不明确时，先取目录／文件结构，再执行精确路径搜索。
4. 大文件以声明大纲定位后只读取当前切片；说明文档按分支披露。

**未验证**：没有测量各替代方案的实际耗时收益，不据此声称某种工具顺序必然更快。
