# TDD 执行复盘

## 1. 高：红灯最初来自测试驱动取错字段，未证明业务断言有效

**事实**：首次原生测试以及首次实现后的运行，都在 `result.isError` 断言失败，实际值为 `undefined`。随后读取原生历史确认查询已成功；问题是测试 helper 从错误的原生结果层读取错误标志。修正 helper 后，代理临时把 Bot 查询路由改成 Map 目录，观察到独立的 `Bot.when` 内容断言失败，恢复路由后转绿。

**建议**：在现有原生 dock 支持层提供具名的工具执行结果读取接口，明确区分原生事件的错误标志与 `result` 载荷，并让新增场景复用它。将“红灯的失败位置是否命中预先声明的业务观察”作为每轮证据要求；接口缺失或驱动故障只记录为前置失败。

**边界**：本次后续故障注入补足了检测错误目录结果的证据；不能据首次红灯声称该行为已被验证。

## 2. 高：原生验收环境缺少集中、可执行的依赖解析

**事实**：代理先复制整个 OMP baseline 目录，取消后又复制指定版本；第二次复制耗时约 210 秒。完整 dock 运行约 586 秒后出现一项安全壳路径错误：设置 `HERDR_BOT_REPO` 不会改变 connect-bot fixture 的默认二进制路径。随后全仓运行额外设置 `HERDR_BOT_BINARY` 与 `HERDR_BOT_METADATA`，该错误消失。

**建议**：在现有 dock 启动设施中增加一次性环境预检，输出并验证实际使用的 OMP 安装、Pi CLI、Node、安全壳、metadata 和配对后端路径；提供一个统一的隔离 worktree 启动入口来传递这些既有参数。复用已安装的精确宿主产物，避免每张票自行复制整个缓存。

**推断**：这能减少环境故障直到长套件末尾才暴露的机会。共享安装的并发安全性及合适的复用机制，本次未验证。

## 3. 中：新增角色需要同步维护的架构检查清单发现过晚

**事实**：`check:integrations` 通过，但全仓测试发现 `import-boundary.test.ts` 的显式角色列表没有 chief，导致两项失败。扩展现有列表后，该文件的 16 项测试全部通过。

**建议**：把现有 import-boundary 检查纳入“新增角色／宿主装配”的早期定向检查入口，与现有 integration 检查一起运行。保留确定性架构检查，不用新的代理文字规则替代它；在装配文档中只增加指向该入口的条件式导航。

**边界**：现有检查确实捕获了遗漏，问题是检查时机，而不是缺少另一套规则。是否已有 CI 或提交钩子承载该检查，本次没有调查，不能断言仓库没有护栏。

## 4. 中：共享文件的并行契约协调应提前到公共接口确定时

**事实**：06 为 `WorkflowRequests` 增加 GET 并抽取私有交换方法；02 同时为确认载荷冻结重构同一文件。双方确认重叠后，父代理决定由自动集成处理，并明确要求同时保留 GET、活动 Session 取消／预算、批准载荷冻结和不确定结果语义。

**建议**：调度同一公共模块的并行票时，先公布公共方法与必须保持的不变量，再让各票独立实现。集成检查应覆盖这些共同不变量，而不是要求后完成者移植另一票的私有组织结构。

**边界**：本次只观察到冲突风险与交接决定，没有看到最终合并或集成验证结果。
