# 17: 交付持久接收去重与人工恢复接口

**What to build:** 后端维护稳定不可变报告与可靠接收事实，允许明确人工重发/查看；并发、更换 chief、进程重启不重复触发已接收报告处理。

**Delivers:** enabling: unblocks P23, P24, P25, P26, P27, P31, P34, P35

**Blocked by:** 04：约束唯一 chief 的创建恢复与登记；14：保存合法 chief 报告后通知当前 chief

**Repositories:** herdr-bot

**Status:** ready-for-agent

来源：[approved contract](../contract.md)、[spec](../spec.md)。

## Acceptance criteria

- [ ] 报告保存和接收状态由后端持久化；重复/并发同 ID 重发、回执丢失、更换 chief、实际后端重启后仍返回已接收，不虚构再次呈现。
- [ ] 同 ID 内容不得被替换；修改内容拒绝或经新确认建立新 ID，原记录保持不变。
- [ ] 重发只通知当前有效 chief，不新建业务报告；没有 chief 或通知失败保留原事实，不安排自动补投。
- [ ] 接收资格、认领和持久去重在竞争中一致；旧 chief 失权后不获得新的接收/派发授权；已提交外部效果不声称可撤回。
- [ ] 接收确认不代表模型呈现/已读/验收；确认后呈现前崩溃保留接收，不自动重播；当前 chief 可按明确请求读取原报告。
- [ ] 恢复独立执行者与直接 Map manager 保留真实委派/原报告关联，不产生新委派、Run 或初始输入重放；未关联同 Task Chat 仍拒绝。

## Coverage ownership

S2 持久状态/并发/失败测试归本票；P23–P27/P34/P35 的完整双宿主恢复验收由 19；P31 的交接授权验收由 20。
