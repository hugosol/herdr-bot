# 03: 从当前 execution 登记解析上游文件输入

**What to build:** 下游在显式派发时直接获得本 Run 来源 node 当前 execution 登记的命名输出地址，不再解析正文或寻找最新文件。来源 node 存在但输出缺失时仍按既有规则启动，并明确说明哪个输入未解析。多个消费者可共享同一登记地址，业务汇总仍由 Map 安排的 node 承担。

**Delivers:** P5, P6；P4, P9, P11, P13, P23, P24 的下列覆盖项。

**Blocked by:** 01: Map 命名输入声明与直接文件初始化；02: report 完成声明与单一来源输出登记。

**Repositories:** herdr-bot

**Status:** ready-for-agent

## Acceptance criteria

- [ ] 通过已保存 Map 和实际 report／dispatch 链路观察输入；按本 Run、来源 node 当前 execution 和输出名解析，不以最新时间、正文路径或目录扫描替代身份。
- [ ] 使用两个 Run、相同逻辑输出名、旧／新 execution 交错报告和误导正文，独立写明预期地址，核对实际初始化。不得从被测实现重算预期。
- [ ] 同 execution 登记按名累积，省略名字和 outputs 都保留既有项；重试后当前 execution 没有该名字时明确未解析，不回退旧执行。
- [ ] 来源存在且依赖已满足但输出缺失时，仍创建并初始化节点 Chat，显示缺失逻辑输入名；不伪造地址、不增加 blocked_by、不撤销上游完成，也不额外自动派发。
- [ ] 节点实际初始化同时保留本次 userInput 和原业务 input；独立正文／上游聊天敏感标记不出现。
- [ ] 保存成功而通知失败的报告仍可用于输入解析，不等待通知成功；与实际报告持久记录核对一致。
- [ ] 用公开 interface 驱动共享输出和业务汇总定义，观察消费者及汇总节点获得正确登记地址；框架不读取／解释／合并业务内容。真实内容消费和汇总字节证明由 08 唯一拥有。
- [ ] manager zone、node zone、业务产物目录不同也能传递原始绝对地址；无复制、移动、zone 内重写或新权威缓存。
- [ ] 更新受影响初始化消费方、行为测试和长期输入解析文档；不新增查询工具、输入模板语言或脚本执行器。
