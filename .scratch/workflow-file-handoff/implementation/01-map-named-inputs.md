# 01: Map 命名输入声明与直接文件初始化

**What to build:** 规划者可保存、读回命名输入，明确选择直接文件或来源 node 加输出名；显式派发后，节点初始化获得本次 userInput、原业务 input 和直接文件地址。无文件输入的既有 Map 继续工作，输入关系不改变 blocked_by，也不自动启动工作。

**Delivers:** P1, P3；P2, P4, P24 的下列覆盖项。

**Blocked by:** None (can start immediately).

**Repositories:** herdr-bot

**Status:** ready-for-agent

## 契约与覆盖归属

依据已批准的 [contract](../contract.md) 与 [spec](../spec.md)。仅复用 S1；初始化的真实 Chat 观察由 07 拥有。下表每项测试均由本票编写／维护，不重复认领其他票的覆盖项。

|---|---|---|---|
| P1 | 两类命名输入字面样例、无输入、非法类型、保存失败保留原定义 | 01 | 无 |
| P2 | 直接输入同卷／异卷／zone 外绝对地址；相对地址拒绝 | 01 | 输出地址：02 |

| P24 | manager zone 下按 Run ID 区分的中间资料位置，与 node zone 解耦 | 01 | 外部输出地址传递：03；真实业务：08 |

## Acceptance criteria

- [ ] 两类输入来源可经现有 Map 保存与读取 interface 往返；来源必须明确，类型错误不能被忽略或转换成另一种来源。
- [ ] 来源 node 不存在、字段类型错误或直接输入为相对地址时拒绝保存，原定义保持不变；独立存储故障也不替换原定义。
- [ ] 直接文件地址接受同卷、不同卷和任何 zone 外的合法绝对地址。路径表达校验不探测存在、可读性、格式或业务授权。
- [ ] 合法输入引用不隐式增加 blocked_by；保存和读取不启动 Chat；只有显式 dispatch 才执行既有派发规则。
- [ ] 通过实际派发捕获初始化，分别对照独立 userInput、业务 input 和地址字面值；上游聊天与文件正文的敏感标记不得出现。
- [ ] 未声明文件输入的既有 Map 仍可保存并显式派发，不被强制生成文件；具名上游来源的运行解析由 03 完成，不在本票制造猜测地址。
- [ ] 节点可获知 manager zone 下按 Run ID 区分的中间资料位置；不同 Run 可区分，node zone 不决定该位置。不新增背景副本、每 node 目录或输出预分配协议，也不把该位置当作输出登记白名单。
- [ ] 同步更新受影响的 Map 消费方、初始化预期和长期协议文档；保留 Task／节点执行角色的既有分工，不新增界面动作。

## Verification

在本票 herdr-bot worktree 根运行受影响的 Map／workflow 定向检查，再运行 `node scripts/test-backend.mjs`。通过公开保存、读取、创建 Run 和显式派发路径做隔离冒烟，记录请求、结果、实际宿主初始化及未显式派发时无启动效果。使用独占临时存储、动态数值回环端口和所属进程；不同卷地址无需对应真实文件。永久测试只断言调用者可见行为，不固定实施字段布局以外的内部组织或指引措辞。
