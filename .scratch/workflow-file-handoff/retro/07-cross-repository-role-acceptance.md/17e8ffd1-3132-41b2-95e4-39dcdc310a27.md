# Ticket 07 TDD 执行复盘

## 范围与结论

本复盘仅依据当前 ticket 执行对话中可见的用户要求、代理行为和工具结果，不评价父 session 或其他代理的执行。读取到的上一轮报告仅用于说明本轮如何接手，不能当作本轮亲自执行的验证。

本轮没有新增产品实现或测试，也没有开展新的红→绿循环；主要工作是核实真实模型验收的依赖阻塞，保留既有实现并交还未完成状态。**没有把受控 dock、网络可达或已有 runner 宣称为真实模型验收通过，这一点应保留。**主要改进空间在于：交接时如何表达依赖用途、如何建立可检查的阻塞判定，以及如何避免已完成探索在重试中反复发生。

## 1. 高：将模型接入的用途与授权边界作为显式交接契约

**事实**

- 本轮最初沿用上一轮判断：专用 `model.json` 和自定义凭据环境变量缺失，因此真实 S2 无法运行。
- Main 随后指出，不能仅因缺少这些自定义变量就排除当前进程已提供的 `PI_PROXY_*`，要求核实其协议、实际服务与凭据用途。
- 代理检查公开安装的 OMP 实现，发现 `PI_PROXY_*` 用于 provider 正向代理，并执行 HTTP CONNECT。
- 不带认证直接访问代理的 `/v1/models` 返回 400；将其作为 HTTPS 代理访问 OpenAI `/v1/models` 返回 401，响应为 `Missing bearer authentication in header`。
- 公开宿主代码将 `PI_TOOL_BRIDGE_TOKEN` 绑定到工具 bridge。本轮没有把该 token 转作模型密钥，也没有读取用户私有 auth 或 Session。

**推断**

早期阻塞判定混合了两件事：“缺少指定形式的配置”和“缺少可用的授权模型接入”。本轮后续调查纠正了判定方法，但最终仍未找到足以运行真实验收的授权材料。

**建议**

由宿主提供一份只读、无密钥值的**模型接入清单**，明确区分：

- 网络代理：协议、目标用途，是否只负责转发；
- 模型服务：provider、model、API 类型与 endpoint；
- 授权：凭据来源的名称、允许传给哪些隔离子进程；
- 工具 bridge：仅供工具调用的凭据边界；
- 禁止访问的用户状态。

将其放在验收依赖说明或宿主公开配置中；入口文档以“真实模型验收缺依赖时”这一分支指向它，而不是在全局指令中重复展开。阻塞判定应完成于“已检查所有明确提供且获授权的接入来源”，而不是“找不到某个约定变量名”。

**验收建议**：代理无需探索用户私有目录，就能回答服务类型、授权来源、可传递范围与缺失项；清单明确不足时，直接报告前提缺失。

**未验证**：本轮没有证明整个机器或其他宿主上下文不存在可用授权，只证明当前可见、获准检查的材料不足。

## 2. 高：为重试交接保存结构化的阻塞判定与证据有效范围

**事实**

- 用户要求处理上一轮未被工作流接收的问题，同时保留已有工作、不重复无需重跑的检查。
- 本轮读取了上一轮报告、既有 `verification.json`、隔离配置和诊断结果，并确认保留的两个源码 HEAD。
- 代理没有重跑既有验收，也明确区分了历史通过结果、历史 canonical 失败与本轮新做的代理鉴别。
- 最终仍因真实模型授权前提缺失而以失败交还。

**建议**

扩展现有交接元数据，而非另建一套运行记录：用结构化字段保存源码 revision、实际依赖来源、阻塞项、已排查来源、授权限制，以及解除阻塞所需的最小新增材料。对已有检查，保留命令、结果、源码和环境适用范围。

重试入口先比较这些前提是否变化：

- 有变化：仅重开受影响的验收路径；
- 无变化：复用证据，明确交还仍缺的前提；
- 信息不完整：只补齐缺口，不重新扫描全部仓库。

**验收建议**：再次调度时，代理能在一次交接读取后确定“哪些结果仍可引用、哪项新增信息才会使本次执行产生不同结果”。机器可解析的字段由宿主检查，避免仅靠长篇报告中的文字约定。

**边界**：本轮未检查调度器实现，因此不能断言它缺少或错误实现了上述能力；建议针对本次可见的重复接手成本。

## 3. 中：失败现场的保留边界应包含原生宿主启动阶段

**事实**

- 本轮读取的上一轮报告记载：canonical 全仓检查有 5 项 OMP ready-frame 超时，失败临时目录已被清理，缺少可继续定位的内部现场。
- 既有两 worker 鉴别实验通过，但代理没有用它覆盖 canonical 失败，也没有据此修改 deadline 或并发策略。

**建议**

在现有 dock 失败保留机制中，将“原生 ready 前失败”作为独立保留分支：进程命令、宿主版本、启动阶段、退出状态、已消费的 stdout/stderr、RPC 帧和必要的隔离配置都应在清理进程后仍可读取。敏感配置采用脱敏副本，不能为了保留现场而遗留凭据。

如果仓库已有此能力，应优先找出该失败路径为什么未保留，而不是再写一套收集器。可为失败保留契约增加确定性回归：触发受控启动失败，断言所属进程清理完成，原始错误与诊断文件仍存在。

**未验证**：本轮未读取 dock 清理实现，也未重新执行失败用例；无法确认现场丢失的具体代码路径，更不能把并发资源竞争认定为超时根因。

对同一 Promise 的组件证据与端到端证据分开标注；真实模型职责要求只能由对应原始对话和工具次序支持。该规则应集中在 TDD 的验收证据说明中，不再散落到多个全局禁止条款。

**验收建议**：仅阅读报告就能区分本轮行为、引用的历史结果和未验证项，且组件通过不会被汇总成整票通过。

## 5. 低：已知符号查找失败时，应直接切换确定性搜索

**事实**

- 本轮对已知环境变量名使用了描述性 `find`；该工具因判断服务返回区域限制而失败，明确提示这不是不存在的证据，应使用 grep。
- 随后的包源码搜索先在 `gitignore: true` 下未命中，关闭忽略后找到了公开安装包中的 proxy 与 bridge 实现。
- 对本地代理 URL，第一次 `read` 只提供 HTTP 400 摘要，随后又用程序读取状态与响应体。

**建议**

工具路由采用更短的分支规则：

- 已知字面量或符号：直接使用确定性搜索；
- 安装包位于 `node_modules`：显式确认忽略策略；
- 协议鉴别：一次采集状态、必要响应头和有界响应体，默认不携带认证；
- 语义查找服务不可用：立即退到文件名或字面量检索，不继续把空结果解释为缺失。

这属于工具使用路径优化，不需要新增 reviewer 编码标准。只有在宿主工具已有适合的选项时才调整默认路由，避免为本次少量探测再造工具。

- 保留证据复用纪律：没有为重述报告而重跑已完成检查，没有用局部诊断绿覆盖 canonical 失败。
- 本轮没有审阅仓库 CI、hook 或完整检查脚本，因此不能据此声称仓库缺少自动化 guardrail。
- 本轮未运行真实 roles 场景，不能判断现有 runner 的完整正确性或真实模型遵从职责的质量。

优先落实前两项：先让授权接入事实可发现，再让重试能识别前提是否变化。它们最直接减少无效重接手，同时不削弱本票真实模型验收的完成标准。
