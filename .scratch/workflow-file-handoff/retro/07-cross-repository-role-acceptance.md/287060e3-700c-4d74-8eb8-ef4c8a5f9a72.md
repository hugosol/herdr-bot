## 1. 高：将真实模型接入资格变成重派前置门禁

**事实**

- 本轮开头读取的上次报告已经指出：缺少明确授权的隔离模型配置，专用 roles 场景尚未完成。
- 本轮环境检查只发现 `PI_PROXY_OPENAI`、`PI_PROXY_OPENAI_CODEX` 两项相关代理声明，没有发现模型配置或凭据声明。
- 协调方随后指出另一条受支持能力：`xd://eval/judge` 暴露的 `completion()`。本轮实际调用成功，但其文档明确为 stateless、no tools/history，公开签名也没有原生工具或历史参数。
- 本轮最终仍因原生模型接入前提不足而终止，没有产生新的 S2 验收结果。

**推断**

工作流将“代理被中止”和“执行所需外部前提尚未满足”压成相近的重派信号，可能导致相同票据在前提没有变化时再次消耗实现槽位。文本模型可访问与原生角色模型可接入，也容易在交接中被误认为同一条件。

**建议**

在现有调度／接手流程中增加机器可读的**前提差量**：阻塞原因、所需公开配置、已检查能力、恢复触发条件。再次派发前先核对是否出现新的授权接入，而不是仅依据上次调用是否正常结束。

对本类票据，资格门禁应检查：

1. 存在明确授权的隔离模型配置及指定凭据环境；检查结果不输出秘密。
2. 接口能由目标原生宿主使用，并保留所要求的工具与历史语义。
3. 前提缺失时保留既有实现和证据，将结果归类为外部前提阻塞。

该建议应落在工作流的依赖解析／调度层，不必再向全局 `AGENTS.md` 增加一段常驻禁令。

**完成判据**：相同前提未变化时不再次启动实现；获得兼容且授权的接入后才恢复专用验收。单独的文本 completion 成功不能解除原生工具链门禁。

## 3. 中：减少跨 shell 引号造成的失败和输出噪声

**事实**

- 本轮通过 Bash 调用 PowerShell 枚举环境变量，命令中的 `$_` 等表达式经过外层解释后失效。
- 工具返回语法错误和大量重复的 `.Name` 无法识别错误；该输出不能证明环境中缺少模型配置。
- 随后改用 `eval` 的 Python 环境检查，成功取得经过凭据遮蔽的结果。

**建议**

将“只读环境能力检查”收敛到一个明确的执行边界：优先使用当前运行时直接读取环境，并统一遮蔽 key／token／secret 值；确需 PowerShell 时，通过结构化参数或单一 shell 执行，避免嵌套解释。

若该检查在多个票据反复出现，可由宿主提供只返回配置名称、是否设置及非敏感定位信息的窄接口。单次错误不值得为仓库新增产品脚本或编码规范。

**完成判据**：检查一次返回结构化结果；不泄露凭据、不产生跨 shell 展开错误，也不将失败输出解释为信息不存在。
