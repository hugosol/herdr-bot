# Ticket 07 TDD 执行复盘建议

## 范围与结论

本复盘仅依据本执行代理的对话及工具结果，包括其读取的上轮报告；不据此评价父 session 或其他票据。上轮报告是本轮读取的交接材料，不等同于已读取上轮完整执行历史。

本轮最终取得真实 Pi/Herdr 角色场景通过证据，以及 toolkit canonical `bun run test` 的 1790 passed、0 failed。最值得改进的不是再增加验收要求，而是明确**允许的模型传输边界、宿主调用生命周期及证据复用条件**，避免把可解决的接入问题反复当成外部阻塞。

以下按严重度排序；均为建议，本轮未执行这些环境改进。

## 1. 高：把真实模型验收的传输边界写进可达的权威说明

**事实**：本轮读取的上次报告将公开 `completion` 的 stateless、无内建 tools/history 视为不能接入原生 Pi 的理由。代理起初沿用该判断，向 Main 报告缺少原生 provider 配置。收到明确澄清后，代理实现测试专属薄传输，把完整真实历史和工具定义发送给真实模型，再将模型自主返回的动作映射成 Pi 响应；最终真实角色链路通过。

**推断**：先前判断额外加入了“模型后端必须直接支持原生工具 wire 格式”的要求。公开能力确实存在，但允许怎样使用它的契约边界不够明确，使交接报告中的判断成为后续执行的默认前提。

**建议**：在真实角色验收说明中集中定义一个“模型传输”分支：

- 真实模型负责决定文本、工具及参数；原生宿主负责执行工具、维护 Session 和历史。
- 测试拥有的传输可以序列化完整上下文并转换响应格式；必须保留输入、原始模型输出和映射证据。
- 固定工具序列、模拟工具结果与预置业务答案属于受控 provider，不能替代真实角色行为验收。
- 这种验收不自动证明模型原生 provider 协议兼容性。

从现有真实宿主测试说明指向这一分支即可，不宜把整段规则放进常驻 `AGENTS.md`。完成标准是：下一位代理能依据同一处说明判断接入是否合格，而不必等待额外解释。

## 2. 高：公开 completion 文档应声明活动调用的生命周期

**事实**：HTTP 工作线程直接调用公开 `completion` 时首先失败，错误为 `Missing session/run/name`；使用 `copy_context()` 后，同一活动 Eval 内的真实 HTTP 探针成功。随后代理把角色 runner 放入独立后台命令，模型回调失败，原始错误为 `No active Python tool bridge session`，角色场景在 300 秒观察窗口后失败。将完整子进程运行和回调放在同一个活动 Eval 内后，场景 exit 0，36 次真实角色模型请求无传输错误。

**建议**：在公开 completion 的工具文档中，将以下两点与线程使用示例放在一起：

1. 工作线程需要传播宿主调用上下文。
2. 调用上下文的复制不延长授权 bridge 的寿命；全部回调必须在其所属活动调用结束前完成。

同时提供一个从启动到关闭都处于活动调用内的最小示例。若 bridge 能在创建后台回调或服务时提前识别失效上下文，可给出明确的生命周期错误，减少等到业务场景超时才定位的成本。

**未验证**：本轮没有核实其他语言内核或其他公开模型接口是否具有相同生命周期，建议不应直接外推。

## 3. 中：为角色 runner 增加基础设施失败的快速诊断出口

**事实**：首次真实场景中，模型 observer 已记录多个 502，completion 原始证据保存了 bridge 失效错误；runner 仍等到“门禁拒绝后 collect 等待”的 300 秒阶段超时才返回。代理随后通过模型流量和 completion 原始记录定位问题。

**建议**：真实角色 runner 的阶段等待应能同时观察已记录的基础设施致命错误。在模型接入或传输明确失败时，停止等待尚不可能出现的业务条件，保留业务阶段、模型错误和清理错误后非零退出。该机制只缩短诊断路径，不重试模型选择、不改变验收预期。

可在现有 CLI/HTTP 验收 seam 增加一项回归：实际模型端点失败时，入口返回明确接入错误、保留原始证据，且不会耗完整个业务观察窗口。它不应被计作真实模型职责覆盖。

**未验证**：本轮没有检查全部错误类型的分类规则，也没有证明所有 502 都适合立即终止；应先区分真正的致命接入错误和已有 SDK 行为。

## 4. 中：交接证据应直接表达“哪些检查可复用”

**事实**：本轮保留了既有构建和检查，没有重跑未受影响的后端回归、workflow-chat 分区和 typecheck；新的真实角色场景及 canonical toolkit 回归实际执行。新 canonical 为 1790 passed、0 failed，旧记录则为 1785 passed、5 个 ready-frame 超时。最终报告明确保留旧失败，并未声称其根因已经修复。

**建议**：让交接证据按命令记录源码范围、依赖和环境指纹，以及需要重跑的触发条件。后续代理便可直接判断：

- 后端源码和构建依赖未变：复用已通过的后端结果。
- 新增测试传输：执行其回归和真实角色场景。
- canonical 存在未解决的不稳定结果：在协调后的窗口重新取得结果，保留新旧记录和环境差异。

这应是运行证据的结构，而非新增一份常驻状态文档。

**推断**：本轮安静窗口 canonical 全绿，说明运行协调值得记录；但没有证据证明并发负载就是旧超时的根因，不能以“已解决资源争抢”归档。

## 5. 中：已知搜索能力不可用时，自动采用可用的定位路径

**事实**：两次 `find` 都报告所有 judge 请求因区域 451 失败，分别发出了 26 和 29 个请求，且明确提示不能据此判断不存在。第一次调用还显示在 `.` 范围列举，而非预期 worktree。之后使用 `glob`、字面搜索和定向读取仍完成了定位。

**建议**：搜索工具遇到明确的能力不可用错误时，在当前执行内记住该状态，后续同类请求直接降级到文件名/结构搜索或确定性字面搜索，并清楚显示实际搜索根。若工具没有这一机制，可在工具使用说明中提供一条简短的失败分支指引。

完成标准是：同一轮执行不再为已知不可用的 judge 后端重复整批请求，同时仍区分“未搜到”与“未能搜索”。这属于工具可靠性和成本问题，不宜扩大为代码审查规则。

## 6. 低：嵌套 shell 的环境检查应有稳定入口

**事实**：代理通过 Bash 调 PowerShell，以含 `$_` 的双引号命令筛选环境变量名；实际命令中的变量被外层展开，产生大量 `.Name` 无法识别错误。改用 Eval 枚举环境变量名后成功，未输出凭据值。

**建议**：对环境变量名、版本和短结构化系统事实，优先提供无需嵌套 shell 插值的查询示例；必须跨 shell 时，示例应明确各层引用规则。这个改进适合工具参考文档，不需要加入项目 `AGENTS.md`。

## TDD 执行中值得保留的做法

- **公共 seam 明确**：新传输回归通过 HTTP 入口观察完整请求、工具参数和落盘证据；受控 completion 仅用于传输契约，没有被冒充为模型角色验收。
- **补足行为性 red**：初始 red 是模块不存在，单独不足以证明断言能抓住行为错误。代理随后注入“向模型遗漏工具定义”的缺陷，观察完整请求断言失败，恢复后再次通过。
- **真实行为与组件证据分开**：OMP/Pi 严格参数 dock、Pi 真实模型角色链路及普通回归分别报告，没有从一个宿主或最终 completed 状态外推出全部承诺通过。
- **保留失败而非改写历史**：活动 bridge 生命周期失败、旧 canonical 超时以及成功场景日志中的 peer-close `ConnectionResetError` 均被保留；成功场景清理结果单独记录为 `cleanupErrors=[]`。
