# Ticket 05 TDD 执行复盘建议

## 范围与结论

本复盘仅依据指定 ticket 的执行 JSONL，截止实现轮首次 `yield`；未读取父 session 或其他执行记录。同伴消息只作为“本票收到的协作信息”，不作为对方验证结果的独立证明。本轮未修改文件，也未重跑验收。

本次有可信的行为 red → green：公开历史缺失、connect 名称覆盖 zone 名称，以及把预算临时改为 60 秒后晚到身份错误入历史。编译、夹具和请求形状错误没有被当作这些行为的 red。最终记录分别报告了 68 项相关后端回归、扩展后的 Pi HTTP 8 项、浏览器 26 项，以及最后诊断修复后的单项浏览器检查；真实 Pi／Herdr 证据与受控模型响应、待用户确认的 H1 也作了区分。

改进重点不是再强调“遵守 TDD”，而是减少环境与夹具造成的假 red、进程生命周期冲突和手工取证成本。以下优先级针对后续执行风险，不表示已交付功能仍有对应缺陷。

## 1. 高优先级：把 Windows 验证生命周期收敛到一个执行入口

**事实**

- 16:59:33，真实隔离 backend 直接运行 `target/debug/herdr-bot.exe` 时，mutation 检查构建失败：Cargo 无法删除正在运行的 EXE，返回 Windows 拒绝访问。
- 17:11:55，在浏览器验证仍运行时再次执行 Cargo，重复遇到同类 EXE 锁定。
- 扩展浏览器回归另有两例在删除临时目录时报 `EPERM`。本票随后用尚未完成的 `agent_get` gate 稳定复现：只终止 backend 父进程，查询子进程仍持有复制的 EXE。进程树清理修复后，包含该回归的 26 个浏览器场景通过。

**建议**

由仓库的验证入口统一安排：依赖准备 → 构建 → 后端测试 → 启动隔离运行产物 → 浏览器／外部检查 → 进程树回收。运行产物使用临时副本，避免长期运行进程占用 Cargo 输出路径。复用本票已修复的测试进程树清理，不再新增一条“注意不要并发构建”的常驻提示。

**完成标准**

同一入口能连续执行两轮；结束时没有其启动的 backend／Herdr 查询遗留，临时目录可删除。构建失败与行为断言失败分别报告。

## 2. 高优先级：补齐浏览器测试的静态检查与自动执行护栏

**事实**

- 当前 `frontend/package.json` 已有 `build`、Vitest 与 Playwright 命令；`build` 包含 `tsc --noEmit`，不能把类型检查描述为完全不存在。
- 但 `frontend/tsconfig.json` 的 `include` 不包含 `browser-tests` 或 `playwright.config.ts`。本票修改的浏览器支撑设施不在这条类型检查路径内。
- 本次出现了字面量动态导入，以及 Promise 构造器写法，由宿主风格提醒触发后才调整。
- 在所检查的常见仓库路径中未发现 CI、pre-commit 或 ESLint／Biome 配置。用户全局 hooks 和仓库外 CI 未核实，不能据此断言完全没有自动护栏。

**建议**

为浏览器测试增加独立的 Node／Playwright 类型检查配置，选择与实际运行环境匹配的库定义；将现有构建、测试命令接入 Windows 自动检查。静态导入等机械要求交给确定性的 lint 规则，而不是增加 `CODING_STANDARDS.md` 或全局提示。Rust 编译器已准确捕获本次变量遮蔽导致的 E0618，无需为同一错误再写一条自然语言规则。

**完成标准**

引入一个浏览器测试类型错误或被禁止的字面量动态导入时，自动检查在运行 Chrome 前失败；合法的运行时模块选择仍可表达。

## 3. 中优先级：给 HTTP／SSE 测试提供一个短导航入口，减少协议猜测

**事实**

本次多次先遇到场景或预期写错，而非目标行为缺陷：

- 读取不存在的 `/api/sessions`，得到 `404 unknown-endpoint`，随后改用现有 SSE 接缝。
- 将 keepAlive 的可观察字段写成 `keepAlive`，实际权威视图字段是 `online`。
- 比较完整快照时把自然变化的 `serverTime` 也要求相等。
- 重启用例重复登记同一 zone，得到 `already-registered`。
- 倒计时命令发送了不允许的 JSON 请求体，之后又把既有 `counting-down` 阶段写成 `countdown`。

**建议**

在现有测试支撑设施旁集中提供“HTTP／SSE 验收”导航：指向 `backend/tests/common/mod.rs`、`common/sse.rs` 和一个最小现有用例。需要区分部署、重新启动与准备业务数据的 helper，避免重启顺带重放登记。

导航只说明去哪里取事实，以及哪些字段是动态观察值；路由、枚举值、必填字段仍由生产类型和现有测试维护，不另抄一份协议表。优先复用已有 `post_over_tcp`、SSE 客户端和配置装配，而不是再造一套测试协议。

**完成标准**

新场景可直接建立公开快照、发送无请求体命令及重启隔离实例；首次执行能到达目标行为断言，而不是先修正接口地址和字段名称。

## 4. 中优先级：将真实 Pi／Herdr 取证编排变成可重复执行的隔离分支

**事实**

真实链路最终成功取得官方精确引用、原生 header，并与独立历史读取比对。但编排主要由本次 Eval 状态承载，中途手工构造的 catalog 先后因缺少 `skills`、模型缺少 agent 适用关系而被拒绝。

真实 `/settings` 探针还揭示了重要边界：Pi 已报告精确路径，但没有形成消息时原生文件尚未落盘。本票没有从文件名猜 ID，而是另用仅监听 loopback 的固定响应模型取得成功证据，并明确这不是用户真实模型任务。

**建议**

优先扩展已有 `scripts/test-native-session-storage.py` 的隔离取证能力，为“经 Herdr 和公开创建 HTTP 完成收录”增加按需分支，复用其受控模型。该分支负责命名测试 session、环境隔离、有效最小 catalog、产物副本、精确引用与 header 比对及清理；外部前提不满足时明确报告。

把“无消息可能无 header”留在现有原生历史说明这一处，脚本输出引用该边界，不在多个代理入口重复解释。

**完成标准**

新 worktree 可用一次明确调用复现原始证据链，不依赖之前的 Python kernel；输出分别标识真实外部部分、受控模型部分及未确认的 H1。

## 5. 中低优先级：给不可用搜索服务增加会话级熔断，并暴露当前 worktree 的图索引身份

**事实**

- 16:43:52，`find` 的 25 个判断请求全部因区域限制返回 451；代理已报告该故障并改用其他工具。
- 17:08:59，再次调用 `find`，又产生 25 个相同失败。
- 当前 worktree 起初没有对应图索引；代理列出项目、创建索引后，成功通过符号查询和声明大纲导航。

**建议**

工具层对明确的服务不可用错误设置会话级熔断，直到配置或服务状态变化再恢复；直接提供可用的图查询／字面搜索回退。宿主在 worktree 建立或首次索引时返回精确 project ID，让代理直接复用，而不是反复列项目确认根目录。

这更适合作为工具状态能力，不适合再往 `AGENTS.md` 添加一段故障处理说明。

**完成标准**

同一运行中一次明确的 451 足以切换后续导航；回退结果不会被表述为“代码不存在”。

## 6. 低优先级：把验证结果保存在一份可追溯记录中，文档只保留解释与入口

**事实**

本次先后新增场景、修正诊断并重复验证，票据评论、验收文档及最终交接中需要多次手动更新测试数量。最终报告已经区分“此前 68 项回归”和“最后 Pi 8 项／定向浏览器检查”，未声称所有结果来自同一次最终全量运行；这一点应保留。

**建议**

让验证入口或宿主产生一份包含源码版本、实际命令、结果和原始产物位置的运行记录。票据链接它；验收文档集中解释覆盖边界、真实外部证据与 H1，不重复维护多份通过数量。复用已留存的 JSON、诊断文本和截图，不再建立第二套状态台账。

**完成标准**

后续添加一个场景或修改源码时，读者可以判断哪些结果仍对应当前版本、哪些只是较早运行证据；无需靠人工同步多处数字。

## 应保留的执行方式

- 保留“行为 red 与环境失败分开”的证据纪律，尤其是 mutation 必须实际击中晚到身份收录，而不是以构建失败代替。
- 保留公开 HTTP／SSE 与真实浏览器接缝；受控 adapter 负责时序，真实 Pi／Herdr 负责外部身份事实。
- 保留发现清理故障后建立紧凑复现、修复实际进程生命周期的做法，而不是增加删除重试或忽略错误。
- 根 `AGENTS.md` 当前已较精简。本次没有足够证据支持扩充全局行为规则；优先投入可执行护栏、可复用夹具和短导航指针。

本复盘未执行以上建议；仓库外自动检查、全局 hooks 及用户实际部署 H1 均保持未验证。
