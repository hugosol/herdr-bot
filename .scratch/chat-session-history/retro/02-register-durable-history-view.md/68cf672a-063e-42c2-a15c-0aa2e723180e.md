# TDD 执行复盘建议

## 范围与结论

本复盘只依据指定 ticket 的实现子会话原始 JSONL、其中的工具结果，以及本轮只读取得的仓库检查入口；未读取父会话或其他票据，未重跑验收。

本次有可确认的有效 red→green：历史读取最初返回 404；空白更新最初覆盖已知名称；浏览器在夹具修复后因缺少切换按钮失败。最终工具结果记录了新增 HTTP 测试 4 passed、浏览器测试 3 passed、前端 205 passed，以及成功构建；交接记录报告相关后端回归为 9 suites／74 passed。浏览器验收使用真实交付后端，并实际查看了桌面和手机尺寸截图。

主要改进机会不在于增加更多常驻指令，而在于让验收证据更有区分力，并把已经存在的检查接入稳定入口。以下按严重度排序。所有条目均为建议，本轮未执行修改。

## 1. 高：验收完成门槛应按子承诺判定，防止测试通过被扩大解释

**事实**：新增的 `explicit_register_survives_restart_without_restoring_current_or_shutdown_intent` 先建立非空监听集合，随后调用 `/api/shutdown/start`，最后重建后端并断言监听为空。原会话读取的既有行为说明明确指出：开始倒计时会消耗监听集合。因此，重启前监听已经不再是非空条件。

同一测试将 `old-native.jsonl` 和附属文件放在普通临时目录，检查历史初始为空、明确 register 后收录，以及文件字节未变。记录没有展示该目录是原生会话发现入口，也没有展示原生文件读取行为的观察。最终却将“不扫描／批量导入”和“不读取正文”等相关验收整体标为完成。

**推断**：新增重启测试本身不能排除“恢复了重启前仍存在的监听”这一错误，因为它没有在该状态下重启。普通临时文件也不能区分“不扫描原生目录”和“扫描了其他原生目录但没碰到此文件”；字节不变只能证明未改写，不能证明未读取。这些是证据区分力问题，不是已经观察到的生产故障。

**建议落点**：复用 TDD 已有的反例检查，在独立审阅的验收输入中落实，而不是再向全局指令重复同一规则：

- 将“非空监听集合下重启”与“存在倒计时下重启”拆成两个场景，分别通过公开快照确认重启前的受测状态真实存在。
- 对不导入旧会话，使用位于隔离、实际可发现位置的有效原生样例；保持从公开 HTTP 观察历史的 seam。
- 将“未改写”“未展示”“未读取”分别登记证据。若批准 seam 无法观察某一项，明确列为实现检查证据或待补证据，避免以另一个性质的断言代替。
- 审阅时逐个确认：包含对应错误的实现是否仍可能通过；需要时再做针对性故障注入。

**完成判据**：每个验收子承诺都能对应一个可辨别的场景或明确说明的其他证据，而不是仅对应一个综合测试名称。

**未验证**：本轮没有逐条审阅全部复用回归测试，不能断言既有测试一定未补齐上述监听场景。

## 2. 高：把已有检查接入仓库级自动关卡，避免只依赖实施代理记得运行

**事实**：`frontend/package.json` 已提供 `build`（含 TypeScript 检查）、`test` 和 `test:browser`。本次实现轮确实主动运行了这些检查及相关 Rust 回归。本轮只读查找未发现 `.github/workflows/*`、`.githooks/*` 或 `.husky/*`。

**建议落点**：优先接线已有命令，不另造一套 lint／check 约定。建立适合本仓库 Windows 依赖的自动关卡，保证前后端构建先于依赖交付产物的浏览器验收；运行已有前端测试、相关 Rust 测试和浏览器测试。完整、较慢的生命周期测试可放入集成关卡，TDD 单切片继续使用定向测试。

关卡的执行方式保留一个权威入口，实施和审阅共享它；脚本名称及命令细节继续由构建配置维护，避免在多份代理文档中缓存副本。

**完成判据**：提交或集成路径能够自动暴露类型错误、回归失败、夹具启动失败和过期交付产物，而不取决于代理是否复述了正确命令。

**未验证**：未检查机器全局 Git hook 或仓库外 CI，故这里只能确认未发现仓库内的这些关卡入口，不能断言所有外部保护均不存在。

## 3. 中：为共享浏览器夹具增加小型契约检查，提前发现环境漂移

**事实**：首次浏览器运行尚未到达页面行为断言，就在 `support.ts` 中失败：`original.split('entrypoints\\')[1].replaceAll(...)` 得到 `undefined`。随后读取元数据发现，扩展入口并不都处于预设的 `entrypoints` 目录。实现轮修正了路径映射，之后才取得有效的页面 red。

实现轮还为浏览器后端补上隔离的 `cwd` 和历史文件路径，并为既有 Rust 测试分配独立历史文件，避免新增持久副作用落到共享默认位置。

**建议落点**：在现有测试体系中增加轻量的夹具契约检查，使用实际元数据及少量明确的路径形态样例，验证入口映射可完成、生成目标不冲突、引用均可用。让后端测试进程的工作目录和持久文件统一归属于夹具临时目录，并由夹具清理。

这是可机械检查的性质，适合放进测试／自动关卡，而不是新增一条“代理应注意路径”的编码标准。

**完成判据**：元数据入口结构或默认持久路径变化后，失败首先定位到夹具契约；修复后才进入产品行为的 red→green。保留本次已经完成的隔离修正，无需重做。

## 4. 中：让 worktree 的导航工具可用性在启动时成为已知事实

**事实**：首次 `find` 的 25 次判断请求全部因地区限制返回 451，未产生定位证据。随后图搜索以 `herdr-bot` 为 project 失败；改用当前 worktree 的绝对路径查询声明大纲仍失败，服务返回该项目未索引。最终依靠目录、字面搜索和范围读取完成定位。

**推断**：worktree 的索引身份与图优先导航要求没有在任务启动时接通；不可用的语义查找也缺少提前暴露的能力状态。问题是导航前提未知，不是源码本身不可访问。

**建议落点**：由 worktree／任务宿主提供准确的 MCP project 标识、索引根路径及就绪状态；未索引时明确提供后备路径。语义查找服务遇到地区限制等确定不可用错误后，在本次运行内降级到字面搜索，避免继续消耗同类请求。

这些信息应由工具或任务启动上下文产生，不应把某个临时 worktree 名称写死进 `AGENTS.md`，也不需要增加更多重复的“优先使用图工具”提醒。

**完成判据**：代理首次定位即可知道可用导航路径；未索引项目能直接采用明确后备方式，而不是猜 project 名称。

## 5. 低：缩短缺失控件的失败反馈，保留长流程的总时限

**事实**：有效的浏览器 red 因找不到“查看历史会话”按钮而等待了整条测试的 90 秒超时。配置虽然设置了 10 秒的 `expect` 超时，但实际操作直接调用 `locator.click()`，未受该断言超时限制。实现后的两个布局场景分别只用了数百毫秒。

**建议落点**：在 Playwright 现有配置中设置适当的 action timeout，或在关键交互前先进行限时可见断言；保留进程启动和真实重启所需的整体测试预算。动作失败应尽早指出缺失控件，环境启动失败则保留独立诊断。

**完成判据**：缺失按钮等确定性 UI red 在动作级期限内返回，而不消耗整个端到端测试时限。本条不意味着本次等待是产品性能回归。
