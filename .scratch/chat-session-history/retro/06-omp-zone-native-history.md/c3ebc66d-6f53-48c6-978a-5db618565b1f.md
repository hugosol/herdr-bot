**最终结果有实际证据支撑：**本轮最终运行的 OMP HTTP／时序测试 7 项、既有历史测试 4 项通过；Chrome 验收 6 项通过。首个收录 tracer 曾因成功创建后历史为空而失败；临时注入“遇到 OMP title 首行即终止”的错误后，同一 tracer 再次失败，恢复实现后通过。真实 Herdr／OMP 的隔离运行也取得了精确引用、header 和独立历史读回。用户实际部署 H1 则明确保持未验证。

主要改进空间不是增加更多“认真测试”的指令，而是让环境更可靠地区分 **行为红灯、夹具红灯、运行器故障和证据缺失**，并减少共享实现尚未就绪时展开多个测试切片的情况。

## 1. 高优先级：让验收产物成为运行器的交付契约

### 事实

浏览器测试最初通过 `test.info().attach(..., { body })` 收集后端警告，配置使用 `reporter: [['list']]`。套件已经通过后，代理检查 `test-results`，发现对应目录为空，没有可交付的警告文件。

随后才改为显式写入 `actual-backend-warning.txt` 并附加文件路径，再次运行故障场景，最后汇总为持久证据 JSON。最终警告原文确实被保存，不能将前一次“测试通过”理解为“证据文件已交付”。

### 建议

把以下能力集中在现有浏览器支撑设施中，而不是让每个票据自行拼接：

- 后端日志具有明确的持久输出路径。
- 要求交付的截图、警告、真实外部运行证据由运行器登记。
- 收尾时检查这些登记的产物实际存在且非空，再返回可引用路径。
- 测试报告中的附件与仓库交付证据使用同一份原始产物，避免手工复制成为第二条事实链。

这是适合确定性检查的文件交付要求，不需要增加一条泛泛的 reviewer 规则。

### 完成标准

在现有 `list` reporter 下完成一次带警告的验收，结束后仍能直接取得已登记的原文文件；声明了附件但文件缺失时，运行器明确报告证据交付失败。

**边界：**补采证据期间还暴露了真实的期限边界诊断问题，因此不能把这些重跑全部归为浪费；可以避免的是“通过以后才发现产物未保存”。

## 2. 高优先级：以交付二进制为单位管理构建与进程生命周期

### 事实

本轮在浏览器仍运行交付进程时启动 `cargo test --test session_history`，Cargo 尝试替换 `herdr-bot.exe`，因 Windows 文件锁失败。浏览器结束后，同一回归命令通过。

较早的浏览器失败还伴随清理目录的 `EPERM`。本轮随后在 `afterEach` 中先释放受控身份查询屏障，再停止服务。可见消息也说明，共享进程树清理修复已有独立交付；但该最终共享提交未导入本 worktree，不能据此宣称本轮已经验证了通用清理修复。

### 建议

在宿主或测试运行器落实两个资源约束：

1. **二进制租约：**同一路径的可执行文件被浏览器服务占用期间，构建或会替换该文件的 Cargo 命令等待其释放；独立路径的 worktree 不必全局串行。
2. **所属进程树清理：**服务启动时登记所属进程，停止后等待清理完成，再删除临时目录。对于已有共享修复，优先接入和验证，不再复制一份近似实现。

这比向 `AGENTS.md` 添加“Windows 下注意不要同时构建”的常驻禁令更可靠，也避免以文件系统重试掩盖遗留进程。

### 完成标准

受控查询仍在等待时结束浏览器测试，所属进程和临时目录均能正常清理；编译请求不会再因同一运行器持有 exe 而产生伪回归失败。

## 3. 中优先级：把已有 TDD 规则落实到当前 tracer 的执行状态

### 事实

本轮存在有效的行为 red 和 mutation 证据，最终没有仅凭编译成功交付。

但执行并非始终保持一个切片闭环：首个收录 tracer 尚未 green 时，已经继续加入并发和失败创建场景；后面也一次性增加了期限前成功、到期终止和保存失败等多个测试。共享实现等待与测试展开交织，增加了判断每次失败属于哪个承诺的成本。

另外，几次失败发生在目标断言之前或来自夹具假设：

- 读取不存在的 `/api/sessions`，得到 404，后来改用已有 SSE 快照接缝。
- 比较完整快照时，将正常变化的 `serverTime` 也当作不变量。
- `/历史|history|…/` 的否定断言命中了测试目录或模板名称。
- 使用不存在的 `tab-chat` 定位器，最终等到 90 秒测试超时。

这些不能与“能识别目标违规的行为 red”等量齐观。本轮后来修正了这些问题，但付出了额外执行成本。

### 建议

不再往 TDD skill 重复添加同义规则；它已经要求区分夹具失败与行为失败。建议宿主在当前 tracer 的执行记录中保留三个简短字段：

- 本切片的独立期望与具体违规。
- 最近一次失败是夹具／运行器失败，还是目标行为断言失败。
- 本切片的 green 证据，或“已有行为已满足”的具体证据。

当前 tracer 尚未闭环时，优先完成必要的共享依赖协调；等待期间可准备外部环境或证据，不继续铺开其他行为测试。对已有实现满足的承诺，直接验证，不制造 red。

公共测试接缝则优先复用已有 `common/sse.rs`、浏览器支撑和可访问导航，避免重新猜 URL、选择器及快照形状。

### 完成标准

复核一条测试演进记录时，可以明确指出它识别了什么违规；404、定位器超时和动态时钟差异被单独分类，不承担行为 red 的证明责任。

## 4. 中优先级：为真实外部验收提供可复用的隔离预检

### 事实

真实运行环境由本轮临时组织，先后遇到：

- 手写最小元数据缺少 `skills` 字段。
- 模型缺少 agent 适用关系。
- 全新 OMP 配置进入 onboarding，提交已确认但尚无可读取的原生 header。
- `/rename` 显示执行成功，也不保证全新对话已经产生主文件。

最终通过隔离配置和 loopback 合成模型完成了真实链路，未借用用户账号或用户模型任务。这部分工作是必要的外部验收，不应被受控 adapter 替代。

### 建议

复用现有已验证的配置工厂或元数据样例，提供一个隔离预检入口：验证 catalog、启动配置、显式命名 Herdr、原生 agent 的初始化状态，以及精确引用是否已经落盘。把本轮发现的 onboarding 和无模型命令不保证落盘的限制，收敛到已有原生验收文档的对应分支。

**保持两个完成条件分离：**产品的“创建成功”仍是可交互且提交获确认；真实验收的“证据完成”才要求精确 header 与历史读回匹配。不要为了让验收方便而把 header 等待重新塞进创建成功关键路径。

### 完成标准

无用户凭证的全新隔离目录可以复现有效外部验收；缺少前提时在提交 probe 前给出具体诊断；只得到内存引用而没有 header 时，明确记录期限内不可得，而非误报收录通过。

## 5. 中优先级：让工具路由根据可用性和覆盖范围降级

### 事实

本轮三次 `find` 调用分别报告全部 25、27、31 个 judge 请求失败，原因均为地区限制 451。每次之后实际都改用文字搜索继续工作。

索引项目列表中未见当前 worktree；代理使用另一项目索引查询多个文件大纲，得到空结果后才继续读取源码。空大纲没有提供有效导航信息。

另外，宿主虽是 Windows，实际 shell 并不接受直接执行的 PowerShell `Get-Command ... | Select-Object ...`；该调用失败后才改用可执行的定位方式。

### 建议

把这些选择交给会话级能力状态，而不是继续增加源码探索步骤：

- 同一工具依赖明确返回地区不可用后，本轮后续查询直接走已有 fallback，不反复触发相同失败链。
- Graph-first 先匹配 worktree 根路径并确认覆盖；没有适用覆盖时，允许直接使用文件和符号搜索。
- 宿主明确暴露实际 shell 类型，供命令选择使用。

### 完成标准

不可用依赖在同一轮只识别一次；大纲查询用于提供信息，而不是仅为满足形式要求；执行 Windows 命令时无需通过失败猜测 shell。

**推断边界：**当前证据能确认索引查询没有帮助，不能证明索引服务本身有缺陷；本轮没有检查其精确覆盖状态。

## 6. 中优先级：补齐浏览器测试的机械检查入口，避免扩张常驻规范

本次文件定位未发现版本化的常见 CI workflow、项目 hooks、ESLint／Biome 配置，也没有 `lint` script。**未检查全局 Git hooks 或外部 CI**，所以不能把它写成“整个项目完全没有自动护栏”。

### 建议

- 让浏览器测试及其运行器配置进入明确的 TypeScript 检查范围，复用现有类型检查体系。
- 先确认是否已有外部守门任务；若没有，将现有 build／test 命令接入版本化 CI 或提交守门，而不是再写一份人工检查清单。

类型检查不能识别错误的 `tab-chat` 字符串、错误 URL 或过宽文本断言，这些仍需要真实接缝测试，不能宣称新增 `tsc` 会解决全部夹具错误。
