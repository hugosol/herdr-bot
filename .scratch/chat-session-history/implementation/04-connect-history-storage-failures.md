# 04: 存储故障可见且不破坏 connect-bot 接入

**What to build:** 历史保存失败不撤销已接受的 connect-bot 接入或停止原有上报，实际操作者明确得知接入成功但历史保存失败。读取失败不伪装为空列表；故障解除后，再次明确成功 register 可恢复保存且不损坏旧数据或首次收录时间。

**Delivers:** P11、P18、P20、P21；P19、P22 的 connect-bot 分区，P26 的 connect 故障／恢复分区。

**Test owner for:** P19 的 connect 操作者警告；P22 的 connect 无新增自动重试／接入／失败预算；P26 的 connect 历史存储故障及恢复。

**Blocked by:** 02: 成功 register 形成可持久读取的历史视图。

**Status:** in-progress

- [x] 对隔离真实存储分别制造不可读、无效内容及写入失败，通过交付运行的公开请求观察明确错误，不伪装为空集合或已保存。
- [x] 读取失败不以空数据覆盖旧持久内容；更新失败不损坏此前记录。解除故障后独立读回此前精确字段，不能仅检查内存缓存。
- [x] 实际浏览器显示历史读取失败而非“没有历史”；失败也不得继续冒充新的成功读取结果。
- [x] 运行实际 connect 命令，证明已接受接入仍保持当前登记、armed 状态及后续上报，实际操作者 UI／stderr 明确区分接入成功和历史保存失败。只返回 caller 忽略的 HTTP 字段或只通知模型上下文不算通过。
- [x] 保持已有接入失败预算、心跳及重试策略；历史失败不 disarm、不自动重新 connect、不引入后台写入重试。失败后不再发起事件，观察没有自主重复写入；不能只测宽松耗时阈值。
- [x] 恢复存储可写后再次明确成功 register：此前未保存的记录新建，已保存记录更新；独立读回唯一完整记录，不产生重复。
- [x] P11：用独立预定服务端时刻验证失败尝试不建立首次时间，首次成功持久化才建立该时间；重复 register、元数据更新及跨重启读回均不改写它。不以当前登记注册顺序作为历史时间。
- [x] P20：另覆盖旧记录更新失败后的重新 register，确认原首次时间保留，后续有效字段更新且不被失败值覆盖。
- [x] P26 本票覆盖 connect 历史故障与恢复：当前登记、keepAlive、后续上报、完成后关机监听及倒计时保持既有语义；使用隔离安全替代执行，绝不真实关机。
- [x] 更新受影响的真实 connect-bot caller、反馈处理与必要说明，保持原有接入语义；警告文案不冻结，操作者必须实际可见。

## 验证边界

依据已批准 contract 的 S1、S2、S3。故障注入确定性、隔离且完整套件安全；不能修改用户真实历史或依赖私有存储函数作为唯一证明。P19／P22 的 zone 覆盖分别归 05、06；P26 的双来源组合故障归 07。
