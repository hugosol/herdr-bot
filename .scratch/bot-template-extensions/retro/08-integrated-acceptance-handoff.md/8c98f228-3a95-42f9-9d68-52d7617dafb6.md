# Ticket 08 执行复盘建议

## 范围与结论

本次仅依据指定 ticket 执行会话的 JSONL 历史及其工具结果复盘，未读取父 session 或其他票据执行历史，未继续实现、重跑验收或修改文件。

本票主要承担最终集成核验与人工验收准备。复用既有 P22/P49 覆盖、核验已经实现的行为，而非人为制造 red，符合 TDD 对“行为已满足”的分支。原执行也正确区分了公开创建成功、原生调用正确、真实扩展加载和实际手机判断：Pi 信任提示没有被代为批准，最终状态保持 `ready-for-human`，没有把 P23/P50 写成整体通过。

以下建议按风险与影响排序，重点是改善后续执行环境，而不是为本次补写通过结论。

## 1. 高：真实外部验收需要先验证一条安全的初始化输入，再扩大到组合矩阵

**事实**

- 初版 `h1-cases.json` 把 `/help` 设为初始化输入。
- 首次真实创建使用了该输入；随后四个 OMP 组合又在一个循环中提交 `/help`。循环只等待公开创建进入终态，原生屏幕观察是在四组提交后统一收集的。
- 实际屏幕出现普通模型回复，而不是原生帮助界面。执行者随后明确披露这一点，并把后续材料改为 OMP `/extensions`、Pi `/settings`。
- `/extensions` 后来确实打开了安装版 OMP 的 Extension Control Center。

**风险判断**

这不是“把模型请求加入依赖检查”的事实；这些请求发生在创建后的初始化阶段。问题是，一个未经安装版验证的命令语义被批量放大，产生了本可避免的模型轮次和额外外部行为。是否实际收费、收费多少，历史没有账单证据，不能下结论。

**环境建议**

在真实 agent 验收入口采用一条明确的 **tracer bullet**：先启动一个实例，读取真实屏幕，确认输入确实进入目标原生界面，再复用到其余组合。完成条件应同时包含“提交已确认”和“实际观察到预期的界面/行为”，而不只检查 HTTP stage。

已验证的原生命令应记录适用的安装版本与证据位置；版本变化时重新验证。把这个分支放在 H1 执行材料中，不需要扩展全局 AGENTS，也不应为此发起模型权限或余额探测。

**建议验收标准**：首个实例若出现普通模型回复、未知命令或批准对话框，矩阵尚未开始；只有语义验证完成才扩大运行。

## 2. 中高：把跨 worktree 的活资源交接从文字提醒升级为宿主可执行的保留契约

**事实**

- 最终 HTTP 验收服务被停止，18787 已释放。
- 多个真实 OMP 实例和停在信任提示的 Pi 正对照仍留在 Herdr 中。
- 这些实例的 session-dir/cwd 引用了本票临时 worktree 下、未进入版本库的 `.data`。
- 交接材料及最终结果明确提示：回收 worktree 前应保留数据，或在最终交付目录重建并记录新标识。

**风险判断**

文字提醒是有价值的，但独立集成流程是否会读取并遵守该提醒，没有本票证据。若宿主按常规在合入后回收 worktree，活实例可能失去其运行目录，人工验收材料也可能失去可直接观察的对象。历史没有证明这种丢失已经发生。

**环境建议**

让宿主的 worktree 回收入口识别本次创建且仍存活的外部资源：至少关联实际 Tab/Pane、运行目录、保留原因和接管方。回收前完成“明确接管并保留”或“归档后重建”其中一条路径；未完成时保留 worktree，而不是仅凭 agent 已结束判断可删除。

这是生命周期机制，适合放在宿主交接/清理工具中。可以用固定的活进程 argv/cwd 引用检查作确定性 guardrail，不应仅增加一条“记得保留资源”的代理指令。

**建议验收标准**：存在本次活资源引用时，自动回收能阻止误删并给出具体引用；已接管或已结束资源时正常放行。归档历史 ID 与当前可操作 ID应明确区分。

## 3. 中：真实环境就绪检查要同时观察 Herdr 状态与原生屏幕

**事实**

Pi 正对照的 `herdr agent start` 返回成功，并报告 `idle`、`interactive_ready: true`；随后真实屏幕仍显示 `Trust project folder?`。执行者通过读屏发现差异，没有批准信任，也没有继续向该对话框提交模板输入。

**推断**

对这一实际环境，仅靠 Herdr 的结构化 readiness 不能判断“已经处于普通输入界面”。本次正确的人工边界依赖后续读屏，而不是启动返回值本身。不能据此泛化为所有 Pi 版本或所有 Herdr readiness 都存在相同问题。

**环境建议**

把 H1 前置条件写成双通道 gate：取得结构化状态后，仍读取一次原生屏幕；看到信任/批准界面时保存实际位置与原文，转交用户处理，其他自动工作继续执行。该要求与“信任仅由用户决定”的规则应放在同一节。

在未来更新 Herdr 适配器时，可把本次真实屏幕作为一个待评估的 readiness 识别案例；本票本身不宜为了通过验收而增加产品特判。

**建议验收标准**：遇到本类提示时，自动流程不会继续投递业务输入，交接明确列出哪个前提阻塞了哪些组，而不是把所有工作统一暂停或统一宣称就绪。

## 4. 中：搜索工具需要能力降级与当前 worktree 的索引身份解析

**事实**

- 首次 `find` 因区域限制返回 451，内部 26 个 judge 请求全部失败，没有判断任何候选。工具正确声明这不是“代码不存在”的证据，执行者随后改用其他搜索。
- MCP 项目列表没有列出本次 `hyper-ticket-qgJDMn` 根目录。执行过程中使用了其他 worktree 的索引项目；其中 `backend/tests/runtime_data.rs` 的 outline 返回 0，但本地随后读到了真实文件。
- 多次关于扩展可观察界面的宽泛图搜索返回大量低相关候选；最终通过已知符号 `showExtensionsDashboard` 的文本搜索定位到 slash 路由。

**环境建议**

1. 搜索服务对区域不可用这类确定性错误做调用内短路，避免对同一不可用后端继续扇出全部候选请求。
2. MCP 提供按当前 cwd 解析项目的入口，并同时返回索引根目录、版本/新鲜度及路径覆盖情况；当前 worktree 未覆盖时，明确转向本地读取，而不是让 agent 自行挑选相近 worktree。
3. 已知符号或字面量直接走精确搜索；行为未知才用语义搜索。空结果附带覆盖信息，使“没有覆盖”与“确实没有声明”可以区分。

这主要是工具路由与返回结构的问题，不适合用更多总是加载的搜索口号解决。本次执行没有反复重试同一个失败的 `find`，这一降级行为应保留。

**建议验收标准**：模拟 451 时一次失败即可给出可用降级路径；当前 worktree 未索引时，返回明确的覆盖缺口，而不把另一个根目录的空 outline 当成本地不存在。

## 5. 中低：用宿主级参数保真测试解决 PowerShell 的双层展开

**事实**

一次 `powershell -Command "…"` 前置环境检查中，原命令的 `$_.IPAddress` 和 `$_` 在实际错误输出里变成了 `server.IPAddress`、`server`，导致网卡和路径检查失败。执行者随后改用 Node 成功取得前提信息；后续另一条 PowerShell 调用使用外层单引号。

**推断**

现象符合外层 shell 先展开 PowerShell 变量的双层 quoting 问题；仅凭本次日志不能归因到 PowerShell 本身。

**环境建议**

优先让宿主支持明确的 shell 选择及独立参数传递，减少“把整段 PowerShell 再包进另一个 shell 字符串”的需求。给这个调用边界加入确定性回归检查，覆盖 `$_`、`$env:…`、空格路径、引号和 `&` 的字面保真。

这是机械问题，应由宿主测试或参数接口兜底，而不是写入 `CODING_STANDARDS.md`，也不应另造一套前端 lint。历史中已读取的 `frontend/package.json` 具备 Vitest、Playwright 和含 `tsc --noEmit` 的 build；这些现有检查不覆盖宿主命令传递。此次没有审计 CI 或 hooks，因此不能断言仓库完全没有自动 guardrail。

## 6. 低：验收文档按“当前操作—分支—证据”分层，保留独立预期而减少事实缓存

**事实**

新增交接文档一次写入约 21 KB，包含已执行集成结果、完整检查表、H1 参数与信任阻塞、H2 设备步骤、故障复现命令和资源保留说明。票据 Comments、交接文档与最终结果也多次陈述了同一批验证摘要和未验证边界。重要的临时 worktree 活资源提醒位于交接文档末尾。

**建议**

让交接入口先回答三个操作问题：现在能做什么、需要用户决定什么、哪些活资源必须保留。随后按真实分支进入 H1 或 H2，原始运行记录与历史检查结果作为按需证据引用。信任规则紧邻 H1 的启动步骤，资源保留条件放在交接入口，而不是要求读到全文末尾才发现。

保持一个权威的验证摘要位置，其他入口用清晰指针引用。这里应保留 `h1-cases.json` 的独立字面预期：它是批准的独立判据，不是可以从生产元数据重新生成的冗余缓存；可削减的是对历史参数、结果和边界的多处散文复述。

是否拆成独立 H1/H2 文件，应由真实使用路径决定，而不是按字数机械拆分。此类层级与共置判断适合文档 review，不宜再给实现 agent 增加一组全局禁令。

- 保留已有覆盖的复用，不为“看起来像 TDD”重写六组合或两视口测试，也不为已满足的行为制造失败。
