# 05: 让旧页面和失效模板可辨认、可拒绝、可修正

**What to build:** 元数据变化后，旧页面提交不能沿用旧选项；已保存的失效选择仍可识别并通过编辑修正，不静默丢弃或默认化。失效仅影响相关模板，运行中元数据错误明确失败，修复文件后后续操作无需重启即可恢复。

**Delivers:** P27、P28、P29、P30、P32

**Blocked by:** 04 — 按模板扩展集合检查依赖并创建 Bot。

**Status:** ready-for-agent

## Acceptance criteria

- [ ] 页面打开后移除或改变适用选项，再提交旧页面保存及创建，均按当前元数据拒绝；直接公开请求同样不能依旧选项通过。
- [ ] 分别移除已保存模型、适用 thinking 级别或扩展元数据后，打开模板仍能辨认原选择并明确不可用，不静默删除、替换、重置为默认或隐藏失效信息。
- [ ] 未知已保存模型标识不导致整个持久文件解析失败；同一文件中的失效模板仍可辨认，其他有效模板仍可读取、编辑并创建。
- [ ] 用户能显式移除失效扩展并修正模型/thinking 等选择，修正后保存成功且独立公开读回准确；仅查看或步骤导航不构成修正或保存。
- [ ] 修正前，页面禁用或拒绝保存和创建并说明原因，直接公开请求也拒绝；复用 04 的无外部副作用观察，确认没有 Tab、agent 或输入提交，不重复认领其通用故障测试。
- [ ] 在同一真实程序实例运行中损坏或移走元数据，相关读取、保存和创建明确失败，页面显示配置位置与原因；不显示保存成功，也不使用旧缓存继续操作。
- [ ] 写回另一份有效元数据后不重启，后续读取、保存和创建恢复，并使用独立预写的新选项及映射，而非故障前缓存。
- [ ] 记录完整真实浏览器修正操作和公开请求结果，更新失效选择及配置修复说明；不新增元数据编辑界面、后台推送或自动修正。

## Verification and scope

依据：[批准契约](../contract.md)、[规格](../spec.md)。本票完整拥有 P27–P30/P32 的自动检查。使用真实持久文件、运行中外部修改、实际页面和直接公开请求，不以私有解析器或全局 mock 证明局部失效。

04 拥有 P35 的各类前置故障无副作用测试；本票的 P29 场景可复用其独立外部观察机制，但拥有失效选择修正前后的消费者行为测试。所有预期来自预写有效/失效样例，不能用当前实现生成期望。
