# 06: 固定每次创建快照并隔离已有 Bot

**What to build:** 每次已接受的 Bot 创建固定使用同一版本模板和完整映射，并发创建独立推进；后续编辑、删除模板或修改元数据只影响后续创建，不混用正在进行的配置，也不改配、关闭或重建已有 Bot。

**Delivers:** P36、P37

**Blocked by:** 04 — 按模板扩展集合检查依赖并创建 Bot。

**Status:** ready-for-agent

## Acceptance criteria

- [ ] 用已有受控 Herdr 能力阻塞一条已接受创建，期间编辑模板及元数据并发起另一条创建；第二条无需等待第一条解除阻塞即可独立推进，不引入全局串行创建队列。
- [ ] 分别观察两条创建的独立进度和外部记录：旧创建准确使用预写旧模板、完整 provider/model、thinking、固定扩展、可选扩展及初始输入，新创建准确使用预写新配置；不得混合任一新旧映射。
- [ ] 被接受创建的后续推进不重新读取模板或元数据而改变本次已接受配置；解除阻塞后仍按原快照完成既有就绪与提交语义。
- [ ] 创建 Bot 后修改模板、删除模板并修改元数据，独立外部调用和对象观察均无新增改配、关闭或重建；不以页面列表不变代替外部结果。
- [ ] 修改后从仍有效的模板创建使用新配置；删除的模板不能作为新创建来源，但删除不改变已有 Bot。
- [ ] 保持既有失败保留现场及输入不自动重发语义，不新增临时创建状态的持久化、恢复或自动重试。记录并发复现场景及实际观察。

## Verification and scope

依据：[批准契约](../contract.md)、[规格](../spec.md)。本票拥有 P36/P37 的全部约定自动检查；通过公开创建、公开模板编辑及真实元数据修改驱动，使用独立外部调用/对象证据和预写新旧字面配置，不仅断言模板名或私有快照对象。

不依赖 05：并发和已有 Bot 隔离使用有效配置即可观察。此处不重新认领 04 的六组合或 03 的模板生命周期测试。
