# 08: 完成最终集成验证并准备 H1/H2 验收

**What to build:** 在全部自动实现和约定检查完成后，用最终交付配置验证运行数据、动态元数据、模板编辑及 Bot 创建能协同工作；准备真实 Herdr→OMP/Pi 扩展加载 H1 和实际手机交互 H2 的可执行材料，明确已经证明、尚待人工确认及真实阻塞的边界。

**Delivers:** P23、P50（完成自动部分并组织 H1/H2；人工部分只有用户确认后才完成）

**Blocked by:** 01 — 集中运行数据并完成一次性切换；06 — 固定每次创建快照并隔离已有 Bot；07 — 完成桌面与移动视口的真实操作验收。

**Status:** ready-for-agent

## Acceptance criteria

- [ ] 先完成所有前票实现与分配的自动检查；人工验收尚未进行不能暂停其他可执行工作。使用合并后的最终交付配置真实启动，在同一服务中完成模板保存、真实进程重启读回、当前元数据读取及公开创建，观察正确磁盘位置与外部启动结果。
- [ ] 复用 04 拥有的 P22 六组合独立调用证据，不把复制、整理材料当作重写同一测试；复用 07 拥有的 P49 桌面和移动视口证据，不另认领相同自动测试。
- [ ] 为 H1 准备 OMP 零项、仅 codebase-tools、仅 connect-bot、两项，以及 Pi 零项、codebase-tools 六组模板与独立预写预期集合；每组均包含对应 model-cost，列明实际启动参数及已执行/待执行状态。
- [ ] 在真实环境可执行的范围内准备或定位各组 Herdr Tab/Pane、可观察加载结果、ambient 额外扩展对照情景及复现步骤；只记录实际得到的标识和结果，不虚构位置或用受控 adapter 冒充真实 Herdr。
- [ ] H1 材料让用户能确认真实 OMP/Pi 加载集合恰为模板集合、ambient 不额外加载；原生开关和参数记录仅证明调用，不作为真实加载通过证据。不将付费模型请求或账号余额探测加入依赖检查。
- [ ] 为 H2 提供真实手机访问方法、环境前提、桌面/移动视口截图及操作记录；步骤覆盖三步流程、命名规则编辑器、复选框、输入与错误修正。实际手机触摸、软键盘和输入判断交用户确认，移动视口不冒充手机通过。
- [ ] 汇总每项自动检查、实际运行证据及 H1/H2 尚待确认项；真实环境不可达时说明具体缺失条件及已尝试操作，完成所有仍可执行的准备，不将真实阻塞包装为已通过。
- [ ] 提供准确最终交接：自动部分已完成不等于 P23/P50 整体完成；用户未确认 H1/H2 时明确标记未验证，不把票标为整体 closed。用户确认后只按实际结果记录结论，失败项回到对应实现票修正并重验。
