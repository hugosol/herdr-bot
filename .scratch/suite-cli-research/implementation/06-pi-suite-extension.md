# 06: Pi 固定扩展的公开 MCP 与模式行为

**What to build:** 提供公开可加载的 pi-suite 扩展，在有 Suite 时追加 MCP 并应用明确模式，无 Suite 时不接管原生行为。

**Delivers:** enabling: unblocks P19, P23, P24, P26, P27

**Blocked by:** None (can start immediately)

**Repositories:** toolkit

**Status:** ready-for-agent

## Acceptance criteria

- [ ] 通过公开 registerMcpServer 追加服务器，保留 builtin MCP 及其配置来源，不替换其读取器、不自建 MCP manager 或管理命令。
- [ ] 通过公开 createCodemodeExtension 应用明确 on/only 并激活；不得同时注册内置和替代 codemode 实例。
- [ ] 定义并记录可靠的工厂期配置消费通道，与协调仓接入对齐；不重定向整个 agent 目录，不复制认证、模型或历史。
- [ ] 从实际公开扩展入口验证追加注册、无 Suite 无覆盖、双向模式切换及 only 底层工具真实文件调用；此处是扩展侧回归，不冒充完整 Herdr 验收。
- [ ] 不修改 Pi、OMP、herdr，不使用内部 monkey patch；更新必要公开入口和作者文档。

## Coverage ownership

本票拥有扩展侧行为回归，不认领完整 P19/P23/P24/P26/P27 通过。P19 的 Pi 契约测试归 09；P23/P24/P26/P27 全部契约测试归 10。

## 契约与交付约束

- 依据同一功能目录内已批准的 contract 与 spec，优先级为已批准契约；沿用 S1 主界面、S2 公开 HTTP、S3 部署配置/启动、S4 经 Herdr 启动的原生 agent 接缝，不新增测试专用公开入口。
- Acceptance mode: Full automation；人工验收例外 none。测试采用独立声明、字面结果或独立计算，不由被测实现重算预期。缺依赖、权限或真实证据明确记为阻塞/未验证，不以 skip、非空日志、零退出码或替身冒充通过。
- 复用既有文件协调、路径根和执行角色边界。不得修改 herdr/OMP/Pi、使用内部 monkey patch、重定向整个 agent 配置目录、复制认证或引入独立工具 manager。
- 测试拥有独占配置、可变目录、动态回环端口和进程；持续消费日志，正常及失败都确认所属进程退出，原始失败与清理失败分别保留。不读用户凭据，不操作用户 Chat/daemon，不真实关机，不自动安装、提权或修改系统 PATH。
- 开发与检查在本票分配的 repository worktree 内执行，遵循该仓测试和作者规范；更新受影响调用者、契约测试和用户文档，删除切换后失效的业务路径，不建立长期兼容双轨。
- P44 为所有票的交付不变量：各票提供自己的变更来源及公开入口证据；14 拥有完整交付清单一致性测试。原型只作输入，不作交付通过证据。

## 检查与证据

在本票 toolkit worktree 根按仓库指引运行 `bun run typecheck`、`bun run check:integrations`、`bun run test`，并实际加载公开扩展执行受控 Pi 场景，记录可复跑命令与独立文件结果。遵循该仓依赖和运行窗口约束，不修改真实用户部署。完整跨仓专项入口与契约测试分别归 09、10。
