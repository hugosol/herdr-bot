# 04: 逐项过滤失效扩展，保留空显式集合策略

**What to build:** 来源 Bot 存在时，一项扩展不可用只跳过该项，其他有效扩展继续用于恢复。用户在页面看到每个失效项与已知原因；即使全部被过滤，也保持有 Bot 的空显式集合，不切换默认发现。普通发起继续严格拒绝相同的无效扩展。

**Delivers:** P6；P5（自动覆盖）, P15（扩展过滤降级覆盖）, P18（无效扩展发起／恢复对照）。P 编号引用本功能已批准合同。

**Test owner for:** P5 的固定／可选扩展逐项过滤自动覆盖；P15 的扩展缺失及空集合单类反馈；P18 的同一无效扩展样例在发起和恢复之间的对照。P5 真实加载归 07 准备并由用户确认，P15 组合覆盖归 05，P18 有效发起覆盖归 02。

**Blocked by:** 01 — 集中既有恢复降级，保留精确恢复与定位规则；02 — 持久记录来源 Bot，按最新 env config 恢复。

**Status:** ready-for-agent

- [ ] 来源 Bot 存在时，固定与所选可选扩展均逐项解析；映射缺失、入口不存在或不可读时只跳过对应项，其余可用项继续提交。Pi 与 OMP 均遵守同一策略。
- [ ] 为固定／可选项分别使用独立预写样例覆盖三类失败，保留另一有效项，核对实际提交集合和具体缺失原因。不可读场景必须实际制造读取失败，不用普通缺失替代。
- [ ] 所有扩展都被过滤时显式集合为空，自动发现仍关闭；不得因空集合切换无来源分支或重新追加默认固定扩展。
- [ ] 降级通过集中机制积累，交付页面列出每个扩展名称或标识、已知原因和跳过策略，已确认恢复时明确表示有降级，不只显示普通成功。
- [ ] 空集合后缺少身份集成而无法确认时，只能如实报告失败或未确认，不假定启动或恢复成功；不新增空集合的人工验收项。
- [ ] 相同无效扩展样例分别用于普通发起与 Resume：发起保持原有明确拒绝且不启动 agent，Resume 逐项过滤；不能把容错选择泄漏给普通发起。有效发起整体配置覆盖由 02 拥有。
- [ ] 不安装、下载、修复、导入探测扩展，不增加运行时异常隔离、自动重试或重启修复；入口可读不等于实际加载成功。
- [ ] 通过公开请求、真实隔离入口与 Herdr 控制观察验证提交行为，并由 agent 操作交付页面观察结果；完成受影响行为测试、恢复 smoke、说明更新与证据记录。不改动用户现有 Chat，不以参数记录宣告 P5 人工覆盖通过。
