# 02: 持久记录来源 Bot，按最新 env config 恢复

**What to build:** 正常由 Bot 发起的 Chat 在确认原生身份后保留可信来源。用户重启服务、编辑该 Bot 后，Resume 使用其最新 env config 与当前 Bot 选项目录，而不重放 trigger config。收录与 register 使用统一的持久信息补齐入口，安全合并同一原生身份的一致互补信息。

**Delivers:** P1, P2, P3, P9, P10；P4（自动覆盖）, P18（有效发起覆盖）。P 编号引用本功能已批准合同。

**Test owner for:** P4 的最新选择／映射、固定与可选显式集合、关闭自动发现及 ambient 排除自动覆盖；P18 的有效发起仍应用 trigger config 与 env config。P4 真实加载由 07 准备并由用户确认，P18 无效扩展发起／恢复对照归 04。

**Blocked by:** None (can start immediately).

**Status:** ready-for-agent

- [ ] 在结构上区分 trigger config（初始消息、初始 Skill 调用、model、thinking）与 env config（当前扩展加载配置），迁移全部受影响调用者。若已交付持久格式需要改变，提供显式迁移，不保留隐式旧字段或路径；不实现未来加载型 skills 或系统提示词注入。
- [ ] 正常发起并确认原生身份后记录可选来源 Bot 标识；只接受发起流程的明确来源，不按显示名、cwd 或短 chatId 猜测，不为测试新增公开来源查询或写历史入口。
- [ ] 发起收录与 register 共用持久信息合并规则，按完整原生身份去重、安全串行写入；缺省值不擦除已知值，来源首次有效后不覆盖，重复相同信息不改变结果、首次时间或备忘。统一补齐不承担查询或降级修复。
- [ ] 分别制造 register 先到、发起收录先到及并发写入，覆盖缺省与明确来源的一致互补信息；使用真实隔离文件与进程重启核对独立身份集合、已知首次时间和备忘。不要求互相冲突的普通可更新字段满足交换律。
- [ ] 以扩展 A／B 的独立预写样例，通过后续 Resume 证明正常发起来源跨重启保留；已知来源 A 后又收录来源 B、无来源 register 及 Resume，结果仍使用 A；当前缺失来源只可由明确发起来源填入。
- [ ] 对两个现有支持的 agent（Pi、OMP），创建后将 Bot 选择由 A 改为 B，并修改当前目录映射；恢复使用最新可用固定项与 B，关闭自动发现且排除 A 和未选 ambient。此票使用有效扩展样例，失效项容错归 04。
- [ ] Resume 不提交初始消息、不调用初始 Skill、不传 Bot model／thinking 覆盖；观察实际输入活动，不能仅检查内部字段。原生会话自身设置沿用既有恢复规则。
- [ ] 先保存有效 Bot，再使 model 或初始 Skill 目录选择失效，同时保留有效扩展与原生对话；恢复仍使用有效 env config，不重放或要求有效 trigger config。
- [ ] 有效普通发起仍应用 trigger config 与 env config；不得因恢复配置解耦放宽普通发起的扩展校验策略。
- [ ] 通过公开 HTTP、真实隔离持久化／重启及 Herdr 控制观察闭环，不以私有补齐函数断言替代正常收录。不改动用户现有 Chat。
- [ ] 完成行为回归与真实请求驱动的恢复 smoke，更新受影响说明并记录证据；受控 adapter 参数仅证明提交内容，不能宣称 P4 人工真实加载覆盖通过。与 01 的相近代码修改需要协调，但不存在行为前置依赖。
