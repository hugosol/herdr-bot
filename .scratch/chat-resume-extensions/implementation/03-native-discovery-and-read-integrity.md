# 03: 无来源时使用原生默认发现，保持查询只读与错误真实性

**What to build:** 旧历史、外部接入 Chat 及来源 Bot 已删除的 Chat 能按 agent 原生默认扩展发现恢复，并在页面解释实际策略。历史读取不猜测来源或修改持久记录；真正的 Bot／配置读取失败不会被伪装成来源缺失或 Bot 删除。

**Delivers:** P8, P17；P7（自动覆盖）, P15（默认发现降级覆盖）。P 编号引用本功能已批准合同。

**Test owner for:** P7 的旧记录、外部接入记录、已删除 Bot 自动覆盖；P15 的原生默认发现单类降级反馈。P7 的真实加载归 07 准备并由用户确认，P15 组合覆盖归 05。

**Blocked by:** 01 — 集中既有恢复降级，保留精确恢复与定位规则；02 — 持久记录来源 Bot，按最新 env config 恢复。

**Status:** ready-for-agent

- [ ] 用旧记录、外部接入记录和正常发起后删除来源 Bot 三类独立样例恢复；两种 agent 均不传关闭自动发现的参数，也不显式追加 Bot 固定／可选扩展，仍选择同一原生对话。
- [ ] 原生默认发现是与有 Bot 的显式集合不同的既定策略，不根据名称、cwd、当前 Bot 或短标识给旧历史补绑来源。
- [ ] 经集中降级机制在交付页面显示默认发现的实际原因与策略；不得仅写日志或将其描述为已完整恢复 Bot 显式扩展。
- [ ] 独立预写缺少来源的历史，多次公开读取及重启不生成来源、不初始化、不补齐、不修复、不产生其他持久修改。
- [ ] Workspace 名称按已存 ID 临时解析；改名后展示新名但持久 ID 不变，名称查询失败仍可读取历史。名称解析不落盘、不进入持久补齐入口。
- [ ] Bot 存储损坏、配置无法解析、配置不可读等独立失败机制明确报错；不假定 Bot 不存在、不执行默认配置启动、不自动修复或改写损坏文件。可明确定位的单项扩展缺失留给 04 的逐项规则处理。
- [ ] 通过交付页面与公开 HTTP 验证反馈和错误，用真实隔离文件及进程重启证明只读性；检查错误路径无非法启动副作用。预期来自独立样例，不依赖实现计算。
- [ ] 完成相关行为测试、真实请求 smoke 与实际浏览器操作，更新说明并记录证据；实际原生默认扩展加载须留待 07 的 H-Pi／H-OMP 确认，不以受控参数冒充。
