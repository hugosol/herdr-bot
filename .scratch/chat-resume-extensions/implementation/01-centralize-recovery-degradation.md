# 01: 集中既有恢复降级，保留精确恢复与定位规则

**What to build:** 用户恢复历史 Chat 时，既有 Workspace 与精确原生 ID 回退有统一、具体且可同时保留的页面反馈；已有目标仍只定位，新进程仍加载同一原生对话并保持历史 cwd。将恢复回退规则集中在同一个文件的 module 中管理，统一降级要素、原因及实际策略，同时保持既有恢复条件、权威结果与执行资格。此票独立交付既有路径，不等待新增来源 Bot 功能。

**Delivers:** P11, P12, P13, P14；P15（Workspace／精确原生 ID 回退覆盖）, P20（既有路径覆盖）。P 编号引用本功能已批准合同。

**Test owner for:** P15 的 Workspace／精确原生 ID 单类降级反馈；P20 的既有路径并发资格、查找／身份核实失败、结构化超时、目标保留及重试查找。其他分区分别由 03／04／05 拥有，本票不宣告这两个 promise 整体完成。

**Blocked by:** None (can start immediately).

**Status:** ready-for-agent

- [ ] 将现有恢复回退规则集中管理，抽取共同降级反馈逻辑；持久信息补齐与降级职责分离，不新增自动修复、后台重试或测试专用 interface。为后续默认发现与扩展过滤复用同一机制，但不预造未来能力。
- [ ] 已有匹配 Herdr 目标时只聚焦正确 Workspace／Tab／Pane，不重启、不另建目标、不提交输入；即使最新启动配置不可用，也不为仅定位动作额外解析或要求扩展恢复。
- [ ] 新进程保持原生 ID／文件身份与历史真实 cwd；包含同名同 cwd 的不同对话反例，不用空白或其他对话替代，不提交新输入，不自动继续中断任务。复用既有真实原生运行证据与回归先例；参数记录不能单独证明真实加载或任务未继续，也不得将本项新增为人工例外。
- [ ] 原 Workspace 信息缺失或成功查询确认已删除时，仅回退到配置的唯一默认 Workspace。默认目标不存在、重名或原位置查询失败时明确报错，不任意放置、不创建替代 Workspace。
- [ ] 回退后重读及进程重启仍保留原 Workspace ID，不将实际回退位置写回原位置。
- [ ] 优先使用可用会话文件；文件不可用时仅以精确原生 ID 加载同一对话。用独立预写的同 ID、另一 ID、不可用文件及不可核实路径样例验证，可读文件身份不一致时拒绝恢复；不扫描最近文件、不改写或修复原生文件。
- [ ] 通过交付页面分别触发 Workspace 与精确 ID 回退，显示具体已知原因及实际策略；保留权威失败／未确认结果，不以创建目标或提交命令作为成功依据。多类新降级的组合覆盖归 05。
- [ ] 复用并维护既有行为回归：同实例同 Chat 并发不排队重复执行；查找／相关身份核实失败不当作无匹配；超时保持未确认并保留目标；后续重试先查找，不自动销毁、重启或创建副本。
- [ ] 使用公开 HTTP、Herdr 控制 interface、真实隔离文件／目录及交付页面验证；浏览器由 agent 实际操作。预期身份和目标来自独立样例，不调用被测实现重算期望。不得改动用户现有 Chat。
- [ ] 完成受影响行为测试和实际恢复路径 smoke，记录证据并更新相关现行说明；不新增源码形状、内部转发或文案逐字匹配测试。
