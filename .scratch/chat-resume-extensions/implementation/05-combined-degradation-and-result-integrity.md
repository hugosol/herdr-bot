# 05: 组合降级不掩盖权威结果，守住 Resume 请求边界

**What to build:** 多种降级同时出现时，用户仍能看到所有已发生要素与实际策略，同时准确区分已确认恢复、失败和启动结果未确认。调用者只能选择历史 Chat，不能通过 Resume 替换后端来源、环境、执行内容或输入。新增容错路径不破坏既有并发、查找、超时与目标保留规则。

**Delivers:** P16, P19；P15（组合覆盖与整体自动覆盖闭环）, P20（新增降级路径交互覆盖）。P 编号引用本功能已批准合同。

**Test owner for:** P15 的多种降级组合与已确认降级恢复状态；P20 的新增默认发现／扩展过滤路径与既有执行规则交互。P15 单类反馈由 01／03／04 拥有，P20 既有路径基础覆盖由 01 拥有；不重复认领相同测试用例。

**Blocked by:** 03 — 无来源时使用原生默认发现，保持查询只读与错误真实性；04 — 逐项过滤失效扩展，保留空显式集合策略。

**Status:** ready-for-agent

- [ ] 通过交付页面分别触发扩展过滤组合 Workspace／精确 ID 回退，以及原生默认发现组合既有回退；每轮显示全部已发生要素、已知原因与实际策略，不覆盖较早的说明。默认发现和有 Bot 过滤互斥，不构造不可能的同轮组合。
- [ ] 已确认恢复且存在降级时明确表示有降级；展示不固定措辞或布局，但不能只有普通成功、笼统警告或服务端日志。
- [ ] 扩展缺失分别结合启动拒绝、身份不符、确认超时及聚焦失败，公开 HTTP 与真实交付页面均保留权威结果和此前已发生的降级；不把命令提交或目标创建当作已确认恢复。
- [ ] 必要身份集成缺失时如实失败或未确认；尚未选择或执行的回退不描述为已发生。失败阶段未到达的后续策略不虚构为实际采用。
- [ ] 以独立请求尝试注入来源 Bot、扩展入口、可执行内容、执行参数、原生路径或输入，证明被拒绝或无法覆盖服务端历史与配置，且无非法启动副作用；保持既有 connect-bot 会话事件写入来源限制。
- [ ] 在新增默认发现与扩展过滤路径中，使用独立请求者及受控延迟验证同 Chat 并发不排队重复启动；查找／相关身份核实失败不变成无匹配；结构化超时保持未确认并保留已创建目标；用户重试先查找，不自动销毁、重启或重复创建。
- [ ] 核对 P1–P21 的所有已分配自动覆盖均已完成，发现实际回归则修复，不把本票变成只运行检查而无完整行为交付的验证空壳；不重复编写 01／03／04 已拥有的单类测试。
- [ ] 使用真实隔离文件、公开 HTTP、Herdr 控制 interface 及实际浏览器完成组合与失败 smoke，保存可观察结果与副作用证据；更新受影响交付说明。不得改动用户现有 Chat，也不得因尚待 H-Pi／H-OMP 人工确认停止其他可执行工作。
