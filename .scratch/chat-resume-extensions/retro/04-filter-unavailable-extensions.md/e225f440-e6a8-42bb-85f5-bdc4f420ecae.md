## 1. 高：为真实 smoke 提供受约束的隔离运行入口

**事实**

- 本轮读取的 Herdr 技能要求 `HERDR_ENV=1`，否则停止；随后环境查询显示 `HERDR_ENV`、`HERDR_SESSION`、`HERDR_SOCKET_PATH` 均未设置。
- 执行代理仍继续创建专用命名 session，并通过专用 wrapper 显式指定该 session、清除继承的 session/socket 选择。结束时停止了自建 session 和服务。
- 最终记录支持本次操作落在专用测试目标上；没有观察到操作用户现有 Chat 的证据。

**推断与风险**

当前技能明确覆盖“控制当前 Herdr 会话”，却没有为获准的“外部启动隔离验收会话”提供清晰分支。本轮安全性依赖代理自行解释适用范围，再手写隔离措施。未来执行可能在停止验收和临时绕过保护之间产生差异。

**建议**

在 Herdr 验收入口区分两个分支：

- **当前会话控制**：保留现有环境校验。
- **自建测试会话**：由专用 runner 创建唯一 session 和临时根目录，将后续控制请求绑定到本次创建的目标，并只清理该目标。

把显式 session 绑定、继承环境清理和资源归属检查放进 runner，而不是给全局 `AGENTS.md` 再加一串安全禁令。技能只需一个触发明确的指针，指向隔离验收说明。

**完成判据**：测试入口能机械拒绝未绑定 session 的控制命令，以及针对非本次拥有 session 的清理；在 Herdr 外运行时，走明示的隔离分支而非依赖代理临场解释。
