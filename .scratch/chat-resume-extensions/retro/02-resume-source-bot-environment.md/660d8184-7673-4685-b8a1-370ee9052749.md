## 1. 高优先级：把测试子进程的网络配置纳入现有护栏

**事实**

- 新增的 `chat_resume_environment.rs` 最初生成了 `listen_addr = '0.0.0.0:0'`，并在此配置下执行过真实服务进程测试。
- 执行代理后来阅读 README 的测试网络边界，才在 12:44:46 将其改为 `127.0.0.1:0`。交付版本已修正，不能据此声称最终代码仍监听所有接口。
- 仓库已有网络护栏：`scripts/check-test-network-policy.mjs` 经 `backend/tests/network_policy.rs` 接入 Cargo，并接入前端多个 `pretest` 入口。它主要识别直接监听 API；字符串先被遮蔽，没有校验测试启动子进程时生成的 TOML 网络配置。

**判断**

这是已有护栏的覆盖缺口，而不是缺少一条“测试应安全”的文字规则。源码没有直接调用 listener，并不保证其启动的服务只绑定回环地址。本次没有观察到外部访问或数据泄露，不能推断发生了这类后果。

**建议**

- 为真实服务进程测试提供共享启动入口，在 `spawn` **之前**校验数值回环地址和关闭 mDNS，并统一处理端口发现、持续消费日志、终止及等待退出。
- 扩展现有确定性护栏，识别绕过共享入口的新服务启动路径；为配置含 IPv4／IPv6 通配地址、非回环地址及启用 mDNS 的情况补拒绝样例。复用现有检查入口，不另建同义检查或仅增加代理禁令。
- 在现有代理导航中增加一个窄触发指针即可，例如：“新增或修改网络／服务子进程测试前，读取 README 的测试网络边界。”地址规则仍以既有文档和检查实现为权威，避免再复制一份。

**完成判据**：不安全配置在服务进程启动前被拒绝；新增测试无需自行实现一套安全检查。当前脚本的静态覆盖缺口已确认，所建议护栏尚未实现或验证。

## 2. 中优先级：让新增不变量拥有独立的 red 证据

**事实**

- 首个测试在 12:40:30 的失败明确证明“恢复遗漏 B”可被观察到；它不是导入或夹具失败。
- “首次可信来源不被覆盖”的实现于 12:41:35 加入；覆盖 A 后又收录 B、缺省 register、来源补齐及并发顺序的专门测试直到稍后才新增，首次执行通过。
- trigger 失效测试的首次失败来自预期错误码写成 `unknown-model`，实际公开类别为 `bot-model-invalid`。代理读取既有类别后修正夹具预期，并在交付证据中说明；这一失败不能算作 trigger/env 解耦的行为 red。

**判断**

本轮不是“没有 TDD”，但首个 tracer 的 red 不能同时证明后来加入的所有不变量。后补测试通过说明最终实现满足了这些场景，不能反向证明每项新增行为都经过自己的 red→green。会话未提供独立审查结果，因此不将此归因为 reviewer 漏检。

**建议**

- 调整 TDD 执行和完成证据的承载方式，按**行为不变量**区分三种路径：新增行为的 red→green、已满足行为的现有证据、以及仅完成了实现后验证的场景。不要用一个覆盖编号列表抹平差别。
- 对首次来源不变这类新增不变量，下一次应先让公开 HTTP／后续 Resume 场景能区分“保留 A”和“被 B 覆盖”，再加入相应保护。
- 如果实现已先于专门测试完成，应如实标记为后补验证；当检查不能确认测试敏感性时，再用局部故障注入证明它能抓住具体违例。不要为了制造红灯而更改已成立的验收要求。

现有 TDD 技能已经要求“一次一个切片”和明确违例，优先改善其执行证据模板，而不是再叠加一段同义规则。

**完成判据**：交付报告能逐项指出新增行为的有效 red，或明确指出哪些仅有现状验证；夹具错误不计入行为 red。这里建议的是未来流程改进，不否定本轮最终测试通过的事实。

## 3. 中优先级：让搜索工具按能力失败快速降级，并按 worktree 定位图索引

**事实**

- 首次 `find` 的 26 个判断请求全部收到区域不可用的 HTTP 451；没有任何候选被成功判断。工具明确表示这不是不存在的证据，代理随后报告问题并改用其他搜索方式，处理方向正确。
- 随后的图工具准备需要读取接口说明、列出 39 个项目，再为当前 worktree 建立独立 fast 索引。当前 worktree 没有直接可用的项目身份，需要代理自行完成这段接线。

**建议**

- 在 `find` 的环境适配层识别“区域／能力不可用”这类不可恢复错误：首个同类失败即可停止本批后续判断，并返回明确的可用降级路径。不要让代理承担对同一能力失败反复尝试的成本。
- 为图工具提供按当前仓库绝对路径解析项目的入口；首次需要时惰性解析或索引，返回 project ID、对应根目录及覆盖状态，避免列出与任务无关的全部项目。
- 保留“索引不完整时回到源码搜索”的分支，不能用图索引替代实时文件事实。

**完成判据**：相同能力错误不会在一个批次内重复展开；当前 worktree 可直接获得精确图项目身份。本轮没有测量该改进能节省多少总时长，不给出收益百分比。

## 4. 较低优先级：把编辑事务对齐到完整语法单元

**事实**

- 截至实现轮首次交付，共记录 138 次工具调用，其中 49 次为 `edit`。
- 配置拆分时，第一次修改 `catalog.rs` 只插入了部分嵌套结构，工具随即警告文件已无法解析；代理又读取该区段，再用后续编辑闭合结构。
- 后来使用 AST 迁移，成功一次应用了 14 处替换；宏内访问和构造样例随后另行迁移。

**判断**

不能仅凭调用数量认定探索或编辑浪费，但本次确有可以避免的语法中间态与额外往返。TDD 的“小步”应指行为切片，不必把同一个语法结构拆成多个暂时无效的写入。

**建议**

- 对嵌套配置或函数签名切换，优先以最小完整结构作为一次编辑事务，而不是逐字段插入到不可解析状态。
- 工具若支持增强，可提供同文件多处修改的原子预览，并在提交前检查语法；失败时保留原文件。跨文件、可结构匹配的消费者迁移继续复用现有 AST 工具。
- AST 迁移的结果说明应明确宏等未覆盖区域，帮助代理补齐边界，而不是把“替换次数”当作调用者已全部迁移的证明。

**完成判据**：同一结构切换不再依靠一段不可解析状态作为中转；调用者覆盖与语法有效性分别有证据。无需为此增加全局编码风格禁令。
