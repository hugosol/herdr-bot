# Ticket 01：TDD 执行复盘建议

## 范围与结论

本复盘只使用本票执行 session 的原始 JSONL、其中的工具结果，以及为核对现有检查入口而读取的仓库配置；不引用父 session 或其他票据的执行结果。本轮未修改文件、运行验收或实施下述建议。

本次有两条明确的行为 red→green：

- 精确原生 ID 回退：新增 HTTP 测试先因缺少 `degradations` 失败，随后同一测试通过。
- Workspace 降级：交付页面测试先因预期一条降级、实际为空数组而失败，随后通过。

最终工具结果记录了 **35 项后端测试通过、13 项浏览器测试通过**；补强未确认反馈断言后，Timeout 浏览器测试又单独通过 2 项。这 2 项是重跑，不应累计成 15 个不同用例。真实 Pi／OMP smoke 也取得了页面收据、原生内容和进程身份观察。以下问题主要是执行环境和反馈时机问题，不等同于最终验收未通过。

## 1. 高优先级：让已有检查成为必经护栏，而不是可绕过的命令约定

**事实**

- `frontend/package.json` 已通过 `pretest:browser` 接入 `scripts/check-test-network-policy.mjs`。
- 本次浏览器验收均直接执行 `npx playwright test …`，没有经过这个 npm 生命周期入口；执行历史中也未见单独运行该网络策略检查。
- 本轮只读查找未发现仓库内的 `.github` workflow、`.husky` 或常见 pre-commit 配置。`npm run build` 已包含 TypeScript 检查，并且本次确实执行成功，不能误报为“没有类型检查”。

**推断与风险**

已有网络护栏存在，但定向验收容易绕过它。若宿主也没有独立必经检查，测试通过不能同时证明测试基础设施仍符合网络策略。这里没有观察到实际网络策略违规，发现的是检查链路的缺口。

**建议**

- 复用现有 npm 入口传递测试选择参数，例如 `npm run test:browser -- …`；不再另造一套等价扫描器。
- 将现有网络策略检查、前端构建和适当的后端／浏览器回归接入 Windows 集成检查。先核对宿主是否已有等效必经检查，再决定使用仓库 CI 还是宿主门禁，避免重复维护。
- 这是机械约束，应由运行入口和自动化保证，不增加一条要求 reviewer 人工搜索违规 API 的规则。

**完成标准**：定向运行某个浏览器文件时同样经过网络策略检查；集成路径能拒绝已有检查定义的违规样例。

**未验证**：本轮没有检查外部 CI、组织级门禁或 Git 的自定义 hooks 路径，因此不能断言整个环境完全没有护栏。

## 2. 高优先级：将“保留旧语义”的回归放进对应 TDD 切片

**事实**

集中反馈实现曾把既有 `fallback` 从“Workspace 回退”扩大为“任意降级”。稍后运行的 `history_workspace.rs` 中，两项既有测试因此失败：实际 `true`，预期 `false`。另一次浏览器回归发现原位置恢复提示消失。最终实现恢复了旧字段语义和原位置反馈，既有预期没有被改成迁就实现。

**推断与风险**

新增反馈测试及时证明了新能力，却没有在同一个切片中同时约束最相邻的旧行为。兼容性错误直到较大范围回归才暴露，增加了返工和重新构建。

**建议**

在 TDD 的“保留现有行为”分支中，采用一个简短的 **兼容性锚点**：改变公开响应构造前，识别被改动字段的既有消费者及相关回归；每个新增行为转绿时，连同最近的兼容性回归一起运行。本票已经有能够发现问题的测试，应优先复用，而不是新增重复测试或源码形状检查。

**完成标准**：在“原 Workspace 存在、仅发生文件回退”的场景中，新降级信息出现，同时旧 `fallback` 仍为 `false`；首次完成该切片就得到这两方面证据。

这属于测试选择与跨调用方语义的判断，不适合用“禁止某段语法”的 lint 规则替代。

## 3. 中优先级：给 Windows 验收二进制建立运行期占用边界

**事实**

本次将 Cargo 回归与浏览器回归并发启动。浏览器会启动 `backend/target/debug/herdr-bot.exe`，Cargo 同时需要更新该文件，随后报出 `failed to remove file … herdr-bot.exe`、`拒绝访问 (os error 5)`。后来先完成 Cargo 测试和构建，再运行浏览器，成功完成验收。

**推断与风险**

这不是业务行为 red，而是两个作业争用同一 Windows 可执行文件。当前 Playwright 配置里的 `workers: 1` 只约束浏览器测试内部，不能阻止外部 Cargo 作业覆盖运行中的产物。

**建议**

优先在验收入口建立 **构建→运行** 依赖：同一产物被浏览器服务占用期间，不启动会重建该产物的 Cargo 作业。若确有并发需求，再考虑将已经构建的二进制复制到每次验收专属目录运行；不必一开始引入复杂调度。

**完成标准**：验收入口在进程占用期间排队构建或使用隔离产物；本类失败能被明确分类为基础设施失败，而不是测试断言失败。

这是可自动控制的资源约束，不应仅在全局代理指令里再增加“注意 Windows 文件锁”。

## 4. 中优先级：由宿主强制执行完成协议和单次提交

**事实**

实现轮的文字契约要求使用带数字 `key` 的 `yield`，每项只提交一次。原始记录里两次调用都只有 `data`，工具均返回 `Result submitted.`；首次交付后收到协作消息，又提交了一次仅含 followup 的结果。

**推断与风险**

文字契约与工具实际接收行为没有对齐。即使本次没有观察到交付丢失，也可能使宿主难以区分正式结果、补充消息和重复完成。

**建议**

- 让当前 invocation 的完成契约直接生成工具参数校验，强制检查对应的 `key`，而非依靠代理记住另一段文字协议。
- 对同一工作项实施原子的单次完成；完成后的协作消息走消息通道，不再形成第二份完成记录。
- 将实现轮、复盘轮各自的输出形状作为调用级配置，不继续叠加互相覆盖的全局说明。

**完成标准**：缺少必填键和重复完成都被工具拒绝；有效完成只产生一条权威结果。

**未验证**：当前证据不能确定宿主当时是否有意采用了宽松的专用 schema；能够确认的是，它没有按文字契约拒绝这两次调用。

## 5. 中优先级：将真实恢复 smoke 的运行知识集中到按需加载的入口

**事实**

真实 smoke 中出现了三个基础设施误用：

1. 在浏览器工具暴露的 Puppeteer `page` 上使用 Playwright 风格的 `getByRole` 链，触发 `TypeError`。
2. 改用 `button:last-child` 后点进备忘编辑，等待 Resume 收据的调用被中止；随后检查页面与 Herdr 状态，确认没有启动 agent，再选择正确的 Resume 按钮。
3. 通用 Herdr helper 对所有输出执行 `JSON.parse`，但 `agent read` 返回终端纯文本，触发解析错误。

此外，本次 smoke 的配置和原生样例来自旧临时目录，再通过多次 Eval 手工复制和调整。它最终成功，但前置条件分散在历史证据、临时配置和交互状态中。

**建议**

在现有验收支持中形成一个可复用的 **原生恢复 smoke** 入口：

- 明确浏览器驱动种类，使用已确认的 Resume 定位方式，并先建立响应等待再点击。
- 区分 Herdr 的结构化命令结果与终端文本结果。
- 显式接收原生样例、真实 cwd 和 agent 安装路径，检查前置条件后再创建专用 session；所有权和清理范围由运行实例记录。
- 在现有验收文档中放置入口及边界说明，只让“需要真实原生恢复 smoke”的分支加载。不要把机器路径和操作步骤搬进常驻 `AGENTS.md`。

**完成标准**：能够在不依赖前次 Eval 内存状态的情况下复现专用运行；错误点击不会被当作已恢复，非 JSON 终端输出能够正常收录；中止后先观察已有状态，再决定后续动作。

## 6. 较低优先级：为不可用的语义搜索提供环境级降级路由

**事实**

首次 `find` 的 24 个 judge 请求全部因区域限制 HTTP 451 失败。工具明确说明这不是“没有匹配”。代理随后改用字面搜索，并为当前 worktree 建立索引、读取声明大纲继续工作，没有把失败当作代码不存在。

**建议**

将“当前检索后端可用性”放到工具路由层：遇到确定的区域不可用错误后，本次环境直接采用可用索引或字面检索；恢复可用后再启用原路径。这个分支应由一个明确条件触发，而不是让每个实现代理重新发现供应商不可用。已知文件名和符号继续使用精准查询，避免为导航读取整份项目清单或大范围证据搜索结果。

**完成标准**：相同环境下不再反复发送已知不可用的 judge 请求，同时保留“搜索不可用不代表目标不存在”的语义。

## 应保留的执行方式与证据边界

- 保留本次两条真实的行为 red→green，以及在已有行为正确时复用既有测试的做法；没有必要为每条正确行为制造失败。
- 保留独立原生样例、公开 HTTP、生产 Herdr adapter 和真实浏览器路径。它们比测试内部反馈函数更能发现错误目标、错误 cwd 和失败误报成功。
- 保留对 OMP 文件变化的如实记录：先观察到哈希不同，再确认新增的是空 assistant／`aborted` 记录；没有把“任务未继续”偷换成“整个原生文件绝对不变”。未来 smoke 应同时记录内容变化、任务活动、模型请求和观测窗口，而不是只检查一个哈希。
- 当前记录支持本次专用环境中没有观察到新任务活动，不支持无限时长、所有 provider 或其他部署配置的普遍结论；本复盘也不代签后续真实扩展集合验收。
- 根 `AGENTS.md` 已是短导航入口，本次没有证据支持继续扩充它，也没有足够证据认定某条全局指令是 no-op。新增知识应优先落在自动检查、工具协议和按分支加载的验收参考中。

建议先处理 **检查入口、兼容性反馈时机和 Windows 产物占用**，再完善完成协议与 smoke 支持；不建议把所有事故各写成一条永久代理禁令。
