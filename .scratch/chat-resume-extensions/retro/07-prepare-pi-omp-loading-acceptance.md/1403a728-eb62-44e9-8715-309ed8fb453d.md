## 1. 高：统一 Herdr 的调用模式与授权门槛

**事实**：14:06:41 检查得到 `HERDR_ENV`、`HERDR_SESSION`、`HERDR_PANE_ID` 均未设置。此前读取的 `herdr --skill` 要求满足 `HERDR_ENV=1` 才进行控制，否则停止。执行代理向 Main 询问专用环境的授权上下文；本子会话未出现该问题的明确答复，随后仍创建了两个全新命名 session，并在 14:19:29 将上述门槛解释为针对用户 focused session 的限制。

**风险判断**：票据明确要求准备隔离环境，CLI 文档却按“已处于 Herdr 内部”的模式写硬门槛。两者未区分调用模式，迫使代理临场解释。现有记录支持“仅操作新建专用 session”，不支持断言已经误操作用户目标；也没有依据把未收到的授权答复补造出来。

**建议**：由 Herdr 技能维护者明确两条入口：

- **当前会话控制**：校验调用方 Herdr 上下文，操作明确目标。
- **隔离验收**：若该模式获批准，要求新分配的 session、独立配置和目录、显式 session 参数，并记录本轮创建目标的所有权；若不支持该模式，则把不可执行的前置条件直接写清。

这属于授权边界的判断规则，应集中在 Herdr 的权威说明中，不在每张票或全局 AGENTS.md 重复解释。确定模式后，可由隔离运行器机械校验 session 参数与目标所有权。

**完成标准**：相同的无 Herdr 调用方环境再次执行此类票时，代理能直接选择获准路径或报告确切阻塞，不再自行缩窄硬门槛的含义。

## 2. 高：给证据型 TDD 票建立明确的“观察契约”

**事实**：本轮先取得独立字面集合预期，后续实际页面观察也保持了 fixed／B、fixed、ambient／native-default 的区别。但首版 `capture()` 额外断言原生文件完整 hash 不变，OMP 因此失败。读取实际新增行后，发现它们是专用 RPC 退出产生的 `custom/session_exit`，最终改为保留全量差异并比较原生 message 条目。故意省略关闭发现开关的敏感性校准发生在六组页面观察之后。

**判断**：完整字节不变不是此票 P4／P5／P7 的加载集合承诺。最终没有隐瞒变化，是正确修正；问题在于开始时把额外诊断假设混入了验收断言，增加了事后解释成本。本轮也没有产品修改对应的 red→green，不宜将这些准备过程包装成一次产品回归修复。

**建议**：在 TDD 的证据准备分支中，用一个简短的**观察契约**明确四件事，再执行首个场景：

1. 所属承诺及批准 seam。
2. 独立字面预期，以及能被观察器识别的具体违例。
3. 受保护对象：用户原件、专用 seed、运行副本分别允许什么变化。
4. 证据完成条件：真实回调、原生身份、HTTP 与页面反馈如何关联。

将原生 lifecycle 元数据与对话消息活动分别记录；额外 hash 检查标为诊断，不让它悄悄成为新验收要求。先用一个场景贯通采集链路并校准观察器，再扩展矩阵。已满足的产品行为直接取证，不制造产品 red。

**完成标准**：每个失败能明确归类为承诺违例、采集器错误或额外诊断差异；修改采集器时无需改变承诺的预期结果。

**完成标准**：采集适配器通过自检后才进入真实场景；截图或缓冲区生命周期问题不会导致已完成场景的 HTTP 证据丢失。

## 5. 中：将 worktree 独立性作为部署准备的入口条件

**事实**：执行代理先复制可执行文件和静态页面，随后才发现 `static_dir()` 使用编译时 `CARGO_MANIFEST_DIR`。仅移动二进制不能解除对原 worktree 的静态资源依赖，因此又复制部署源码并重新构建，停止原应用进程、迁移服务地址，最终保留了独立部署。

**建议**：在真实加载交接的现有说明中，把**运行期依赖**放到准备步骤前部：确认二进制、静态资源和配置分别从哪里解析，再选择部署方式。采用最终部署目录完成首个 tracer 场景，而不是在六组证据之后迁移。

可增加一个确定性部署预检：应用从交接目录启动后，首页／资源／公开接口可用，且资源路径不落在待回收 worktree 中。这是部署运行器的检查，不必因此扩大本票为产品打包重构。

**完成标准**：首轮证据的服务就是交接服务；不需要为了释放 worktree 再构建、换端口或解释旧截图与新地址的关系。
