## 范围与结论

本复盘仅依据指定 ticket 子会话的原始 JSONL，审阅范围截至该实现轮首次提交结果；未读取父 session 或其他票据的执行历史，也未重跑验收、修改文件。

**事实：**本轮存在有效的行为 red → green：`missing_source_and_deleted_bot_use_native_discovery_without_guessing` 首次因公开恢复结果缺少降级说明而失败，实现后通过。最终工具结果记录相关后端 **27 项通过**、实际浏览器 **17 项通过**，提交为 `63f8909`。历史只读和读取错误原本已满足的部分增加了边界覆盖，没有为了制造 red 改坏生产实现。交付明确保留了 H-Pi／H-OMP 的真实扩展加载验证边界。

主要改进机会不是增加通用“认真测试”指令，而是让**已有检查入口、测试启动前提和行为迁移范围**更容易被正确使用。以下按优先级排列。

## 1. 中高优先级：通过既有入口执行浏览器验收，保留网络策略前置检查

### 观察事实

会话读取的 `frontend/package.json` 已定义：

- `pretest:browser`：执行 `scripts/check-test-network-policy.mjs`。
- `test:browser`：执行 `playwright test`。

实际浏览器验收却使用了：

```text
npx playwright test browser-tests/chatResumeDiscovery.spec.ts browser-tests/chatResumePi.spec.ts --output test-results/native-discovery-03
```

该调用没有经过 npm 的 `pretest:browser` 生命周期；会话中也没有单独执行网络策略检查的记录。

### 风险判断

**推断：**直接调用底层 runner 使已有 guardrail 在这次验收路径上被绕过。17 项浏览器通过并不能补充证明网络策略静态检查通过。

这不是发现了网络越界，也不能据此断言仓库没有 CI 或提交钩子；本会话没有提供这些证据。

### 建议

- 将宿主的浏览器验收模板改为调用已有入口并转发参数：`npm run test:browser -- …`。直接复用现有检查，不新增第二套网络策略规则。
- 若独立集成验收也有统一命令生成器，让它使用同一入口；这是机械执行约束，适合由 runner 保证，而不是在全局 `AGENTS.md` 再写一条提醒。

**完成标准：**一次带文件筛选参数的浏览器验收，其日志同时包含网络策略检查与 Playwright 结果；前置检查失败时不进入浏览器执行。

## 2. 中优先级：固化真实进程测试的“合法启动基线”，减少 fixture 失败占用 TDD 循环

### 观察事实

新增只读测试最初刻意不提供 Bot、zone 和 catalog 文件。实际启动进程立即失败：

```text
选项元数据 options.toml：读取失败：系统找不到指定的文件。
```

此时尚未执行历史 GET，不能形成只读行为的 red。随后 agent 补上合法 catalog，并继续断言历史字节、mtime、Bot／zone 文件缺失及重启后的行为；修正后的测试通过。

### 风险判断

**推断：**现有真实进程测试帮助函数没有把“启动必需的配置”和“当前行为刻意缺失的持久文件”清楚分开。新样例容易把环境不可启动误认为目标行为失败。

本轮最终正确区分了 fixture 失败和行为 red，建议保留这一做法，而不是把两次失败统一描述为 TDD red。

### 建议

- 在既有真实进程测试 harness 中提供明确的合法启动基线：启动配置与最低合法 catalog 就绪，而 Bot、zone、history 是否存在由场景决定。
- 配置损坏／不可读场景沿用本轮成功模式：先启动合法服务，再改变真实文件边界，以确保请求到达要验收的运行时读取路径。
- 将启动前提的说明放在 harness 入口附近，使用一个权威位置；无需增加全局上下文，也无需为这一个前提创建新文档。

**完成标准：**新建只读历史样例可直接到达公开 GET；故意删除启动必需文件时，失败被明确归类为 fixture／启动错误，而非验收行为 red。

## 3. 中优先级：行为切换后的回归使用非短路收集，并由 review 核对被替换的覆盖

### 观察事实

agent 先搜索了 `no-extensions`、`degradations` 等文字并迁移部分旧断言，但仍遗漏两类不同写法：

1. OMP 的无来源历史仍预期“缺失固定集成项应在 settings 阶段失败”；第一次多测试目标运行停在该失败。
2. 修正 OMP 后，下一次运行才暴露 Pi 的 `args.windows(2)` 固定入口断言及同类缺失集成项前提。

两轮失败均包含约 10 秒的确认等待。最终 agent 将这些旧前提按新策略迁移，并保留错会话文件、错误 cwd 等仍适用的断言。

### 风险判断

**推断：**按参数字面量搜索不足以发现同一行为的全部旧表达；多个测试 binary 的默认短路执行，又让相邻问题分两轮出现。

这些失败本身不能证明 agent 为求通过而弱化验收：票据明确要求无来源不显式追加 Bot 扩展，因此原 fixed-only 前提确实与本次切换冲突。但涉及删除旧失败场景时，仍值得独立审查覆盖归属。

### 建议

- 在完成首个 tracer green 后，相关跨 agent 回归采用 Cargo 的 `--no-fail-fast` 收集多个测试目标的失败；继续保持单个 tracer 的短反馈循环，不把全量回归塞进每次 red → green。
- 对“显式集合 → 原生发现”这类策略切换，按**行为前提**核对旧测试，而不只按 CLI 参数拼写搜索。
- 将“删改的旧场景是否仍有对应验收证据”交给 reviewer 判断：场景是被新合同淘汰、在当前票保留，还是明确转移至其他覆盖所有者。这是语义判断，不适合用禁止删测试的机械规则替代。

**完成标准：**同一轮相关回归能收集 Pi／OMP 两侧失败；每个被删除或重写的行为场景都能说明其合同变化及覆盖去向。

## 4. 中低优先级：让参数化验收的报告粒度与覆盖矩阵一致

### 观察事实

核心新测试把 Pi／OMP × legacy／external／deleted 六个场景放在一个 Rust 测试的嵌套循环中。首个 red 在 legacy/Pi 的 `degradations` 长度断言处终止，因此这次 red 尚未执行到后面的完整 argv 断言，也未执行其余五个场景。

后续 green 执行通过了整个循环，浏览器又将六种组合分别报告为独立用例；最终证据并非只剩一个模糊的测试名称。

### 风险判断

**推断：**后端的 `1 passed` 报告容易掩盖实际覆盖矩阵；失败时也只能首先看到一个组合。这降低诊断与证据追溯效率，但不构成“其余组合未执行 green”的证据。

### 建议

- 首个 tracer 保持一个具体场景；green 后扩展其余必要组合时，让测试框架或现有参数化方式逐项命名并报告。
- 验收摘要区分“首次 red 实际命中的断言”与“green 后覆盖的完整矩阵”，继续保留完整 argv 对发现策略的独立约束。
- 不必为了每个参数组合制造一次 red；仅当某个错误分支是否会被测试捕获仍不明确时，再做针对性故障注入。

**完成标准：**测试输出能直接定位 agent 与来源场景；red 证据不被表述为已分别验证所有分支的失败敏感性。

## 5. 低优先级：由工具环境提供当前 worktree 的索引身份和搜索可用性

### 观察事实

导航阶段出现了几项可避免的摩擦：

- `find` 的 24 个 judge 请求全部因地区限制返回 HTTP 451，未产生有效判断；agent 随后正确切换到字面搜索。
- 为寻找当前索引，先分页列出 41 个项目；当前临时 worktree 不在其中，随后才显式索引当前目录。
- 已有符号大纲将降级相关声明定位在 `backend/src/resume.rs`，但仍尝试读取猜测的 `backend/src/resume/degradation.rs`，得到路径不存在。

### 建议

- 工具宿主随 worktree 上下文提供当前可用的项目 ID、根路径与索引状态，或提供按精确根路径查询身份的入口；避免通过全局项目枚举寻找临时工作区。
- 搜索服务将会话级不可用状态暴露为能力信息，使地区限制时直接进入可用的 graph／grep 路径。
- 导航优先消费工具返回的 `file + lines`；对 inline module 沿当前文件读取。这里已有足够定位信息，不需要再给仓库添加重复的目录地图。

**完成标准：**新临时 worktree 可直接获得或建立自己的索引；不可用的语义搜索有明确降级路径；源文件读取沿已返回位置进行。

## 应保留的做法与未验证边界

- **保留真实边界。**公开 HTTP、实际服务重启、真实损坏 JSON／TOML、目录替换造成的 OS 读取错误，以及外部 CLI 记录，使本轮没有用内部 mock 替代关键机制。
- **保留完成证据的分层。**真实浏览器操作证明交付页面，受控 Herdr 证明参数和响应处理，H-Pi／H-OMP 才承担真实扩展集合确认；最终交付没有将这些证据混为一谈。
- **保留隔离与状态解释。**本轮提交了独立 worktree，未自行合入集成分支；票据依项目“已合入才 closed”的规则暂留 `in-progress`，这不是测试失败的替代状态。
- **未验证：**父会话、其他票据的实际覆盖、集成后的结果、CI／hook 是否覆盖已有检查，以及真实 Pi／OMP 默认扩展加载。本复盘不对这些项目作完成判断。

以上建议均为环境或流程改进候选，本轮没有执行建议。
