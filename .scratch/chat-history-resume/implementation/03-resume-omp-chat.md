# 03: 无匹配时恢复 OMP 历史 Chat

**What to build:** 用户通过同一个历史 Resume 入口恢复 OMP Chat，在查找无匹配后加载指定 OMP 原生对话，确认后聚焦。使用 resume 而不是会自动继续中断工作的 restore，不发送输入或重放 Bot 预设。

**Delivers:** P6、P10、P11、P12、P13、P14、P15 的 OMP 部分；P22 的 OMP 恢复确认部分。

**Test owner for:** P6、P10、P11、P12、P13、P14、P15、P22 的 OMP 自动分项；不重复认领 02 的通用类型无效与默认 Workspace 用例。

**Blocked by:** 02: 无匹配时恢复 Pi 历史 Chat。

**Status:** ready-for-agent

- [ ] 复用已交付的先查找流程、新进程恢复流程、默认 Workspace 解析和权威操作结果，从实际历史页面及独立 HTTP 请求恢复 OMP Chat，不建立第二套恢复流程。
- [ ] 仅在成功查找且无匹配时创建并启动目标；已有目标、查询失败或聚焦失败不得被绕过为新启动。
- [ ] 使用当前配置的 OMP 命令及所需集成，通过原生 resume 加载历史，不能使用 restore。
- [ ] 以独立 OMP 原生身份样例覆盖文件和 ID 同时存在、仅 ID、文件不可用：优先可用文件，ID 回退仍须明确指向同一原生对话，不接受空白或其他对话。
- [ ] 使用历史 cwd；真实临时目录覆盖含空格的合法路径并观察实际目标 cwd，目录不存在时明确失败、不改目录。
- [ ] OMP 原生对话不可用时明确反馈，不把 agent 启动或空白对话当作恢复成功。
- [ ] 以可辨认 Bot 初始指示和不同的 Bot 模型／思考级别为背景，观察没有初始输入、新输入或 Bot 设置覆盖，不把 agent 自身恢复设置误写成本项目保证。
- [ ] 自动检查观察 resume 而非 restore，且无新输入提交；不自动继续中断任务的真实运行结果由 07 的 H-OMP 确认。
- [ ] 只有确认正确对话恢复并聚焦后，页面及 HTTP 才报告恢复成功；不声称 Windows 桌面窗口置前。
- [ ] 自动检查经真实请求观察受控 Herdr 的完整阶段、副作用与失败；实际操作交付页面验证 OMP 恢复及失败反馈，不以参数记录代替真实原生加载证明。
- [ ] 将 OMP 恢复及 resume／restore 限制更新至现有相关说明，不扩大为自动继续任务或通用进程恢复功能。

## 覆盖分区

本票唯一拥有 P6、P10、P11、P12、P13、P14、P15、P22 的 OMP 自动分项。02 拥有对应 Pi 分项与通用无效类型用例，04 拥有持久化行为，06 拥有两类 agent 的启动超时分项。

H-OMP 的真实身份、历史加载、焦点、无输入及未自动继续任务由 07 准备并提交用户确认。本票不增加独立人工轮次，相关承诺仍须全部分项完成。
