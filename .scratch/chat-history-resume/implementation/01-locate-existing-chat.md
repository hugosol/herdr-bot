# 01: 从历史 Chat 定位已有原生对话

**What to build:** 用户可以从每个历史 Chat 发起 Resume；后端根据历史记录中的原生身份查找 Herdr 已有对话，并在匹配时聚焦其实际 Workspace、Tab、Pane，而不是提交输入或另开副本。浏览器呈现后端确认的结果，不以当前会话登记或原有 Herdr 绑定作为入口资格。

**Delivers:** P1, P2, P3, P4, P5, P20, P23, P24；P22 的已有目标定位部分。

**Test owner for:** P2、P3、P4 的自动检查；P22 的已有目标定位自动检查。真实环境部分统一由 07 准备并提交人工确认。

**Blocked by:** None (can start immediately).

**Status:** ready-for-agent

- [ ] 真实交付页面对每个历史 Chat 提供 Resume；旧记录、connect-bot 来源记录、登记已移除及服务重启后的记录均可通过页面和独立 HTTP 请求发起操作。信息不足可以明确失败，不能隐藏入口。
- [ ] 请求只选择历史 Chat；命令、参数、原生身份、文件引用和工作目录来自后端记录及配置。伪造可执行文件、参数、原生路径或输入等额外内容，不能覆盖后端权威数据或形成任意执行入口。
- [ ] 每次操作实际查询 Herdr，不用会话登记在线状态代替查询。原生 ID 与会话路径的不同表达能够判定为同一身份，不混用 agent 名称、Pane 身份和原生 session ID。
- [ ] 使用独立预写原生文件头及 ID／路径相等、不相等样例验证身份；同名且同 cwd 的不同对话不得匹配。
- [ ] 唯一匹配时聚焦目标实际所在的 Workspace、Tab、Pane；即使与历史偏好位置不同，也不搬迁、不创建 Tab 或 agent。
- [ ] 多个匹配时页面给出提示，按明确且稳定的目标排序自动选择；改变查询枚举顺序不改变选择，不增加选择交互或启动副本。
- [ ] 目标正在工作或等待输入时，定位均不提交 prompt 或任何会话输入。
- [ ] Herdr 不可达、错误响应、无法解析及聚焦失败分别明确反馈；不得作为无匹配继续创建或启动。
- [ ] 影响所选 Chat 匹配的身份资料暂不可读时，明确报告核实失败并停止；无关 agent 的资料不可读不得无条件阻止可确定的匹配。两类边界均有独立用例。
- [ ] 定位成功仅表示已确认的 Herdr 内部导航，不声称 Windows 桌面窗口已置前。查询成功但无匹配时明确表示尚未恢复，不能将其报告为恢复成功；新进程恢复由后续票交付。
- [ ] 保持既有会话事件同机来源限制，独立验证不允许来源的会话事件仍被拒绝且未修改登记；不扩展该边界或重构登记生命周期。
- [ ] 自动检查覆盖 HTTP 与可观察 Herdr 副作用；实际操作交付页面验证入口、多目标提示及错误反馈。原生真实焦点检查交由 07，不以受控结果冒充真实环境确认。

## 覆盖分区

本票拥有 P1、P5、P20、P23、P24 的全部合同覆盖，P2、P3、P4 的自动覆盖，以及 P22 的已有目标定位覆盖。P2、P3、P4、P22 引用的真实原生身份、焦点和输入观察复用 07 的 H-Pi／H-OMP，不另设人工轮次；相关承诺须等待其全部分项完成。
