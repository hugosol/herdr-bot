# 07: 完成合同跨路径验证与原生对话验收

**What to build:** 在全部交付路径完成后，验证 Pi／OMP 恢复与历史收录、重启和结果呈现的组合行为，并准备两项专用原生对话真实环境验收。用户能够基于明确证据确认正确对话及 Herdr 焦点，不需要冒险改动现有 Chat。

**Delivers:** P6、P21、P22 的最终验证部分；P2、P3、P4、P10、P12、P13、P15 复用 P6 人工项的真实环境验证部分。

**Test owner for:** P21 的 Pi／OMP 恢复后正常接入与重启交叉用例；P22 的跨路径结果一致性用例；P6 的 H-Pi／H-OMP 验收材料与记录，以及 P2、P3、P4、P10、P12、P13、P15 引用的同一人工证据。人工结果由用户确认。

**Blocked by:** 04: 保留原 Workspace 与历史身份，支持重启后恢复；06: 启动超时保留不确定性与目标，重试重新查找。两项通过传递依赖覆盖 01–05。

**Status:** ready-for-agent

- [ ] 首先完成全部实现和已分配自动检查；本票不接收以等待人工为由遗留的可执行实现或自动验证，也不重复编写前票已有的同一路径用例。
- [ ] 对 Pi、OMP 分别验证恢复同一原生对话后，经正常接入及历史读取，加载前后、登记移除后与进程重启后的独立预写身份集合保持正确，没有重复历史条目。使用真实临时文件及重启，不依赖当前登记存在；预期集合不得由被测实现计算。
- [ ] 实际运行交付页面及公开 HTTP 路径，对照 Herdr 控制结果验证已有定位、新进程恢复、失败和超时的结果一致性；不把创建 Tab、提交命令或未确认启动当作成功，不声称 Windows 窗口已置前。
- [ ] 复用已有自动检查证明 P1–P24 的所有自动覆盖已完成；只有本票拥有的跨路径组合用例在此新增，不用参数形状、非空结果或受控 adapter 代替真实原生证明。
- [ ] H-Pi 使用专用 Pi 旧对话，准备已有目标定位和无匹配后新进程恢复两条可重复验收路径；记录原生 ID／文件身份、cwd、已知历史内容、恢复前后 Herdr 目标、实际启动参数、页面结果，以及输入／任务活动观察。
- [ ] H-OMP 使用专用 OMP 旧对话准备相同证据与步骤，并明确检查 resume 而非 restore、加载指定历史且未自动继续中断任务。
- [ ] 两项人工验收均覆盖真实身份与路径／ID 对应、已有目标实际焦点、无额外输入，以及新目标确实加载旧对话。证据只支持实际观察，不把 agent 自身恢复设置扩大为项目保证。
- [ ] 不关闭、重启、提交输入或改动用户现有 Chat 来制造场景；只操作专用对话和目标，使用当前公开控制能力，不新增测试专用恢复接口。
- [ ] 先完成全部可执行自动工作，再一次性向用户交付 H-Pi／H-OMP 的步骤、证据及待确认事项；计划中的人工项不得阻塞其他可执行工作。
- [ ] 人工项在用户明确确认前始终标为未验收，不把证据已准备等同通过。记录两项确认结果；遇到真实环境前提不可达时，准确记录缺少的前提、已尝试步骤及仍可完成的工作，不静默降低合同保证。
- [ ] P6 及其引用的真实环境分项、P21、P22 只有各自全部覆盖完成后才可整体标为完成；本票在必要人工确认前不能标为 closed。
- [ ] 更新现有验收或集成说明，保留必要证据，移除本轮临时验证脚本和无用搭建；不另增人工轮次或功能范围。
