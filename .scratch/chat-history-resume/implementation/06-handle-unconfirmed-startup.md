# 06: 启动超时保留不确定性与目标，重试重新查找

**What to build:** Pi 或 OMP 恢复启动等待超时后，页面与操作结果明确表示“启动结果未确认”，保留已创建目标供检查，不自动清理或重启。用户再次 Resume 时重新查找，能定位首次启动后才出现的对话，而非盲目重放启动。

**Delivers:** P17, P18, P19；P22 的启动超时及不充分成功条件部分。

**Test owner for:** P22 的超时未确认、仅创建 Tab 或提交命令不足以成功的检查。

**Blocked by:** 03: 无匹配时恢复 OMP 历史 Chat；05: 同一 Chat 的并发 Resume 不重复执行。

**Status:** ready-for-agent

- [ ] 分别对 Pi、OMP 施加可控启动确认超时，浏览器及 HTTP 结果均保留不确定性，不声称恢复成功或确定未启动。
- [ ] 已取得的 Workspace、Tab、Pane 或 agent 目标信息在操作结果和页面中可识别，供用户检查；只表达实际已取得的信息，不编造确认。
- [ ] 超时后目标仍存在；没有自动关闭、终止、再次创建、再次启动或自动提交输入。
- [ ] 明确区分创建 Tab、提交命令、确认正确对话加载和完成聚焦；前两者不足以报告完整恢复成功，超时不能冒充安全失败。
- [ ] 首次超时后使同一原生目标变得可识别，用户再发起 Resume 时观察重新查询并聚焦该目标，没有第二次启动。
- [ ] 超时后的新操作仍遵守查询失败、身份核实失败和聚焦失败不得创建副本的规则，不通过重放上次启动规避查询。
- [ ] 覆盖启动等待期间独立请求者重复操作、超时结果返回后并发重试，以及执行资格释放；不排队执行旧重复请求，不让超时永久占用资格。
- [ ] 使用真实 HTTP 请求观察完整控制副作用，并在实际交付页面操作超时及重试路径；检查保留的真实目标状态，不只检查返回字段。
- [ ] 更新现有用户说明中的“启动结果未确认”、目标保留和重试语义，不提供会自动再次启动的隐藏重试机制。
