## 1. 较高：契约语义后补时，补齐独立的 red 证据

**事实**

- 原日志第 197–208 行记录了确认超时的有效 red：HTTP 返回 `outcome: failed`，测试独立要求 `unconfirmed`；随后修改实现并得到 green。
- 第 257–271 行分别暴露 Tab 创建等待和启动等待仍返回 `failed`，再逐步实现。
- 但第 283 行同一批编辑中，同时将生产代码的 `tabCreated: false` 改成 `null`，并把测试预期从 `false` 改成 `null`。日志没有记录这一状态语义修正单独经历 red。

**判断**

`null` 更符合“超时不能断言未创建”的票据要求，不能据此认定最终预期错误。缺口在于：记录没有独立证明，测试在该断言上能抓住“把未知表达为未发生”的旧实现。前面已有 `outcome` 的 red，也不能替代后面新增语义的检测证据。

**建议**

在 TDD 技能现有的“Preserve the criterion／Check the evidence after green”附近，明确这一分支的完成条件：**新增或修正一项契约断言时，先保留旧实现运行该断言，确认失败来自所命名的违例，再修改实现。** 若实现已先改好，采用最小定向回退或 fault injection 验证该断言，再恢复 green。

保留独立来源，例如本例的“未知创建结果 → `null`”，而不是从生产分支条件反推测试预期。这是对现有规则的触发条件澄清，无需另建复盘清单或重复一份 TDD 文档。

**预期收益**：最终通过之外，每个新增的重要状态语义也有可辨识的检测证据。

## 2. 中：阶段等待测试应同时观察操作提前结束，避免把 fixture 错误拖成超时

**事实**

- 新增测试最初写出的 catalog fixture 缺少所需配置。两轮运行都在等待外部 `agent_get` 阶段时耗尽约 10 秒，只得到 `external control stage must be reached: Elapsed(())`。
- 随后加入 `tokio::select!`，同时等待目标阶段或首个 HTTP 请求返回，才立即暴露 `502 invalid-agent-settings`，具体原因是缺少固定扩展；该次失败约 0.03 秒。
- 补齐真实固定扩展文件与 metadata 后，测试才到达预期的行为 red。原记录已存在可用的 Pi／并发测试配置样例，但新增 setup 仍重新拼装了不完整版本。

**建议**

优先改进测试设施，而非写一条“仔细检查 fixture”的常驻提醒：

1. 对“请求正在执行，同时等待外部阶段”的场景，复用本轮最终采用的双向观察模式：**到达阶段，或立即报告请求已经结束的状态码与正文**。阶段截止仍用于诊断真正的卡住。
2. 将重复出现的有效 Resume 测试 metadata／固定扩展文件准备收敛到现有 `backend/tests/common` 中一个窄用途 fixture 入口，继续使用真实临时文件和真实 catalog 校验；场景差异仍由测试明确设置。

完成标准应是：无效前置条件直接暴露真实响应，合法前置条件才进入行为断言；不要通过 mock catalog 或绕过校验来缩短测试。

**预期收益**：少掉无效的等待轮次，也避免把 setup 失败误记为功能 red。本轮实际最终区分了二者，这一点应保留。

## 4. 中低：搜索工具对确定性不可用错误应快速降级，worktree 图索引句柄应由宿主提供

**事实**

- 首次 `find` 内部发起 26 次判断请求，均返回地区不可用的 HTTP 451，没有产生有效命中。
- agent 没有把失败当作“代码不存在”，而是降级到文本搜索，处理正确。
- 后续还读取了图工具 schema、列举全部 38 个项目，并为当前临时 worktree 建立一次 fast 索引。声明大纲随后确实帮助定位了 adapter 和浏览器 support。

**建议**

改进工具与宿主接线，而非要求 agent 增加搜索前说明：

- `find` 对地区限制、权限缺失等同一后端的确定性不可用错误快速熔断，明确提示可用替代路径，避免在同一请求中继续扇出同类判断。
- worktree 初始化时，宿主提供当前索引的精确 project 句柄；确实尚未索引时再初始化一次。无需每个 ticket 先列举全局项目。

这不是建议取消索引：本轮大纲有实际收益；应减少的是路由与失败探测的重复成本。

**未验证**：工具是否已有可配置的熔断或项目绑定能力，及各 schema 读取是否受宿主缓存限制。原记录只足以证明本轮发生了这些调用。

## 5. 低：修复多 suite 测试输出摘要的耗时归属

**事实**

**建议**

这是工具的机械性解析问题，应由自动测试守住，不应转换成每个 coding agent 都必须手工重算耗时的新规则。

**未验证**：已上报问题是否修复。
