## 1. 优先：将共享构建产物作为验收调度的互斥资源

**事实。** 04:32:12，本执行同时启动 Playwright 和 `cargo test --test chat_resume --test chat_resume_pi --test chat_resume_omp`。浏览器测试通过，但 Cargo 尝试移除正在运行的 `backend/target/debug/herdr-bot.exe` 时返回 Windows `os error 5`。浏览器退出后，顺序执行同一组 Cargo 测试，19 项全部通过。

**推断。** 两条命令表面上分属前后端，实际上共享同一个后端可执行产物。仅按命令或目录判断“独立”不足以保证安全并发。此次失败是验收资源冲突，不是恢复行为的 red。

**建议。** 在工作流验收调度层为 Cargo 构建／测试与使用该二进制的浏览器运行声明同一个资源键，以当前 worktree 的 Cargo target 目录为作用域：先完成会写入产物的阶段，再运行持有二进制的浏览器阶段，且在浏览器服务清理结束后释放资源。独立 worktree 的不同 target 目录仍可并行。

这是可机械执行的约束，应由调度器或验收入口保证，而不是交给 reviewer 记忆一条“不要并行测试”的宽泛规则。

**建议的完成标准。** 同一 target 目录的相关阶段不会重叠；任务失败时仍执行清理并释放资源；不同 target 目录不被无谓串行化。

## 2. 中优先：图索引查询应先绑定当前 worktree，再提供覆盖与新鲜度证据

**事实。** 本执行分页列出索引项目后，使用了 `chat-resume-02` 的索引读取声明大纲。该索引的 root 并非本票 worktree。返回的 `resume.rs` 大纲只有旧版 `post_resume`、`failure` 等声明；紧接着读取的本地源码已经包含 `restore_pi`。同一索引对本地存在的 `backend/tests/chat_resume_pi.rs` 返回空大纲。日志中未见对这些引用路径执行覆盖／新鲜度核实。

**推断。** 图工具在这里没有提供与当前检出版本一致的导航结果。“调用过大纲工具”并不等于获得了可靠的大纲；空结果也不能说明文件没有声明。本次依靠本地源码继续完成了工作，但此类不一致可能误导后续定位。

**建议。** 在工具路由层按当前 cwd 自动匹配索引 root，并让大纲结果携带来源 root 和可用的新鲜度信息。当前 worktree 无对应索引、路径未覆盖或结果与本地文件不一致时，明确转入本地声明／范围读取，不把另一个 worktree 的索引静默当作当前源码。真正需要查询外部 OMP 仓库时，再显式选择外部项目。

优先修复查询默认值和结果标识，不要向项目 `AGENTS.md` 加入经常变化的索引项目名清单；那会成为另一份缓存。

**建议的完成标准。** 当前 worktree 查询不会无提示地使用其他 root；空大纲能够与“未覆盖／过期”区分；本地回退不需要代理先分页浏览全部项目。

## 3. 中低优先：对明确不可用的搜索后端采用快速降级

**事实。** 一次 `find` 调用报告“all 24 judge requests failed”，原因是服务返回 HTTP 451：`Typesafe is not available in your region`。此后执行使用字面搜索和图工具继续定位，没有把失败结果当成代码不存在。

**推断。** 同一类地区限制不会因对更多候选文件继续发起判断请求而改善。日志足以说明存在重复失败请求，但不足以推算其费用或认定它是本次主要耗时来源。

**建议。** 在搜索工具内部为这类明确的能力不可用错误设置短期熔断：首次识别后停止本轮候选判断，并在本执行内返回可用的本地或图搜索路径。普通网络瞬断仍可按原有重试策略处理；不要把所有错误都归为永久不可用。

**建议的完成标准。** 稳定的地区／权限限制不会引发整批同类请求；降级结果明确标为“搜索能力不可用”，而不是“无匹配”。这一改进属于工具实现，不需要项目新增搜索禁令。
