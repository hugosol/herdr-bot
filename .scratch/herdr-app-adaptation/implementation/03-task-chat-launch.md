# 03: 从 Task 发起 Chat 并提交首条指示

**What to build:** 用户从 zone 发起 Chat 时，所选宿主以 Task 的 trigger config 与 env config 启动目标；后端核对关联与 ready 后才通过所选终端提交初始指示，页面读到权威进度。依据[合同](../contract.md)的 S1 与[规格](../spec.md)。

**Delivers:** P6, P7, P19, P20, P21, P22, P49, P50, P53

**Test owner for:** P6/P7/P22/P49 的 S1 决策与终端调用，P19/P20 的后端关联与去重，P50 的初始化与已提交；05 拥有真实生产链路。

**Blocked by:** 02 — 选择 TUI 或 App，并核对目标实例

**Repositories:** herdr-bot

**Status:** ready-for-agent

- [ ] 公开发起路径按声明装配模型/thinking、Suite、固定扩展与初始指示；场景预设 zone、当前容器与不同的默认容器，验证实际选择不会统一强制默认。App 不读取不需要的 TUI 状态扩展，仍保留适用固定能力。
- [ ] 使用受控生产协议输入验证允许和拒绝的同机来源：拒绝先于状态变更；错误、陈旧、其他会话或目标的证据不能解锁本次，独立普通 connect-bot 登记仍按既有规则。
- [ ] TUI/App 共用启动资格和初始输入决策。重复／乱序 ready 不产生第二次首条提交；通过终端而非原生消息 API，保留普通文本、命令、Skill 与模板语义。
- [ ] 公开 HTTP/页面区分初始化与已提交，浏览器只观察；安全关机替身证明 ready 不改变在线／离线、关机权威或 idle 与等待用户输入的区别，不调用生产关机。
- [ ] 记录 ADR 0014 中受启动关联约束的原生上报与 TUI 官方引用的不同信任边界，不伪造文件或提前提交；07 补充互不重叠的 B1 恢复说明。
