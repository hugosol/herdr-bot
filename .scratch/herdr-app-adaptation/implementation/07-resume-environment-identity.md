# 07: 恢复历史 Chat 并如实显示环境与身份结果

**What to build:** Resume 使用来源 Task 的最新会话环境，或明确提示已切换到原生默认发现；区分已核实身份、已请求并定位但身份未确认、以及硬失败。依据[合同](../contract.md)的 B1、S1 与[规格](../spec.md)。

**Delivers:** P29, P30, P31, P32, P33, P34, P35, P36, P52

**Test owner for:** 恢复配置、身份结果、真实页面降级反馈、来源持久事实与一次启动；08 独占真实双向恢复的原生场景。

**Blocked by:** 03 — 从 Task 发起 Chat 并提交首条指示；06 — 为历史 Chat 确定恢复位置并定位目标

**Repositories:** herdr-bot

**Status:** ready-for-agent

- [ ] 通过公开 Resume 验证正常来源使用修改后的最新 env config、Suite 及角色适用固定能力，不重放原模型覆盖、初始 Skill 或初始消息。新 Chat 不使用 B1 降级。
- [ ] 真正无来源、来源已删除、env config 读取失败、Suite 配置错误四个独立场景，均走同一原生默认发现策略，不追加 Task/Suite 或强制 connect-bot。保存的 sourceTaskId 不清除、不伪称无来源；原因可区分。
- [ ] Resume 对应按钮附近显示统一的真实原因、策略及结果；配置错误、无来源及后续失败／未确认仍保留提示，说明默认资源范围可能变化，不宣称恢复旧 Suite。
- [ ] 有可靠证据则验证原生 ID/file/agent 类型；错误 ID、冲突文件头、类型冲突、历史读取错误及真实启动／定位失败不报正常降级或已确认。默认发现无替代证据时只报道实际已请求并定位、身份未确认，不自动改绑或补启动；核对历史和启动次数。
- [ ] 补充 ADR 0014 的 B1 未确认边界；不放宽 03 的新 Chat 输入资格。公开检查包含已确认、未确认、硬失败和零 trigger 重放。
