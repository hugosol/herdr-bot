# Contract — herdr-bot TUI / App 双端适配

Source: [已确认 spec](spec.md)
Acceptance mode: Rapid iteration
Approval: approved

三个决策 gate 均已获用户明确批准：S1/S2/S3 seam；六面检查后的恢复降级取舍（含用户补充的配置错误降级及统一提示）；快速迭代，唯一人工项为两端原生提示音的实际听音确认。

本合同继承 spec 的 Implementation Decisions、Out of Scope 及相关 ADR；不重述需求叙事，不规定实现顺序。恢复确认的例外按最终获批 B1 执行，不再沿用先前“强制补充 connect-bot”或“恢复环境配置错误一律硬失败”的建议。

**Complete implementation and all assigned automated checks before the human-led acceptance round. Planned human-led checks do not pause otherwise executable work. At the final handoff, report the remaining checks together with their prepared evidence; they remain unverified until the user confirms them. Report genuine blockers when encountered.**

## Promises

Coverage 中“自动”由 agent 承担实现、TDD 和约定验收；“人工”只保留明确写出的判断，其实现和可自动检查部分仍由 agent 承担。人工确认前该项不能视为通过。

覆盖规则：

- 宿主相关操作分别覆盖 TUI/App；涉及 agent 输入、身份、环境或生命周期差异时覆盖 OMP/Pi × TUI/App 四种组合。与 agent 无关的规则不要求重复四次。
- 预期来自本表、spec 和独立字面场景，不用实现自己的计算结果作 oracle。固定配置名称、选定原生身份、期望目录和无关进程都由场景预先确定。
- S1 的成功回执不能代替 S3 的真实效果。受控 adapter 用于确定性错误、时序及副作用检查；真实安装宿主负责证明实际兼容性。原型已有证据不自动认证尚未实现的生产链路。
- 恢复错误分成环境可降级、身份/启动/定位硬失败和缺证据未确认，不得合并为泛化成功。原始失败与资源清理证据保留。
- 本表不存储手工完成状态。交付工作及其阻塞关系由 `/to-tickets` 关联；完成状态从交付工作、所需检查和人工确认共同推导。

## Seam decisions

|Seam|Exposes|Hides|Alternatives considered|Reversibility|
|---|---|---|---|---|
|S1 — herdr-bot 对外操作 interface|配置后的应用启动、已有 HTTP 操作与会话上报、浏览器结果、公开历史及既有持久数据格式。覆盖 bot 使用的全部宿主相关操作，并非包装上游全部命令。|内部业务编排、adapter 调用顺序的实现细节、数据访问与计时器组织。|只测控制 adapter 无法证明 Chat/chief/Run 语义；只看浏览器文字无法证明失败机制与持久数据。选用现有最高消费者 interface，并以必要的持久/真实效果补证。|中：内部重构自由；改变公开结果分类或持久身份语义需同步消费者与合同。|
|S2 — toolkit framework 扩展订阅 interface|会话级 ready、当前 owner/身份关联及失效语义；由公开消费者订阅，不依赖私有回调。|OMP/Pi 如何读取各自初始化条件、UI 观测实现、事件分发与扩展构造细节。|只在 connect-bot 内特判会留下两套宿主规则；把 startup/idle 改名不能满足初始化含义。选择已批准的 framework 语义事件扩展，不另外暴露编辑器。|中：具体观测实现可换；改变 ready 含义会影响订阅方和 bot 初始输入契约。|
|S3 — 真实宿主交互 interface|实际容器/终端、交互输入、原生会话身份与历史、焦点、进程退出及原生提醒。操作由 S1/S2 的生产路径驱动，效果通过公开 native interface 与实际表面观察。|上游内部状态机、GUI 实现、终端传输细节和音频实现；不要求修改它们。|受控 adapter 可精确制造故障，但不能证明真实兼容；仅原型直发输入不能证明生产链路。故保留真实观察，不新增第四个产品 interface。|低耦合观察：上游版本变化需重验 adapter 与证据，不能以实现更新默默改变承诺。|

### 已批准检查结果

- 六个表面全部适用并已检查：入口；数据与状态；外部依赖；错误与失败；输出与可观察性；资源与并发。没有“不适用”项。完整检查工作记录保留，不以额外 seam 替代资源约束。
- `in-process`：framework 内部事件和状态；`local-substitutable`：确定性时间及文件设施；`remote but owned`：toolkit 与 bot 的跨进程上报；`true external`：本工作不能修改的 TUI/App/core、agent 和操作系统。依赖类别决定证据方式，不要求为每类新建一个公开 port。
- 必需的推导已标为 inferred：既有当前/默认选择、陈旧事件隔离、刷新不重置尝试、相同初始消息规则覆盖相关调用者、报告存储及安全状态不回归。这些不增加新产品能力。
- B1 最终选择：无来源/已删除来源以及恢复环境配置读取失败、Suite 配置错误，使用原生默认环境；统一降级 module 管理策略与提示。无可靠身份证据时如实返回未确认，不强制加入 connect-bot。正常配置仍装配最新 Task/Suite；已知身份冲突和真实启动/定位失败仍失败。
- B1 被否决的替代方案是“所有恢复都强制补充 connect-bot”，原因是用户优先保持降级恢复的原生环境。原先“恢复环境配置错误必须硬失败”的建议也被用户明确替换；这不放宽应用启动配置或新 Chat 校验。
- B1 的未来代价：原生默认资源可能比目标 Suite 更广，且缺证据恢复不保证自动核实同一会话；提示必须公开这两点。未来若要求 toolkit-free 恢复也必有可靠身份确认，须引入新的已验证身份来源并修订合同，不能悄悄把启动参数当证明。
- 额外内部 module 划分、事件序列化和计时实现留给实现工作；本合同不要求私有辅助 interface 或通用重试框架。若实现推翻某 seam，先修改合同再重开受影响票据。
