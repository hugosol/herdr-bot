# Contract — omp Map 运行系统

Source: [omp Map 运行系统：需求与设计 Spec](spec.md)
Acceptance mode: Rapid iteration
Approval: approved

## Approval and inheritance

2026-10-28，本轮用户先以“同意”确认修正后的四个 seam（文档不独立设 seam），再以“确认”批准六类表面审查方向，最后选择“Rapid iteration”。验收模式选择对应当时提出的两项人工最终判断，其具体覆盖与证据要求只保存在下表 P69、P70。

本契约继承 [Implementation Decisions](spec.md#implementation-decisions)、[Testing Decisions](spec.md#testing-decisions)及 spec 引用的领域词汇、ADR 和已解决设计决定。管理者独占状态操作、completed 的交接含义、报告保存与通知分离、人工恢复、三份运行记录、部分提交、重启只读、同机信任及运行期间配置不变均是上游事实，不在此重新决策。普通 Chat Resume 的既有语义不变。

本文件批准的是 promises、观察 seam 与 coverage，不表示实现完成、运行通过或人工验收已确认。每项完成事实由交付工作与检查结果推导，不维护 promise 状态列。`/to-tickets` 须在实施票据中引用 P 编号并建立交付映射；未切票前没有交付完成事实。

**Complete implementation and all assigned automated checks before the human-led acceptance round. Planned human-led checks do not pause otherwise executable work. At the final handoff, report the remaining checks together with their prepared evidence; they remain unverified until the user confirms them. Report genuine blockers when encountered.**

## Promises

Source 的 story 编号均指 [User Stories](spec.md#user-stories)；“决定”指 [Implementation Decisions](spec.md#implementation-decisions)；“验收”指 [Testing Decisions](spec.md#testing-decisions)。每行是一个可观察结果，coverage 中的多个场景是该结果的不同输入，不是要求另建 interface。

默认 coverage 由 Agent 完成。自动化期望取自批准的承诺、独立字面样例或预先算定结果，不调用被测 implementation 重算预期。受控 adapter 用于稳定构造成功/失败条件，不作为真实 Herdr、omp 或模型行为的证明。

## Seam decisions

| Seam | Exposes | Hides | Alternatives considered | Reversibility |
| --- | --- | --- | --- | --- |
| S1 用户操作 interface | Task 配置、scheduler 发起、workflow 观察、实际 Resume、可见性与错误反馈 | 页面内部拆分、缓存/状态组织、图实现细节 | 仅 HTTP 不能证明真实入口可达、图可读及轮询表现，故保留页面观察；不按页面内部模块另设 seam | 中：可替换内部实现，改变用户交互承诺需修订契约及相关验收 |
| S2 herdr-bot 对外 HTTP interface | 定义/Task/Chat 的既有操作及新增 Run 查询、动作、report、collect；准入、错误、部分效果与时序 | 状态计算、通知索引、锁和内部模块划分 | 仅端到端 Agent 链路难以稳定构造所有故障；直接测试私有状态 helper 又不能证明调用方得到的结果，故使用真实调用 interface | 中：内部可改；公开请求/响应变更影响前端和扩展调用者，需同步契约 |
| S3 omp 工具与宿主交互 interface | 实际角色工具、Prompt/Session/HTTP 公共能力、Herdr 启动/输入/Resume 的可观察效果、原生身份与执行产物 | 扩展内部 common/foundation 组织、传输实现、宿主内部实现 | 受控 adapter 不能证明原生身份、实际工具指引和产物使用；全部依赖真实模型又难以稳定故障取证，故保留受控故障覆盖与必要真实证据 | 中至低：宿主能力或公共 toolkit interface 变化会影响 adapter 和接入验收，内部重组不改变承诺 |
| S4 持久记录与迁移 interface | 运行记录、迁移输入/输出、进程重启后的保存事实及文件错误效果 | 私有文件 helper、锁实现、临时文件具体命名和内存索引 | 仅返回值/页面不能证明磁盘、尾部残缺或迁移保留事实；不把通用文件层的每个私有函数升为契约 seam | 中至低：持久格式是外部可读承诺，变化可能需要迁移；不因此新增版本平台或兼容层 |

上述是四个外部观察 seam，不要求新建四套抽象层。已有 TestServer 的真实 HTTP、隔离 Herdr 记录型 adapter、真实进程重启与文件样例、交付浏览器页面和 toolkit 公共 interface 均提供复用基础。新增内容是 Run 操作/查询及角色工具等已批准功能，不因测试数量增加而新设 interface。

### 文档修正与拒绝理由

初稿曾将交付文档列为第五个 seam。用户要求解释测试方式后，修正为：可执行指南在 S1/S3 验证，纯文档完整性作为 P66 的非运行 seam 交付审查。用户明确同意。拒绝第五个 seam 的原因是文档交付物本身不构成可替换行为的 interface；不能为表格全覆盖制造抽象。

未采用“所有承诺只在端到端观察”：页面成功不证明落盘结果，HTTP 成功不证明真实 omp 接入，受控外部记录不证明模型实际读取材料。只有不同证据确有必要时才跨 seam，不要求所有场景在全部层次重复。

### 依赖类别与 implementation 自由

- **In-process**：状态判断、派生快照、报告适用性；通过 S2 观察，不规定私有算法或额外 adapter。
- **Local-substitutable**：隔离文件系统及本机受控进程条件；用于确定性失败覆盖，S4 的目标 Windows 替换保证仍需真实证据。
- **Remote but owned**：自有跨进程运行协议、toolkit 与 Herdr 集成所经 interface；复用现有生产 adapter 和受控 adapter，不复制第二套业务规则。
- **True external**：模型提供方及不受项目控制的宿主行为；受控结果仅覆盖确定性调用语义，真实能力由 S3 取证。
- 单一 adapter 的内部调用不自动构成需要新 port 的理由。真实取消、文件错误或顺序故障需要的内部注入保持私有，不把故障专用入口发布给用户。
- 允许内部模块、算法、索引、临时文件命名和测试组织调整，但不得静默改变已继承的公共 framework 分层、文件提交保证或外部可观察行为。

### 已接受的未来成本

持久记录与工具/HTTP interface 会成为调用者依赖；未来若改为数据库、改运行归属或提高跨文件一致性保证，需要修改相应 interface/迁移与 S2–S4 验收。当前仍按上游选择交付三文件及弱化事务保证，不提前建设数据库或兼容平台。此处记录已有选择的后果，不新增高影响取舍或 ADR。
