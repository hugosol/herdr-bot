# 04: 有效 Map 启动管理者并进入 Run 详情

**What to build:** 有效 Map 经同一预检创建独立 Run，保存本次要求，启动真实 manager Chat 并在关联落盘后提交指示；用户取得 Run 标识后进入可刷新的基础详情。

**Delivers:** P2, P9, P10, P12, P13, P15, P16, P17, P45, P54, P59, P67, P68

**Test owner for:** P2.02, P9.02, P10.01, P13.01, P15.01, P16.01, P17.01, P45.01, P54.01, P59.01, P67.01, P68.01（仅本票所列分区；整个 promise 须全部分区完成）。

**Blocked by:** 03 — scheduler 启动预检与无副作用拒绝

**Status:** ready-for-agent

## 契约与范围

依据：[approved contract](../contract.md) 与其继承的 [spec](../spec.md)。P 编号与 S1–S4 的含义以 contract 为准；本票不重新定义 promise 或新增观察 seam。

随能力交付三份记录初始化、稳定存储配置、manager 原生身份/Workspace 获取、公共 Prompt 指引与 run status 工具、基础详情及诊断。管理者工具入口从首次开放即校验同机来源与真实归属，不等待安全矩阵票才实施约束。状态查询基于已提交当前事实，不持久化 ready。manager 启动错误只在当前后端内存可查询；普通 Chat Resume 不变。失败不假称外部 Chat 回滚。

仅交付本票的覆盖分区；共享 promise 不因某一分区通过就算整体完成。实现前沿是所有列出的阻塞票均完成的票，不按编号强制全串行。

## 验证与证据

从 scheduler 启动真实 manager，核对记录及实际初始输入；刷新/重新进入详情不增加启动次数；对初始化、身份、关联及指示提交分别注入失败并观察实际效果。

遵守仓库测试指引：复用真实 HTTP TestServer、现有前端/npm 浏览器入口及 toolkit 公共 interface；页面能力观察实际交付页面，宿主能力需要真实 Herdr/omp 证据。受控 adapter 只证明确定性故障/时序，不证明模型或原生宿主行为。

普通检查只用数值回环、独占临时数据/cwd/动态端口与必要 Herdr 副本，持续消费并清理所属子进程；不操作用户对话或产物，不绕过 npm 网络护栏。LAN/mDNS、真实符号链接和关机仍遵守显式人工授权规则。

自动化预期取自契约、独立字面样例或预先算定结果，不用被测实现重算预期。负向自动行为检查注明有界观察窗口并保留外部调用证据；取消/错误不得伪造快照或自动重试。真实环境缺失如实报告阻塞，不以替身或跳过宣称通过。
