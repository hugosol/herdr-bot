# 12: 失败核实、原执行 recover 与人工交接

**What to build:** 用户核实或修复现场后向管理者表达意图：派发失败只修正已确认事实，执行失败可恢复原 Chat 跟踪，真实可交接时可以人工 complete。

**Delivers:** P20, P35, P38, P39, P40, P42, P68

**Test owner for:** P20.04, P35.03, P38.02, P68.06（仅本票所列分区；整个 promise 须全部分区完成）。

**Blocked by:** 09 — 暂停新执行与恢复派发资格

**Status:** ready-for-agent

## 契约与范围

依据：[approved contract](../contract.md) 与其继承的 [spec](../spec.md)。P 编号与 S1–S4 的含义以 contract 为准；本票不重新定义 promise 或新增观察 seam。

交付 fail、reconcile_dispatch、recover 及执行失败 complete 的实际工具路径、当前原因和历史。无任意状态后门；不确定派发保持 failed，执行失败不能借派发核实任意改写。paused 允许不启动动作；不自动暂停、重试、终止 Chat，不伪造报告或补发材料。

仅交付本票的覆盖分区；共享 promise 不因某一分区通过就算整体完成。实现前沿是所有列出的阻塞票均完成的票，不按编号强制全串行。

## 验收标准

- [ ] **P20.04**（本票编写并执行的契约检查）：重复 fail 保留首次失败说明和历史，不重复产生状态效果或外部动作。
- [ ] **P35.03**（本票编写并执行的契约检查）：Run 终态拒绝 fail、reconcile_dispatch、recover 和人工 complete，保留首次终态事实与外部调用不变。
- [ ] **P38.02**（本票编写并执行的契约检查）：执行 fail 保留阶段/原因/原 Chat，查询及磁盘一致；有界外部观察证明无新增自动动作。
- [ ] **P39.01**（本票编写并执行的契约检查）：仅派发失败可核实：确认已创建则关联真实 Chat→running，未创建→pending，不确定保持 failed；所有分支无新 Chat，执行阶段失败不能借此修正。
- [ ] **P40.01**（本票编写并执行的契约检查）：执行阶段 failed 经人工确认后 recover 恢复原跟踪，身份不变、失败历史保留、无启动调用；paused 可执行该非启动动作。
- [ ] **P42.01**（本票编写并执行的契约检查）：人工已处理的执行阶段 failed 可显式 complete 解除依赖，但报告记录无伪造内容，不自动传材料；通过已有 Chat 补充结果地址/限制，不依赖新消息工具。
- [ ] **P68.06**（本票编写并执行的契约检查）：派发/执行失败不自主重试、暂停或终止 Chat；核实/recover/人工 complete 不启动新执行或补发材料。
- [ ] 完成上述能力所需调用者、错误反馈和角色/用户指引；不留占位实现、假成功、运行时旧格式兼容或未接线入口。
- [ ] 保留本票真实入口的可重复验证证据及检查结果；相关长期说明随能力更新，不只更新临时票据。

## 验证与证据

分别演示已创建、未创建、不确定三种核实，以及原身份 recover 和人工 complete；观察无新 Chat，失败历史仍可读，下游仅因显式交接获得资格。

遵守仓库测试指引：复用真实 HTTP TestServer、现有前端/npm 浏览器入口及 toolkit 公共 interface；页面能力观察实际交付页面，宿主能力需要真实 Herdr/omp 证据。受控 adapter 只证明确定性故障/时序，不证明模型或原生宿主行为。

普通检查只用数值回环、独占临时数据/cwd/动态端口与必要 Herdr 副本，持续消费并清理所属子进程；不操作用户对话或产物，不绕过 npm 网络护栏。LAN/mDNS、真实符号链接和关机仍遵守显式人工授权规则。

自动化预期取自契约、独立字面样例或预先算定结果，不用被测实现重算预期。负向自动行为检查注明有界观察窗口并保留外部调用证据；取消/错误不得伪造快照或自动重试。真实环境缺失如实报告阻塞，不以替身或跳过宣称通过。
