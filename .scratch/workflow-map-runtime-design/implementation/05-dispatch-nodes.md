# 05: 管理者按依赖派发独立节点 Chat

**What to build:** 管理者查询可派发项和阻塞原因，显式批量派发节点；每个合法目标启动独立原生 Chat，单项拒绝或启动失败不取消其他合法目标。

**Delivers:** P8, P10, P11, P13, P14, P15, P16, P18, P19, P20, P38, P45

**Test owner for:** P8.02, P10.02, P13.02, P14.01, P15.02, P16.02, P18.01, P20.01, P38.01, P45.02（仅本票所列分区；整个 promise 须全部分区完成）。

**Blocked by:** 04 — 有效 Map 启动管理者并进入 Run 详情

**Status:** ready-for-agent

## 契约与范围

依据：[approved contract](../contract.md) 与其继承的 [spec](../spec.md)。P 编号与 S1–S4 的含义以 contract 为准；本票不重新定义 promise 或新增观察 seam。

沿 node→Bot→Task 使用定义 zone 和管理者实际 Workspace，保留完整 trigger config；先取得并保存关联，再提交节点指示。派发失败持久保留阶段、原因与可得 Chat 引用。节点指引和稳定路径随本票提供；不注入 Bot 文档、完整 Map 或 user_input，不自动选路。

仅交付本票的覆盖分区；共享 promise 不因某一分区通过就算整体完成。实现前沿是所有列出的阻塞票均完成的票，不按编号强制全串行。

## 验证与证据

通过真实管理者工具派发独立节点，并用受控 adapter 演示同批拒绝、失败和成功；核对原生身份、实际目录及 Workspace，而非仅核对 Tab。

遵守仓库测试指引：复用真实 HTTP TestServer、现有前端/npm 浏览器入口及 toolkit 公共 interface；页面能力观察实际交付页面，宿主能力需要真实 Herdr/omp 证据。受控 adapter 只证明确定性故障/时序，不证明模型或原生宿主行为。

普通检查只用数值回环、独占临时数据/cwd/动态端口与必要 Herdr 副本，持续消费并清理所属子进程；不操作用户对话或产物，不绕过 npm 网络护栏。LAN/mDNS、真实符号链接和关机仍遵守显式人工授权规则。

自动化预期取自契约、独立字面样例或预先算定结果，不用被测实现重算预期。负向自动行为检查注明有界观察窗口并保留外部调用证据；取消/错误不得伪造快照或自动重试。真实环境缺失如实报告阻塞，不以替身或跳过宣称通过。
