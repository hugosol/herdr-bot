# 06: 节点报告保存与独立 Herdr 通知

**What to build:** 节点通过真实 report 工具仅提交正文；系统归属报告并先保存，再独立通知管理者，清楚区分保存和通知结果。

**Delivers:** P24, P25, P26, P27, P28, P59, P61, P68

**Test owner for:** P25.01, P26.01, P27.01, P28.01, P59.02, P68.02（仅本票所列分区；整个 promise 须全部分区完成）。

**Blocked by:** 05 — 管理者按依赖派发独立节点 Chat

**Status:** ready-for-agent

## 契约与范围

依据：[approved contract](../contract.md) 与其继承的 [spec](../spec.md)。P 编号与 S1–S4 的含义以 contract 为准；本票不重新定义 promise 或新增观察 seam。

随本票交付 node 工具、真实会话归属校验及公共 Prompt 指引。报告只追加事实，不推进状态。派生索引/通知不形成第四份业务记录；诊断不复制正文，日志失败不撤销或重投。collect 可收取性由后续 collect 票完成，不在本票冒称完整 P25/P26 通过。

仅交付本票的覆盖分区；共享 promise 不因某一分区通过就算整体完成。实现前沿是所有列出的阻塞票均完成的票，不按编号强制全串行。

## 验收标准

- [ ] **P24.01**（本票编写并执行的契约检查）：真实 node report 只接受正文；核对系统生成标识、时间、来源、当前执行归属和同 Run manager 接收者，报告前后状态不变。
- [ ] **P25.01**（本票编写并执行的契约检查）：真实或受控存储失败使 report 返回保存失败，不写报告、不生成待办索引且无 Herdr 投递调用。
- [ ] **P26.01**（本票编写并执行的契约检查）：保存成功而投递失败/延迟时返回明确区分阶段，报告仍在，不回滚、不暂停、不仅为投递失败重发；保留外部调用证据。
- [ ] **P27.01**（本票编写并执行的契约检查）：同一执行连续提交互异报告标识，保留每条追加历史，按 node 汇总最新适用报告。
- [ ] **P28.01**（本票编写并执行的契约检查）：连续直接读取和通知提交不清除未完成节点的报告待办。
- [ ] **P59.02**（本票编写并执行的契约检查）：node 通过公共 Prompt 能力获得实际 report 指引，结合真实调用证明工具仅提供正文，不要求自报 Run/node/接收者；不以 description 替代实际注入。
- [ ] **P61.01**（本票编写并执行的契约检查）：报告保存后成功/失败投递诊断包含 Run、报告、目标 Chat、结果与原因但不重复正文；诊断失败不撤销报告或再次投递。
- [ ] **P68.02**（本票编写并执行的契约检查）：通知失败/诊断失败的有界窗口无自主重投或仅因投递失败自动重报。
- [ ] 完成上述能力所需调用者、错误反馈和角色/用户指引；不留占位实现、假成功、运行时旧格式兼容或未接线入口。
- [ ] 保留本票真实入口的可重复验证证据及检查结果；相关长期说明随能力更新，不只更新临时票据。

## 验证与证据

让真实 node 提交报告，检查归属、正文、持久记录和管理者输入；分别制造保存失败、投递失败/延迟与诊断失败，观察无假成功、回滚或补投。

遵守仓库测试指引：复用真实 HTTP TestServer、现有前端/npm 浏览器入口及 toolkit 公共 interface；页面能力观察实际交付页面，宿主能力需要真实 Herdr/omp 证据。受控 adapter 只证明确定性故障/时序，不证明模型或原生宿主行为。

普通检查只用数值回环、独占临时数据/cwd/动态端口与必要 Herdr 副本，持续消费并清理所属子进程；不操作用户对话或产物，不绕过 npm 网络护栏。LAN/mDNS、真实符号链接和关机仍遵守显式人工授权规则。

自动化预期取自契约、独立字面样例或预先算定结果，不用被测实现重算预期。负向自动行为检查注明有界观察窗口并保留外部调用证据；取消/错误不得伪造快照或自动重试。真实环境缺失如实报告阻塞，不以替身或跳过宣称通过。
