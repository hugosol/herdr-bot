## 1. 高优先级：把“可交接”检查前移到完成出口

### 事实

- 用户提供的拒收原因精确列出了未提交票据及三个未跟踪目录；本轮首次 `git status --short` 返回相同内容（会话第 24 行）。
- 最终通过外移目录、提交票据和检查 porcelain 输出解决问题（第 55–63 行），没有修改或重测实现。
- **工作流已有干净工作树检查，而且确实阻止了接收。**问题不是缺少检查，而是直到完成被拒收后才补齐交接条件。
- 已读取仓库现有入口：`scripts/test-backend.mjs` 默认将日志写入系统临时目录，并继承 `CARGO_TARGET_DIR`；本票继承的验证命令显式把日志和 target 放进 `.scratch/`，绕开了前者的默认位置。`.gitignore` 只列有常规 `/backend/target`，没有覆盖本票自定义 target。

### 建议

在工作流的**实现完成出口**复用现有接收检查，先完成所属产物保全、应提交文件提交，再允许发出“交给集成”的完成信号。检查应区分已跟踪修改和未跟踪产物，并对用户或其他任务的文件只报告，不自动清理。

为每次 run 统一分配 worktree 外的产物根目录；日志继续利用现有 runner 默认能力，独占的 `CARGO_TARGET_DIR` 也落在该根目录。不要靠扩大 `.scratch/` 忽略规则来隐藏问题，否则票据和重要未提交内容也可能失去可见性。

**建议的完成判据：**交接出口直接返回提交标识、干净状态和可访问的证据根目录；本类问题在原执行内被拦截，而不是再启动一次实现 agent 才发现。

**推断边界：**没有读取工作流接收器源码，无法确定最便宜的接入位置，也不能断言现有出口完全没有类似预检；能确认的是本次仍走到了拒收后返工。

## 2. 中优先级：让证据定位独立于原 worktree 路径

### 事实

本轮成功保留了全部产物，但目录搬迁后，`summary.json` 内的 `outputDir`、日志绝对路径和 executable 路径仍指向原位置。agent 在票据中追加了搬迁说明，人工读者可据此找到新目录（第 58–60 行）。

### 建议

由宿主管理的交接元数据保存“运行标识 → 证据根目录”的映射，证据文件使用根目录下的相对路径。原始日志保持不变，保留当时执行环境；导航信息负责解释当前位置。

优先从运行开始就使用稳定的外置产物目录，避免最后搬迁。确需搬迁时，让交接工具返回新根目录及相对证据路径，不再依赖 agent 在票据正文里手写一组机器专属绝对路径。

**建议的完成判据：**独立集成者仅凭交接元数据即可打开汇总和指定日志，无需推断旧路径应替换成哪里。

**推断边界：**本轮没有发生证据丢失，也没有观察到消费者读取失败；这是针对已出现的路径失配提出的可靠性改进，不是已证实的故障。

## 3. 中优先级：为“只修复交接”的执行增加明确分支

### 事实

本轮用户明确要求保留已有工作、不要重复已完成检查。agent 最终遵守了这一点，但仍加载了 TDD 测试设计／mocking 参考和一段通用领域词汇；实际工作没有新增测试、替身、业务逻辑或领域决策。

同时，最终结果使用了 `implemented-and-verified` 状态，又在详细字段中说明验证来自此前执行、完整后端回归仍失败。人类阅读全文能够区分，单独消费总状态的工具未必能够区分。

### 建议

在现有 TDD／交接流程中设置一个正向触发分支：**继承实现和验证证据，仅修复接收条件**。该分支读取本票、原提交、实际证据和交接规则；只有发现代码／测试发生变化、证据不适用或验收缺口时，才进入对应 TDD 验证步骤。

让宿主分别记录：

- 交接状态：是否已提交、worktree 是否干净；
- 验证来源：本轮执行还是继承证据；
- 验证范围：本票定向通过、完整回归失败／未执行部分。

这应放在条件触发的流程分支或宿主结构化结果中，不宜向全局 `AGENTS.md` 增加一套每轮都加载的说明，也无需建立第二份人工维护的状态账本。

**建议的完成判据：**本类修复不触发无关测试设计阅读或重复验收；下游无需从自由文本里猜测“verified”究竟覆盖什么。

**推断边界：**本次结果确实详细披露了继承来源与未通过项，没有观察到下游误判；建议是消除状态歧义，而非认定本轮伪报验证。

### 建议

**建议的完成判据：**一份简短投影足以准确说明“55 个 binary 通过、1 个失败、5 个未派发、doctest 未执行”，随后只读取相关日志，避免先读折叠摘要再重读大对象。
