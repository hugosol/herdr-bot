# Ticket 14 TDD 执行复盘建议

## 范围与结论

本复盘仅依据指定 ticket 执行日志，截止实现轮的首次 `yield`；未读取父 session 或其他执行轮，也未重跑验收。下述行号均指该 JSONL 日志。

本轮 TDD 的主要证据成立：P43、P46 的新增检查首次通过，执行者没有为了凑 red 而破坏已满足的行为；P44 两项检查先在明确部分生效反馈缺失处失败，再补实现转绿。故障条件使用真实 Windows 文件权限，观察包含 HTTP、查询及磁盘；受控 Herdr 与真实宿主能力也有明确区分。最终 `workflow_dispatch` 为 **50 passed**，但完整后端回归未全绿。

优先改进点不是再增加“认真测试”的指令，而是让**交接完整性、运行前置和信息来源适用性**成为环境可检查的边界。

## 1. 高优先级：让交接检查覆盖票据与证据产物，而不只覆盖实现提交

**事实**：执行者修改了本票状态、验收勾选和结果说明；最后的 `git add` 明确只列出五个代码、测试及长期文档文件，没有列出票据。提交结果也是五个文件。验证产物则写入 worktree 内的 `.scratch/target-ticket14`、`.scratch/ticket14-verification` 和 `.scratch/ticket14-verification-prepared`，最终报告随即宣布交出 worktree。见日志第 298、320、333、336、339–343 行。

**推断与边界**：这说明“实现已提交”和“本轮所有交付物已完成交接”之间存在缺口。日志没有最终文件状态证据，因此不能仅据此断言工作区是否干净、目录是否被忽略，或集成系统一定拒收。

**建议**：由宿主交接入口执行一次非破坏性的 **handoff preflight**，而不是给实现者再追加一条笼统自查规则：

- 对照本轮实际修改清单，核对实现文件及票据处置是否都有明确归宿。
- 将构建缓存放到 worktree 外的独占目录；将需要保留的日志登记到证据清单，由宿主保存或搬运，并更新引用。
- 未提交票据、未归档证据、未结束所属进程等情况，以具体路径和处置要求阻止交接；保留文件，不自动 reset 或删除。

**完成标准**：故意遗漏一份已修改票据或留下一份未登记产物时，交接入口准确指出缺项；完整交接时，提交和证据清单足以供集成者复现，无需重新猜测文件归属。

## 2. 高优先级：把完整后端测试的前端产物依赖前移为 fail-fast 前置

**事实**：执行者在运行前已读 `docs/agents/testing.md`。该文档推荐完整后端入口，但其运行前提没有直接说明进程级后端检查需要已构建的前端。首次完整运行先完成约 68 秒构建，随后才在 `herdr_config` 发现 `backend/static/index.html` 缺失；整轮约 **146.8 秒**，39 个目标未派发。之后依照 README 执行离线安装与真实前端构建，`herdr_config` 才通过。见第 99、303、304–319、325 行。

**建议**：复用现有 `scripts/test-backend.mjs`，在昂贵构建和测试派发前检查所需静态产物。缺失时直接报告真实构建前置及 README 指针；不要生成空页面充数，也不要未经说明自动联网安装。测试指引只需补一个针对“完整后端／进程级检查”的清晰导航分支，无需复制 package 脚本或整段安装流程。

**完成标准**：在新 worktree、前端未构建的条件下，入口在启动 Cargo 构建前报告缺失产物；完成真实前端构建后继续正常执行。已有入口负责前置检查，文档负责解释依赖。

## 3. 中优先级：图索引必须绑定当前 worktree，跨 worktree 结果降级为导航线索

**事实**：项目列表没有直接提供当前 ticket worktree 的索引；执行者转而查询 `workflow-retry-13`。该索引的 `NodeState` 大纲没有当前源码中的 `previous_executions`，`save_run` 等行号也与当前源码不一致。后续确实出现读取错误范围、再次转向当前文件的过程。见第 104–142 行，尤其第 130 行大纲与第 162 行当前源码结果。

**推断**：跨 worktree 大纲能够帮助定位同名模块，却不能可靠承担当前源码的结构和行号依据。这里未观察到因陈旧索引造成的错误提交，但额外查询没有消除来源不一致。

**建议**：在图工具或宿主会话绑定层提供当前 cwd 对应的项目身份，并返回索引 root 与快照身份。索引不匹配时明确降级：结果可用于发现候选文件，实际符号和范围由当前 worktree 核实。优先修正工具绑定，不把“始终再确认所有图结果”的长规则塞进全局指令。

**完成标准**：两个 worktree 的同名文件存在不同字段或行号时，查询不会把其中一个的大纲无标记地当作另一个的当前事实。

## 4. 中优先级：为 Herdr 受控夹具补一个精准导航指针

**事实**：新增批次检查最初使用了未确认存在的 `native_session_prefix` 与 `request.finish()`。执行者随后经过多次目录和字符串查询，才找到 `HerdrFixture` 实际复制的 `backend/src/bin/herdr-fixture.rs`，以及 `OpenJsonRequest::response()`，并在运行测试前修正。见第 195–234 行。未发生可归因于这两处草稿的编译失败，不能把它们计作实际 red。

**建议**：在现有测试指引的夹具分支加一个简短指针，例如：

> Herdr 故障或时序测试：先读 `backend/tests/common/mod.rs` 的 `HerdrFixture`／`OpenJsonRequest`，行为键及 gate 约定见 `backend/src/bin/herdr-fixture.rs`。

把参数定义继续留在现有夹具源码及其注释中，避免再维护一份行为键表。此处是导航问题，不需要新增编码规范或专用 linter；现有 Rust 编译检查已经负责接口拼写。

**完成标准**：从测试指引沿指针即可找到真实进程夹具、支持的 gate 和请求完成方法，不必先猜测 `fixtures/lib` 是否承载该能力。

## 5. 中优先级：搜索服务不可用时，在工具层结束无效分支

**事实**：首次行为搜索中，`find` 发起的 26 个 judge 请求全部因同一地区限制返回 HTTP 451；工具正确声明这不是“未找到”的证据，执行者随后报告问题并改用其他搜索方式。见第 87、104 行。

**建议**：对明确的提供方不可用错误实施会话级熔断或前置可用性判断：首个足以确定全局不可用的响应后，停止继续扇出等价请求，返回失败原因及本地检索的候选线索。不要缓存为“没有匹配代码”，也不要通过添加全局禁用规则牺牲服务恢复后的能力。

**完成标准**：模拟地区性 451 时，工具只产生必要的失败请求，保留“搜索未完成”的语义，并提供可继续使用的本地导航信息。

## 6. 低优先级：收敛运行说明中的错误语义，分离操作说明与验证索引

**事实**：本轮读取时 `docs/workflow-runtime.md` 已约 60 KB；其中 complete/finish、retry、pause/resume 已各自解释状态提交与历史失败。本轮又在文件前部加入独立读取、部分提交、角色责任及一长段测试名称索引。见第 127、277–279 行。

**推断**：新增总则有价值，但同一错误语义散落多处，后续响应协议变化可能需要多点修改；大量测试名称还会占用运行者和角色 Chat 的阅读路径。这是维护风险，不是本轮已经证明的行为错误。

**建议**：以“独立记录与部分提交”为唯一权威解释区，各动作章节只保留自身特有的返回位置及链接。运行说明保留用户决策所需的状态含义、读取入口和下一步；测试实现细节放在现有测试指引的按需分支，通过一个指针到达。保留必须写明的语义，减少重复的禁止清单和易过期的测试清单。

**完成标准**：历史失败语义变化时，只需更新一个权威段落；读取某一动作的 Agent 能沿一个指针获得完整解释，而不必遍历整份长文。

## 应保留的做法与未验证项

- **保留已有行为首次即绿的处理**：P43、P46 没有制造无关失败；P44 的 red 证明的是明确反馈缺口，不应改写成“原有存储回滚机制错误”。
- **保留多面观察**：HTTP 成功或报错均与后续查询、实际文件、成功历史联合核对，外部 gate 保留在真实机制之外。
- **保留如实回归报告**：准备前置后的完整运行是 55 个 binary 通过、1 个失败、5 个未派发，doctest 未执行；失败在 `zone_commit` 的 10 秒观察断言。日志不足以认定它是既存失败、环境偶发或本票引入的问题，不建议据此自动重跑、扩大超时或跳过。
- **不新增泛化 TDD 禁令**：本轮没有证据表明需要强制所有检查都出现 red，或强制每项通过后都做 mutation。
- 本复盘未审查 CI、Git hooks、集成后的工作区或真实角色宿主，因此不宣称仓库缺少全局 guardrail，也不评价尚未观察到的 reviewer 或集成结果。

以上均为环境改进建议，本轮未执行任何建议、修改文件或继续实现。
