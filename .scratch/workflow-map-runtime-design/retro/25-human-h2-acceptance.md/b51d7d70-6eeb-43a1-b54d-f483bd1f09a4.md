## 2. 高：为人工票统一“完成”的含义

**事实**

本轮加载的执行要求包含“持续执行直到票据 closed”，而本票明确要求用户未确认时保持 `ready-for-human`、不得关闭；仓库状态说明还将 `closed` 与实现、测试、合并关联。本轮又被要求交出 worktree，由独立代理集成。

代理正确保留未通过状态，但必须自行解释这些不同层次的完成条件。

**建议**

在执行宿主的票据路由中，为人工验收票单列分支：

- Agent 的终点：核对证据，记录通过条件或精确阻塞，提交自己拥有的变更并交接。
- 用户的终点：对完整证据给出明确判断。
- 集成的终点：由独立集成流程负责。

让该分支替换通用的“直到 closed”要求，而不是在后面继续追加例外。使用正向、可检查的完成条件，避免把 Agent 调用结束、提交成功和契约验收通过混成一个状态。

**改进验收**：遇到缺证据或缺用户判断时，代理能合法完成自己的交接，同时票据和 promise 继续保持未通过，不需要靠临场推导化解指令冲突。

## 4. 中：将票据 Comments 收束为证据索引，而非第二份验收指南

**事实**

**建议**

1. 本次审查结论及仍未满足的验收项；
2. 对应原始证据的精确链接；
3. 后续由谁提供什么证据，何时再请用户判断。

保留“历史证据不是本轮重验”的限定。对证据真实性、使用是否清楚可行等判断，继续由 Agent 审查和用户判断承担，不用关键词检查替代。

**改进验收**：读者能快速区分“本轮新增结论”和“被引用的既有结果”；操作规则变化时只需维护长期指南，不必同步改写多个票据中的同义说明。
