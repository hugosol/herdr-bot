**完成标准**：每项真实宿主验收都能对应到已具备的前提，或明确标为外部阻塞；不再出现可写范围内无法闭合、却仍被无条件标为可完整执行的票据。

## 2. 高：让 TDD 的红灯分类和共享夹具消除设置噪声

**事实**

首次红灯是缺少 `run_directory` 的编译错误，随后才到达 HTTP 404。之后又依次遇到外部扩展入口缺失、原生引用夹具把 `source` 写成 `omp` 而非 `herdr:omp`、前端缺少 `tsc`、HTTP helper 参数类型错误，以及路径规范化导致的预期差异。浏览器第一次还因把现有按钮 `+ 发起 Run` 写成 `发起 Run`，消耗了完整 90 秒超时；第二次才到达真正缺少的“启动 Run”动作。

这些失败最终都被识别并修正，没有被冒充为行为证明。

**建议**

- 在现有测试支持层提供经过验证的角色启动夹具：隔离元数据入口、官方原生引用字面样例、独立数据目录及稳定说明路径。只准备外部条件，不复制 Run 业务规则。
- 在新 worktree 准备阶段完成锁文件依赖安装，避免把工具未安装混入功能红灯。
- 让执行记录区分**设置红灯、接口红灯、行为红灯**；只有后者，或明确允许的接口缺失，支持进入相应实现切片。现有 TDD skill 已有此要求，应改善夹具和记录呈现，而不是再添加一份同义禁令。
- 对预期缺失的 UI 动作使用局部、短时的存在性断言，先确认既有导航已到位，避免让整个用例时限承担“元素本来就不存在”的判断。

**完成标准**：复用夹具的新场景可直接到达目标条件；失败报告能说明是否真正触达了待验证行为。

**建议**

对于具有明确外部顺序承诺的票据，先让外部 gate 与实际记录形成一条最小 tracer bullet，再逐项加入身份、关联、提交故障及 status。为每个当前切片保留一句具体的**反例**：什么错误实现会被本场景识别。这里的 P16 应从一开始就使用互异的非空文档与工作信息标记，P2 的空文档继续作为独立场景。

**完成标准**：每个已认领行为都有能到达其条件、并区分其具体反例的测试；空样例不再被用于证明非空信息没有泄漏。

## 4. 中高：把验收证据落盘做成确定性的公共测试能力

**事实**

最初使用 `testInfo.attach({ body: ... })` 保存外部调用及运行记录。执行尾声检查实际输出目录时，只看到了截图，没有找到这些 JSON 文件。随后改为显式写入 `outputPath()`，再次运行三项浏览器场景，才保留了调用、记录和失败效果文件。

**建议**

在现有浏览器支持层提供一个小的 `writeEvidence` helper：将 JSON 写入用例输出目录，再按需要把同一路径附给 reporter。证据命名与保存规则只保留一个来源。对要求“留证”的场景增加产物检查，验证约定文件存在且可解析；不要用新的断言重新实现业务预期。

**完成标准**：采用当前 reporter 的成功运行结束后，调用者无需从聊天输出重建证据，即可读取承诺的文件。上述发现只针对本次 reporter／输出配置，不应推导为所有 Playwright attachment 都不会持久保存。

**建议**

- 让顶层导航变更优先触发已有的 tab 键盘、浏览器导航和窄屏检查，再进入完整验收。
- 在仓库内显式接线现有检查入口到合适的提交或 CI 门禁；网络护栏继续独立执行，但不把它视为业务回归已经运行。
- 保留测试侧独立的导航字面预期，避免直接导入生产 tab 数组来消除失败，从而把测试改成同源自证。

这些是确定性检查与入口接线问题，不适合增加依赖人工判断的 `CODING_STANDARDS.md` 条目。

**完成标准**：导航顺序或窄屏布局出错时，现有测试能在交接前自动阻止进入成功状态；门禁是否运行有可读结果。
