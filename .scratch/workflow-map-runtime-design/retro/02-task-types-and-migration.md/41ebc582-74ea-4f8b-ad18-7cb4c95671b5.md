# TDD 执行复盘建议

## 范围与结论

本复盘只依据指定 ticket 执行的 JSONL 原始记录及其中的工具结果，不引用父 session 或其他 ticket 的执行结果；本轮未修改文件、执行建议或重跑验收。

本次形成了有效的行为证据：HTTP 默认类型缺失、页面类型入口缺失、列表混装角色扩展、旧可选字段迁移失败都出现过可观察的 red；迁移测试还通过临时清空 `prompt` 的故障注入证明了字段保留断言的敏感性，随后恢复正确实现。最终记录显示：后端完整入口通过，前端 205 项通过，浏览器 301 项通过、1 项显式手动检查跳过，迁移 CLI 4 项通过。

但“自动化通过”不等于“全部验收完成”：最终交接明确保留了真实 Herdr/omp Resume 未验证这一缺口。以下建议按严重度排序。

## 1. 高：把真实宿主验收准备前置，并明确隔离实验的授权分支

**事实**：票据要求实际迁移、重启读取及 Resume，并明确受控 adapter 不证明原生宿主行为。本次在受控 Resume 已通过后，才读取真实 Herdr 的 `--help`、`--skill` 并检查环境。三个 Herdr 上下文变量均为空；宿主指引要求在管理 pane 内控制会话，同时又提到隔离实验使用命名测试 session。记录中没有独占宿主副本或命名测试 session 的实际启动尝试，也没有这条路径明确不可用的证据。

**判断**：停止触碰用户会话是正确的安全选择；但证据只能支持“真实宿主验收未执行、当前控制上下文受限”，不能进一步证明“所有安全隔离路径均不可用”。这里首先是验收环境入口不清晰，而不是应当降低验收标准。

**建议落点**：在现有 `docs/agents/testing.md` 的真实宿主分支提供一个经维护者批准的隔离验收入口，或指向已有入口。把“控制当前用户会话”和“创建本次测试拥有的宿主实例”分别说明，明确各自前提与授权边界。由宿主在启动相关 ticket 前提供或检测这些前提，减少实现后才发现证据缺口的情况。

**完成标准**：该分支能明确给出“可执行、需授权、明确不可用”之一；可执行时记录独占数据位置、目标宿主身份、原生 Chat 身份及所属进程清理结果。受控测试仍保留，但单独标注证明范围。

## 2. 高：让 red 对应当前行为，而不只对应复合测试的第一个失败点

**事实**：最初的 HTTP 测试同时覆盖默认类型、角色与 agent 组合、类型切换、扩展限制；首次 red 只到达 `Null != "normal"`。随后一次实现加入了多项约束。后续还暴露出编辑请求误用 POST 导致 405，而不是预期的业务拒绝。迁移首次 red 则是脚本不存在，尚未到达字段保留断言。

**判断**：这些初始失败分别证明了默认字段缺失、路由方法错误或入口缺失，并不各自证明后续每条业务约束已经经历 red。最终测试有覆盖，不应因此反推整个实现过程都已逐项 test-first。迁移的后续故障注入很好地补强了这一点。

**建议落点**：收紧现有 TDD skill 的执行判据，而不是再增加一份流程文档。每个 tracer bullet 绑定一条当前行为、一个具体违例及一个可到达的观察点。复合测试在前置断言失败时，只记录该前置条件的 red；其余行为继续通过下一条 tracer 或必要的定向故障注入建立证据。

**完成标准**：每项新增约束能对应到一次针对该约束的行为失败，或明确记录为已有行为及其现有覆盖。编译、依赖、导入、路由和缺失入口失败与行为 red 分开表述，预期值始终来自契约或独立样例。

## 3. 中：用类型检查提前发现现行 Task 夹具漏迁移，保留独立契约预期

**事实**：新增必需字段 `taskType` 后，前端首次回归有 22 项失败；后端一个稳定字段数量断言仍期待 9 而不是 10。完整浏览器回归先出现 11 项失败，修正后仍有 2 项遗漏，最后才达到全量通过。多处原因是现行 Task 字面夹具或严格字段集合漏迁移。生产构建中的 `tsc --noEmit` 没有提前阻止这些遗漏。

**已有检查**：记录中的 `package.json` 已提供类型检查加构建、Vitest、完整浏览器入口及网络护栏。建议复用这些入口，不重建另一套测试平台。测试源码的具体 TypeScript 纳入范围、CI 和提交 hook 是否接线，本次历史未完整核验，不能据此认定它们不存在。

**建议落点**：对表示“当前合法 Task”的前端和浏览器夹具使用公共类型约束，例如 `satisfies Task` 或 `satisfies TaskInput`，并确保已有类型检查入口实际检查这些声明。故意表达旧格式或非法输入的样例保留独立类型边界。

**完成标准**：漏写当前必需字段时，现行合法夹具在轻量检查阶段就失败；旧格式迁移与非法 HTTP 样例仍能有意构造。字段集合、标签和迁移结果的期望继续保持独立字面值，不通过被测序列化器或响应反算期望。跨视图是否一致仍由真实页面测试和评审判断，不用静态字段检查替代。

## 4. 中：让异步测试在终态失败时立即给出完整原因

**事实**：角色环境装配测试轮询 `stage === succeeded`，实际任务已经进入 `failed`，却等满 10 秒才报告失败。随后查看实现与夹具，确认空输入会被拒绝，再为该装配场景提供非空输入。

**建议落点**：改进浏览器测试的完成观察方式：先等待任一终态，再断言预期终态；失败时附上公开任务响应和该测试拥有的外部调用记录。让前置条件错误直接呈现为前置条件错误，而不是通用轮询超时。

**完成标准**：不可恢复的 `failed` 立即终止等待并显示原因；真正仍在进行的任务才耗尽等待预算。测试只观察既有公开边界，不为诊断新增产品接口，也不自动重试业务动作。

## 5. 中低：把工具默认输出收敛为摘要，详细材料按需展开

**事实**：本次两次行为检索各在 20 秒后超时；随后一次图查询选用了其他路径的项目并返回零结果，之后才索引当前 worktree。另有两个明显的输出膨胀点：早期批量编辑打印完整工具对象，带出整段旧、新源码；浏览器分区检查输出约 7,376 行 manifest，而当前决策只需要分区数量与一致性结果。后续编辑调用改为仅打印 `.text`，已经展示了更紧凑的可行方式。

**建议落点**：

- 由宿主提供与当前 worktree 精确对应的索引项目身份和覆盖提示；零命中时先区分索引路径不符、覆盖缺口与确实无结果。
- 编辑结果默认显示成功或失败及窄 diff；完整快照保留为按需读取的 artifact。
- 浏览器分区检查默认显示数量、交并集结论及详细产物位置，完整 manifest 通过显式详细模式获取。

**完成标准**：常规成功输出足以作出下一步决定；失败输出保留定位信息，详细证据仍可读取。优先改进工具契约和默认输出，不把这些机械约束堆进 reviewer 规则或全局 `AGENTS.md`。

## 建议保留的做法

- 保留实际 HTTP、交付页面、迁移 CLI 和真实进程重启这些已批准 seam；本次测试确实发现了只看编辑表单会漏掉的列表角色混装问题。
- 保留迁移的定向故障注入方法：它证明断言能够识别真实字段丢失，而不只是证明命令成功退出。
- 保留最终交接中的证据分层：受控 Herdr 参数装配、实际后端流程、真实原生宿主能力分别报告；手动授权检查的 skip 与通过分开报告。

根目录 `AGENTS.md` 在本次记录中很短，且已有测试指引指针。没有证据支持再增加一层总纲；优先完善既有测试分支、确定性检查和工具输出。
